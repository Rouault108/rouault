# Rouault

**Rouault（ルオー）** は、個人的なメモ（ノート）を閲覧するための専用Webアプリケーションです。
一般的なドキュメントサイトのように、サイドバー・メモ本文・目次（TOC）の **3カラム構成** でコンテンツを整理し、プライバシーを重視したセキュアな環境でナレッジベースにアクセスできます。

---

## 🎯 プロジェクトの目的

- **パーソナルナレッジマネジメント**: 音楽、文学、美術、計算機科学など多様なジャンルのメモを閲覧・整理
- **プライバシーファースト**: Cloudflare Access による認証なしではコンテンツにアクセス不可
- **高アクセシビリティ**: WCAG 2.1 Level AA 準拠を目標
- **モダンブラウザ最適化**: 古いブラウザの互換性より機能性を優先
- **恒久的リンク**: コンテンツの各バージョンを永続的に参照可能

## 📐 サイト構成

### レスポンシブブレークポイント

| サイズ | 幅 | カラム構成 |
|--------|-----|------------|
| **デスクトップ** | ≥768px | 3カラム（サイドバー + メモ + TOC） |
| **タブレット** | 768px未満 〜 中間 | 2カラム（メモ + TOC）、サイドバーはボタンで開閉 |
| **モバイル** | 小 | 1カラム + スティッキー要素 |

### ページレイアウト

#### デスクトップ（3カラム構成）

```
┌─────────────────────────────────────────────────────────────────┐
│ [スキップリンク: メインコンテンツへスキップ]                       │
├─────────────────────────────────────────────────────────────────┤
│                     <header> ヘッダー                            │
│ [ロゴ]  [ジャンル一覧▼] [このサイトについて]    [🔍 検索] [テーマ] │
├────────────┬──────────────────────────────────┬─────────────────┤
│  <aside>   │           <main>                 │    <aside>      │
│ サイドバー  │          メモ本文                 │      TOC        │
│ (階層選択)  │                                  │  (自動階層化)    │
│ (タグ絞込) │                                  │                 │
├────────────┴──────────────────────────────────┴─────────────────┤
│                     <footer> フッター                            │
│                       © 著作権表記                               │
└─────────────────────────────────────────────────────────────────┘
```

#### タブレット（2カラム構成）

- **ヘッダー**: デスクトップと同様
- **サイドバー**: 非表示（左下にフローティングボタンで開閉）
- **メイン**: メモ本文
- **TOC**: 右側に表示

#### モバイル（1カラム＋スティッキー要素）

- **ヘッダー**: ロゴ + 検索アイコン + テーマボタン + ハンバーガーメニュー
- **スティッキーTOC**: ヘッダーの高さ分スクロール後に表示、現在のセクションタイトル + **円形の極小プログレスインジケータ**
- **サイドバーボタン**: 画面左下にフローティングアイコン
- **ホームアイコン**: スティッキーTOC左側に常時表示

### メモの構成

```markdown
[パンくずリスト] ← 5階層以上は中間を「...」で省略
[ドラフトアイコン（draft: true の場合）] [タイトル]
[説明]
[タグ（ジャンル）] ← High Density UI（高密度・小フォント）、色分け、クリックで一覧ページへ
[ライセンス表記（あれば）]
[作成日・更新日] ← CI/CDで自動更新（2024年1月21日 形式）
────────────────── （ボーダーライン）
[メモ本文] ← デフォルトフォントサイズ 14px
```

- **1カラム構成**（ただし3カラム時と同じ幅を維持、左右は空白）
- 記事は **リスト形式** で表示（タイトル + メタデータ）

- カスタム404ページを用意

│   └── jazz/

├── literature/                 # 文学ジャンル
├── art/                        # 美術ジャンル
├── computer-science/           # 計算機科学ジャンル
├── economics/                  # 経済学ジャンル
├── sociology/                  # 社会学ジャンル
├── political-science/          # 政治学ジャンル
├── law/                        # 法学ジャンル
└── mathematics/                # 数学ジャンル

### ファイル名規則

- **ケバブケース必須**（例: `the-nutcracker.md`）
- **日本語ファイル名は使用しない**（URLエンコード問題を回避）
- サイドバー表示名はフロントマターの `title` を使用

### メモのフロントマター

```yaml
---
title: "楽曲分析: くるみ割り人形"
description: "チャイコフスキーのバレエ音楽を分析したメモ"
genre:                          # タグ一覧・色分け用（ディレクトリ構造とは独立）
  - music
  - classical
  - ballet
cover: "/images/covers/nutcracker.jpg"  # OGP/メタ画像用
license: "CC BY 4.0"
licenseNote: "© Original Author"
draft: false                    # true でドラフトアイコン表示（デフォルト: false）
---
```

### ディレクトリ vs タグ（genre）の関係

| 項目 | ディレクトリ構造 | genre（フロントマター） |
|------|------------------|------------------------|
| **用途** | サイドバー分類、木構造ナビゲーション | タグ一覧ページ、色分け |
| **整合性** | **不要**（独立して管理） | — |
| **例** | `music/classical/tchaikovsky/` | `[music, analysis, ballet]` |

### 並び順設定（_config.json）

```json
{
  "order": [
    "the-nutcracker.md",
    "swan-lake.md"
  ]
}
```

- **継承なし**（各ディレクトリ独立）
- 指定がないファイル: **アルファベット順 → 日本語順**

### ドラフト機能

- `draft: true` を指定した場合:
  - メモタイトル前にドラフトアイコン（`aria-label="下書き"`）を表示
  - サイドバーのタイトル前にもドラフトアイコンを表示
- デフォルト: `false`

## 🔗 パーマリンク戦略

コンテンツの内容が変わっても参照先の内容が保証される**恒久的リンク（Permanent URL）**を提供。

### URL方式

| URLタイプ | 形式 | 役割 |
|-----------|------|------|
| **Canonical URL** | `/{slug}` | 最新版の表示、SEO、シェア |
| **Permanent URL** | `/archives/{hash}` | 引用、過去版参照（`robots: noindex`） |

### ハッシュ仕様

| 項目 | 仕様 |
|------|------|
| **URL構造** | `/archives/{hash}` |
| **ハッシュ長** | 12文字（SHA-256の先頭48bit） |
| **ハッシュ形式** | 小文字の16進数 |
| **ハッシュ対象** | 正規化後の Markdown 全体（Frontmatter + 本文、`updated_at` 除外） |

### 正規化処理

1. `updated_at` フィールドを除外
2. 改行コードを `LF` に統一
3. 末尾の空白を除去
4. ファイル末尾に改行を追加（POSIX準拠）
5. SHA-256を計算し、先頭12文字をハッシュとして使用

### アーキテクチャ

| コンポーネント | 役割 |
|---------------|------|
| `config/permalinks.json` | ハッシュ履歴とメタデータを管理 |
| Cloudflare R2 (`rouault-archives`) | 正規化後 Markdown を保存 |
| Cloudflare Workers | `/archives/{hash}` へのアクセス時に R2 から取得・レンダリング |

### permalinks.json スキーマ

```json
{
  "currentHash": "a1b2c3d4e5f6",
  "history": [
    { "hash": "a1b2c3d4e5f6", "date": "2025-12-22", "message": "バージョン2.0" },
    { "hash": "f7e8d9c0b1a2", "date": "2025-11-01", "message": "初版公開" }
  ]
}
```

### 衝突対策

| ケース | 対処 |
|--------|------|
| 新規コンテンツ | 新規ハッシュとして登録、R2にアップロード |
| 同一コンテンツ（Revert等） | 既存ハッシュを使用（再アップロード不要） |
| 衝突（ハッシュ一致、内容不一致） | ハッシュを16文字に延長して再計算 |

### CI/CDフロー

```
main ブランチへの PR マージ
  ↓
GitHub Actions: アーカイブ生成ジョブ起動
  ↓
変更された記事を検出（git diff）
  ↓
各記事に対して:
  1. 正規化処理
  2. ハッシュ計算（12文字）
  3. permalinks.json で重複チェック
     ├─ 重複なし → R2 にアップロード、permalinks.json 更新
     └─ 重複あり → スキップ
  ↓
permalinks.json をコミット（自動）
```

## 🏭 レンダリング戦略 (SSG/SSR)

### コンセプト: Hybrid SSG + Client Hydration

本プロジェクトでは **SSG (Static Site Generation)** を基本としつつ、`@lit-labs/ssr` を活用して Web Components をビルド時にプリレンダリングします。

### アーキテクチャ判断

1.  **`@lit-labs/ssr` の用途**
    *   **SSG 目的で使用**: リクエスト毎の動的レンダリング（SSR）ではなく、Eleventy のビルドプロセス内で Lit コンポーネントを HTML 文字列に変換するために使用します。
    *   **ハイドレーション**: クライアント側で Lit がロードされると、既存の Declarative Shadow DOM を「活性化」（Hydration）し、インタラクティブになります。

2.  **擬似的な ISR (Incremental Static Regeneration)**
    *   Cloudflare Pages の **「Git プッシュごとの自動ビルド」** を活用します。
    *   コンテンツ更新頻度が比較的低いため、動的な ISR（Next.js のようなオンデマンド再生成）ではなく、修正のたびに静的ファイルを全生成する SSG で十分と判断しました。
    *   これにより、CDN エッジからの超高速配信（TTFB の最小化）と、最新コンテンツの維持を両立します。

3.  **SSR (リクエスト時生成) を採用しない理由**
    *   個人メモという性質上、ユーザーごとに異なる動的コンテンツが少ないため。
    *   検索機能（Pagefind）やナビゲーションはクライアントサイドで効率的に動作するため。

### レンダリングフロー

```mermaid
graph TD
    A[Markdown Content] -->|Eleventy Build| B(Static HTML Generation)
    C[Lit Components] -->|@lit-labs/ssr| B
    B --> D[Cloudflare Pages / CDN]
    D -->|Request| E[Browser]
    E -->|Declarative Shadow DOM| F[Fast FCP]
    G[Client JS] -->|Hydration| H[Interactive UI]
```

## ♿ アクセシビリティ

### 目標

**WCAG 2.1 Level AA** 準拠

### 実装

| 機能 | 実装方法 |
|------|----------|
| **スキップリンク** | ページ先頭に「メインコンテンツへスキップ」リンク |
| **ランドマーク** | `<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>` |
| **セマンティックHTML** | 適切な見出し階層、リスト、テーブル構造 |
| **ARIA属性** | `aria-label`, `aria-describedby`, `aria-live` |
| **フォーカス管理** | 可視フォーカスリング、論理的なタブ順序 |
| **カラーコントラスト** | 4.5:1 以上（通常テキスト）、3:1 以上（大きなテキスト） |
| **モーション配慮** | `prefers-reduced-motion` 対応 |
| **ドラフトアイコン** | `aria-label="下書き"` を追加 |

### 非実装

- **キーボードショートカット**: VoiceOver 等のスクリーンリーダーとのショートカット競合を避けるため非実装
