# Search Trigger

## 概要

本書は、`ui-search-trigger` の公開契約、状態モデル、アクセシビリティ、視覚契約、および関連する統合条件を整理するものです。

`ui-search-trigger` は、ヘッダーやツールバーに配置される、**検索ダイアログの起動要求を通知する stateless launcher** です。見た目は検索入力欄に近い外形を取りますが、実体はネイティブ `<button>` であり、文字入力、検索語保持、ダイアログ状態保持は行いません。

したがって、本コンポーネントの契約は、**検索入力のように見えること**ではなく、**検索ダイアログの起動主体として誤解なく機能すること**を優先します。Input-like な外形は二次的な visual idiom にとどまり、意味論の中心は launcher にあります。Rouault においては、読書中の視線を過度に乱さず、必要なときに検索へ移行できる静かな導線として扱います。

---

## 適用範囲

本書は、`ui-search-trigger` の次の事項を対象とします。

- 公開契約
- 状態モデル
- DOM / Accessibility
- Visual Contract
- 環境別の振る舞い
- 関連契約
- 境界条件
- Storybook 契約
- 現行実装で未対応または未整合の事項

一方で、本書は次の事項を扱いません。

- 検索インデックスの生成
- 検索クエリの入力、補完、履歴管理
- `ui-search-dialog` 自体の描画と状態管理
- グローバルショートカットの登録
- 検索結果の表示やナビゲーション
- アプリケーション全体の検索体験設計

これらは上位レイヤまたは別コンポーネントの責務です。

## 設計の基本方針

`ui-search-trigger` では、長期的な設計の安定性のため、次を固定します。

- 本体の役割は **search dialog launcher** であり、input control ではありません。
- `placeholder` は **視覚ラベル専用** とし、検索コンテキストやアクセシブル名を兼ねません。
- `open-search-dialog` は **起動要求イベント** であり、開状態の真実源泉を持ちません。
- ダイアログ状態、ショートカット登録、フォーカス復元は上位レイヤの責務です。
- Input-like な見た目は visual idiom であり、意味論の中心ではありません。

## 公開契約

`ui-search-trigger` は、`placeholder` と `disabled` を公開入力として扱います。内部実装はネイティブ `<button>` ですが、利用者は `ui-search-trigger` を契約単位として扱います。

`placeholder` の既定値は `"検索..."` です。これは **視覚表示用のラベル** であり、アクセシブル名、検索対象スコープ、検索語初期値を兼ねません。アクセシブル名は button の `aria-label` により独立して与えます。

`disabled=true` の場合、内部 button は無効化され、ユーザー操作およびプログラム的起動の結果として `open-search-dialog` を発火しません。

### 入力契約

| 名前 | 種別 | 必須 | 内容 | 契約 |
| --- | --- | --- | --- | --- |
| `placeholder` | property / attribute | いいえ | 視覚表示用テキスト | 既定値は `"検索..."` です。アクセシブル名には使用しません。 |
| `disabled` | property / attribute | いいえ | 無効状態 | `true` の場合、内部 button を無効化し、起動しません。 |

### 入力値正規化契約

`placeholder` は次の規則で解釈します。

- 属性未指定、`undefined`、property 未設定時は既定値 `"検索..."` を使用します。
- 空文字 `""` は有効値として受理します。
- `placeholder` は視覚表示専用であり、アクセシブル名、検索語の初期値、検索対象スコープとして解釈しません。
- 長文、改行、過剰な文字数は 1 行表示の省略表現に吸収し、複数行表示にはしません。
- `placeholder` の意味は、「この control が検索起動導線であることの視覚説明」に限定します。

本契約は、`placeholder` を入力モデルや検索コンテキストへ接続しないこと、および文字列の見え方がコンポーネント責務の範囲で閉じることを固定します。

### 公開イベント契約

`ui-search-trigger` は、明示的なアクティベーション時に `open-search-dialog` を発火します。

| 名前 | 発火条件 | bubbles | composed | cancelable | detail |
| --- | --- | --- | --- | --- | --- |
| `open-search-dialog` | click または button 既定のキーボード起動 | `true` | `true` | `false` | なし |

このイベントは、検索ダイアログを **自動で開く command** ではなく、**上位レイヤに起動要求を通知する request event** です。利用側はこのイベントを監視し、`ui-search-dialog` の表示制御へ橋渡しします。

加えて、次を固定します。

- イベントは内部 button ではなく、**ホスト要素 `ui-search-trigger` の公開契約**として扱います。
- 1 回のアクティベーションに対して、`open-search-dialog` は 1 回だけ発火します。
- pointer 操作、Enter / Space による button 起動、公開 `click()` は同一の起動契約へ合流します。
- `detail` は持たず、追加のペイロードに依存しません。

### 公開メソッド

`ui-search-trigger` は、ホスト要素に対する基本操作を内部 button へ委譲するため、次の公開メソッドを持ちます。

| 名前 | 種別 | 契約 |
| --- | --- | --- |
| `focus(options?)` | method | 内部 button にフォーカスを委譲します。 |
| `blur()` | method | 内部 button からフォーカスを外します。 |
| `click()` | method | 内部 button の click を起動します。 |

これらは Shadow DOM 内部実装を利用側に露出させないための公開面です。利用者は Shadow DOM を直接探索せず、これらの公開メソッドを使用します。

加えて、長期契約として次を固定します。

- `click()` はユーザー click と同じ起動契約へ合流します。
- `focus()` と `blur()` は内部 DOM 詳細を隠蔽するための便宜 API であり、検索状態の変更を伴いません。
- これらの API は launcher の意味論を補助するものであり、内部構造への依存点を増やすためのものではありません。

### 属性反映契約

`placeholder` と `disabled` は property と attribute の両面から操作できます。`disabled` は boolean attribute として扱います。

| property | attribute | reflect | 備考 |
| --- | --- | --- | --- |
| `placeholder` | `placeholder` | あり | 既定値は `"検索..."` です。 |
| `disabled` | `disabled` | あり | boolean attribute として扱います。 |

### CSS Parts 契約

現行実装が公開している `part` は次のとおりです。

| part 名 | 役割 |
| --- | --- |
| `button` | 内部ネイティブ button |
| `icon` | 検索アイコンのラッパー |
| `placeholder` | プレースホルダー表示領域 |

利用者は `::part(...)` に対して装飾調整を行えます。ただし、意味を変更するための display 構造破壊、button 性の喪失、アクセシビリティ属性の破壊は行いません。

### 非対応公開面契約

次のものは、現行の公開契約に含めません。

- `slot` と slot-based composition
- 子ノードの描画や透過表示
- `name` `value` `form` などのフォーム参加属性
- form-associated custom element としての振る舞い
- 内部 button 以外の Shadow DOM 構造への依存
- 内部 class 名や未公開 `part` への依存

したがって、利用者は `ui-search-trigger` を **単一責務の検索起動ボタン** として扱い、入力コントロールやフォームコントロールとしては扱いません。

### 責務範囲

責務範囲には、内部 button の描画、状態に応じた属性反映、検索 trigger としての視覚表現、アクティベーション時の `open-search-dialog` 発火、レスポンシブ時の icon-only 表示、および必要なアクセシビリティ属性の付与を含みます。

一方で、検索ダイアログの開閉状態を保持すること、グローバルショートカットを監視すること、入力値を管理すること、検索結果を表示することは責務に含めません。フォーム送信、値の保持、バリデーション参加、候補提示も責務に含めません。

要するに、本コンポーネントは **検索機能そのもの** ではなく、**検索機能への入口** だけを責務とします。

## 状態モデル

`ui-search-trigger` の主要状態は、**launcher として起動可能か、無効か、visual idiom をどこまで保持するか、狭い画面でどう縮退するか** によって読み分けます。なお、本コンポーネントは open / closed の内部状態を持ちません。

### 基本状態

最小状態は、`placeholder="検索..."`、`disabled=false` の状態です。この状態では、検索アイコンとプレースホルダーテキストを持つ静かなトリガーとして振る舞います。

### 無効状態

`disabled=true` の場合、内部 button は `disabled` となり、ポインター操作およびキーボード操作の起動対象になりません。視覚上は不透明度低下と `not-allowed` カーソルを伴います。

### フォーカス状態

`focus-visible` 時には、背景色を通常時より明るい面へ切り替え、境界線とアウトラインを表示します。これは **launcher が起動可能状態にある** ことを示す視覚状態であり、入力準備そのものを意味しません。フォーカス取得だけでは検索ダイアログを開きません。

### 押下状態

`active` 時には背景色と境界線を強め、`transform: scale(...)` によって軽いタクタイルシグナルを与えます。押下状態は一時的なものであり、保持状態は持ちません。

### モバイル縮退状態

`max-width: 640px` では、プレースホルダーを非表示にし、アイコンのみの正方形ボタンへ縮退します。これは情報量の削減ではなく、限られた横幅で検索導線を維持するための状態です。

### 空プレースホルダー状態

`placeholder=""` は受理します。この場合でも button 自体の機能は維持され、アクセシブル名も固定 `aria-label` により保たれます。ただし、デスクトップ表示における説明力は低下するため、通常運用では空文字列に依存しません。

## DOM / Accessibility

ルートは `:host` です。Shadow DOM 内部に単一のネイティブ `<button>` を持ち、その内部にアイコンとプレースホルダーを配置します。

```text
<ui-search-trigger>
  #shadow-root
    <button part="button" type="button">
      <span class="icon" part="icon" aria-hidden="true">
        <iconify-icon icon="lucide:search" aria-hidden="true"></iconify-icon>
      </span>
      <span class="placeholder" part="placeholder" aria-hidden="true">
        検索...
      </span>
    </button>
</ui-search-trigger>
```

### Accessibility 契約

アクセシビリティ上の重要点は次のとおりです。

- 対話主体はネイティブ `<button>` です。
- `type="button"` を明示し、フォーム送信の副作用を持ちません。
- button は固定 `aria-label="検索ダイアログを開く"` を持ちます。
- button は `aria-haspopup="dialog"` を持ち、ダイアログ起動を予告します。
- button は `aria-keyshortcuts="Control+K Meta+K"` を持ち、支援技術へショートカットを通知します。
- アイコンおよびプレースホルダーは `aria-hidden="true"` とし、アクセシブル名の計算に参加しません。
- `placeholder` は視覚表示専用であり、アクセシブル名の代替手段ではありません。

本コンポーネントで重要なのは、**入力欄に似た見た目であっても、実体として button を維持すること** です。`div[role="button"]` や擬似入力欄には依存しません。

### フォーム文脈契約

`ui-search-trigger` はフォーム文脈に配置できますが、フォームコントロールにはなりません。次を固定します。

- `type="button"` により、form submit の起点になりません。
- 値を持つコントロールとして扱いません。
- 制約検証、送信データ構築、既定値復元の対象になりません。
- `name` `value` `form` などのフォーム参加 API は公開しません。

この契約により、見た目が入力欄に近くても、フォーム入力部品として誤用しません。

## Visual Contract

`ui-search-trigger` の視覚契約は、**検索導線として静かに認識できること** と、**実際には入力不可の launcher であること** を同時に伝えることにあります。検索入力欄に似た見た目は採りますが、それは launcher の性質を補助する visual idiom であり、契約の中心ではありません。

### Input-like visual idiom

本コンポーネントは、検索ボックスに似た外形を持ちます。ただし、これは input control であることを意味しません。launcher としての静かな導線を成立させるため、入力欄に近い外形を借りています。

テキストカーソルや入力フォーカスの期待を生まないよう、通常時のカーソルは `pointer` ではなく `default` を用います。これは、通常のボタンほど強く自己主張せず、しかし入力欄でもないことを示すためです。このカーソル方針は search-trigger 固有の例外仕様であり、汎用 button 群へ一般化しません。

### レイアウト

- ルートは `inline-flex` です。
- 内部 button は `inline-flex` で中央配置します。
- デスクトップでは、検索アイコンとプレースホルダーを横並びに配置します。
- button の高さは既定で `32px`、幅は `120px` に固定します。
- モバイルでは、正方形の icon-only 表示へ縮退します。

### 占有レイアウト契約

`ui-search-trigger` は、親レイアウトの残余幅を埋める検索欄ではなく、**独立した inline-level trigger** として扱います。したがって、次を固定します。

- 既定では親コンテナ幅いっぱいへ自動伸長しません。
- 横幅はコンポーネント規定値を基準とし、入力欄のような可変幅を前提にしません。
- ヘッダーやツールバーで隣接要素と共存することを前提にし、単独の主役要素としては扱いません。
- モバイル縮退時も、視覚要素は減っても起動領域は維持します。

### 視覚仕様

- 通常時は控えめな面背景を持ちます。
- hover 時は境界線を明示し、インタラクティブであることを示します。
- `focus-visible` 時は白地に近い背景とアウトラインで、起動可能状態を明示します。
- `active` 時は軽い縮小で押下感を与えます。
- `disabled` 時は不透明度を下げ、操作不能を示します。

### プレースホルダー表示

プレースホルダーは `white-space: nowrap`、`overflow: hidden`、`text-overflow: ellipsis` を用い、長文時にも 1 行内で省略表示します。プレースホルダーは **入力値** でも **検索スコープ表示** でもなく、launcher の視覚説明補助です。

### Forced Colors での扱い

`forced-colors: active` では、システムカラーを使用し、境界線と背景を強制的に可視化します。これは本コンポーネントが「Input に見える Button」であるため、背景や境界が失われると意味判別が難しくなるためです。

### 外部スタイル介入の上限

外部スタイルは、見た目の調整には使用できますが、意味論や動作モデルの変更には使用しません。特に次は公開契約に含めません。

- `::part(button)` に対する `display` の意味変更
- `pointer-events` の無効化やイベントモデルの改変
- 疑似要素による代替ラベルや代替アイコンの常設
- `position` 調整に依存した内部レイアウト再構成
- 内部構造を前提にした descendant selector

見た目を整えるための拡張は許容しますが、button としての意味、可視ラベルの責務、起動契約は外部 CSS で再定義しません。

## 環境別の振る舞い

### モバイル

`max-width: 640px` では、プレースホルダーを非表示にし、検索アイコンのみの正方形ボタンとして表示します。これは、ヘッダー横幅を圧迫せずに検索導線を維持するための縮退です。

長期契約としては、視覚サイズそのものよりも **最低起動領域の一貫性** を優先します。具体的な px 値は design token 側の control 最低サイズ契約へ従属させ、`search-trigger` 単独では重複定義しません。

### テーマ差し替え

暗色系テーマそのものに対する専用メディアクエリは持ちませんが、背景色、境界線色、文字色は CSS Custom Properties により差し替え可能です。したがって、ダークモード相当の配色はトークン差し替えで成立させます。

### Forced Colors

`forced-colors: active` では、背景、境界線、フォーカスアウトライン、内部アイコン色、プレースホルダー色をシステムカラーへフォールバックします。box-shadow に依存せず、実線の境界とアウトラインで判別可能性を維持します。

### Reduced Motion

現行契約では、`prefers-reduced-motion` に対する専用挙動は固定しません。押下時の縮小や遷移は通常の視覚効果として扱い、Reduced Motion 対応を公開契約へ昇格させる場合は、実装、Storybook、契約書を同時に更新します。

## 関連契約

### 検索ダイアログ統合契約

`ui-search-trigger` は検索ダイアログそのものではありません。起動時に `open-search-dialog` を発火するだけであり、実際のダイアログ表示、フォーカストラップ、閉じる操作、検索語入力は `ui-search-dialog` または上位レイヤが担います。

`open-search-dialog` は request event であり、trigger 自身は open / closed の真実源泉になりません。したがって、開状態に応じた再入抑止、既存ダイアログへのフォーカス復帰、重複表示抑止は上位レイヤで扱います。

### グローバルショートカット統合契約

ショートカットの登録、OS 別表示、文脈別有効化は trigger の責務ではありません。`Ctrl+K` / `Cmd+K` を実際に監視するのは上位レイヤの責務です。

ショートカットハンドラから起動したい場合、利用者は `ui-search-trigger.click()` を使用できます。これにより、Shadow DOM を直接探索せずに既存の起動契約へ合流できます。

長期的には、ショートカット hint の表示や `aria-keyshortcuts` の付与は、**実際にそのショートカットが有効な環境でのみ整合する形** で扱うのが望ましい方針です。trigger 自身はショートカットの真実源泉になりません。

### フォーカス移譲契約

`ui-search-trigger` 自身は、起動後のフォーカス遷移先を決定しません。次を固定します。

- 起動後に検索入力やダイアログ先頭要素へフォーカスを移すかどうかは上位レイヤの責務です。
- ダイアログを閉じた後に trigger へフォーカスを戻すかどうかも上位レイヤの責務です。
- trigger 自身はフォーカストラップやフォーカス復元を実装しません。

したがって、本コンポーネントは **起動の起点** であり、フォーカス管理の真実源泉ではありません。

### スタイル拡張契約

外部スタイル拡張は、CSS Custom Properties と `::part(button)`、`::part(icon)`、`::part(placeholder)` に限定します。内部 class 名、Shadow DOM 内部構造、未公開 part には依存しません。

## 境界条件

### フォーカスのみでは起動しない

button がフォーカスを得ても、`open-search-dialog` は発火しません。起動には click、Enter、Space、または公開 `click()` の呼び出しが必要です。

### disabled 時は起動しない

`disabled=true` の場合、ユーザー操作でもプログラム的 `click()` でも `open-search-dialog` は発火しません。

### 1 アクティベーションにつき 1 回だけ発火する

単一の click、Enter、または Space に対して `open-search-dialog` は 1 回だけ発火します。1 回の操作から重複発火する実装には依存しません。

### 連続クリックでは連続発火する

連続クリック時、`open-search-dialog` はクリック回数に応じて複数回発火します。ダイアログの重複表示抑止は上位レイヤの責務です。

### 空プレースホルダーでもアクセシビリティは維持する

`placeholder=""` を指定しても button のアクセシブル名は固定 `aria-label` で維持されます。ただし、視覚説明力は低下します。

### 長文プレースホルダーは省略表示する

長い `placeholder` は 1 行で省略表示されます。複数行化や自動折り返しには依存しません。

### モバイルでは icon-only 表示へ縮退する

狭い画面ではプレースホルダーを非表示にします。モバイル時の説明力は視覚ラベルではなく、アイコンとアクセシブル名に依存します。

## 補足

`ui-search-trigger` の要点は、検索欄のように見せること自体ではありません。**検索という大きなモード遷移へ入る前に、読書の流れを壊さない静かな導線を与えること** にあります。

したがって、今後の変更でも次の 6 点は崩さない方がよいです。

1. 実体は常にネイティブ `<button>` であること。
2. 本体の役割は stateless launcher であり、input control ではないこと。
3. `placeholder` をアクセシブル名や検索コンテキストの代替にしないこと。
4. `open-search-dialog` を request event として扱い、open state の真実源泉を持ち込まないこと。
5. フォーカスだけでダイアログを開かないこと。
6. ショートカット処理とダイアログ状態管理を trigger 自身に持ち込まないこと。

## 将来拡張の原則

本節は現行実装の公開契約ではなく、将来追加を検討する場合の設計指針です。追加機能は、検索トリガーを多機能化するためではなく、**search dialog launcher としての単一責務を保ったまま、検索導線の明確さを高めつつ読書の没入を壊さない場合に限って** 採用します。

### 最優先で検討する価値がある拡張

#### 1. ダイアログ関係属性の外部制御

`aria-expanded`、`aria-controls` を受け取れるようにすると、検索ダイアログとの関係がより明示的になります。ただし、状態の真実源泉は trigger ではなく上位レイヤです。

この拡張を採用する場合、次を満たします。

- 状態は外部制御とし、自前で open state を保持しません。
- `ui-search-dialog` との関係だけを意味論として補強し、視覚表現を過剰に増やしません。
- trigger 自体を stateful widget へ拡張しません。

#### 2. アクセシブル名の外部注入

現行契約ではアクセシブル名は内部既定値で与えます。多言語 UI や文脈別文言が必要な場合は、可視プレースホルダーとは別にアクセシブル名を外部注入できる設計を検討する価値があります。

この拡張を採用する場合、次を満たします。

- 可視プレースホルダーとアクセシブル名の責務を混同しません。
- 既定値を持ちつつ、明示上書きを可能にします。
- ローカライズの責務を上位レイヤと整合させます。

#### 3. 密度バリアント

現行実装は viewport に応じて icon-only へ縮退しますが、実際のレイアウトでは「画面幅は広いが配置領域だけ狭い」状況もあります。`default` / `compact` / `icon-only` のような密度バリアントは、レスポンシブ判定だけに依存しない制御手段として検討価値があります。

この拡張を採用する場合、次を満たします。

- 選択肢は有限個に限定し、自由幅や自由形状にはしません。
- `icon-only` は意味論ではなく視覚密度の差として扱います。
- compact 化しても launcher であることが判別できる視覚契約を維持します。
- viewport ベースの縮退と競合しない優先順位を定義します。

### 条件付きで価値がある拡張

#### 4. ショートカット hint の外部注入

ショートカットバッジや `kbd` 表示を採用する場合は、trigger 自身がショートカットの真実源泉にならないように扱う必要があります。

この拡張を採用する場合、次を満たします。

- 実際に有効なショートカットだけを表示します。
- OS や文脈によって表示内容を外部制御します。
- `kbd` 表現は補助情報として扱い、アクセシブル名を汚染しません。
- `::part(badge)` を正式公開する場合は、DOM 実装と Storybook 契約を同時に更新します。

#### 5. icon-only 時の補助ラベル

compact / icon-only 運用が増える場合、hover や focus 時の補助ラベル、または `title` 相当の視覚補助は条件付きで検討価値があります。これはアクセシブル名の代替ではなく、視覚的な迷いを減らすための補助として扱います。

この拡張を採用する場合、次を満たします。

- アクセシブル名の代替手段としては扱いません。
- 常時表示の重い tooltip UI には発展させません。
- icon-only 密度時だけに限定するなど、適用条件を明示します。

#### 6. Reduced Motion 対応

押下時の縮小や遷移が存在するため、`prefers-reduced-motion` への追従は条件付きで検討価値があります。ただし、これは `search-trigger` 単体の独自機能ではなく、control 系コンポーネントの共通方針として導入する方が望ましい拡張です。

この拡張を採用する場合、次を満たします。

- `search-trigger` 単独ではなく、control 系共通契約として整理します。
- transform、duration、focus animation の抑制方針を統一します。
- 実装、Storybook、契約書を同時に更新します。

### 採用しない方針

次の方向は、検索トリガーの責務を汚しやすいため採りません。

- trigger 自身に検索入力値を保持させること
- trigger 自身にダイアログ表示状態を内蔵すること
- `placeholder` に検索スコープやアクセシブル名の責務を兼務させること
- 検索候補や最近使った検索語を trigger 内へ持ち込むこと
- グローバルショートカット登録を trigger 内で自動化すること
- OS 判定やキーマップ差分吸収を trigger 内で完結させること
- 通常 button と同じ強い主張の視覚表現へ寄せること

## 現行実装で未対応または未整合の事項

本節は、現行の `search-trigger.ts` および `search-trigger.stories.ts` を基準として、**コメントや Storybook で言及されているが、実装では未反映または未整合である事項** を整理するものです。

### 1. ショートカットバッジ

コメントおよび Storybook では、デスクトップ時に「検索アイコン + プレースホルダー + ショートカットバッジ」を表示する前提になっています。しかし、現行の `render()` はアイコンとプレースホルダーしか描画しておらず、バッジ DOM は存在しません。

したがって、**ショートカットバッジは現行公開契約には含めません**。`../kbd/kbd` の import、`.badge` の CSS 言及、`part="badge"` のコメント記述は残っていますが、実装面としては未完了です。

### 2. バッジ関連アクセシビリティ記述

Storybook の説明文には「バッジは `aria-hidden="true"`」という説明がありますが、現行 DOM にバッジ要素自体が存在しません。したがって、この記述は **将来構想または未整合な説明** として扱います。

### 3. `aria-keyshortcuts` と実際のキーバインド

button は `aria-keyshortcuts="Control+K Meta+K"` を持ちますが、現行コンポーネントはグローバルな `Ctrl+K` / `Cmd+K` の監視を実装していません。したがって、この属性は **存在告知** であり、実際のショートカット処理ではありません。

### 4. request event と「即座にモーダルを開く」という説明のずれ

現行実装の責務は `open-search-dialog` を発火することに限られます。実際にダイアログやモーダルを表示する処理は持っていません。しかし、`search-trigger.ts` および `search-trigger.stories.ts` の説明コメントには、「アクティブ化によって即座にモーダルを展開します」と読める記述が残っています。

したがって、**現行実装はダイアログ表示主体ではなく request event の発火主体である** という契約を優先します。Storybook やソースコメントでの「即座にモーダルを開く」という表現は、実装責務を過剰に表現した未整合な説明として扱います。

### 5. モバイルのタッチターゲット説明

コメントおよび Storybook では `44×44px` のタッチターゲット確保が説明されていますが、現行実装で使用される既定トークンは `--control-min-touch: 24px` です。加えて、DOM / CSS 実装と説明文の間には記述の揺れがあります。

したがって、**44px タッチターゲットは現行契約として固定しません**。現時点では、モバイル時に icon-only 表示へ縮退することのみを固定します。

### 6. アクセシブル名の固定文字列

現行実装では `aria-label` が固定で `"検索ダイアログを開く"` に設定されており、公開入力ではありません。`placeholder` を変えてもアクセシブル名は変化しません。

これは日本語 UI では一貫性がありますが、多言語運用や文脈別文言切り替えには未対応です。

### 7. 環境別最適化の限定性

現行実装で専用分岐がある環境対応は、モバイル縮退と Forced Colors に限られます。Reduced Motion、Print、Dark Mode 専用メディアクエリは持ちません。ダークテーマ相当はトークン差し替えで成立しますが、**環境専用契約として強く固定されているわけではありません**。Reduced Motion も同様に未固定です。

### 8. `badge` part の未公開化

コメント上は `@csspart badge` が列挙されていますが、実際の DOM に `part="badge"` を持つ要素はありません。したがって、**`badge` は現時点で実際には公開されていない part** として扱います。

### 9. 未使用の `kbd` 依存

`search-trigger.ts` は `../kbd/kbd` を import していますが、現行の `render()` では `ui-kbd` もバッジ DOM も描画していません。したがって、**ショートカットバッジ機能は未実装のまま、関連依存だけが残っている** 状態です。

これは公開契約そのものではありませんが、実装としては不要な依存関係、バンドル上のノイズ、将来の誤解を生みやすい状態です。ショートカットバッジを正式採用しない限り、この依存は実装から除去する方が整合的です。

### 10. 本節の扱い

本節に記載した事項は、現行公開契約として利用者が依存してよいものではありません。これらを採用する場合は、実装、Storybook、契約書の 3 点を同時に更新し、未整合状態を残したまま公開契約へ昇格させません。
