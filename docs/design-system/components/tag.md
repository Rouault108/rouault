# Tag

## 要約

`ui-tag`は、**単一のタグ項目**を表現するコンポーネントです。タグ項目は静的表示に加えて、必要に応じて **開く操作** と **除去操作** を持てます。ただし、これらはタグ項目そのものの意味論を増やすものではなく、**同一項目に付随する補助操作**として扱います。

本契約は、`ui-tag`をバッジ、ボタン、チェックボックス、フィルターチップの代替として拡張するのではなく、**情報の識別、軽量な操作、可読性維持**を両立するための境界を定義します。特に、`href + removable`を一対象二操作モデルとして扱うこと、除去イベントの値は現行実装では可視ラベルから導出されること、`plain`を無彩色の最小表現として固定することを中核方針とします。

---

## 概要

本書は、`ui-tag`の公開契約を定義します。対象は、公開入力、状態モデル、イベント、アクセシビリティ、視覚契約、および境界条件です。

`ui-tag`は単一のタグ項目を表現し、必要に応じて **開く操作** と **除去操作** を持てます。ただし、これらはタグ項目そのものの意味を増やすものではなく、**同一項目に付随する補助操作**として扱います。

したがって、`ui-tag`はバッジ、ボタン、チェックボックス、フィルターチップの汎用代替としては扱いません。契約は、**情報の識別、軽量な操作、可読性維持**を両立する範囲で固定します。

## 基本設計方針

### 単一の意味論

`ui-tag`は、**単一のタグ項目を表現する**コンポーネントです。静的表示、リンク導線、除去可能トークンは別々のUI類型に見えますが、本契約ではいずれも「同一のタグ項目が0〜2個の補助操作を持つ状態差」として扱います。

### 補助操作の意味

`ui-tag`が持ちうる補助操作は次の2つです。

- **開く操作**: タグ項目に関連するページ、検索結果、詳細文脈などを開く操作
- **除去操作**: 現在の表示文脈からタグ項目を除去する操作

ここでいう除去は、**表示中トークンの除去または選択状態の解除**を意味し、データエンティティ削除を意味しません。

### 一対象二操作モデル

`href`と`removable`を併用する場合、`ui-tag`は「1つのタグ項目に対して、開く操作と除去操作の2操作を持つ複合状態」とみなします。これは単なる近接配置ではなく、**一対象二操作モデル**です。

### リンク責務の限定

`ui-tag`のリンク契約は、**ネイティブなアンカー要素を提供すること**に限定します。アプリケーションルータ統合、外部リンクポリシー、URL検証は本コンポーネントの責務に含めません。

### 視覚重量の抑制

`ui-tag`は、本文や注記より強い常時強調を行いません。視覚的な強さは、分類や文脈差を補助する範囲にとどめます。

## 公開契約

`ui-tag`は、`variant`、`size`、`color`、`href`、`removable`、`disabled`を公開入力として扱います。スロットは既定スロットと`icon`スロットを持ちます。内部実装はLitによるShadow DOMコンポーネントですが、利用者は`ui-tag`を契約単位として扱います。

`variant`の既定値は`default`です。`size`の既定値は`xs`です。`color`の既定値は`neutral`です。`href`が未指定または空文字列の場合、タグはリンクとして扱いません。`removable=true`の場合、除去操作を提供します。

### 入力契約

| 名前        | 種別                 | 必須   | 内容           | 契約                                                    |
| ----------- | -------------------- | ------ | -------------- | ------------------------------------------------------- |
| `variant`   | property / attribute | いいえ | 視覚バリアント | `default` / `outline` / `solid` / `plain`               |
| `size`      | property / attribute | いいえ | サイズ         | `xs` / `sm`                                             |
| `color`     | property / attribute | いいえ | 意味的カラー   | `neutral` / `red` / `blue` / `violet` / `pink` / `gold` |
| `href`      | property / attribute | いいえ | 遷移先URL     | 非空文字列の場合、開く操作を提供します                  |
| `removable` | property / attribute | いいえ | 除去可能状態   | `true`の場合、除去操作を提供します                     |
| `disabled`  | property / attribute | いいえ | 非活性状態     | 開く操作または除去操作を無効化します                    |

### 入力の意味制約

- 除去イベントの`detail.value`は、現行実装では既定スロットの可視ラベルをtrimした値です。
- `disabled`は開く操作または除去操作を持つ状態に対してのみ意味を持ちます。静的タグに`disabled`を与えた場合の表示および動作は正規契約に含めません。
- `variant="plain"`の場合、`color`は意味を持ちません。`plain`は常に最小強度の無彩色表現として扱います。

### スロット契約

| 名前         | 種別       | 位置づけ | 内容                             |
| ------------ | ---------- | -------- | -------------------------------- |
| 既定スロット | slot       | 正規入力 | タグの可視ラベルを受け取ります   |
| `icon`       | named slot | 補助入力 | 先頭の装飾アイコンを受け取ります |

既定スロットはタグの可視ラベルを受け取ります。長いラベルは1行に固定され、省略表示されます。

### スロット内容制約

既定スロットは、タグの可視ラベルを構成する`phrasing content`相当の内容を受け取ることを前提とします。利用者は、既定スロット内に対話要素を含めてはなりません（MUST NOT）。これは、対話主体をリンクまたは除去ボタンへ一意に保つためです。

`icon`スロットは装飾専用です。`icon`スロットに主意味の提示を担わせてはなりません（MUST NOT）。`icon-only`構成は静的装飾用途に限って許容し、開く操作または除去操作を伴う`icon-only`タグは利用してはなりません（MUST NOT）。

`icon`スロットの許容内容は1要素です。複数アイコンやテキスト混在を前提にしてはなりません（MUST NOT）。

### 公開イベント

`ui-tag`は、除去操作に対して次のカスタムイベントを公開します。

| 名前            | 発火条件         | detail              | bubbles | composed | cancelable |
| --------------- | ---------------- | ------------------- | ------- | -------- | ---------- |
| `ui-tag-remove` | 除去ボタン起動時 | `{ value: string }` | `true`  | `true`   | `false`    |

`detail.value`は現行実装では可視ラベルのtrim結果です。公開入力`value`由来ではありません。

### イベント伝播契約

除去ボタンの内部`click`は、コンポーネント外へそのまま公開するためのイベント契約ではありません。利用者が除去操作を購読する場合は、ネイティブ`click`ではなく`ui-tag-remove`を監視します。

`ui-tag-remove`は`bubbles: true`かつ`composed: true`で発火し、Shadow DOM境界を越えて上位へ伝播します。一方で`cancelable`ではないため、既定動作のキャンセル対象としては扱いません。除去後の状態更新、配列更新、DOM除去は、常に上位コンポーネントの責務です。

### 属性反映契約

公開入力はpropertyとattributeの両面から操作できます。boolean値はattributeの有無で反映します。

| property    | attribute   | reflect | 備考                             |
| ----------- | ----------- | ------- | -------------------------------- |
| `variant`   | `variant`   | あり    | 列挙値以外は未サポートです       |
| `size`      | `size`      | あり    | `xs` / `sm`を受理します         |
| `color`     | `color`     | あり    | `plain`では意味を持ちません     |
| `href`      | `href`      | あり    | 空文字列はリンクとして扱いません |
| `removable` | `removable` | あり    | boolean attributeとして扱います |
| `disabled`  | `disabled`  | あり    | 静的タグでは使用しません         |

### 列挙外値・無効値の扱い

`variant`、`size`、`color`は公開上は列挙値を契約とします。HTML属性として列挙外文字列を与えること自体は可能ですが、表示結果は未定義として扱います。利用者は列挙外値に依存してはなりません（MUST NOT）。

`href`は非空文字列であることのみを前提に扱います。URL妥当性検証、相対URL / 絶対URLのポリシー、外部リンク時の`rel` / `target`制御は本コンポーネントの責務に含みません。

### `href` 安全性契約

`ui-tag`は`href`の安全性を保証しません。危険なスキームや不正なURLを拒否、正規化、サニタイズする責務は上位レイヤにあります。したがって、利用者は信頼できない入力を`href`に直接渡してはなりません（MUST NOT）。

本コンポーネントは、`href`を受け取った場合にネイティブなリンク構造を提供するだけであり、リンクの安全性、遷移ポリシー、外部リンク制御はアプリケーション側で定義します。

### 責務範囲

責務範囲には、タグ本体の描画、色・サイズ・バリアントの適用、リンク化、除去ボタン描画、除去イベント発火、disabled時の操作抑止、長文ラベルの省略表示、フォーカス表示、および高コントラスト / ダークモード / モーション軽減対応を含みます。

責務に含めない事項の一覧は、本書の「適用範囲」に従います。

## 状態モデル

`ui-tag`の主要状態は、見た目の差だけでなく、**単一のタグ項目がどの補助操作を持つか**によって読み分けます。

### 静的状態

最小状態は、`variant="default"`、`size="xs"`、`color="neutral"`、`href`なし、`removable=false`の状態です。この状態では、装飾的な分類ラベルとして振る舞います。

### 開く操作状態

`href`が非空文字列の場合、タグ項目は開く操作を持ちます。開く操作の対話主体は常にネイティブ`<a>`です。

### 除去操作状態

`removable=true`の場合、タグ項目は除去操作を持ちます。除去操作の対話主体は常にネイティブ`<button>`です。除去操作は現在の表示文脈からの除去を意味し、ドメインデータの削除を意味しません。

### 複合状態

`href`と`removable`を併用する場合、`ui-tag`は一対象二操作モデルを取ります。開く操作と除去操作は同一項目に属する独立した補助操作であり、`role="group"`を持つ構造で表現します。

### 非活性状態

`disabled=true`の場合、開く操作および除去操作の双方を無効化します。非活性状態は単なる視覚状態ではなく、**実際の操作抑止**を意味します。

### バリアント状態

| `variant`値 | 意味             | 想定用途                             | 非推奨用途     |
| ------------ | ---------------- | ------------------------------------ | -------------- |
| `default`    | 控えめな面表現   | 通常の分類ラベル、本文近傍のメタ情報 | 強い注意喚起   |
| `outline`    | 軽い境界線表現   | 背景干渉を避けたい分類               | 常時強調       |
| `solid`      | 強い塗り表現     | 例外的な強調、限られた状態ラベル     | 多数並列表示   |
| `plain`      | 最小限の文字表現 | 本文近傍の補助ラベル                 | 色相による分類 |

### サイズ状態

`size`は`xs`と`sm`を受理します。`xs`は通常運用対象であり、`sm`はやや強調したい場合に用います。

### 色状態

`color`は`default`、`outline`、`solid`に対する色相選択に用います。各色の意味づけと視認性補正は、「視覚契約」の「色契約」に従います。

## DOM / アクセシビリティ

`ui-tag`は、状態に応じて4種類の内部構造を持ちます。

### 1. 静的タグ

```text
<ui-tag>
  #shadow-root
    <span class="tag-root">
      [span.icon-slot]
      <span class="text-slot"><slot></slot></span>
    </span>
</ui-tag>
```

### 2. 開く操作のみ

```text
<ui-tag href="...">
  #shadow-root
    <a class="tag-link" href="...">
      [span.icon-slot]
      <span class="text-slot"><slot></slot></span>
    </a>
</ui-tag>
```

### 3. 除去操作のみ

```text
<ui-tag removable>
  #shadow-root
    <span class="tag-root">
      [span.icon-slot]
      <span class="text-slot"><slot></slot></span>
      <button class="tag-remove-button" type="button"></button>
    </span>
</ui-tag>
```

### 4. 開く操作 + 除去操作

```text
<ui-tag href="..." removable>
  #shadow-root
    <div class="tag-group" role="group" aria-label="...">
      <a class="tag-link" href="..."></a>
      <button class="tag-remove-button" type="button"></button>
    </div>
</ui-tag>
```

### アクセシビリティ契約

- 対話主体は常にネイティブ要素です。開く操作はネイティブな`<a>`、除去操作はネイティブな`<button>`を用います。
- `href`と`removable`を併用する場合、`<a>`と`<button>`は並列配置し、`interactive content`の不正な入れ子を作りません。
- 除去ボタンは、表示ラベルに基づく内部生成文言をアクセシブル名として持ちます。
- 開く操作 + 除去操作の構成では、グループ全体に`role="group"`と表示ラベルに基づくアクセシブル名を付与します。
- `disabled=true`のリンクは`aria-disabled="true"`と`tabindex="-1"`を持ちます。
- `disabled=true`の除去ボタンは`disabled`、`aria-disabled="true"`、`tabindex="-1"`を持ちます。
- 長いラベルは1行に固定し、省略表示します。
- フォーカス可視表示はリンクおよび除去ボタンの`:focus-visible`で扱います。

### アクセシブル名・ローカライズ契約

現行実装はアクセシブル名上書き用の公開入力を持ちません。利用者が依存してよいのは、**対話主体が常にアクセシブル名を持つこと**です。文言の多言語化や文脈依存の読み上げ最適化が必要な場合は、別途公開APIを設計します。

### キーボード操作契約

キーボード操作は、各対話主体のネイティブの挙動に従います。開く操作のみを持つ場合はリンクのみがフォーカス対象となり、除去操作のみを持つ場合は除去ボタンのみがフォーカス対象となります。開く操作 + 除去操作の場合、フォーカス順序は`document order`に従い、開く操作、除去操作の順に到達します。`role="group"`自体はフォーカス対象ではありません。

`disabled=true`の場合、開く操作および除去操作はキーボード操作対象から除外されます。利用者はdisabled状態のタグに対してEnterまたはSpaceによる起動を期待してはなりません。

### タッチターゲット契約

対話主体は、**最小保証値として24×24 px相当の補助ターゲット**を持ちます。加えて、タッチ主体の配置では **44×44 px相当を推奨値**とします。

本コンポーネントが保証するのは最小保証値までであり、推奨値の確保は親レイアウトおよび利用文脈と協調して達成します。

## 視覚契約

`ui-tag`の視覚契約は、タグであることを認識できる最小限の輪郭を持ちつつ、本文や注記より前に出過ぎないことにあります。

### 情報順位

- `default`は最も中立で、背景を持ちながらも静かなタグです。
- `outline`は背景を持たず、境界線で輪郭だけを示します。
- `solid`は最も重い視覚表現で、白文字と強い塗りを持ちます。
- `plain`は背景も境界線も持たず、文字情報だけを残す無彩色表現です。

### レイアウト

ホストは`inline-flex`です。ラベルは単一行で表示し、必要に応じて省略します。`icon`スロットはラベルの先頭に置かれ、装飾アイコンとして扱います。開く操作 + 除去操作では、誤操作防止のため除去領域を右端へ固定します。

### バリアント別の見え方

- `default`は彩度を抑えた背景面を持ち、ホバー時に境界線のみを薄く強めます。
- `outline`は背景透明、境界線ありです。
- `solid`は高彩度背景と白文字を用います。`neutral`でも濃い無彩色背景 + 白文字とします。
- `plain`は背景透明、枠線なし、無彩色文字です。

### 色契約

- `neutral`は無彩色です。
- `red`は注意寄りの文脈で利用できますが、アラート意味を単独で保証する色ではありません。
- `blue` / `violet` / `pink` / `gold`は、主として分類、分野、文脈差の補助に用います。
- `gold`は高明度背景での視認性低下を避けるため、背景と文字に専用補正を適用します。
- `plain`では色相による意味づけを行いません。

### ホバー / フォーカス / 非活性

- ホバー時の視覚差分は`default`と`outline`に限定されます。
- `solid`と`plain`はホバーによる境界線強調を持ちません。
- フォーカス時は`outline`によるリング表示です。
- `disabled`は`opacity`低下と操作抑止を伴います。

## 環境別の振る舞い

### ダークモード

`ui-tag`自身はダークモード判定を行いません。テーマ解決はrootのデザイントークン層に集約し、`ui-tag`は`--tag-*`系のrecipe tokenを参照して描画します。

したがって、明暗の決定源は常にアプリケーションのテーマ状態です。`light` / `dark` / `system`の切り替えはroot側の責務であり、`ui-tag`は解決済みトークンに従うだけです。

これにより、OSの`prefers-color-scheme`とアプリ内テーマ指定が競合しても、コンポーネント単位で表示が食い違うことはありません。`gold`の補正値もtoken層で管理します。

### 強制色モード

`forced-colors: active`環境では、背景、文字、境界線をシステムカラーに置き換えます。リンクは`LinkText`、その他は`Canvas` / `CanvasText`基準で描画します。

### モーション軽減

`prefers-reduced-motion: reduce`環境では、トランジション時間を極小化します。フォーカスアニメーションもトークン側で抑制できる前提です。

## 関連契約

### 起動・除去契約

`ui-tag`は、リンク遷移について独自イベントを公開しません。開く操作はネイティブな`<a>`の動作に従い、除去操作だけを`ui-tag-remove`として公開します。

複合状態、disabled時の扱い、除去後のDOM更新責務については、「状態モデル」「公開イベント」「境界条件」に従います。

### スタイル拡張契約

`ui-tag`は`::part(...)`を公開していません。外部からの安定したスタイル拡張面は、CSS Custom Propertiesに限定します。

内部class名やShadow DOM構造の細部は公開契約に含みません。たとえば`.tag-root`、`.tag-link`、`.tag-group`、`.tag-remove-button`、`.text-slot`などの内部識別子には依存してはなりません（MUST NOT）。

### CSS Custom Properties の安定性分類

本書の「参照トークン」に列挙したCSS Custom Propertiesは、`ui-tag`のテーマ調整に用いる公開スタイル面として扱います。利用者は、色、余白、角丸、フォーカスリング、サイズなどの調整にこれらのトークンを利用できます。

一方で、内部で派生的に計算される色式、クラス構造、疑似要素の詳細、DOMの入れ子順は公開スタイル面に含みません。したがって、トークン経由で達成できない見た目の差分を内部構造へ直接当てる形で実現してはなりません（MUST NOT）。

### ラベル値契約

可視ラベルはスロットで表現します。除去イベントの`detail.value`は、現行実装では可視ラベルのtrim結果です。これは公開入力由来の安定識別子ではないため、永続ID、検索キー、厳密一致用データとして扱ってはなりません（MUST NOT）。

### テキスト正規化契約

可視ラベルの文字列化結果は、表示・読み上げの補助にのみ用います。可視ラベルの正規化文字列を永続ID、検索キー、厳密一致用データとして扱ってはなりません（MUST NOT）。

## 境界条件

### 1. 静的タグ

`href`も`removable`も持たない場合、タグは装飾的な分類ラベルとして描画します。

### 2. `href` 空文字列

`href=""`はリンクとして扱いません。構造は開く操作状態にならず、静的タグまたは除去操作状態になります。

### 3. `removable` と除去イベント値の関係

`removable=true`の場合、除去操作は可視ラベルのtrim結果を`ui-tag-remove.detail.value`として公開します。安定識別子が必要な場合は、親レイヤで表示ラベルとは別に対応表を持ちます。

### 4. `href + removable`

`href`と`removable`を併用する場合、`<a>`の中に`<button>`をネストしません。`role="group"`を持つ並列構造で描画し、同一項目に属する2操作として扱います。

### 5. `disabled + static`

静的タグでは`disabled`は意味を持ちません。静的タグに`disabled`を与えた場合の表示および動作は正規契約に含めません。

### 6. `disabled + href`

`disabled=true`かつ`href`ありの場合、リンクは`aria-disabled="true"`と`tabindex="-1"`を持ちます。加えて、実装はポインティングデバイスおよびキーボードによる起動を抑止し、遷移を発生させません。

### 7. `disabled + removable`

`disabled=true`かつ`removable=true`の場合、除去ボタンは無効化され、`ui-tag-remove`は発火しません。

### 8. 長いラベル

長いラベルは`white-space: nowrap`、`overflow: hidden`、`text-overflow: ellipsis`により省略されます。多行表示には対応しません。

省略表示は、親コンテナまたは配置文脈に有限幅制約がある場合に成立します。`ui-tag`単体が無制約幅環境で常に`truncate`を保証するものではありません。レイアウト上の幅制御は親レイヤの責務です。

### 9. `plain + color`

`variant="plain"`は`color`を意味的に受理しません。`plain`を色付きテキストとして運用してはなりません（MUST NOT）。

### 10. アイコンのみのタグ

`icon-only`タグは静的装飾用途に限定します。`href`または`removable`を伴う`icon-only`構成は、アクセシブル名の成立条件と誤操作防止条件を別途定義しない限り、正規契約に含めません。

### 11. 除去後の処理

`ui-tag-remove`発火後も、コンポーネント自身は残り続けます。除去後のDOM更新は親コンポーネントが担います。

## Storybook 契約

各Storyは見本ではなく、**契約確認点**として扱います。Storybookはデモではなく実行可能な契約の一部とし、契約書の記述と矛盾してはなりません（MUST NOT）。

| ---------------------- | ----------------------------------------------------------------------------------------- |
| `Default`              | 既定状態が`default` / `xs` / `neutral`の静的タグであること                              |

## 現行実装で未対応の事項

本節は、現行の`tag.ts`および`tag.stories.ts`を基準として、公開契約との未整合を整理するものです。

### 1. `disabled` の適用範囲未強制

本契約では`disabled`を対話状態にのみ許容しますが、現行実装は静的タグに対しても視覚的に適用可能です。したがって、意味制約が未強制です。

### 2. `plain` と `color` の契約未整合

本契約では`plain`を無彩色最小表現として固定しますが、現行Storybookのcontrolsは`plain`に対しても全`color`を選択可能に見えます。したがって、文書と検証面が未整合です。

### 3. タッチターゲット説明の未整合

本契約では最小保証値24 px、推奨値44 pxの二層契約に固定します。説明文を追加する場合は、この区別を維持します。

### 4. `icon-only` 対話構成の防止未実装

本契約では開く操作または除去操作を伴う`icon-only`タグを禁止しますが、現行実装はこの制約を明示的には強制していません。

### 5. Storybook 契約の未整合

`VariantColorMatrix`の描画と検証内容、表記ゆれなどに未整合が残っています。Storybookを実行可能な契約とするには、契約書に合わせた再整理が必要です。

### 6. 既存 Story の構成例の未整合

`DisabledVariants`および`AllStates`には、静的タグに`disabled`を付与した構成例が含まれています。本契約ではこれは無効な組み合わせです。

### 7. JSDoc / Docs サンプルの未整合

`tag.stories.ts`のDocsサンプルには、`<ui-tag variant="plain" color="blue">Muted</ui-tag>`のような、現行契約と整合しない例が残っている可能性があります。

### 8. 本節の扱い

本節に記載した事項は、現行公開実装として利用者が依存してよいものではありません。これらを採用または修正する場合は、実装、Storybook、契約書の3点を同時に更新し、未整合のまま公開契約へ昇格させません。
