# Card

## 概要

本書は、`ui-card` の公開契約、状態モデル、アクセシビリティ、および視覚契約を整理するものです。

`ui-card` は、関連する情報をひとまとまりの読解単位として提示するコンポーネントです。単に枠付きのコンテナを描画するのではなく、**どの情報を独立したまとまりとして扱うか**、**カード全体をクリック可能領域として成立させるか**、**通常カードとリンクカードをどの入力面で切り替えるか**を公開契約として固定します。

また、バリアント、クリック委譲、フォーカス表示、高コントラスト対応、印刷時の振る舞いは、局所的な見た目調整ではなく、**状態契約とトークン契約**によって成立させます。

Rouault における card は、本文を阻害する装飾ではなく、**読むべきまとまりを静かに分節するための面**です。したがって、本コンポーネントの契約は、情報のまとまりを示すことと、**「没入して読む」ことのできるデザイン**を維持することを両立する方向で定義します。

## 適用範囲

本書は、`ui-card` の次の事項を対象とします。

- 公開契約
- 状態モデル
- DOM / Accessibility
- Visual Contract
- 環境別の振る舞い
- 関連契約
- 境界条件
- Storybook 契約
- 現行実装で未対応または未整合の事項

一方で、本書は次の事項を扱いません。

- ページ全体でどのカードをどの優先度で並べるかという情報設計
- カード内部に配置する本文、メタ情報、画像の編集規則
- OGP 取得やリンクメタデータ収集そのもの
- ルーティング、遷移先画面、検索結果生成など上位レイヤの責務
- カード集合のレイアウトグリッドや一覧仮想化

これらは上位レイヤまたは別コンポーネントの責務です。

## 公開契約

`ui-card` は、`variant`、`clickable`、`cardKind`、`href`、`cardTitle`、`description`、`imageSrc`、`siteName` を公開入力として扱います。描画モードは `generic` と `link` の 2 系統です。

`variant` の既定値は `outlined` です。`cardKind` の既定値は `generic` です。`clickable` の既定値は `false` です。

`generic` モードでは、`header`、既定、`footer` の 3 スロットを受け取るスロットベースのカードとして描画します。`link` モードでは属性駆動でリンクカードを描画し、スロットは描画に参加しません。

本コンポーネントでは、`cardKind` を**要求モード**、実際の描画・挙動・視覚状態を決めるものを**有効モード**として区別します。

- 要求モードは `cardKind` によって指定します。
- 有効モードは入力完全性を評価した結果として決まります。
- `cardKind="link"` かつ `href` 非空かつ `cardTitle` 非空のときに限り、有効モードは `link` です。
- それ以外のすべての組み合わせでは、有効モードは `generic` です。

したがって、**リンクカードとして扱う場合は `href` と `cardTitle` を与えなければなりません（MUST）**。要求モードとして `card-kind="link"` を指定していても、入力が不完全であれば link 固有の描画、挙動、視覚契約は成立しません。

また、`clickable` は generic カード専用の入力です。`link` モードでは `clickable` を解釈せず、カード全体が主リンクとして振る舞うのは link モード自体の契約によります。

### 入力契約

| 名前          | 種別                                | 必須     | 内容                               | 契約                                                                                                                       |
| ------------- | ----------------------------------- | -------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `variant`     | property / attribute                | いいえ   | 外観スタイル                       | `outlined` / `elevated` / `flat` / `ghost`                                                                                 |
| `clickable`   | property / attribute                | いいえ   | generic カードのカード全体クリック | 有効モードが `generic` のときだけ意味を持ちます。`true` の場合、主要リンクへのクリック委譲とフォーカスリングを有効化します |
| `cardKind`    | property / attribute (`card-kind`)  | いいえ   | 要求モード                         | `generic` / `link`。既定値は `generic` です                                                                                |
| `href`        | property / attribute                | 条件付き | リンクカードの遷移先               | 有効モードを `link` にするために必須です                                                                                   |
| `cardTitle`   | property / attribute (`card-title`) | 条件付き | リンクカードの見出し               | 有効モードを `link` にするために必須です。空文字および空白のみは未指定として扱います                                       |
| `description` | property / attribute                | いいえ   | リンクカードの補足説明             | 140 文字を超える場合は文字列を切り詰めます                                                                                 |
| `imageSrc`    | property / attribute (`image-src`)  | いいえ   | リンクカード右側画像               | 与えない場合は画像なし 1 カラム構成になります                                                                              |
| `siteName`    | property / attribute (`site-name`)  | いいえ   | リンクカードの出典サイト名         | 先頭のアイブロウとして表示します                                                                                           |

### 文字列正規化契約

`href`、`cardTitle`、`description`、`imageSrc`、`siteName` は、描画時に前後空白を除去した値として解釈します。したがって、空白のみの文字列は未指定と同等に扱います。

この規則は、`href` に限らず文字列入力全体に適用します。たとえば `description="   "` は説明文なしとして扱い、`image-src="   "` は画像なしとして扱います。

特に `link` モードでは、trim 後の `href` と `cardTitle` の両方が非空でなければなりません。いずれかが未指定相当である場合、有効モードは `generic` に戻ります。

### 見出し表現契約

`link` モードのタイトルは、内部見出し要素として描画します。現時点の実装は `<h3>` を採用していますが、利用者は具体的な見出しタグ名に依存してはなりません（MUST NOT）。

本コンポーネントが公開契約として固定するのは、次の 2 点です。

- リンクカードのタイトルが内部見出しとして表現されること
- 見出しレベルを公開入力として受け取らないこと

したがって、ページ全体の見出し階層と厳密に同期した見出しレベル制御が必要な場合は、本コンポーネントをそのまま使うのではなく、別契約または別コンポーネントで扱います。

### スロット契約

`ui-card` のスロットは `generic` モードでのみ意味を持ちます。

| 名前         | 種別       | 位置づけ | 内容                                                 |
| ------------ | ---------- | -------- | ---------------------------------------------------- |
| `header`     | named slot | 補助入力 | 見出し、カテゴリ、メタ情報などカード上部領域         |
| 既定スロット | slot       | 正規入力 | カード本文、説明、主要内容                           |
| `footer`     | named slot | 補助入力 | 日付、補助メタ情報、アクション補助などカード下部領域 |

`link` モードでは内部で専用マークアップを生成するため、上記スロットは描画に参加しません。したがって、**スロット入力と `cardKind="link"` を同時に用いて内部構造を混在させる運用には依存してはなりません（MUST NOT）**。

また、`generic` モードにおける各スロットは、**配置位置を提供するための入力面**です。`ui-card` 自体は `header` と `footer` に対して専用の区切り線、余白階層、文字サイズ、背景差分を自動付与しません。したがって、スロット内容の装飾と内容設計は利用側の責務です。

### 属性反映契約

公開入力のうち、`variant`、`clickable`、`cardKind` は reflect されます。`href`、`cardTitle`、`description`、`imageSrc`、`siteName` は property / attribute として入力できますが、reflect はしません。

| property      | attribute     | reflect | 備考                             |
| ------------- | ------------- | ------- | -------------------------------- |
| `variant`     | `variant`     | あり    | 既定値は `outlined` です         |
| `clickable`   | `clickable`   | あり    | boolean attribute として扱います |
| `cardKind`    | `card-kind`   | あり    | `generic` / `link` を受理します  |
| `href`        | `href`        | なし    | リンクカードの遷移先です         |
| `cardTitle`   | `card-title`  | なし    | リンクカードの見出しです         |
| `description` | `description` | なし    | リンクカードの補足説明です       |
| `imageSrc`    | `image-src`   | なし    | リンクカード右側画像 URL です    |
| `siteName`    | `site-name`   | なし    | リンクカードのサイト名です       |

### 列挙外値・無効値の扱い

`variant` と `cardKind` は公開上は列挙値を契約とします。HTML 属性として列挙外文字列を与えること自体は可能ですが、表示および動作は未定義として扱います。利用者は列挙外値に依存してはなりません（MUST NOT）。

また、要求モードとして `cardKind="link"` を指定していても、`href` または `cardTitle` を欠く状態は**公開契約上は不完全入力**です。この場合、有効モードは `generic` として扱います。利用者はこの縮退に依存してはなりません（SHOULD NOT）。

### 既定 role 契約

Rouault における `ui-card` は、主として**独立した読解単位**を表す用途で用いるため、接続時に `role` 属性が未指定である場合のみ `role="article"` を既定値として補います。

ただし、これは card 一般の普遍意味ではなく、**本プロジェクトにおける既定運用**です。情報のまとまり方が `article` に適さない場合、利用側は `role` を明示して意味論を上書きしなければなりません（MUST）。

明示的に `role="section"` や `role="none"` を指定した場合、コンポーネントはその値を尊重します。したがって、意味論を変えたい場合は利用側で `role` を明示しなければなりません（MUST）。

この自動設定は接続時の一回限りです。接続後に `role` を削除しても、`ui-card` は `article` を再補完しません。したがって、`article` は恒常的な強制値ではなく、初期接続時の既定値です。

`article` が適するのは、本文・メタ情報・関連リンクを束ねた読解単位です。一方で、単なる装飾枠、設定フォーム断片、一覧セルのような用途では、より適切な `role` を利用側で与えることを推奨します。

### URL / メディア入力責務契約

`href` と `imageSrc` は、trim 済み文字列をそのままリンク先 URL および画像 URL として使用します。`ui-card` は URL のスキーム検証、到達可能性確認、同一オリジン判定、安全性審査、`rel` 付与、`target` 切替、`download` 指定を行いません。

したがって、URL の妥当性と安全性は利用側の責務です。`ui-card` は URL を描画に流し込むだけであり、URL ポリシーを保証しません。

また、`link` モードの画像は補助的な装飾メディアです。読み込み方式は実装選択であり、現時点の実装は遅延読み込みを採用していますが、利用者は具体的な読み込み属性値に依存してはなりません（MUST NOT）。

本コンポーネントは、eager 読み込み、代替画像、再試行 UI、画像失敗時のフォールバック画像を公開入力として提供しません。画像取得に失敗した場合でも、カードの意味成立はタイトルとリンク先情報によって維持されることを前提とします。

### 責務範囲

責務範囲には、カードの外観描画、モードごとの内部構造切り替え、必要な `role` の既定設定、クリック可能カードにおける主要リンクへの委譲、フォーカス可視表示、リンクカード説明文の切り詰めと行あふれ検知を含みます。

一方で、どのリンクを主要リンクとみなすべきかの情報設計、説明文原文の生成、画像取得、URL の妥当性確認、リンク先の安全性判断、カード集合の並び順は責務に含めません。

したがって、`ui-card` は**情報単位を静かに成立させるための容器兼操作面**であり、コンテンツ意味そのものやリンク意味の解釈までは担いません。

## 状態モデル

`ui-card` の主要状態は、見た目の種別ではなく、**要求モードと有効モードの関係**、**カード全体クリックが有効か**、**どのバリアントで表現するか**によって読み分けます。

### 1. モード解決状態

`ui-card` はまず要求モードを受け取り、その後に有効モードを解決します。

- 要求モードが `generic` の場合、有効モードも `generic` です。
- 要求モードが `link` であっても、`href` または `cardTitle` が不足している場合、有効モードは `generic` です。
- 要求モードが `link` で、かつ `href` と `cardTitle` が揃っている場合に限り、有効モードは `link` です。

描画、クリック挙動、カーソル、フォーカスリング、内部 DOM 構造は、要求モードではなく**有効モード**によって決まります。

### 2. 基本状態

最小状態は、`variant="outlined"`、`cardKind="generic"`、`clickable=false` の状態です。この状態では通常のスロットベースカードとして描画し、カード自体はクリック委譲を持ちません。

### 3. バリアント状態

`variant` は視覚的階層のみを切り替えます。意味は次表のとおりです。

| `variant` 値 | 意味                     | 想定用途                         |
| ------------ | ------------------------ | -------------------------------- |
| `outlined`   | 枠線で輪郭を示す既定表現 | 通常の情報カード                 |
| `elevated`   | 影と面で浮上を示す       | 背景から一段持ち上げたいまとまり |
| `flat`       | 背景色で領域を示す       | 影を使わずに面を作りたい場面     |
| `ghost`      | 最小限の枠線のみ         | 主張を最も抑えたい場面           |

`variant` は視覚重量を制御しますが、意味そのものを保証しません。たとえば `elevated` は重要度を保証するものではなく、背景との差を視覚的に増やすだけです。

### 4. クリック可能状態

有効モードが `generic` で `clickable=true` の場合、カード全体の背景クリックを主要リンクへ委譲します。`clickable` は generic 専用入力であり、有効モードが `link` の場合は解釈しません。

主要リンクは、`ui-card` の Light DOM 部分木を文書順で走査したときに最初に見つかる `a[href]` とします。`header`、既定、`footer` のいずれに配置されていても、この機械規則で選定します。

ただし、次の場合は委譲しません。

- 主ボタン以外のクリック
- `metaKey` / `ctrlKey` / `shiftKey` / `altKey` 押下
- 当該 `ui-card` 内部に由来するテキスト選択が存在する場合
- 独立して操作可能な要素への直接クリック

独立して操作可能な要素には、少なくとも `a`、`button`、`input`、`textarea`、`select`、`summary`、`[role="button"]`、`[role="link"]`、`[contenteditable="true"]`、`[tabindex]:not([tabindex="-1"])` を含みます。

この状態は、**どこを押しても同じ主要リンクへ到達できる**ことを目的としますが、ブラウザのネイティブ操作やコピー操作を奪わないことを同時に満たさなければなりません。

### 5. リンクカード状態

有効モードが `link` の場合、`ui-card` は属性駆動リンクカードとして描画します。この状態では内部に単一の主リンクを生成し、`clickable` がなくてもカード全体が主リンクとして振る舞います。

このとき、カード全体クリックは Shadow DOM 内の主リンクへ委譲されます。フォーカス可視表示もホスト側の `:focus-within` に一本化し、内部リンクの既定 outline は抑止します。`clickable` を同時指定していても link モードの振る舞いは変化しません。

### 6. リンクカード本文状態

リンクカード本文は次の要素から構成されます。

- `siteName` がある場合のみ表示されるアイブロウ
- `cardTitle` を表示する見出し
- `description` がある場合のみ表示される補足説明
- `imageSrc` がある場合のみ表示される右側画像

`description` は 140 文字を超える場合に文字列レベルで切り詰めます。さらに表示上 2 行に制限し、文字列切り詰めがなくても行あふれがある場合は視覚的な省略表現を付与します。

### 7. role 状態

`role` 未指定で接続された場合は `article` となります。`role` 明示時は外部指定値を保持します。したがって、`article` は固定値ではなく既定値です。

## DOM / Accessibility

`ui-card` はモードに応じて 2 種類の DOM 構造を持ちます。

### generic モード

```text
<ui-card role="article|...">
  #shadow-root
    <slot name="header"></slot>
    <slot></slot>
    <slot name="footer"></slot>
</ui-card>
```

### link モード

```text
<ui-card card-kind="link" role="article|...">
  #shadow-root
    <a class="link-card" href="...">
      <div class="link-card__body">
        [p.link-card__eyebrow]
        [heading.link-card__title]
        [p.link-card__description]
      </div>
      [img.link-card__media alt=""]
    </a>
</ui-card>
```

### Accessibility 契約

アクセシビリティ上の重要点は次のとおりです。

- 既定 role は `article` ですが、これは Rouault における既定運用です。
- カード自体に `tabindex` は設定しません。
- `generic` のクリック可能状態では、内部リンクがフォーカス主体です。
- `link` モードでも実際の起動主体は内部のネイティブ `<a>` です。
- フォーカス可視表示はホストの `:focus-within` によりカード全体へ描画します。
- `link` モードの画像は装飾扱いで `alt=""` を使用します。
- テキスト選択中はクリック委譲を抑止し、コピー可能性を維持します。

`link` モードのタイトルは内部の `<h3>` 要素であり、見出しレベルは固定です。また、画像は常に装飾画像として扱い、代替テキスト入力面は公開しません。したがって、**意味を持つ画像や、文書アウトラインに厳密参加させたい見出しを `link` モードに直接担わせることは想定しません**。

本コンポーネントで重要なのは、**カードそのものを不必要にフォーカス可能コンテナへしないこと**です。操作主体はあくまで内部リンクまたは内部の独立インタラクティブ要素です。

## Visual Contract

`ui-card` の視覚契約は、情報のまとまりを**枠、面、影、補助テキスト、画像比重**で表現し、本文より強く主張しすぎないことにあります。

### 情報順位

- `outlined` は最も中立的な既定表現です。
- `elevated` は面と影で一段上の物理感を与えます。
- `flat` は背景色でまとまりを示します。
- `ghost` は最小限の輪郭のみを残します。

本文近傍では、カードは読解の主役ではありません。したがって、どのバリアントでも常時過剰な発光や強い色面を持ち込まず、**面としての区切りを静かに提示すること**を優先します。

視覚契約上、card は本文より先に注意を奪ってはなりません。したがって、既定状態では次を正式契約に含めません。

- 持続的な発光表現
- 大きな拡大縮小アニメーション
- 高彩度の塗り面による常時強調
- 本文テキストより高い視覚コントラストでの常時主張

hover / focus-within においても、変化量は**カードが操作可能であることを示すのに必要な最小限**に留めます。

### generic カードの視覚仕様

- `outlined` は境界線を持ち、背景は透明です。
- `elevated` は境界線を持たず、`--bg-surface-2` とシャドウで浮上を示します。
- `flat` は境界線を持たず、`--bg-fill-muted` によって領域を示します。
- `ghost` は薄い枠線のみを持ち、背景は透明です。

### クリック可能状態の視覚仕様

有効モードが `generic` かつ `clickable=true` の場合、または有効モードが `link` の場合に限り、ホストに `cursor: pointer` を与えます。

また、`outlined` では hover / focus-within 時にシャドウと境界線色変化を与え、`elevated` ではシャドウを強化します。

`flat` および `ghost` では、クリック可能性を示すための専用 hover アニメーションや拡大縮小は必須契約に含めません。これらのバリアントにおける主要シグナルは、**カーソル、フォーカスリング、内部リンクの存在**です。

したがって、クリック可能であることの主要な視覚シグナルは、カーソル、フォーカスリング、内部リンクの存在、ならびに `outlined` / `elevated` で観測できる状態変化です。`flat` / `ghost` の hover 差分、scale 変化、背景色強調は正式契約に含めません。

### リンクカードの視覚仕様

リンクカードは、左にテキスト、右に画像を置く 2 カラムを基本とします。画像がない場合は 1 カラムへ縮退します。

- タイトルは 2 行までに制限します。
- 説明文は 2 行までに制限します。
- 説明文原文が 140 文字を超える場合、文字列を切り詰めて末尾に省略記号を付与します。
- 原文上は 140 文字以内でも表示 2 行を超える場合、視覚上の省略表現を追加します。
- 画像は `object-fit: cover` で収めます。

### フォーカス表示

有効モードが `generic` かつ `clickable=true` の場合、または有効モードが `link` の場合、ホストに `outline` と `outline-offset` によるフォーカスリングを描画します。リンクカード内部の `<a>` は `:focus-visible` で独自 outline を持たず、カード外形にフォーカス表示を集約します。

### スタイル拡張面と参照トークン

`ui-card` が外部に安定した拡張面として公開するのは CSS Custom Properties です。現行実装では `::part(...)` を公開しません。

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、`transition-duration` を `--duration-instant` に短縮します。また、hover / focus-within 時の `transform` は無効化します。

ただし、現行実装では通常状態における `transform` 変化自体が定義されていないため、実質的な差分は主としてトランジション時間短縮です。

### Forced Colors

`forced-colors: active` 環境では、全バリアントに `CanvasText` の境界線を強制付与します。`clickable` または `link` モードの hover / focus-within では `Highlight` のアウトラインを与えます。これは、背景色やシャドウが失われる環境でもカード境界を読み取れるようにするためです。

### Print

`@media print` では、シャドウと背景色を除去し、`break-inside: avoid` によりカード途中での分断を抑えます。`elevated` と `flat` は印刷時に黒 1px 境界線へ置き換え、`outlined` と `ghost` も境界線色を黒へ寄せます。

## 関連契約

### クリック委譲契約

有効モードが `generic` で `clickable=true` の場合、カード背景クリックは主要リンクへ委譲します。有効モードが `link` の場合は Shadow DOM 内の主リンクへ委譲します。

generic clickable card における主要リンクは、**現時点では** `ui-card` の Light DOM 部分木を文書順で走査したときに最初に見つかる `a[href]` として解決します。`header`、既定、`footer` のいずれに配置されていても、この機械規則で選定します。

本コンポーネントが固定する本質契約は、**カード背景クリックがただ一つの主要リンクへ委譲されること**です。主要リンクの選定アルゴリズム自体は、将来別契約で拡張される可能性があります。

ただし、現行利用者は、複数リンクを含む generic card では文書順先頭リンクが主要リンクとして扱われる前提で設計しなければなりません（MUST）。

ただし、次の場合は委譲しません。

- 主ボタン以外のクリック
- `metaKey` / `ctrlKey` / `shiftKey` / `altKey` 押下
- 当該 `ui-card` 内部に由来するテキスト選択が存在する場合
- 独立して操作可能な要素への直接クリック

独立して操作可能な要素には、少なくとも `a`、`button`、`input`、`textarea`、`select`、`summary`、`[role="button"]`、`[role="link"]`、`[contenteditable="true"]`、`[tabindex]:not([tabindex="-1"])` を含みます。

### スタイル拡張契約

`ui-card` は `::part(...)` を公開していません。公開する拡張面は CSS Custom Properties に限られます。

したがって、利用者は内部 class 名や Shadow DOM 内部構造に依存してはなりません（MUST NOT）。たとえば `.link-card__title` や `.link-card__description` などは内部実装詳細であり、互換性を保証しません。

### ナビゲーション契約

`link` モードの遷移は、内部のネイティブ `<a href>` の標準挙動に従います。現行実装は `target`、`rel`、`download` を公開入力として受け取りません。したがって、既定の同一タブ遷移以外のナビゲーション制御は本コンポーネントの公開契約に含めません。

また、現時点で `ui-card` は host 要素に対する専用の命令的 API を公開契約として定義しません。利用者は `ui-card.click()` や `ui-card.focus()` の特定結果に依存してはなりません（MUST NOT）。

操作主体は内部リンクまたは内部インタラクティブ要素です。

### イベント契約

`ui-card` は、カード操作通知のための独自カスタムイベントを公開契約には含めません。利用者が依存できるのは、内部リンクや内部インタラクティブ要素から発生する標準イベントです。

したがって、カード操作通知を `card-click` や `card-activate` のような独自イベントで受け取れることを前提にしてはなりません（MUST NOT）。

また、背景クリック委譲時のネイティブイベントの伝播順序や外部からの観測順序は、公開契約に含めません。

### モード切替契約

`cardKind` は要求モードを切り替えますが、有効モードは `href` と `cardTitle` の入力完全性を含めて解決します。したがって、`cardKind="link"` 単独では link モードは成立しません。

有効モードは、属性の存在そのものではなく、**trim 後に意味ある入力が揃っているか**によって決まります。利用者は、要求モードと有効モードが一致しない縮退状態を前提に設計してはなりません（SHOULD NOT）。

### フラッシュメディア表現の非保証

`ui-card` は、現時点では flush media / bleed media のための専用入力面、専用スロット、専用 `part` を公開しません。カバー画像等をカード内余白なしで敷く表現は、利用側の内容スタイリングによる局所実現であり、互換性保証の対象外です。

正式サポートする場合は、専用 slot、専用 variant、または明示的なレイアウト契約を追加した上で別契約として定義します。

## 境界条件

### 1. generic カードの最小構成

既定スロットのみに内容を置いた場合でもカードとして描画します。`header` と `footer` は省略できます。

ただし、正式構成としては既定スロットに読解可能な内容を持つことを前提とします。完全に空の generic カードをレイアウト用スペーサとして用いることは想定しません。

### 2. 3 スロット併用

`header`、既定、`footer` をすべて与えた場合、それぞれ独立した位置に表示します。スロット未使用でも追加のラッパーは挿入しません。

### 3. clickable だが内部リンクなし

有効モードが `generic` で `clickable=true` でも内部に `<a href>` が存在しない場合、クリック時に例外を投げず何も起こしません。ただし、公開契約上は不完全構成です。

### 4. clickable + 複数リンク

カード背景クリック時は、Light DOM 部分木を文書順で走査した最初の `<a href>` のみを主要リンクとして扱います。後続リンクは副リンクとして残ります。

### 5. インタラクティブ要素の共存

内部に `button`、`input`、`select`、`textarea`、`summary`、`[contenteditable="true"]`、`[role="button"]`、`[role="link"]`、`[tabindex]:not([tabindex="-1"])` など独立して操作可能な要素がある場合、それらへの直接クリックでは委譲を行いません。独自操作を優先します。

### 6. テキスト選択中

当該 `ui-card` 内部に由来するテキスト選択が存在する場合、カード背景クリックでも委譲しません。選択解除後は再び通常どおり委譲します。ページ上の他領域に残る選択は、当該カードのクリック委譲を抑止する理由にしません。

### 7. `card-kind="link"` だが `href` または `cardTitle` なし

要求モードとして `card-kind="link"` を指定していても、`href` または `cardTitle` が未指定相当である場合、有効モードは `generic` に戻るため、リンクカード専用構造は描画されません。利用者はこの縮退に依存せず、link モードでは `href` と `cardTitle` を必ず与えます。

### 8. `description` が空文字

リンクカードでは説明文要素を描画しません。

### 9. `imageSrc` が空文字

リンクカードでは画像を描画せず、1 カラム構成になります。

### 10. 画像取得失敗

画像 URL が不正または取得に失敗しても、`ui-card` は代替画像や再試行 UI を保証しません。画像は補助的な装飾メディアとして扱い、カードの意味成立はタイトルとリンク先情報で担保します。

### 11. `role` 明示指定

`role="section"` や `role="none"` を与えた場合、自動 `article` に上書きしません。

## 追加を検討する価値がある機能

本節は、現行契約を前提としたうえで、将来的に `ui-card` へ追加を検討する価値がある機能を整理するものです。ここに記載する項目は**現時点の公開契約ではありません**。正式採用する場合は、`card.ts`、`card.stories.ts`、本契約書を同時に更新します。

### 最優先で検討する価値がある機能

#### 1. 有効モードと視覚状態の一致

現行契約では、描画、クリック挙動、カーソル、フォーカスリングは有効モードによって決まるべきです。したがって、要求モードではなく**有効モードに基づいて CSS と DOM 状態を解決する仕組み**を追加する価値があります。

この機能を採用する場合、たとえば `data-effective-kind="generic|link"` のような内部状態反映を導入し、視覚状態もこれに一致させます。これにより、`card-kind="link"` だが入力不完全で有効モードは `generic` という場合でも、link 寄りのカーソルやフォーカス表示が残りません。

これは見た目の改善ではなく、**契約と実装を一致させるための基盤機能**です。したがって、他の機能追加より優先度を高く扱います。

#### 2. `link` モードの `target` / `rel` / 外部リンク契約

現行の `link` モードは、内部のネイティブ `<a href>` に依存しつつも、`target`、`rel`、外部リンク表示の入力面を公開していません。そのため、外部参照カードや別タブ遷移カードを正式に扱うには契約が不足しています。

この機能を採用する場合、少なくとも次の入力面を追加する価値があります。

- `target`
- `rel`
- `external` または外部リンクであることを示す補助表示契約

ただし、generic モードまで同じ入力面を広げません。**link モードに限定したナビゲーション契約拡張**として追加します。

#### 3. Flush / Cover Media の正式サポート

現行契約では、カード内余白なしで画像を敷く表現は非保証です。しかし、リンクカードや特集カードでカバー画像を正式に扱いたい要求があるなら、専用入力面を持つ価値があります。

この機能を採用する場合、`variant` を増やすよりも、``** のような専用スロット**を追加する方が設計としてきれいです。見た目の違いではなく、**内容構造として media 領域を持つ**ことを明確にできます。

採用時は、次の契約を同時に定義します。

- media 領域が generic / link のどちらで利用可能か
- 角丸、クリッピング、余白有無の規則
- 装飾 media と意味を持つ media のどちらを想定するか
- フォーカスリングと hover 状態が media 領域上でも破綻しないこと

### 条件付きで検討する価値がある機能

#### 1. 画像意味論の分岐（`media-mode`）

現行契約では、`link` モードの画像は常に装飾画像です。これを拡張するなら、単純な `image-alt` 追加ではなく、**画像の意味論そのものを分岐する入力面**として設計する方がよいです。

この機能を採用する場合、たとえば次のように定義します。

- `media-mode="decorative|informative"`
- `informative` の場合に限り `image-alt` を必須化
- `decorative` の場合は従来どおり `alt=""`

ただし、Rouault における card が本文補助的な静かなリンクカードにとどまるなら、優先度は上げません。**画像を意味主体にしたい明確な要件がある場合に限って検討します。**

#### 2. 見出しレベル指定

現行契約では、`link` モードのタイトル見出しは内部で `<h3>` 固定です。文書アウトラインへの厳密参加が必要な場合には、見出しレベル指定を追加する価値があります。

この機能を採用する場合、`heading-level` のような入力を追加し、`h2` から `h6` の範囲で明示指定できるようにします。

ただし、card を文書構造コンポーネントに近づけすぎると責務が膨らみます。したがって、**ページ全体の見出し階層と card タイトルを厳密同期させる要件が継続的に存在する場合に限って検討します。**

#### 3. 公開 `part` の追加

現行契約では、安定したスタイル拡張面は CSS Custom Properties に限定しています。タイトル、説明、media などの内部要素単位で外部調整する需要が明確なら、公開 `part` を追加する価値があります。

この機能を採用する場合、候補は次のとおりです。

- `part="body"`
- `part="title"`
- `part="description"`
- `part="media"`

ただし、`part` は Shadow DOM 内部構造を強く固定します。したがって、**テーマ調整需要が高く、内部構造の安定公開に見合うだけの継続価値がある場合に限って採用します。**

#### 4. 主要リンクの明示指定

現行契約では、generic clickable card の主要リンクは文書順で最初の `a[href]` です。この機械規則は単純で再現性がありますが、複雑なカードでは不便になる場合があります。

この機能を採用する場合、たとえば次のいずれかを追加します。

- `primary-link-selector`
- `data-card-primary-link`

ただし、この機能は「複雑な card を許容する方向」の拡張です。Rouault の card は、なるべく単純な読解単位として保つ方が設計上きれいです。したがって、**複数リンクを持つ高度な generic card が実運用で継続的に必要になった場合に限って検討します。**

## 補足

`ui-card` の要点は、装飾の豊富さではありません。**独立した読解単位を静かに切り出し、必要なときだけカード全体を主要リンクへ接続し、それでもコピーや副操作を壊さないこと**にあります。

したがって、今後の変更でも次の点は崩さない方がよいです。

1. 既定 role を持つ独立した情報単位であること。
2. generic と link の描画モードを混線させないこと。
3. クリック委譲がネイティブ操作やテキスト選択を阻害しないこと。
4. 視覚重量が本文を追い越さないこと。

## 現行実装で未対応または未整合の事項

本節は、現行の `card.ts` と `card.stories.ts` を基準として、**Storybook 記述や設計意図と実装の間に差分が残っている箇所**を整理するものです。

### 1. Hover 時の `transform` 変化

Storybook では clickable カードにスケール変化がある前提の説明がありますが、現行実装の CSS には hover / focus-within 時に `transform` を実際に変更する規則が存在しません。`transition` と reduced motion 側の `transform: none` はありますが、通常系の変化は未定義です。

したがって、**モーション契約として scale を公開契約に昇格させるには実装が不足しています**。

### 2. outlined hover 時の背景変化

Storybook の説明には `outlined` が hover 時に背景不透明化する旨がありますが、現行実装では `border-color` と `box-shadow` の変化のみで、背景色変更は定義していません。

したがって、**outlined hover の背景変化は現行実装の事実ではありません**。

### 3. flat / ghost の clickable 状態差分

Storybook の説明には `flat` / `ghost` にも状態変化があるように読める箇所がありますが、現行実装では専用 hover 差分を定義していません。視覚変化は主として `outlined` と `elevated` に限られます。

### 4. `card-kind="link"` 指定時の有効モードと視覚状態

契約上は `href` と `cardTitle` が揃わない限り有効モードを `generic` としますが、現行実装は属性セレクタ `[card-kind='link']` に基づくスタイルを持つため、要求モードだけが `link` の状態でも link 寄りのカーソルやフォーカス表示が残る余地があります。

したがって、**要求モードと有効モードを完全一致させる契約に対して、現行実装の視覚状態解決は未整理です**。

### 5. link カードの必須入力強制

公開契約上は link カードに `href` と `cardTitle` を与えることを前提としますが、現行実装は `href` 欠落時に generic へ縮退し、`cardTitle` 欠落時も空見出しのまま描画し得ます。描画停止や警告はありません。

したがって、**link モードの入力完全性は実行時に強制されていません**。

### 6. テキスト選択ガードの適用範囲

契約上は当該 `ui-card` 内部に由来するテキスト選択だけを委譲抑止対象としますが、現行実装は `window.getSelection()` に基づいてページ全体の選択状態を参照しています。

したがって、**局所選択のみを対象とする契約に対して、現行実装は適用範囲が広すぎます**。

### 7. 直接操作を保護する要素の範囲

契約上は `role="link"`、`summary`、`[tabindex]` 要素を含む広い保護範囲を定義しますが、現行実装が明示的に除外している要素集合はそれより狭いです。

したがって、**独立操作要素の保護範囲は契約に対して未追従です**。

### 8. `href` 正規化の未追従

契約上は、`href` を trim 済み文字列として解釈しますが、現行実装の link card 描画では `href=${ifDefined(this.href || undefined)}` として、**trim 前の元値**をそのまま内部 `<a>` に渡しています。  
一方、`_isLinkCard` 判定では `this.href.trim()` を用いているため、**モード判定に使う値と実際に出力される `href` 値が一致していません**。

したがって、**文字列入力を trim 済み値として扱うという契約は、現時点では `href` についてのみ実装と不整合です**。

### 9. JSDoc の公開面と現行契約の不整合

`card.ts` の JSDoc には、`--bg-surface-1`、`--elevation-sm`、`--scale-hover-sm` などの `@cssprop` が列挙され、さらに Flush Content の利用指針も記載されています。しかし、現行契約ではこれらを正式公開面として扱っておらず、scale 変化や outlined hover 背景変化も実装されていません。逆に、契約書で公開している `--ui-card-description-fade` は JSDoc の `@cssprop` 列挙に含まれていません。fileciteturn9file0

したがって、**実装ファイル先頭の JSDoc が、現行契約より広い公開面を示唆しており、公開面の定義源として整合していません**。

### 10. Storybook 契約と実際の story 定義の不整合

契約書の Storybook 契約には `LinkCardRequiresHrefAndTitle` を記載していますが、現行の `card.stories.ts` には同名 story の export が存在しません。また、Storybook の story index にも該当 story は現れていません。fileciteturn11file0 fileciteturn11file1
