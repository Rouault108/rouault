# Badge

## 概要

本書は、`ui-badge` の公開契約、入力解釈規則、更新契約、状態モデル、および表示上の読み方を整理するものです。

`ui-badge` は、**件数、状態、更新有無**などの小さなシステム状態を提示するコンポーネントです。形状は **pill** を基本とし、`variant="dot"` の場合に限って最小の視覚インジケーターとして正円を採用します。ユーザー定義の分類を表すタグとは、形状と役割の両面で区別します。

本コンポーネントの要点は、短い文字列を表示すること自体にはありません。**数値を優先表示するか、スロット内容を表示するか、あるいは内容を持たない dot として扱うか**、および **どの値を表示対象として採用するか** を一定の契約として固定することにあります。

また、配色、高コントラスト対応、およびテーマ差分は、コンポーネント固有の条件分岐ではなく、**トークン契約**によって成立させます。

## 公開契約

`variant`、`count`、`max`、`color`、`ariaLabelText`、`countAriaLabel`、`announce` を公開入力とします。`variant` の既定値は `solid`、`max` の既定値は `99`、`color` の既定値は `primary`、`announce` の既定値は `off` です。`count` が存在しない場合に限り、`variant !== "dot"` のときにスロット内容を表示します。

`variant="dot"` は、件数表示やラベル表示ではなく、**内容を持たない視覚インジケーター**として扱います。したがって、`count`、`countAriaLabel`、およびスロット内容は表示対象に含めません。dot は可視テキストを持たないため、`aria-label` を指定しなければなりません（MUST）。`aria-label` を欠いた dot は、描画可否にかかわらず契約上は成立しません。

`count` は数値入力として扱います。数値が存在する場合、スロット内容は無視します。`max` は表示上限として扱い、実数値そのものを切り捨てたり丸めたりするものではありません。`count > max` の場合に限り、表示文字列を `${max}+` とします。数値状態のアクセシブルネームは既定では正規化後の実数値に基づいて内部生成し、`countAriaLabel` が指定された場合に限ってその明示値を正本として扱います。

`announce` は数値状態にのみ適用する通知モード入力です。受理値は `auto` と `off` の 2 値に限定します。`off` は既定の静的表示であり、数値状態をライブリージョンとして扱いません。`auto` は文脈上の通知性を明示したい場合に用い、数値状態を通知可能な状態表示として扱います。

公開面に新しい入力を加える場合でも、**1 つの拡張は 1 つの責務だけを増やす**こと、**既存の `dot > count > slot` 優先順位を維持する**こと、**見た目の派生ではなく意味の派生だけを許容する**こと、**formatter・callback・複雑な mode 群のような高自由度 API は持ち込まない**ことを原則とします。

| 名前             | 種別                                | 必須         | 内容                         | 契約                                                                                                                        |
| ---------------- | ----------------------------------- | ------------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `variant`        | property / attribute                | いいえ       | 視覚バリアント               | `solid` / `subtle` / `dot` を受け付けます。未知の値は存在しないものとして扱います。                                         |
| `count`          | property / attribute                | いいえ       | 件数                         | 数値として解釈できる場合に限り数値表示を採用します。存在しない場合はスロット経路へ移行します。                              |
| `max`            | property / attribute                | いいえ       | 表示上限                     | 表示文字列の上限値です。既定値は `99` です。数値として解釈できない場合は既定値を採用します。                                |
| `color`          | property / attribute                | いいえ       | 意味色                       | `primary` / `neutral` / `success` / `warning` / `danger` を受け付けます。未知の値は存在しないものとして扱います。           |
| `ariaLabelText`  | property / attribute (`aria-label`) | dot 時は必須 | 代替テキスト                 | `variant="dot"` では指定しなければなりません（MUST）。                                                                      |
| `countAriaLabel` | property / attribute                | いいえ       | 数値状態のアクセシブルネーム | 数値状態にのみ適用します。指定時は内部生成値ではなく、この明示値を正本として扱います。                                      |
| `announce`       | property / attribute                | いいえ       | 数値状態の通知モード         | `auto` / `off` を受け付けます。既定値は `off` です。`auto` は数値状態を通知可能な状態表示として扱い、`off` は静的表示です。 |
| default slot     | slot                                | 条件付き     | テキストラベル               | `count` が存在せず、`variant !== "dot"` の場合にのみ表示します。空スロットは有効状態として扱いません。                      |

責務には、件数の正規化、表示文字列の決定、dot の代替テキスト付与、数値状態のアクセシブルネーム決定、通知モードの適用、意味色の適用、および必要なアクセシビリティ属性の付与を含みます。

一方で、クリック操作、削除ボタン、閉じる操作、キーボード操作、通知件数の更新元管理、通知頻度制御、通知抑制ポリシー、および外部イベント発火は責務に含めません。

### 入力解釈規則

各公開入力は、property と attribute の両方から受理できます。ただし、**意味の正本は常にコンポーネント内部の正規化済み状態**です。利用者は、属性文字列そのものではなく、正規化後の表示結果およびアクセシビリティ結果に依存しません。

`variant` と `color` は列挙値として解釈します。未知の値は存在しないものとして扱います。未知値は独自の意味を持たず、属性未指定と同等に扱います。したがって、結果として `variant` は `solid`、`color` は `primary` へ収束します。

`count` と `max` は数値入力として解釈します。property では `null` / `undefined` により不在を表現します。attribute では属性未指定により不在を表現します。数値として解釈できない値は存在しないものとして扱います。したがって、`count` の不正値は数値状態を成立させず、`max` の不正値は既定値 `99` を採用します。

`count` が存在しないとは、property では `null` / `undefined`、attribute では属性未指定、または数値として解釈できない値であることを指します。`count` が存在しない場合に限り、スロット経路へ入ります。

`ariaLabelText` は DOM 上では `aria-label` として扱います。`variant="dot"` の場合、この値は表示内容ではなく代替テキストの正本です。空文字列は有効値として扱いません。

`countAriaLabel` は数値状態にのみ適用する単一文字列入力です。空文字列、空白のみ、または可視意味を持たない値は有効値として扱いません。その場合は内部生成のアクセシブルネームへフォールバックします。

`announce` は列挙値として解釈します。`auto` は通知可能な状態表示、`off` は静的表示を意味します。未知の値、空文字列、または未指定は `off` と同等に扱います。`announce` は数値状態にのみ適用し、dot 状態およびスロット状態には影響しません。

### Property / Attribute 対応

| 入力             | Property         | Attribute          | 既定値    | 解釈上の注意                                                 |
| ---------------- | ---------------- | ------------------ | --------- | ------------------------------------------------------------ |
| `variant`        | `variant`        | `variant`          | `solid`   | 未定義値には依存しません。                                   |
| `count`          | `count`          | `count`            | 不在      | 数値化できない値は不在として扱います。                       |
| `max`            | `max`            | `max`              | `99`      | 数値化できない値は既定値 `99` を採用します。                 |
| `color`          | `color`          | `color`            | `primary` | 未定義値には依存しません。                                   |
| `ariaLabelText`  | `ariaLabelText`  | `aria-label`       | なし      | dot 時は必須です。空文字列は無効です。                       |
| `countAriaLabel` | `countAriaLabel` | `count-aria-label` | なし      | 数値状態にのみ適用します。空文字列は内部生成値へ戻します。   |
| `announce`       | `announce`       | `announce`         | `off`     | `auto` / `off` のみを受け付けます。未知値は `off` 扱いです。 |

## 更新契約

`ui-badge` は、公開入力が変更されたとき、表示状態を再評価します。再評価の結果、**dot / count / slot** のいずれか 1 つの状態へ再収束します。

### 再評価の単位

次の変更は再評価を引き起こします。

- `variant` の変更
- `count` の変更
- `max` の変更
- `color` の変更
- `ariaLabelText` の変更
- `countAriaLabel` の変更
- `announce` の変更
- default slot の内容変更

`color` の変更は視覚表現のみを更新します。`variant`、`count`、`max`、`countAriaLabel`、`announce`、slot 内容の変更は、表示経路またはアクセシビリティ結果を変更し得ます。

### 状態遷移

入力変更時の遷移規則は次のとおりです。

- `variant` が `dot` へ変わった場合、現在の `count` と slot 内容を無視して dot 状態へ遷移します。
- `variant !== "dot"` かつ `count` が存在する場合、slot 内容を無視して数値状態へ遷移します。
- `variant !== "dot"` かつ `count` が存在しない場合、非空の slot があるときに限ってスロット状態へ遷移します。
- `variant="dot"` かつ `aria-label` が存在しない場合、dot 状態は成立しません。

この遷移規則は常に **dot > count > slot** の優先順位に従います。ただし、dot は `aria-label` が存在する場合に限って成立し、slot は非空である場合に限って成立します。

### アクセシビリティ更新

数値状態のアクセシビリティは、**通知的な件数表示**と**静的な件数表示**を区別して扱います。Badge の数値は常にライブリージョンとして通知されるとは限らず、未読件数、更新件数、保留件数のように文脈上の通知性が明確な場合に限って通知可能な状態表示として扱います。単なる集計値、一覧補助、静的メタデータとしての件数表示は、静的テキストとして扱います。

したがって、数値状態に `role="status"` を常時付与することは公開契約に含めません。既定では `announce="off"` の静的表示とし、`announce="auto"` が明示された場合に限って通知可能な状態表示として扱います。Badge 自身は通知システムではなく、小型状態表示です。高頻度に変化するカウンターや連続更新用途には使用しません（SHOULD NOT）。

dot 状態では `role="img"` を付与し、スロット状態では無ロールの静的表示とします。数値状態では、`announce="auto"` の場合に限って `role="status"` を付与し、`announce="off"` では無ロールの静的表示とします。状態遷移に伴い、必要なアクセシビリティ属性は再評価します。

## 状態モデル

`ui-badge` の表示状態は、`variant` と `count` の組み合わせで決定します。判定順序は **dot 判定 → count 判定 → slot 判定** です。

`variant === "dot"` かつ `aria-label` が存在する場合、dot 状態を採用します。それ以外で、正規化後の `count` が存在する場合、数値状態を採用します。それ以外で、非空のスロット内容が存在する場合、スロット状態を採用します。それ以外の場合、`ui-badge` は有効な可視状態を持ちません。

`count` は次の規則で正規化します。

- `null` / `undefined` → 不在
- 数値として解釈できない値 → 不在
- 負数 → `0`
- 小数 → `Math.floor()` により整数化
- `Infinity` / `-Infinity` → 不在

`max` は次の規則で正規化します。

- 数値として解釈できない値 → `99`
- `null` / `undefined` → `99`
- `Infinity` / `-Infinity` → `99`
- 小数 → `Math.floor()` により整数化
- `1` 未満 → `1`

表示文字列は `count > max ? \`${max}+\` : \`${count}\`` とします。数値状態のアクセシブルネームは、`countAriaLabel`が有効値として存在する場合はその明示値を正本とし、存在しない場合は正規化後の実数値を基準に内部生成します。したがって、表示が`99+` でも、アクセシブルネームは必要に応じて実数値基準で保持します。

数値状態の通知性は `announce` により決定します。`announce="off"` は静的表示、`announce="auto"` は通知可能な状態表示です。`announce` は数値状態にのみ適用し、dot 状態およびスロット状態では無視します。

| 状態         | 条件                                                               | 表示                | アクセシビリティ                                                                                                                  |
| ------------ | ------------------------------------------------------------------ | ------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| dot 状態     | `variant === "dot"` かつ `aria-label` が存在する場合               | 8px の正円のみ      | 内部要素に `role="img"` を付与し、`aria-label` で意味を与えます。                                                                 |
| 数値状態     | `variant !== "dot"` または dot 不成立、かつ `count` が存在する場合 | 数値または `{max}+` | `countAriaLabel` があればそれを優先し、なければ内部生成値を用います。`announce="auto"` の場合に限って通知可能な状態表示とします。 |
| スロット状態 | 数値状態が成立せず、非空スロットが存在する場合                     | スロット内容        | 静的ラベルとして扱い、`role="status"` は付与しません。                                                                            |
| 不成立状態   | dot / count / slot のいずれも成立しない場合                        | 表示しません        | アクセシビリティ対象を持ちません。                                                                                                |

最小状態は `count` を持たず、非空スロットに短い文字列のみが与えられた状態です。この場合、通常の pill ラベルとして表示します。

## DOM / Accessibility

ルート要素は `<ui-badge>` です。表示内容は Shadow DOM 内の単一 `<span>` により表現します。ホスト自身に `role` は付与しません。

```text
<ui-badge>
  #shadow-root
    <span ...>
      [displayText | <slot> | empty]
    </span>
</ui-badge>
```

状態ごとの DOM は次のとおりです。

```text
dot:
<span role="img" aria-label="新着"></span>

count (`announce="off"`):
<span aria-label="128 件">99+</span>

count (`announce="auto"`):
<span role="status" aria-label="未読 128 件">99+</span>

slot:
<span><slot></slot></span>
```

数値状態は既定では静的ラベルとして扱います。`role="status"` は `announce="auto"` の場合に限って付与し、`announce="off"` では付与しません。`countAriaLabel` が指定されている場合、数値状態のアクセシブルネームは内部生成値ではなくその明示値を採用します。スロット状態は静的ラベルであり、ライブリージョンとして扱いません。

`variant="dot"` は可視テキストを持たないため、`aria-label` によって意味を補います。`aria-label` を欠く dot は契約上成立せず、代替テキストのない視覚記号として運用しません。

ホスト要素はフォーカス対象ではありません。`tabindex` を持たず、`disabled`、`error`、`aria-disabled` 等の状態も持ちません。Rouault における読み方として重要なのは、**バッジを最後まで情報表示専用の要素として実装すること**、および **状態ごとに必要な意味ロールだけを付与すること** です。見た目のみの疑似状態へ依存しません。

### スロット内容の制約

default slot は、短い非空のインラインテキストを主対象とします。複雑な子要素構造、複数行レイアウト、対話要素の内包は公開契約に含めません。

slot に複数ノードや装飾要素を与えた場合でも描画自体は行われ得ますが、見た目、折り返し、読み上げ順序、および省略表示の結果は公開保証しません。利用者は、**短い単一ラベル**を前提として利用します。

空文字列、空白のみ、または可視内容を持たない slot は有効状態として扱いません。`count` も存在しない場合、バッジは成立しません。

## Visual Contract

正規の見え方は、`solid`、`subtle`、`dot` の 3 系統です。`solid` は背景色つきの強調表示、`subtle` は低いトーンの境界付き表示、`dot` は最小の視覚シグナルです。つまり `ui-badge` では、**情報の強度差を形状ではなくトーンと内容で分ける**ことを基本とします。

ホスト要素は `inline-flex` とし、中央揃え、`white-space: nowrap`、`overflow: hidden`、`text-overflow: ellipsis` を持ちます。したがって、長い文字列を受け取っても単一行の pill として振る舞います。

`solid` および既定状態は、高さ `var(--control-height-2xs, 16px)`、最小幅も同値、左右パディング `var(--space-1, 4px)`、最大幅 `12ch` を基準とします。`subtle` は左右パディング `var(--space-2, 8px)` を採用し、背景は `var(--bg-surface-2, var(--bg-default))`、文字色とボーダー色は意味色に一致します。`dot` は幅・高さともに `8px` を基準とし、内容を持ちません。

文字組は `--text-2xs`、`--font-bold`、`--tracking-wider`、`line-height: 1` を採用します。内部 `span` には `translateY(-0.05em)` を与え、フォントメトリクスによる視覚的な下寄りを補正します。

| success 背景 / 前景 | `--success`, `--on-success`      |
| danger 背景 / 前景  | `--danger`, `--on-danger`        |
| warning 背景 / 前景 | `--warning`, `--on-warning`      |
| neutral 背景 / 前景 | `--fg-default`, `--bg-default`   |

| 文字間隔            | `--tracking-wider`               |

### 色の意味

| `color` 値 | 用途の目安                   |
| ---------- | ---------------------------- |
| `primary`  | 既定の件数、一般的な状態     |
| `neutral`  | 中立状態、アーカイブ的表示   |
| `success`  | 正常、安定、公開済み         |
| `warning`  | 下書き、注意、準備中         |
| `danger`   | 非推奨、エラー寄りの強い注意 |

### スタイル公開面

本コンポーネントは、**公開入力とセマンティックトークン参照結果**を公開面とします。利用者は、`variant`、`color`、`count`、`max`、`aria-label`、およびホスト要素に対する外部レイアウト指定に依存できます。

一方で、Shadow DOM 内部の要素構造、内部 `span` の存在、DOM 階層、内部セレクタ、将来追加される補助要素には依存しません。`::part`、内部クラス名、内部ノード順序は公開契約に含めません。

外部スタイルによる大幅な形状変更、内部余白の再定義、状態ごとの意味色の差し替えは、公開契約外として扱います。見た目の調整は、原則として公開入力およびトークン系設計によって行います。

### ホスト要素のレイアウト契約

ホスト要素はインライン文脈に配置できる小型表示要素です。本文、見出し、ボタンラベル近傍、リスト項目などの行内に配置できます。

ホストの `display` は `inline-flex` を前提とします。利用者がこれを `block` や複雑なレイアウトコンテナへ変更した場合の見え方は公開保証しません。外部 `margin`、周辺配置、親の配置文脈への参加は許容しますが、内部サイズ計算や省略表示はコンポーネント自身の契約を優先します。

---

## 環境別の振る舞い

本コンポーネントは、ライトモードとダークモードを個別分岐で処理しません。テーマ差分はトークン差し替えにより成立します。

`forced-colors: active` 環境では、システムカラーへ退避します。ホストは `ButtonText` ベースの境界を持ち、`solid` は `ButtonText` 背景と `ButtonFace` 前景を採用します。`dot` は視認性確保のため `10px` に拡張します。

モーション契約は持ちません。トランジションやアニメーションは定義しません。したがって、`prefers-reduced-motion` 依存の振る舞いも持ちません。

---

## 関連契約

`ui-badge` は、タグコンポーネントと混同しません。Badge は **件数・状態・更新有無・公開状況** など、表示対象そのものの現在状態を短く付記する要素です。一方、タグは **分類・主題・属性・検索キー** など、対象をどの集合に属させるかを示す要素です。

したがって、Badge は状態変化に伴って値や表示有無が変化し得ますが、タグは分類体系が変わらない限り比較的安定したラベルとして残ります。Badge の典型例は「3」「99+」「Draft」「New」「Archived」であり、タグの典型例は「Math」「Lit」「UI」「研究メモ」です。

形状を pill に固定する理由は、この差を視覚的に補助するためです。ただし、Badge とタグの区別は最終的には見た目ではなく意味論で決まります。ユーザー定義の分類や検索用ラベルを表示したい場合はタグ契約へ、対象の現在状態や件数を表示したい場合は Badge 契約へ寄せます。

---

## 非目標

本コンポーネントは、次の機能を目標としません。

- フィルターチップやトグルのような操作要素化
- 削除可能ラベルや閉じるボタンの内包
- 通知件数の取得、永続化、同期
- 不成立時の表示方針入力（`emptyPolicy` / `empty-policy`）
- 件数文言の組み立て関数、複数言語辞書、テンプレート式 formatter
- 通知強度の細分化、通知頻度制御、遅延、抑制ポリシー
- ツールチップや補助説明の自動表示
- 複雑なアイコン複合や複数行ラベルレイアウト

これらが必要な場合は、上位コンポーネントまたは別契約のコンポーネントで扱います。

## 不変条件

次の条件は常に成立しなければなりません。

- 可視状態は常に `dot`、`count`、`slot` のいずれか 1 つであり、複数状態を同時に取りません。
- `dot` 状態は `aria-label` が存在する場合に限って成立します。
- `dot` 状態では可視テキストを持ちません。
- `count` が有効な場合、slot 内容は表示しません。
- `variant="dot"` は `count` と slot の両方より優先します。ただし、dot の成立条件を満たさない場合は次順位へ移行します。
- スロット状態は非空 slot が存在する場合に限って成立します。
- 数値状態では可視文字列とアクセシブルネームを分離します。
- ホスト要素はフォーカス可能になりません。
- 本コンポーネントはカスタムイベントを発火しません。

---

## 境界条件

`count=0` は有効値です。`null` や `undefined` とは異なり、`"0"` を表示します。

`count` が負数や小数であっても、正規化後の数値状態へ入ります。負数は `0`、小数は `Math.floor()` により整数化します。

`count` が `NaN`、`Infinity`、`-Infinity`、空文字列、または数値として解釈できない値である場合、`count` は存在しないものとして扱います。したがって、その場合は数値状態を成立させません。

`max=0`、負数、小数は下限補正および整数化の対象です。`max` が `NaN`、`Infinity`、`-Infinity`、空文字列、または数値として解釈できない値である場合、`max` は既定値 `99` を採用します。

`variant="dot"` は `count` を無視します。ただし、`aria-label` を欠く場合、dot は成立しません。その場合、次順位の count または slot 判定へ移行します。

`variant` または `color` に未知値が与えられた場合、それらは存在しないものとして扱います。したがって、既定値へ収束します。

`variant` を省略した場合は `solid` と同義です。

長いスロット文字列や大きな件数文字列は、ホストの `max-width` と `ellipsis` に従って切り詰められます。内容全体の可視保証は行いません。

## Storybook 契約

各 Story はデモではなく**契約確認点**として扱います。将来の変更時には、各 Story が固定する契約を維持します。

| Story                    | 固定する契約                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------ |
| `Default`                | 既定状態が `solid` / `primary` / slot 経路であること                                 |
| `VariantColorMatrix`     | 全 `variant` × 全 `color` の視覚マトリクスと dot の無内容契約                        |
| `CountBadge`             | 数値状態、`99+` 表示、およびアクセシブルネームの実数値保証                           |
| `TextBadge`              | `count=null` 時の slot 表示と静的ラベル契約                                          |
| `CountAriaLabelOverride` | `countAriaLabel` / `count-aria-label` が数値状態のアクセシブルネームを上書きする契約 |
| `AnnounceModes`          | `announce="off"` と `announce="auto"` の差、および通知モード適用範囲                 |
| `CountMaxCombinations`   | `count` と `max` の組み合わせ、および閾値境界                                        |
| `ContentPriorityLogic`   | `dot > count > slot` の優先ロジック                                                  |
| `CountNormalization`     | `NaN` / `Infinity` / 負数 / 小数の正規化                                             |
| `MaxNormalization`       | `max` の下限補正と整数化                                                             |
| `CountZero`              | `0` を有効件数として扱う契約                                                         |
| `CountUndefined`         | `undefined` が slot 経路へ入る契約                                                   |
| `DotIgnoresCount`        | dot が slot / count / `countAriaLabel` / `announce` を無視する契約                   |
| `NonInteractive`         | 非インタラクティブ設計とフォーカス不可契約                                           |
| `ThemeContrastAudit`     | Light / Dark 相当トークン下でのコントラスト監査契約                                  |
| `ForcedColorsContract`   | forced-colors 退避ルールの存在契約                                                   |
| `AllStates`              | 全体状態一覧による視覚的退行検知                                                     |

## 破壊的変更の判断基準

次の変更は、原則として破壊的変更として扱います。

- `variant` の受理値集合を変更すること
- `color` の受理値集合を変更すること
- 未知の `variant` / `color` を存在しないものとして扱う規則を変更すること
- `dot > count > slot` の優先順位を変更すること
- dot の成立条件から `aria-label` 必須を外すこと
- slot の成立条件から非空制約を外すこと
- `count` および `max` の正規化規則を変更すること
- 数値状態を既定で静的表示として扱う契約を変更すること
- `countAriaLabel` / `count-aria-label` の適用範囲、優先順位、または空値時の解釈を変更すること
- `announce` の受理値集合、既定値、または `auto` / `off` の意味を変更すること
- `announce` が数値状態にのみ適用される契約を変更すること
- 非インタラクティブ契約を破り、フォーカスや操作を持たせること

一方で、公開面に影響しない内部 DOM 再編、実装詳細の整理、内部ノードの差し替えは、公開契約を維持する限り破壊的変更とは扱いません。

---

## 補記

現行実装と Storybook から読み取れる契約として、もっとも重要なのは次の 3 点です。

- **表示優先順位は \*\***dot > count > slot\***\* で固定します。**
- **数値表示は可視文字列と意味上の件数を分離し、通知性は文脈依存で扱います。**
- **バッジは最後まで非インタラクティブのまま維持します。**

この 3 点を崩す変更は、単なる見た目変更ではなく、コンポーネント契約の変更として扱う必要があります。

## 実装追随状況

`src/components/ui/badge/badge.ts` および `src/components/ui/badge/badge.stories.ts` は、2026-03-23 時点で本書の公開契約へ追随しています。

現在の実装では、少なくとも次の項目が本書どおりに成立します。

1. `count` は `NaN`、`Infinity`、`-Infinity`、空文字列、非数値文字列を不在として扱い、負数は `0`、小数は `Math.floor()` で正規化します。
2. `max` は不正値時に既定値 `99` へ収束し、有限値は整数化のうえで `1` 未満を `1` に補正します。
3. `variant="dot"` は `aria-label` がある場合に限って成立し、欠く場合は count または slot 判定へフォールバックします。
4. 空スロットのみで `dot`、`count`、`slot` のいずれも成立しない場合、`ui-badge` は表示しません。
5. 未知の `variant` / `color` は内部正規化により既定値へ収束します。
6. `countAriaLabel` / `count-aria-label` により、数値状態のアクセシブルネームを明示的に上書きできます。
7. `announce` は `off` / `auto` を受け付け、既定では静的表示、`auto` の場合のみ `role="status"` を適用します。

将来この節に再び未対応項目を追加する場合は、必ず次の 3 点を併記します。

1. どの公開契約に対する差分か
2. 利用者が観測できるズレは何か
3. 実装追随の優先順位をどこに置くべきか
