# Article Header

## 概要

本書は、`ui-article-header` の公開契約、状態モデル、DOM / アクセシビリティ契約、表示契約、イベント契約、および Storybook 契約を定義します。

`ui-article-header` は、記事冒頭における **識別情報**、**時間情報**、**分類情報**、**帰属情報** を提示するヘッダーコンポーネントです。本コンポーネントでは、見出しを主情報、日付と読了時間を主要メタデータ、タグを分類情報、出典とライセンスを補助メタデータとして段階化して扱います。

本コンポーネントの中核契約は次のとおりです。

- 記事タイトルは常に主情報として扱います。
- 代表日付は `updatedDate > published` の優先順位で決定します。
- 日付入力は公開契約上 `YYYY-MM-DD` 形式の正規値のみを受理し、正規値のみを `<time datetime>` に反映します。
- `created` は可視テキストとしては表示せず、日付の補助文脈としてのみ扱います。
- タグは独立行で表示する周辺ナビゲーションとして扱います。
- 出典とライセンスは帰属情報として扱い、表示前に必要な正規化を行います。

配色、モーション、高コントラスト対応は、コンポーネント固有のモード分岐ではなく、トークン契約およびメディアクエリにより成立させます。

## 適用範囲

本書は、`ui-article-header` の次の事項を対象とします。

- 公開契約を対象とします。
- 状態モデルを対象とします。
- DOM / アクセシビリティ契約を対象とします。
- 表示契約を対象とします。
- イベント契約を対象とします。
- Storybook 契約を対象とします。
- 関連契約を対象とします。
- 契約が不明瞭な点を対象とします。
- 現行実装で未対応の事項を対象とします。

本書は、次の事項を対象外とします。

- ルーティング実装は対象外とします。
- タグ一覧ページの存在保証は対象外とします。
- CMS ごとの入力差分吸収は対象外とします。
- 記事自体の permalink 提示、copy link 操作、共有導線は対象外とします。
- 任意 slot による拡張は対象外とします。
- SNS シェアボタン群は対象外とします。
- 著者情報、Hero image、パンくず、目次、ページネーション、検索導線等との上位統合は対象外とします。
- テーマ切替ロジックそのものは対象外とします。

これらは上位レイヤまたは別契約の責務です。

## 1. 公開契約

本章では、`ui-article-header` が受理する入力、公開面の責務、および属性反映規則を定義します。

### 1.1 入力面

`heading` は必須入力です。`published`、`created`、`updatedDate`、`tags`、`readingTime`、`status`、`source`、`license` は任意入力です。

`updatedDate` は property 名です。対応する HTML 属性名は `updated` です。

`tags` は正規入力です。現行契約では property 専用で受理し、表示前に正規化します。HTML 文字列からの供給が必要な場合は、`ui-article-header` の公開契約ではなく、Markdown bridge または adapter 層で `tags` property へ受け渡します。

`source` と `license` は現行では単純入力です。ただし、帰属情報の拡張は `sourceLabel` や `licenseHref` のような場当たり的な prop 追加では受けません。必要になった時点で、表示ラベル、遷移先、種別を分離した構造化帰属情報モデルとして扱います。

| 名前          | 種別                                  | 必須   | 内容             | 契約                                                                                                                                                                                                      |
| ------------- | ------------------------------------- | ------ | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `heading`     | property / attribute                  | はい   | 記事タイトル     | 公開契約上は必須です。実装上は空文字既定値を持ちますが、空文字運用は行いません。                                                                                                                          |
| `published`   | property / attribute                  | いいえ | 公開日           | `YYYY-MM-DD` 形式の正規値を受理します。代表日付の候補です。                                                                                                                                               |
| `created`     | property / attribute                  | いいえ | 作成日           | `YYYY-MM-DD` 形式の正規値を受理します。可視表示には用いず、日付の補助文脈にのみ用います。                                                                                                                 |
| `updatedDate` | property                              | いいえ | 更新日           | `YYYY-MM-DD` 形式の正規値を受理します。HTML 属性名は `updated` です。代表日付の最優先候補です。                                                                                                           |
| `tags`        | property                              | いいえ | タグ配列         | 正規入力です。現行契約では各要素を表示名兼識別子として扱う文字列配列です。前後空白除去と空要素除外を行います。構造化が必要になった場合は `key` / `label` / 必要に応じて `href` を持つ別契約へ移行します。 |
| `readingTime` | property / attribute (`reading-time`) | いいえ | 読了時間（分）   | 四捨五入後に 1 以上の整数値のみ表示します。                                                                                                                                                               |
| `status`      | property / attribute                  | いいえ | 読者向け注意状態 | `draft` / `archived` / `wip` / `deprecated` のみ有効です。単一表示のみ許容します。                                                                                                                        |
| `source`      | property / attribute                  | いいえ | 出典 URL         | `http:` / `https:` のみ表示対象です。現行契約では単一 URL を受理します。帰属情報の拡張が必要になった場合は、個別 prop 増築ではなく構造化帰属情報モデルへ移行します。                                      |
| `license`     | property / attribute                  | いいえ | ライセンス表示名 | 表示専用の文字列です。可視表示前には前後空白を除去し、空文字列は非表示とします。帰属情報の拡張が必要になった場合は、個別 prop 増築ではなく構造化帰属情報モデルへ移行します。                              |

### 1.2 受理値と非受理値

- `heading` が空文字または空白のみ文字列である場合は、契約上の正常入力とはみなしません。
- `published`、`created`、`updatedDate` は `YYYY-MM-DD` 形式の正規値のみ受理します。
- 正規値でない日付文字列は無効値として扱い、日付項目の候補に含めません。
- `readingTime` が `null`、`NaN`、または四捨五入後に 0 以下となる場合は、無効値として扱います。
- `status` が未知値である場合は、非表示とします。
- `source` が `http:` / `https:` 以外である場合は、無効値として扱います。
- `license` は trim 後に空文字列となる場合は、無効値として扱います。

### 1.3 責務境界

本コンポーネントは次を責務に含みます。

- 見出しを表示します。
- 代表日付を決定します。
- 読了時間を正規化して表示します。
- ステータスを表示します。
- タグを正規化します。
- 現行の文字列タグ契約では、互換目的の標準形 `href` を派生します。
- 出典 URL を安全化します。
- ライセンス表示文字列を正規化して表示します。
- 現行の単純入力契約から帰属表示を構成します。
- 必要なアクセシビリティ属性を付与します。
- `tag-click` イベントを発火します。

本コンポーネントは次を責務に含みません。

- タグ一覧ページの実在を保証しません。
- タグ識別子体系、slug 規則、最終的な URL policy を設計しません。
- 出典先の妥当性を保証しません。
- ライセンス文字列の意味を検証しません。
- 帰属情報スキーマの法的・編集的妥当性を検証しません。
- URL ルーティングを制御しません。
- 記事全体レイアウトを統括しません。

### 1.4 属性反映契約

公開入力のうち、attribute 経路と property 経路の対応は固定します。

| 入力名        | HTML 属性名    | property      | 契約                                      |
| ------------- | -------------- | ------------- | ----------------------------------------- |
| `heading`     | `heading`      | `heading`     | attribute / property の双方を受理します。 |
| `published`   | `published`    | `published`   | attribute / property の双方を受理します。 |
| `created`     | `created`      | `created`     | attribute / property の双方を受理します。 |
| `updatedDate` | `updated`      | `updatedDate` | HTML 属性名は `updated` に固定します。    |
| `readingTime` | `reading-time` | `readingTime` | number 変換後に評価します。               |
| `status`      | `status`       | `status`      | attribute / property の双方を受理します。 |
| `source`      | `source`       | `source`      | attribute / property の双方を受理します。 |
| `license`     | `license`      | `license`     | attribute / property の双方を受理します。 |
| `tags`        | なし           | `tags`        | property 専用の正規入力です。             |

`tags` は property 専用の正規入力です。

## 2. 状態モデル

本章では、入力から表示状態へ変換する規則、および表示有無を決定する条件を定義します。

### 2.1 代表日付

代表日付は `updatedDate > published` の優先順位で決定します。

1. `updatedDate` が空でない場合は、`updatedDate` を採用します。
2. `updatedDate` が空であり、`published` が空でない場合は、`published` を採用します。
3. 両方が空である場合は、日付項目を表示しません。

採用された日付のラベルは次のとおりです。

| 条件                         | 表示ラベル   |
| ---------------------------- | ------------ |
| `updatedDate` を採用した場合 | `最終更新日` |
| `published` を採用した場合   | `公開日`     |

`created` は独立した可視項目ではありません。`created` が存在する場合は、`time` 要素の `aria-label` に `作成日: ...` を補助文脈として付加します。

### 2.2 日付表示文字列

日付表示は正規値 `YYYY-MM-DD` をそのまま表示します。

- 前後空白は除去して評価します。
- 正規表現 `^\d{4}-\d{2}-\d{2}$` に一致する場合のみ有効値とします。
- 有効値のみを表示値として採用します。
- 無効値は表示しません。

したがって、本コンポーネントは **緩い日付パース** を責務に含みません。表示のための補正や変換が必要な場合は adapter 層で処理します。

### 2.3 読了時間

`readingTime` は四捨五入した整数分として表示します。表示条件は次のとおりです。

- `readingTime === null` である場合は、非表示とします。
- `Number.isNaN(readingTime)` である場合は、非表示とします。
- `Math.round(readingTime) <= 0` である場合は、非表示とします。
- それ以外の場合は、`読了目安 N分` として表示します。

### 2.4 タグ

タグは描画前に正規化します。正規化規則は次のとおりです。

- `tags` が 1 件以上存在する場合は、`tags` を採用します。
- 各タグ文字列の前後空白は除去します。
- 空文字列は除外します。
- 現行の文字列タグ契約では、各要素を論理的に `key` と `label` が同一である 1 件のタグとして解釈します。
- 現行の文字列タグ契約における標準形 `href` は `/tags/${encodeURIComponent(key)}/` です。
- 入力順は保持します。
- 重複は保持します。ただし、これは現行の文字列タグ契約に限った互換規則です。構造化入力へ移行する場合は、重複可否を `key` 単位で再定義します。

正規化後の配列が空である場合は、タグ行を表示しません。

現行の標準形 `href` は互換目的の基準情報です。最終的な URL 規則そのものは親レイヤまたはルーティング層の責務です。

### 2.5 出典とライセンス

現行契約では、`source` は単一 URL、`license` は単一の表示文字列として扱います。

`source` は安全化した上でのみ表示します。

- 前後空白は除去します。
- `new URL()` により解釈可能である場合は、評価対象とします。
- `protocol` が `http:` または `https:` である場合は、表示します。
- `protocol` が `http:` または `https:` 以外である場合は、存在しないものとして扱います。

`license` は表示専用文字列として扱います。

- 前後空白は除去します。
- trim 後に空文字列となる場合は、存在しないものとして扱います。
- 可視表示には trim 後の文字列を用います。

`source` と `license` の両方が空である場合は、補助メタデータ行を表示しません。

帰属情報の拡張が必要になった場合は、`sourceLabel` や `licenseHref` のような個別 prop を追加しません。表示ラベル、遷移先、種別、必要に応じて複数件を保持できる構造化帰属情報モデルとして扱います。それまでは現行の単純入力契約を維持します。

### 2.6 ステータス

status は現行契約では単一の読者向け注意状態として扱います。対応関係は次のとおりです。

| `status` 値  | 表示ラベル | アイコン         | トーンクラス        |
| ------------ | ---------- | ---------------- | ------------------- |
| `draft`      | 下書き     | `file-pen`       | `status-draft`      |
| `archived`   | アーカイブ | `archive`        | `status-archived`   |
| `wip`        | 作業中     | `construction`   | `status-wip`        |
| `deprecated` | 非推奨     | `alert-triangle` | `status-deprecated` |

未知の値は描画しません。

### 2.7 最小状態

最小状態は `heading` のみが与えられた状態です。この場合は、見出しのみを表示し、主要メタデータ行、タグ行、補助メタデータ行、ステータスバッジは表示しません。

### 2.8 無効値・空白値の正規化

- `heading` は契約上の必須入力として扱います。
- `heading` が空文字または空白のみ文字列である場合は、正常入力として扱いません。
- `published`、`created`、`updatedDate` は前後空白を除去して評価します。
- `time[datetime]` に設定する値は、正規値として受理された `YYYY-MM-DD` のみです。
- `datetime` 属性値に無効値を反映しません。
- `source` は前後空白を除去した上で URL 解釈します。
- `license` は前後空白を除去して評価します。
- `license` が空白のみ文字列である場合は、非表示とします。
- `status` は列挙値一致である場合にのみ表示します。
- `status` の前後空白は吸収しません。
- `tags` 由来の各タグ文字列は trim した上で評価します。
- `tags` 由来の各タグ文字列が空文字列である場合は、除外します。

この契約は、可視表示の正規化を本コンポーネント内で完結させつつ、意味妥当性の拡張判断は adapter 層または親レイヤへ委譲するためのものです。

## 3. DOM / アクセシビリティ契約

本章では、`ui-article-header` が生成する DOM 構造、およびアクセシビリティ上の成立条件と非責務を定義します。

### 3.1 構造

ルート要素は `<header>` です。記事タイトルは `<h1>` です。主要メタデータ群および補助メタデータ群は `<ul>` と `<li>` により表現します。採用された日付は `<time datetime="..."></time>` で表現します。タグは `ui-tag` により表現します。出典は `<a>` により表現します。

```text
<header class="article-header">
  [div.status-badge]
  <h1 class="heading">...</h1>
  [ul.metadata-list.metadata-list--primary]
  [nav.tags-nav > ul.tag-list > li > ui-tag*]
  [ul.metadata-list.metadata-list--secondary]
</header>
```

### 3.2 日付のアクセシビリティ契約

日付項目の `aria-label` は、採用された日付の意味文脈を含みます。

- `updatedDate` を採用した場合は `最終更新日: ...` を含みます。
- `published` を採用した場合は `公開日: ...` を含みます。
- `created` が存在する場合は `、作成日: ...` を後続付加します。

### 3.3 出典リンクのアクセシビリティ契約

出典リンクは次の属性を持ちます。

- `target="_blank"` を付与します。
- `rel="noopener noreferrer"` を付与します。
- `aria-label="出典（外部リンク）"` を付与します。

### 3.4 タグのアクセシビリティ契約

現行の文字列タグ契約では、各タグは `ui-tag` として描画し、論理上の `key` と `label` は同一の文字列として扱います。`aria-label` は `タグ: {label}` です。

`href` は現行互換の標準形として `/tags/${encodeURIComponent(key)}/` を用います。タグ群は周辺ナビゲーションとして扱い、`nav` と list semantics の内部に配置します。

この `href` 規則は現在の公開契約における基準情報ですが、URL 規則そのものを本コンポーネントの長期固定責務とはしません。将来、入力側から `href` が与えられる契約へ移行した場合は、明示入力を優先します。

### 3.5 非責務

本コンポーネントは、見出し自体をアンカーリンク化しません。タグ遷移先の実在保証やルーティング統合は行いません。タグ群の意味論は周辺ナビゲーションに固定しますが、その外側のページ全体ナビゲーション設計は親レイヤの責務です。

### 3.6 見出しレベルおよび利用文脈

本コンポーネントは記事ページの主題見出しを表すため、見出し要素として常に `<h1>` を描画します。したがって、利用文脈は次に限定します。

- 記事詳細ページで使用します。
- 単一ノートページで使用します。
- 文書本文の主題ヘッダーとして使用します。

次の文脈では本コンポーネントをそのまま使用しません。

- 一覧カード内の見出しには使用しません。
- ダイアログやサイドバー内の部分見出しには使用しません。
- 1 ページ内に複数回出現する主題ヘッダーには使用しません。

再利用が必要である場合は、見出しレベルを切り替える派生コンポーネントまたは別コンポーネントとして分離します。

### 3.7 装飾アイコンとランドマーク責務

本コンポーネント内のアイコンは装飾専用です。意味情報はテキストにより担保し、アイコン単体に可読名を持たせません。

ルートの `<header>` は文書上のセクション見出しを包含しますが、固有の landmark 名は持ちません。ページ全体のランドマーク構成および補助ラベル付与は親レイヤの責務です。

## 4. 表示契約

本章では、情報順序、レイアウト、タイポグラフィ、トークン参照、およびリンク表示の規則を定義します。

### 4.1 情報順序

正規の情報順序は次のとおりです。

1. ステータスバッジ
2. 記事タイトル
3. 主要メタデータ行
4. タグ行
5. 補助メタデータ行

この順序は、**信頼性シグナル → 主情報 → 時間情報 → 分類情報 → 帰属情報** という読み順を固定するためのものです。

### 4.2 レイアウト契約

- `:host` は `display: block` とします。
- 最大幅は `var(--reading-measure, var(--width-reading, 72ch))` とします。
- `ui-article-header` 自身は文脈固有の読書幅を固定せず、親レイヤが与える `--reading-measure` に追従します。
- 親レイヤが `--reading-measure` を与えない場合は、`var(--width-reading, 72ch)` を fallback とします。
- ルート下端には本文との境界として `border-block-end` を設けます。
- 主要メタデータ行と補助メタデータ行では `flex-wrap: wrap` を許容します。
- メタデータ項目間の区切り文字には `・` を使用します。
- タグ行は独立段として扱います。
- タグ行では `inline-flex` + `wrap` により複数タグを並べます。
- 主見出しの視覚整列を優先します。
- 先頭に装飾アイコンを含む主要メタデータ行および補助メタデータ行は、光学補正のため小さな開始インセットを持ってよいものとします。
- したがって、メタデータ行は主見出しとコンテナ左端の完全一致を必須としません。
- `heading` 以降の metadata/tag stack では、**タイトル直下の段間だけを一段大きくする**ことを契約とします。
- stack 内の段間は、**要素固有 margin の偶発ではなく、隣接要素間 selector により制御**します。
- 段間は次を基準とします。
  - タイトル → 主要メタデータ: `20px`
  - タイトル → タグ（主要メタデータなし）: `16px`
  - タイトル → 補助メタデータ（主要メタデータ・タグなし）: `16px`
  - 主要メタデータ → タグ: `12px`
  - 主要メタデータ → 補助メタデータ: `12px`
  - タグ → 補助メタデータ: `12px`
- `breadcrumbs-row` および `status-badge` の余白契約は、この stack ルールには含めません。
- `ui-article-header + .prose` の本文開始間隔は page-level 契約として扱い、component 内ではなくグローバルレイアウト側で維持します。

### 4.3 タイポグラフィ契約

- 見出しには `clamp()` による流体サイズを適用します。
- 見出しの行高には `var(--line-height-tight)` を使用します。
- 見出しの字間には `var(--tracking-tight)` を使用します。
- `font-feature-settings: 'palt'` を適用します。
- `word-break: auto-phrase` を適用します。
- `overflow-wrap: break-word` を適用します。

### 4.4 セマンティックトークン契約

本節に列挙するトークンは、公開契約に含める **public semantic tokens** のみです。内部実装都合のエイリアス、フォールバック連鎖、component-local custom property、実装一時変数は公開契約に含めません。

主な参照トークンは次のとおりです。

| 用途                            | トークン                               |
| ------------------------------- | -------------------------------------- |
| 見出し色                        | `--fg-default`                         |
| 主要メタデータ色                | `--fg-muted`                           |
| 補助メタデータ色 / セパレータ色 | `--fg-subtle`                          |
| 作業中ステータス                | `--fg-warning`                         |
| 非推奨ステータス                | `--fg-danger`                          |
| 文脈注入される読書面 measure    | `--reading-measure`                    |
| 既定の読書幅 fallback           | `--width-reading`                      |
| 余白                            | `--space-*`                            |
| フォントサイズ                  | `--text-*`                             |
| 行高                            | `--line-height-tight`                  |
| トラッキング                    | `--tracking-tight`                     |
| フォーカスリング色              | `--focus-ring-color`                   |
| フォーカスリング幅              | `--focus-ring-width`                   |
| フォーカスリングオフセット      | `--focus-ring-offset`                  |

### 4.5 リンク表示契約

出典リンクのクラスは `.link-text.source-link` です。リンクは既定状態で下線を持ちます。`hover` および `focus-visible` では、文字色とフォーカスリングにより可視性を補強します。

## 5. イベント契約

本章では、`tag-click` の発火条件、通知内容、および親側による介入可能性を定義します。

### 5.1 tag-click 発火条件

tag-click は現行イベント名を維持しつつ、意味論上はタグ activation を契機として発火します。発火条件は次のとおりです。

- タグ要素が描画されている場合にのみ発火します。
- クリック対象が当該タグリンクである場合にのみ発火します。
- 1 回の activation に対して 1 回のみ発火します。

本イベントは hover、focus、pointerenter 等では発火しません。pointer と keyboard の双方による activation を対象とします。

### 5.2 tag-click イベント契約

タグ活性化時には `tag-click` イベントを発火します。これは単なる通知ではなく、**ネイティブリンク遷移へ介入可能なキャンセル可能イベント**です。

| 項目          | 契約                                                                               |
| ------------- | ---------------------------------------------------------------------------------- |
| イベント名    | `tag-click`                                                                        |
| `detail.tag`  | 活性化されたタグ文字列です。現行の文字列タグ契約では `key` と `label` が同一です。 |
| `detail.href` | 現行互換の標準形 `href` です。                                                     |
| `bubbles`     | `true`                                                                             |
| `composed`    | `true`                                                                             |
| `cancelable`  | `true`                                                                             |

親側が `preventDefault()` を呼び出した場合は、内部の click handler が元のクリックイベントに対して `event.preventDefault()` を実行し、ネイティブ遷移を中止します。

`detail.href` は現行の文字列タグ契約における基準情報です。タグ遷移先は `/tags/${encodeURIComponent(detail.tag)}/` を標準形としますが、これは互換目的の標準値であり、最終的な URL 規則は親側で置き換えられます。

将来的にタグ入力を構造化する場合でも、既存互換のため `detail.tag` と `detail.href` は維持し、必要な識別情報は追加 detail で拡張します。

## 6. 境界条件

本章では、入力が欠落または無効である場合の最終表示結果を定義します。

- `heading` のみが与えられた場合は、見出しのみを表示します。
- 正規化後のタグ配列が空である場合は、タグ行を描画しません。
- `readingTime` が無効値である場合は、読了時間項目を描画しません。
- `source` が安全でない場合は、描画しません。
- `source` と `license` の双方が空である場合は、補助メタデータ行を描画しません。
- `status` が未知値である場合は、描画しません。

## 7. Storybook 契約

本章では、各 Story が固定する確認観点と、変更時に維持すべき契約を定義します。

各 Story は単なる表示例ではなく、将来変更時の契約確認点です。

| Story                         | 固定する契約                                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `CompleteState`               | フル構成時の総合契約、更新日優先、作成日の `aria-label` 付加、出典リンク属性、タグ数、ステータス表示             |
| `PublishedFallback`           | `updatedDate` 不在時に `published` へフォールバックする契約                                                      |
| `StatusStateMatrix`           | `status` 値ごとのラベル、アイコン、トーンクラス対応                                                              |
| `TagEventContract`            | `tags` の property 経路、`tag-click` の発火条件とキャンセル可能性                                                |
| `HeadingOnlyBoundary`         | 見出しのみ最小構成                                                                                               |
| `NormalizationBoundary`       | `tags`・`readingTime`・`source` の正規化契約、およびタグ行の `nav > ul > li > ui-tag` 構造                       |
| `StrictDateBoundary`          | 非正規日付を表示しない契約、`created` を `aria-label` に混入させない契約、空白ライセンスで補助行を生成しない契約 |
| `UnsafeSourceOnlyBoundary`    | unsafe source 単独時に補助メタデータ行ごと非表示とする契約                                                       |
| `AccessibilityMediaContracts` | `prefers-reduced-motion` MUST、`forced-colors` MUST、coarse pointer discoverability SHOULD の CSS 契約           |
| `DarkModeTokenContract`       | public semantic tokens 参照によるモード非依存契約                                                                |

`AccessibilityMediaContracts` の強度は次のとおりです。

- `prefers-reduced-motion` は MUST とします。
- `forced-colors` は MUST とします。
- coarse pointer discoverability は SHOULD とします。

前二者の不成立は契約違反として扱います。coarse pointer discoverability の不成立は改善課題として扱います。

## 9. 関連契約

本章では、`ui-article-header` が依存する下位契約と、親レイヤへ委譲する責務を整理します。

本書は次の契約と接続します。

- `ui-tag` のリンク契約と接続します。
- Link text style 契約と接続します。
- トークン契約（色・余白・タイポグラフィ・モーション）と接続します。
- 記事ページ全体のレイアウト契約と接続します。

### 9.1 依存契約

`ui-article-header` は単独で完結するコンポーネントではなく、下位契約に依存します。

- タグのクリック可能性、`href` の保持、タグのアクセシビリティ属性は `ui-tag` の契約に依存します。
- 出典リンクの視覚表現は link text style 契約に依存します。
- 色、余白、タイポグラフィ、フォーカスリング、モーションはトークン契約に依存します。

したがって、本コンポーネント契約は下位要素の内部実装を再定義しません。接続条件として必要な振る舞いのみを定義します。

### 9.2 親責務

本コンポーネントは次の事項を扱いません。

- タグ一覧ページの有無および内容は扱いません。
- タグ識別子体系、slug 規則、最終的な URL policy は扱いません。
- HTML 文字列から `tags` property への受け渡し、および Markdown bridge / adapter 層での入力整形は扱いません。
- 出典リンク先の到達可能性は扱いません。
- ライセンス表記の法的妥当性は扱いません。
- 帰属情報の構造化、複数件管理、表示ラベル設計は扱いません。
- 著者表示は扱いません。
- パンくず、目次、ページネーション等との結合は扱いません。
- `<header>` に対するページ固有ラベル付与は扱いません。
- ルータ連携、prefetch、履歴制御は扱いません。

`ui-article-header` 単体では、これらの外側にあるナビゲーション意味論やページ構造全体を完結させません。

新しい情報群が必要になった場合は、`ui-article-header` 自体に props を増やさず、上位の compound component または別コンポーネントへ分離します。

## 10. 現行実装との整合メモ

本章では、文書契約と現行実装の対応関係、および移行途上の扱いを整理します。

### 10.1 タッチ環境向けメディアクエリ

`AccessibilityMediaContracts` Story が確認する `@media (hover: none) and (pointer: coarse)` は、`article-header.ts` 単体ではなく、共通の link text style 契約である `linkTextStyles` により Shadow DOM 内へ合成されます。

したがって、touch 向けの coarse pointer discoverability 契約は、**`ui-article-header` が `linkTextStyles` を採用していること**を通じて成立します。本コンポーネント固有 CSS に同一メディアクエリを重複定義することは契約条件ではありません。

### 10.2 トークン名の実装修正

主要メタデータのアイコン色に対する public semantic token 名は `--fg-subtle` です。過去に存在した `--fg-sabtle` は誤記であり、現行実装では採用しません。

### 10.3 タグ入力の移行完了

`tagsJson` 補助入力は廃止済みです。`ui-article-header` の公開入力面は `tags` property のみとし、HTML 文字列からの橋渡しは adapter 層で扱います。

SSR およびレイアウト層では、必要に応じて adapter 用のメタデータを介して `tags` property を設定しますが、これは公開契約ではありません。したがって、`ui-article-header` 自体は `tagsJson` を受理しません。
