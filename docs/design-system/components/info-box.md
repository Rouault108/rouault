# Info Box

## 概要

本書は、`ui-info-box` の公開契約、状態モデル、アクセシビリティ、および視覚契約を整理するものです。

`ui-info-box` は、**価値中立な参照情報を構造化して提示する静的コンテナ**です。操作の起点や警告通知を担うものではなく、本文の読書リズムを大きく崩さずに、補足情報、前提条件、作品情報、章の要点などを独立した塊として示すために用います。

Rouault における info-box は、単に枠付きのボックスを描画するのではなく、**見出しの有無に応じてどのようなセマンティクスを公開するか**、**ランドマークとして公開してよい条件は何か**、**空内容をどのように扱うか**を公開契約として固定します。

また、バリアント、見出し階層、アイコン、強制カラー対応は、場当たり的な装飾ではなく、**状態契約とトークン契約**によって成立させます。

Rouault における info-box は、読書を中断させる強い UI ではなく、**「没入して読む」ことのできるデザイン**の中で、必要な情報を静かに切り出す補助要素として扱います。したがって、本コンポーネントの契約は、情報の独立性と、読書面での静かな存在感を両立する方向で定義します。

## 公開契約

`ui-info-box` は、`heading`、`icon`、`headingLevel`、`landmark`、`variant` を公開入力として扱います。スロットは既定スロットのみを持ちます。内部実装では Shadow DOM 内に `.info-box`、`.header`、`.body` を持ちますが、利用者はこれらの内部 class 名を契約面として扱いません。

`heading` の既定値は空文字です。空文字または空白のみの場合、ヘッダーは描画しません。`icon` の既定値は空文字です。`headingLevel` の既定値は `undefined` です。`landmark` の既定値は `false` です。`variant` の既定値は `default` です。

`heading` は trim 後の文字列を有効値として扱います。空白のみの文字列は、見出しなしとして扱います。`heading` は**プレーンテキスト専用**です。HTML 断片やリッチ内容を注入する入力としては扱いません。`heading` が存在しない場合、`icon` は描画に参加せず、`headingLevel` も意味を持ちません。将来リッチ見出しが必要になった場合は、文字列 property を拡張せず、別 slot または別コンポーネントとして契約を分離します。

`icon` は、見出し左側に表示する Lucide アイコン名を受け取ります。公開契約としては、`music` のような**プレフィックスなしのアイコン名**のみを正規入力とし、内部で `lucide:${name}` を解決します。利用者は `lucide:` を含む完全名の入力に依存しません。不正形式や未知のアイコン名は、長期的には**非描画**として扱うのが正規方針です。

`headingLevel` は、`heading` が存在し、かつ値が `1` から `6` までの整数である場合にのみ適用します。この条件を満たすときだけ、ヘッダー文字列要素に `role="heading"` と `aria-level` を付与します。無効値は例外にせず、無視します。``** を成立させるには、**``** の有効値も必要**です。

`landmark=true`、`heading` あり、`headingLevel` 有効、かつ内容が空でない場合に限り、ホスト要素を `role="region"` として公開し、内部見出しを `aria-labelledby` で参照します。それ以外の状態では、ホスト要素に**意味ロールを既定付与しません**。したがって、**ランドマーク化は heading・headingLevel・非空内容を前提条件とする条件付き契約**です。

`variant` は `default` と `filled` を受理します。列挙外値が与えられた場合、描画上は `default` として扱います。利用者は列挙外値に依存してはなりません。

既定スロットに、要素ノードまたは非空白テキストノードが存在しない場合、`ui-info-box` は何も描画しません。このときホスト要素も**意味ロールを公開しません**。これは空の情報枠や空の補助セマンティクスを出さないための契約です。

### 入力契約

| 名前             | 種別                                     | 必須  | 内容        | 契約                                                                                                  |
| -------------- | -------------------------------------- | --- | --------- | --------------------------------------------------------------------------------------------------- |
| `heading`      | property / attribute                   | いいえ | ヘッダーラベル   | trim 後に空でなければヘッダーを描画します                                                                             |
| `icon`         | property / attribute                   | いいえ | ヘッダーアイコン名 | `heading` がある場合のみ描画します。`music` のような Lucide 名を受け取ります                                                 |
| `headingLevel` | property / attribute (`heading-level`) | いいえ | 見出し階層     | `heading` があり、`1`-`6` の整数のときのみ `role="heading"` / `aria-level` を付与します。`landmark=true` を成立させる場合は必須です |
| `landmark`     | property / attribute                   | いいえ | ランドマーク化   | `true` かつ `heading` あり、`headingLevel` 有効、非空内容のときだけ `role="region"` になります                            |
| `variant`      | property / attribute                   | いいえ | 視覚バリアント   | `default` / `filled`。既定値は `default` です                                                              |

### スロット契約

| 名前     | 種別   | 位置づけ | 内容                              |
| ------ | ---- | ---- | ------------------------------- |
| 既定スロット | slot | 正規入力 | 参照情報、説明、リスト、定義リスト、補助本文などを受け取ります |

既定スロットは静的コンテンツを受け取ります。コンポーネント自身は内容の意味解釈を行わず、**要素ノードまたは非空白テキストノードが存在するかどうか**のみを描画条件として扱います。空ラッパー要素を渡さないこと、本文内部のタイポグラフィや要素間余白を整えることは利用側の責務です。

### Light DOM 更新追従契約

`ui-info-box` は初回描画時の内容だけでなく、**接続後の Light DOM 内容変化**にも追従します。子ノードの追加・削除、入れ子要素配下を含む文字列更新を契機として、意味のある内容の有無を再評価します。

したがって、空の状態から本文が追加された場合は再接続なしで描画が成立し、逆に本文が取り除かれて空になった場合は `.info-box` の描画を停止し、ホスト要素からも意味ロールと関連属性を除去します。利用者は、初回描画時点の内容だけで描画成立やセマンティクス公開が固定される挙動に依存しません。

### 見出し参照 ID 契約

`landmark=true`、`heading` あり、`headingLevel` 有効、非空内容で `role="region"` を公開する場合、`aria-labelledby` に使う見出し ID は**内部で自己完結して生成・維持**します。外部から `aria-labelledby` を与えてラベル参照へ介入する運用には依存しません。

一方で、ID の**具体的な命名規則**は公開契約ではありません。利用者は `info-box-heading-*` のような内部命名や採番規則に依存しません。公開契約は、`region` と見出しの関連付けが維持されることにあります。

### 属性反映契約

公開入力のうち、`heading`、`icon`、`headingLevel`、`landmark`、`variant` は property と attribute の両面から操作できます。`headingLevel` の HTML 属性名は `heading-level` です。boolean 値は attribute の有無で反映します。

| property       | attribute       | reflect | 備考                        |
| -------------- | --------------- | ------- | ------------------------- |
| `heading`      | `heading`       | あり      | 空白のみは見出しなしとして扱います         |
| `icon`         | `icon`          | あり      | `heading` がない場合は描画に参加しません |
| `headingLevel` | `heading-level` | あり      | 有効値は `1`-`6` の整数です        |
| `landmark`     | `landmark`      | あり      | boolean attribute として扱います |
| `variant`      | `variant`       | あり      | 列挙外値は描画時に `default` 扱いです  |

### 列挙外値・無効値の扱い

`variant` は `default` または `filled` を正規入力とします。列挙外値は受理されても、描画上は `default` にフォールバックします。利用者は列挙外値による独自状態表現に依存してはなりません。

`headingLevel` は、有限整数かつ `1` から `6` の範囲にある場合のみ有効です。`0`、`7`、小数、`NaN` 相当値は、見出しセマンティクスを付与しません。

### 開発時保証とフォールバック契約

`variant` の列挙外値と `headingLevel` の無効値に対して、`ui-info-box` は**例外を投げずに描画を継続**します。`variant` は `default` へフォールバックし、`headingLevel` は見出しセマンティクスを付与しない状態として扱います。

`icon` の不正形式または未知名は、長期的には**非描画**として扱うのが正規方針です。現行実装に開発時警告がない場合でも、契約としては「warning の有無」ではなく「公開結果」を優先します。したがって、本コンポーネントの入力品質は、型、レビュー、Storybook、利用側のテストで担保します。利用者は実行時 warning の存在に依存しません。

### 公開イベント・公開メソッド

`ui-info-box` は、独自の公開イベントを持ちません。公開メソッドも持ちません。これは本コンポーネントが**静的な情報コンテナ**であり、起動主体やインタラクション主体ではないためです。

### 責務範囲

責務範囲には、見出しの有無に応じたヘッダー描画、ランドマーク条件の同期、見出し階層セマンティクスの付与、バリアントごとの視覚差分、空内容時の非描画、空内容時のセマンティクス非公開、内部ラベル参照の自己完結性を含みます。

一方で、次の事項は責務に含めません。

- dismiss 可能な通知ボックスとしての振る舞い
- 開閉可能な disclosure としての振る舞い
- 警告 / 成功 / エラーのトーン体系
- クリック処理や遷移処理
- 内部コンテンツの意味解釈

## 状態モデル

`ui-info-box` の主要状態は、**見出しがあるか、ランドマークとして公開するか、背景を持つか、内容が存在するか**によって読み分けます。

### 1. 基本状態

最小状態は、内容を持ち、`heading` なし、`landmark=false`、`variant="default"` の状態です。このときヘッダーは描画せず、ホスト要素は**追加の意味ロールを持たない**静的コンテナとして振る舞います。

### 2. ヘッダー状態

`heading` が有効な文字列を持つ場合、ヘッダーを描画します。`icon` も `heading` があるときだけ描画されます。したがって、ヘッダーは `heading` を起点とする従属状態です。

### 3. 見出しセマンティクス状態

`headingLevel` が有効な場合、ヘッダー文字列要素に `role="heading"` と `aria-level` を付与します。`heading` がなければこの状態は成立しません。`headingLevel` はヘッダー描画そのものの前提ではありませんが、**ランドマーク化の前提**です。

### 4. ランドマーク状態

`landmark=true`、`heading` あり、`headingLevel` 有効、かつ内容が空でない場合に限り、ホスト要素は `role="region"` となります。このとき、内部見出し要素の ID を `aria-labelledby` で参照します。いずれかの条件を欠く場合、`region` は成立せず、追加の意味ロールも公開しません。

### 5. バリアント状態

`variant` は視覚的な重さのみを切り替えます。意味は次のとおりです。

| `variant` 値 | 意味         | 想定用途                 |
| ----------- | ---------- | -------------------- |
| `default`   | 境界線主体の中立表示 | 補足情報、作品情報、軽い参照情報     |
| `filled`    | 面を持つ静かな強調  | 前提条件、章の要点、本文導入前の補助情報 |

`filled` は強調ではありますが、警告バナーのような強い注意喚起ではありません。読書面を壊さない範囲で、まとまりを少し前に出すための差分です。

### 6. 空内容状態

既定スロットに意味のある内容が存在しない場合、`ui-info-box` は `.info-box` 自体を描画しません。空の装飾枠だけが残る状態は成立させません。また、この状態ではホスト要素も意味ロールを公開しません。

## DOM / Accessibility

ルートは `:host` です。Shadow DOM 内部に `.info-box` を持ち、その中に任意のヘッダーと本文領域を配置します。

```text
<ui-info-box>
  #shadow-root
    <section class="info-box" data-variant="...">
      [div.header]
        [iconify-icon.icon]
        [div.heading]
      <div class="body">
        <slot></slot>
      </div>
    </section>
</ui-info-box>
```

ホスト要素は、条件に応じて `role="region"` を持つか、または意味ロールを持ちません。ランドマークの公開主体は内部 `section` ではなくホスト要素です。

### Accessibility 契約

アクセシビリティ上の重要点は次のとおりです。

- `landmark=true`、`heading` あり、`headingLevel` 有効、非空内容のときだけ、ホスト要素は `role="region"` になります。
- 上記以外の状態では、ホスト要素は追加の意味ロールを持ちません。
- `region` の場合、`aria-labelledby` は内部見出し要素を参照します。
- `headingLevel` が有効な場合のみ、内部見出し要素に `role="heading"` と `aria-level` を付与します。
- アイコンは装飾であり、`aria-hidden="true"` を持ちます。
- `heading` がない場合、ヘッダー自体を描画しないため、アクセシブル名のための空ヘッダーを残しません。
- 本コンポーネントは対話要素ではないため、独自のキーボード操作契約やフォーカス契約を持ちません。

本コンポーネントで重要なのは、**見た目の見出しがあること**ではなく、**どの条件で補助領域をランドマークとして公開するかを明示的に制御すること**です。ランドマークを過剰に増やさないため、`landmark`、`heading`、`headingLevel`、非空内容の 4 条件を前提条件とします。

### 非描画時のホストセマンティクス契約

本文が空で `.info-box` を描画しない場合、ホスト要素は存在し続けますが、**意味ロールおよび関連属性は公開しません**。したがって、`ui-info-box` の非描画状態は、視覚面でもセマンティクス面でも非参加状態として扱います。

利用者は、空内容時に `region`、`note`、`aria-labelledby` などが残存する挙動に依存しません。

## Visual Contract

`ui-info-box` の視覚契約は、本文から独立した情報の塊であることを、**境界線、余白、見出し、小さなアイコン、静かな面差**によって示すことにあります。

### 情報順位

- `default` は最も中立的な表示です。
- `filled` は少しだけ前景化しますが、警告 UI のような強い主張は持ちません。
- ヘッダーは本文より小さく、補助見出しとして扱います。
- アイコンは意味の主役ではなく、見出しの読み取り補助です。

### レイアウト

ルートは block です。内部 `.info-box` は grid コンテナです。ボックス全体は境界線と角丸を持ち、ヘッダーと本文を上下に積みます。

ヘッダーは横並びレイアウトで、アイコンと見出しを並置します。本文領域は単純な内側余白付きコンテナであり、内部コンテンツの詳細レイアウト、タイポグラフィ、要素間余白には介入しません。本文の整形責務は利用側にあります。

### 視覚仕様

- ボックスは `--border-style-subtle` と `--radius-md` を基準に構成します。
- `default` は透明背景です。
- `filled` は `--bg-fill-muted` を背景に用います。
- ヘッダーは下境界線を持ちます。
- ヘッダー文字は `text-xs` 相当の小さめの補助タイポグラフィを用います。
- 既定ではヘッダー文字色は `--fg-muted` です。
- `filled` ではヘッダー文字色を `--fg-default` に切り替えます。
- アイコンは `currentColor` を継承し、ヘッダー文字色に従います。
- 本文領域は `--space-4` の内側余白を持ちます。

### 読書面での使い分け

`ui-info-box` は、読書の主役を奪うための装置ではありません。本文の近傍では、読者が「ここは別種の情報塊である」と理解できる程度の差分にとどめます。したがって、常時強い背景色、過度な装飾、警告色、持続的アニメーションには依存しません。

Storybook の配置例が示すとおり、`ui-article-header` と役割を混在させず、**記事メタデータは article header、読む前提や補足説明は info-box** という分離を保つことが重要です。

### 参照トークン

本コンポーネントは、主として次のトークンに依存します。

| 用途        | トークン                      |
| --------- | ------------------------- |
| 境界線       | `--border-style-subtle`   |
| 角丸        | `--radius-md`             |
| filled 背景 | `--bg-fill-muted`         |
| 既定文字色     | `--fg-default`            |
| 補助文字色     | `--fg-muted`              |
| ヘッダー上下余白  | `--space-3` / `--space-4` |
| 本文余白      | `--space-4`               |
| ヘッダーギャップ  | `--space-2`               |
| ヘッダー文字サイズ | `--text-xs`               |
| ヘッダー太さ    | `--font-semibold`         |
| 文字間       | `--tracking-wide`         |
| 行高        | `--line-height-tight`     |
| アイコンサイズ   | `--icon-xs`               |

## 環境別の振る舞い

### Forced Colors

`forced-colors: active` 環境では、境界線、ヘッダー下線、アイコン色を `CanvasText` に合わせます。これにより、独自色に依存せず、システム配色下でも輪郭と見出し構造を維持します。

### Dark Mode

本コンポーネントは `prefers-color-scheme` に直接依存しません。Light / Dark の追従はセマンティックトークンの差し替えで吸収します。したがって、コンポーネント固有のダークモード分岐は持ちません。

### Reduced Motion

本コンポーネントは、固有のアニメーションを持ちません。したがって、Reduced Motion に対する個別分岐も持ちません。

### Print

本コンポーネントは、印刷専用の非表示契約や簡略化契約を持ちません。印刷時の扱いは上位レイヤの印刷設計に委ねます。

## 関連契約

### 情報種別契約

`ui-info-box` は、価値中立な補助情報を受け持ちます。したがって、次のような用途に適します。

- 作品情報
- 章のポイント
- 読む前提条件
- 補足説明
- 関連注記

一方で、次の用途には依存しません。

- 閉じられる通知
- 危険操作の警告
- 成功 / 失敗ステータス表示
- 即時の注意喚起バナー

これらが必要な場合は、別コンポーネントまたは別契約で扱います。

### `article-header` との責務分離

Storybook の閲覧用ストーリーが示すとおり、記事タイトル、公開日、更新日などのメタデータは `ui-article-header` の責務です。読む前提、背景条件、局所的な補助説明は `ui-info-box` の責務です。両者を混在させる運用には依存しません。

### スタイル拡張契約

`ui-info-box` は CSS Custom Properties によるテーマ差し替えを前提にします。一方で、`::part(...)` は公開していません。利用者は内部 class 名や Shadow DOM 構造に依存してはなりません。

したがって、外部スタイル拡張はトークン差し替えに寄せ、`.header`、`.body`、`.heading` などの内部 class 名を契約として扱いません。

### アイコン契約

アイコンは装飾要素です。意味の主役は見出し文字列であり、アイコン単独で情報種別を伝える設計には依存しません。見出しがない場合はアイコンも描画しません。公開入力としてはプレフィックスなしの Lucide 名のみを受け取り、`lucide:` 付き完全名や未知名に依存しません。

## 境界条件

### 1. `heading` が空白のみ

`heading` が空文字または空白のみの場合、ヘッダーは描画しません。`landmark=true` であっても `region` にはならず、追加の意味ロールも公開しません。

### 2. `icon` のみ指定

`icon` を指定しても、`heading` がなければアイコンは描画しません。見出しなきアイコンヘッダー状態は成立しません。

### 3. 無効な `headingLevel`

`headingLevel=0`、`7`、`2.5` などの無効値では、`role="heading"` も `aria-level` も出力しません。`landmark=true` であっても `region` は成立しません。例外は投げません。

### 4. `landmark=true`、`heading` あり、`headingLevel` 有効、非空内容

この場合のみ、ホスト要素は `role="region"` と `aria-labelledby` を持ちます。`aria-labelledby` は内部見出し要素を参照します。見出し ID の具体値は内部実装に属し、利用者はその命名規則に依存しません。

### 5. 無効な `variant`

列挙外の `variant` 値を与えた場合、描画上は `default` として扱います。列挙外値を使った独自な見た目差分には依存しません。

### 6. 空スロット

要素ノードも非空白テキストノードも存在しない場合、`.info-box` を描画しません。空枠だけを表示する状態は作りません。また、ホスト要素も意味ロールを公開しません。

### 7. `filled` のヘッダー配色

`filled` では、ヘッダー文字色を `--fg-default` へ切り替えます。`default` のヘッダー文字色は `--fg-muted` です。バリアント差は、背景だけでなくヘッダー文字色にも及びます。

### 8. 接続後の内容更新

接続後に Light DOM の本文が追加、削除、または文字列更新された場合、`ui-info-box` は意味のある内容の有無を再評価します。したがって、`EmptySlotDoesNotRender` は初期状態だけの契約ではなく、接続後の状態遷移にも拡張されます。非空から空へ遷移した場合は、描画停止と同時にホストの意味ロールも除去します。

### 9. `region` 参照 ID の安定性

`landmark=true`、`heading` あり、`headingLevel` 有効、非空内容の状態では、`aria-labelledby` が参照する見出し ID はインスタンス内で安定して扱います。利用者は ID の命名規則には依存せず、関連付けが維持されることだけに依存します。

### 10. 外部 `aria-labelledby`

利用者はホスト要素へ外部の `aria-labelledby` を与えて、`ui-info-box` のラベル参照を制御しません。ラベル参照はコンポーネント内部で自己完結して管理します。

## Storybook 契約

各 Story は見本ではなく、**契約確認点**として扱います。将来変更時には、次の契約を維持します。

| Story                             | 固定する契約                                                               |
| --------------------------------- | -------------------------------------------------------------------- |
| `Default`                         | `heading`、`icon`、`headingLevel`、`landmark`、`variant` の基本組み合わせが成立すること |
| `ReadingPrerequisitePlacements`   | 読む前提条件を article header と分離して配置できること                                  |
| `VariantStateMatrix`              | `default` / `filled`、`heading` 有無、`landmark` の主要分岐が成立すること            |
| `HeadingLevelBoundaries`          | `headingLevel` の有効値・無効値の扱いが固定されること                                   |
| `LandmarkRequiresHeadingBoundary` | `landmark=true` でも `heading` が空なら `region` を公開しないこと                  |
| `IconRenderingBoundary`           | アイコンは `heading` があるときだけ描画し、装飾扱いであること                                 |
| `InvalidVariantFallback`          | 不正な `variant` が `default` にフォールバックすること                               |
| `EmptySlotDoesNotRender`          | 意味のある内容がない場合は描画せず、意味ロールも公開しないこと                                      |
| `StyleContracts`                  | トークン利用と forced-colors ブロックが維持されること                                   |
| `DarkModeTokenContract`           | ダークモードはトークン追従で成立し、固有の `prefers-color-scheme` 分岐を持たないこと               |

## 補足

`ui-info-box` の要点は、装飾された箱を増やすことではありません。**中立な補助情報を、本文や記事メタデータから切り離して、静かに構造化すること**にあります。

したがって、今後の変更でも次の 6 点は崩さない方がよいです。

1. ランドマーク化は `landmark`、`heading`、`headingLevel`、非空内容の 4 条件を前提条件とすること。
2. 見出しがない状態では、ヘッダーもアイコンも描画しないこと。
3. `filled` は警告 UI ではなく、静かな面差として扱うこと。
4. 空内容では描画せず、意味ロールも公開しないこと。
5. `aria-labelledby` の管理は内部で自己完結させること。
6. 本文の整形責務を `ui-info-box` 自身へ広げすぎないこと。

## 新規で追加を検討する価値がある機能

本節は、`ui-info-box` を**静的・中立・読書補助**という軸のまま強くするために、将来的な追加を検討する価値がある機能を整理するものです。ここで扱うのは、責務を拡散させる機能ではなく、既存契約を保ったまま使い勝手や環境適応性を高める機能に限ります。

### 最優先で検討する価値がある機能

#### 1. `density` または `size`

最も検討価値が高いのは、**意味ではなく視覚密度だけを切り替える機能**です。現行契約では、本文余白、ヘッダーの上下余白、ボックスの見え方が 1 系統に固定されています。しかし、`ui-info-box` は本文中、前提条件、補助領域、狭い横幅など、配置文脈が変わりやすいコンポーネントです。

このとき、密度差を `variant` に吸収し始めると、`variant` が「面の強さ」と「余白の密度」を同時に背負い、責務が濁ります。したがって、将来的には次のような独立入力として分離する方がきれいです。

- `density="comfortable" | "compact"`
- `size="md" | "sm"`

長期的には、``** は視覚的強度、**``** は空間密度**として責務分離するのが最も保守しやすいです。

#### 2. Print 契約

次に検討価値が高いのは、**印刷時の識別性を保証する契約**です。現行実装は print 専用最適化を持たず、背景や境界線の扱いは上位レイヤに委ねています。しかし、`ui-info-box` が読む前提条件や補足説明を担う以上、印刷や PDF 化でボックスの区切りが消えると、本文との構造差が失われます。

追加する場合でも、複雑なオプションは不要です。まずは次の最低限を契約として固定する価値があります。

- 印刷時も境界線による区切りを維持すること
- `filled` 背景に依存せず識別できること
- ヘッダーと本文の分離が残ること
- ページまたぎで極端に崩れないこと

これは利用 API を増やさずに品質を上げられるため、費用対効果が高い機能です。

### 条件付きで検討する価値がある機能

#### 3. `heading` slot

現契約では、`heading` はプレーンテキスト専用です。これは API としてきれいですが、将来的に見出し内へ inline code、補助ラベル、限定的な強調を入れたい要求が出る可能性はあります。

この要求に対して、`heading` property へ HTML を流し込む方向は採りません。追加するなら、次のように**文字列入力とリッチ入力を分離**するのが正規方針です。

- `heading` property はプレーンテキスト専用のまま維持すること
- `slot="heading"` を追加すること
- `slot="heading"` がある場合は `heading` property より優先すること

ただし、これは API を一段複雑にします。したがって、実需が明確になるまでは導入せず、必要になった時点で慎重に昇格させるのがよいです。

#### 4. 限定的な `::part(...)` 公開

現契約では、外部スタイル拡張はトークン差し替えに寄せ、内部 DOM や内部 class 名は非公開です。この方針は原則として維持すべきです。

一方で、テーマやアプリケーション文脈ごとの差し替え要求が積み上がり、トークンだけでは吸収しにくくなる可能性はあります。その場合でも、`part` の公開は最小限に留める方がよいです。たとえば次の程度です。

- `part="container"`
- `part="header"`
- `part="body"`

`heading` や `icon` まで細かく公開すると内部構造が凍結しやすいため、公開するなら大きいブロック単位までに留めます。

#### 5. layout 系の派生入力

意味トーンではなく、**構成差だけ**を表す派生入力は条件付きで検討価値があります。たとえば、見出しと本文の間の境界線有無や、ヘッダーの見せ方だけを切り替えたいケースです。

追加する場合は、次のように**意味ではなくレイアウトだけ**を扱う入力として切り出します。

- `layout="stacked" | "inline-header"`
- `header-divider="auto" | "none"`

ただし、ここを増やしすぎると `variant` や `density` と競合しやすいため、実際に導入する場合は最小限に留めます。

### 追加しない方がよい機能

#### 1. 意味トーンの追加

`tone="info" | "warning" | "success" | "danger"` のような意味トーンは、このコンポーネントには追加しません。`ui-info-box` は中立な補助情報コンテナとして保つ方が役割分離が明快です。意味トーンが必要な場合は、別コンポーネントまたは別契約で扱います。

#### 2. dismiss / collapse

閉じる、折りたたむといった機能は追加しません。dismiss は通知 UI、collapse は disclosure UI であり、どちらも静的コンテナという本コンポーネントの責務を超えます。

#### 3. action slot

ボタンや操作群を標準搭載する `action` slot は追加しません。`ui-info-box` が操作面へ寄ると、読むことの補助という軸が崩れます。

#### 4. 自動アイコン推論

見出し文言や内容からアイコンを自動選択する機能は追加しません。推論規則が不透明になり、文言変更で見た目が揺れるため、契約として不安定です。

### 本節の扱い

本節に記載した機能は、現時点ではいずれも公開契約ではありません。これらを採用する場合は、**責務を増やすのではなく責務分離を保つ**という原則に従い、実装、Storybook、契約書の 3 点を同時に更新します。

## 現行実装で未対応の事項

本節は、本書で定義した**長期的な正規契約**に対して、現行の `info-box.ts` および `info-box.stories.ts` が未対応、またはまだ強制していない事項を整理するものです。現行実装をそのまま正当化するためではなく、今後の収束先を明示するために置きます。

### 1. 複数トーン体系

現行実装の `variant` は `default` と `filled` の 2 種のみです。警告、成功、注意、補足のような意味トーンは公開していません。したがって、現時点の `ui-info-box` は**中立な情報コンテナ**に用途を絞っています。

### 2. `::part(...)` によるスタイル拡張

現行実装は `part` を公開していません。したがって、外部から内部要素を `::part(...)` で精密に装飾する契約は未対応です。

### 3. 公開イベント・公開メソッド

現行実装は独自イベントも公開メソッドも持ちません。動的な開閉、dismiss、再計算トリガーなどの公開 API は未対応です。

### 4. 無効入力に対する開発時警告

`headingLevel` の無効値や `variant` の列挙外値は、現行実装では静かに無視またはフォールバックします。`icon` の不正形式や未知名に対する明確な警告方針も固定されていません。したがって、**不正入力の検知補助は未対応**です。

### 5. `icon` 入力正規化と非描画方針

本契約では、`icon` はプレフィックスなしの Lucide 名のみを正規入力とし、不正形式や未知名は最終的に非描画へ収束させる方針を採ります。現行実装は入力文字列をそのまま `lucide:${icon}` へ連結するため、`lucide:` 付き入力の二重連結や未知名の扱いを公開結果として固定していません。この方針への収束が必要です。

### 6. ホストセマンティクスの再同期タイミング

本契約では、`heading`、`headingLevel`、`landmark`、および内容の有無が変化したとき、ホスト要素の意味ロールと関連属性も常に再同期されることを前提とします。現行実装が `heading` と `landmark` の変更時にしか再同期せず、`headingLevel` の変更や空内容化の後に旧い `role` / `aria-labelledby` を残す場合、この方針への収束が必要です。

### 7. 印刷専用最適化

現行実装は print 用の個別スタイルを持ちません。印刷での簡略表示や非表示化は未対応です。

### 8. 意味付きアクセシブルトーン

本契約では、既定状態に `note` を与えず、必要最小限の場合だけ `region` を公開する方針を採ります。`status`、`alert` などの意味付きライブリージョン契約は持ちません。通知系コンポーネントとしてのアクセシビリティ契約は未対応です。

### 9. 外部 `aria-labelledby` 非依存への収束

本契約では、ラベル参照はコンポーネント内部で自己完結して管理し、外部 `aria-labelledby` への依存を公開しません。現行実装が外部属性を採用する場合、この方針への収束が必要です。

### 10. 空内容時の完全非参加

本契約では、空内容時は描画だけでなく意味ロールの公開も停止します。現行実装が非描画時にもホストセマンティクスを残す場合、この方針への収束が必要です。

### 11. `landmark` 成立条件の厳格化

本契約では、`landmark` は `heading`、`headingLevel`、非空内容のすべてを前提条件とします。現行実装が `headingLevel` なしで `region` を公開する場合、この方針への収束が必要です。

### 12. Storybook 受け入れ基準の旧仕様依存

本契約では、既定状態で `note` を公開せず、`region` の成立条件も `heading`、`headingLevel`、非空内容へ厳格化します。現行の `info-box.stories.ts` や Meta description が、`heading` のみで `region` を成立させる前提や、非ランドマーク時の `note` フォールバックを受け入れ基準として保持している場合、この方針への収束が必要です。契約書だけを更新して Storybook を旧仕様のまま残しません。

### 13. 本節の扱い

本節に記載した事項は、現行公開契約として利用者が依存してよいものではありません。これらを採用する場合は、実装、Storybook、契約書の 3 点を同時に更新し、未対応状態を残したまま公開契約へ昇格させません。
