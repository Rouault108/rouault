# Spinner

## 文書の目的

本書は、`ui-spinner` の公開契約、状態モデル、アクセシビリティ、視覚契約、および長期的な設計論点を整理するコンポーネント契約書です。

`ui-spinner` は、**完了時刻や進捗率を示さない不定進捗（indeterminate progress）** を表現するためのコンポーネントです。単に回転する図形を描画するのではなく、**いつローディング状態を示すべきか**、**スクリーンリーダーへどのような意味で公開するか**、**本文や操作要素の読書リズムをどの程度妨げずに示すか** を公開契約として固定します。

Rouault における spinner は、装飾的なアニメーションではなく、**処理中であることを静かに知らせる状態表示** として扱います。したがって、本コンポーネントの契約は、進行中の可視化と、**「没入して読む」ことのできるデザイン** の維持を両立する方向で定義します。

- 公開契約

## 公開契約

`ui-spinner` は、`size` を property / attribute の両面で、`label` を JavaScript property として、`aria-label` を HTML attribute として公開入力に持ちます。`label` と `aria-label` は、同一のアクセシブル名入力を別経路から与えるための公開面です。内部実装は単一の SVG ですが、利用者は `ui-spinner` を契約単位として扱います。

`size` の既定値は `default` です。`aria-label` の既定値は `"読み込み中"` です。アクセシビリティ上のホスト属性として、`role="status"` と `aria-label` を常にホスト要素に維持します。利用者が `role` を別値へ変更しようとしても、公開契約上は `status` に正規化されます。

`ui-spinner` は **不定進捗専用** です。完了率、現在値、最小値、最大値を表す API は公開しません。したがって、百分率や段階進行を伝える用途に使用してはなりません（MUST NOT）。その場合は progress 系コンポーネントを用います。

### 入力契約

| 名前           | 種別                   | 必須  | 内容                      | 契約                                                    |
| ------------ | -------------------- | --- | ----------------------- | ----------------------------------------------------- |
| `size`       | property / attribute | いいえ | スピナーサイズ                 | `default` / `lg`。既定値は `default` です                    |
| `label`      | property             | いいえ | JavaScript から与えるアクセシブル名 | `trim()` 後に空なら `"読み込み中"` へ正規化されます                     |
| `aria-label` | attribute            | いいえ | HTML から与えるアクセシブル名       | 内部では `label` と同義に扱い、`trim()` 後に空なら `"読み込み中"` へ正規化されます |

`ui-spinner` は ``** のような別名 property を公開しません**。JavaScript からは `label`、HTML からは `aria-label` を用います。

### 属性反映契約

公開入力のうち、`size` は property / attribute の両面から操作できます。`aria-label` は HTML 属性として受け取り、内部的には `label` property として扱います。アクセシブル名は、property / attribute のどちらから入力しても、``** 後の解決済みラベル** をホストへ同期します。

| property | attribute    | reflect | 備考                          |
| -------- | ------------ | ------- | --------------------------- |
| `size`   | `size`       | あり      | 列挙値以外は `default` に正規化されます   |
| `label`  | `aria-label` | なし      | `trim()` 後に空なら既定ラベルへ正規化されます |

たとえば `label = " 保存中 "` または `aria-label=" 保存中 "` は、最終的に `aria-label="保存中"` としてホストへ反映されます。

### 固定アクセシビリティ契約

`ui-spinner` はホスト要素に対して、次を常に維持します。

| 名前           | 値        | 契約                                      |
| ------------ | -------- | --------------------------------------- |
| `role`       | `status` | 利用者が別値を与えても `status` に正規化します            |
| `aria-label` | 解決済みラベル  | 未指定または `trim()` 後に空の場合は `"読み込み中"` を用います |

このため、`ui-spinner` を `progressbar`、`img`、`presentation` など別の意味役割で運用してはなりません（MUST NOT）。

### 自己修復契約

`ui-spinner` は、接続時、属性変更時、および更新時にアクセシビリティ契約を再同期します。したがって、利用者がホストの `role` や `aria-label` を実行時に壊しても、最終的には契約値へ戻ります。

- `role` を `progressbar` などへ変更しても、最終的に `status` へ戻ります。
- `aria-label` を空文字や空白のみへ変更しても、最終的に `"読み込み中"` へ戻ります。
- 利用者は `role` や未正規化の `aria-label` を外部可変設定点として扱ってはなりません（MUST NOT）。

### 列挙外値・無効値の扱い

`size` は公開上 `default` と `lg` のみを契約とします。列挙外文字列が与えられた場合、`default` にフォールバックし、属性値も `default` に正規化します。

`label` / `aria-label` は文字列として受理しますが、`trim()` 後に空となる文字列は有効入力として扱いません。解決済みラベルは常に非空文字列です。

### 非公開面契約

`ui-spinner` は次を公開しません。

- custom event
- 公開 method
- slot
- `::part(...)`
- determinate progress 用の値 API

したがって、利用者は spinner 自身から状態変化通知を受けることや、公開メソッドを通じて動作制御することを期待してはなりません（MUST NOT）。

### 責務範囲

責務範囲には、SVG による不定進捗表示、ホストへのアクセシビリティ属性同期、サイズごとの寸法制御、reduced motion・forced colors・print への適応を含みます。

一方で、読み込み対象の説明文表示、overlay の遮蔽、周辺文言の disabled 制御、live region の詳細制御、複数 spinner 間の優先順位制御は責務に含めません。

## 状態モデル

`ui-spinner` の主要状態は、**サイズ**、**アクセシブル名**、**モーション許容有無**、**表示文脈** によって読み分けます。視覚バリアントや完了率状態は持ちません。

### 1. 基本状態

最小状態は、`size="default"` かつ `aria-label="読み込み中"` の状態です。この状態では、ホスト寸法は `1em` に追従し、本文・ボタン内・インライン要素内で周囲の文字サイズに追従して表示されます。

### 2. サイズ状態

`size` は `default` と `lg` を受理します。

| `size` 値  | 意味           | 想定用途                      |
| --------- | ------------ | ------------------------- |
| `default` | 文字サイズ追従の標準寸法 | ボタン内、文中、行内補助表示            |
| `lg`      | 大きめの強調寸法     | overlay、ページ全体読み込み、空状態中央表示 |

`default` は `1em` を基準とするため、親要素の `font-size` に追従します。`lg` は `--icon-xl` を参照し、未定義時は `32px` を用います。

### 3. アクセシブル名状態

`aria-label` が未指定、空文字列、または空白のみである場合、アクセシブル名は `"読み込み中"` に正規化されます。明示指定したラベルが存在する場合、その値をホストに維持します。

利用者は、文脈に応じて `"保存中"`、`"ページを読み込み中"` のように処理対象を含むラベルを与えてよいです。一方で、視覚テキストが別途併記されている場合でも、`ui-spinner` 自体はホスト単位で `aria-label` を保持します。

### 4. 役割固定状態

`ui-spinner` は常に `role="status"` を維持します。利用者が `progressbar` など別の role を指定しても、それを公開契約として認めません。これは、本コンポーネントが値付き進捗ではなく、**状態通知用の不定進捗表示** であるためです。

### 5. モーション状態

通常環境では、SVG 全体の回転アニメーションと円弧の dash アニメーションを併用します。

`prefers-reduced-motion: reduce` 環境では、連続アニメーションを停止します。この場合でも spinner 自体は不可視にせず、静的な円弧として表示を維持します。したがって、**モーション停止は表示停止を意味しません**。

### 6. 表示文脈状態

`ui-spinner` は次のような文脈で使用できます。

- button 内のインラインローディング
- overlay 内の中央ローディング
- 空状態やパネル内の補助ローディング
- 文中または行内の軽量な処理中表示

ただし、どの文脈でも spinner 単体が主要内容になってはなりません。読み込み理由や対象が重要な場合は、上位レイヤでテキスト説明を補います。

## DOM / Accessibility

ルートは `:host` です。Shadow DOM 内部に単一の `<svg>` と `<circle>` を持ちます。

```text
<ui-spinner role="status" aria-label="読み込み中">
  #shadow-root
    <svg viewBox="0 0 50 50" aria-hidden="true" focusable="false">
      <circle class="spinner-circle" cx="25" cy="25" r="20"></circle>
    </svg>
</ui-spinner>
```

### Accessibility 契約

アクセシビリティ上の重要点は次のとおりです。

- 意味主体はホスト要素です。
- ホストは常に `role="status"` を持ちます。
- ホストは常に非空の `aria-label` を持ちます。
- 解決済みアクセシブル名は `trim()` 済みの文字列です。
- 内部 SVG は `aria-hidden="true"` かつ `focusable="false"` です。
- 内部 SVG に role を付与しません。
- spinner 自体はフォーカス対象ではありません。
- spinner は操作主体ではなく、対話 role や押下状態を持ちません。

本コンポーネントで重要なのは、**図形そのものを読ませるのではなく、処理中状態を意味として伝えること** です。したがって、内部 SVG はアクセシビリティツリーから隠蔽し、意味はホスト側へ集約します。

### live region の位置付け

`role="status"` により、`ui-spinner` は状態通知の意味を持ちます。ただし、通知の丁寧さ、再読上げ頻度、周囲テキストとの組み合わせ方は上位レイヤの設計責務です。本コンポーネントは `aria-live`、`aria-atomic`、`aria-describedby` などの詳細制御を公開しません。

## Visual Contract

`ui-spinner` の視覚契約は、**主張しすぎない連続運動** と、**文字色・文脈色に追従する静かな可視性** にあります。

### 情報順位

spinner は、本文、見出し、主要 CTA より強く主張してはなりません。状態表示として必要十分な視認性は確保しつつ、視線を奪い続ける強い装飾には依存しません。

### レイアウト

ホストは `inline-flex` です。`inline-size` と `block-size` は同一で、正方形を維持します。`vertical-align: middle` により、インライン文脈で周辺テキストと自然に揃えます。

### 視覚仕様

- 色は `currentColor` に追従します。
- 円は塗りなし (`fill: none`) です。
- 線端は `round` です。
- 円弧は dash アニメーションで可変長となります。
- SVG 全体は回転します。
- `default` は `1em` です。
- `lg` は `--icon-xl` を参照し、未定義時は `32px` です。

### 形状不変条件

次の事項は、単なる内部実装詳細ではなく、視覚回帰の許容範囲を規定する不変条件です。

- 内部 SVG は正方形の `viewBox="0 0 50 50"` を持ちます。
- 描画主体は単一の円図形です。
- 線端は `round` を維持します。

### 参照トークン

本コンポーネントは、主として次のトークンまたは CSS Custom Properties に依存します。

| 用途             | トークン / 変数                     |
| -------------- | ----------------------------- |
| 既定寸法           | `--spinner-size`              |
| 大サイズ           | `--icon-xl`                   |
| 回転時間           | `--spinner-rotation-duration` |
| dash アニメーション時間 | `--spinner-dash-duration`     |
| 線幅             | `--spinner-stroke-width`      |
| イージング          | `--ease-in-out`               |
| 描画色            | `currentColor`                |

### 読書文脈での扱い

本文近傍では `default` を優先し、文字サイズとの調和を崩さないことを重視します。ページ全体の待機や overlay 中央表示のように、状態の認知を少し強める必要がある場合に限って `lg` を用います。

### 採らない表現

次の表現には依存しません。

- 常時点滅
- 複数色を用いた強い注意喚起
- 影や発光による装飾的強調
- 完了率があるかのような誤認を招く表示

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、SVG の回転アニメーションと円弧の dash アニメーションを停止します。このとき、円弧の形状は静的な表示に切り替え、処理中状態は維持します。

### Forced Colors

`forced-colors: active` 環境では、ホスト色を `CanvasText` に合わせます。`forced-color-adjust: auto` を維持し、システム色との整合を優先します。

### Print

`@media print` では `:host` 自体を非表示にします。`ui-spinner` は印刷物上で意味を持ちにくい一時的状態表示であるため、印刷対象に含めません。

## 関連契約

### 使用文脈契約

`ui-spinner` は単体で完結する情報表示ではありません。利用者は、必要に応じて次のいずれかの構成を選びます。

| 文脈                | 推奨構成                   |
| ----------------- | ---------------------- |
| button 内処理中       | spinner + ボタン文言または周辺文言 |
| overlay / ページ読み込み | spinner + 読み込み対象を示す文言  |
| 空状態補助             | spinner + 説明文          |
| 軽量な行内表示           | spinner 単体または短い補助文言    |

spinner 単体だけでは、**何を読み込んでいるか** が利用者に十分伝わらない場合があります。その場合の説明責務は上位レイヤが負います。

### スタイル拡張契約

`ui-spinner` は CSS Custom Properties と `color` 継承による拡張を想定します。`::part(...)`、スロット、公開メソッドは持ちません。

利用者が依存してよい **公開スタイリング API** は次です。

- `color`
- `font-size`
- `--spinner-size`
- `--icon-xl`
- `--spinner-rotation-duration`
- `--spinner-dash-duration`
- `--spinner-stroke-width`
- `--ease-in-out`

各値は次の制約を満たす必要があります。

- size 系変数は正の長さであること
- duration 系変数は 0 より大きい時間であること
- stroke width は 0 より大きい長さであること

優先順位は、`size="default"` では `--spinner-size`、`size="lg"` では `--icon-xl` を用います。`lg` では `--spinner-size` より `--icon-xl` を優先します。

利用者は、上記公開 API を通じて見た目を調整できます。ただし、意味を変えるための内部 SVG 構造依存や Shadow DOM 内部 class 名依存には寄りません（MUST NOT）。

### 非対話契約

`ui-spinner` は非対話コンポーネントです。したがって、次の性質を公開契約として固定します。

- フォーカス移動の対象ではありません。
- 押下、選択、切替の状態を持ちません。
- `tabindex`、`aria-pressed`、`disabled`、click 起点の意味付けを前提にしません。
- 操作主体の責務は button や上位コンポーネントが負います。

### 役割分担契約

`ui-spinner` は処理中状態を示しますが、次の責務は持ちません。

- 周辺 UI の操作不能化
- 読み込み完了後の通知
- 非同期処理キャンセル
- timeout 表示
- error 状態への遷移

これらは、button、dialog、page shell、data fetching 層などの責務です。

## 境界条件

### 1. 既定状態

`<ui-spinner></ui-spinner>` は `size="default"`、`role="status"`、`aria-label="読み込み中"` として成立しなければなりません（MUST）。

### 2. `size="default"`

`default` は `1em` を基準とし、親要素の文字サイズに追従します。したがって、button 内や本文内で自然にスケールします。公開契約として、`size="default"` の実効幅および実効高は、ホストの実効 `font-size` と一致しなければなりません。

### 3. `size="lg"`

`lg` は `--icon-xl` を優先して参照します。`--icon-xl` が未定義の場合は `32px` を用います。

### 4. 無効な `size`

列挙外値は `default` に正規化されます。property 値だけでなく、反映された属性値も `default` であることを契約とします。

### 5. 空の `aria-label`

`aria-label=""`、空白のみの入力、または前後に余分な空白を含む入力は `trim()` 後の値で扱います。`trim()` 後に空となる場合は `"読み込み中"` に正規化されます。空のアクセシブル名を残してはなりません（MUST NOT）。

### 6. `role` 上書き試行

`role="progressbar"` などの上書き試行があっても、最終的なホスト role は `status` を維持します。利用者は role 上書きに依存してはなりません（MUST NOT）。

### 7. 外側コンテナとの role 重複

spinner を配置する外側コンテナが別途 `role="status"` を持つ設計は、重複通知や意味の衝突を招きやすいため推奨しません。少なくとも Storybook 上では、外側コンテナに同じ role を重複付与しないことを確認対象とします。

### 8. 印刷時

どのサイズ、どのラベルであっても、印刷時は非表示です。

各 Story は見本ではなく、**契約確認点** として扱います。将来変更時には、次の契約を維持します。

| Story                | 固定する契約                                                                 |
| -------------------- | ---------------------------------------------------------------------- |

| `DarkMode`           | ダーク背景上でも `currentColor` ベースで可視性を維持すること                                 |

加えて、各 Story で次の詳細契約を確認します。

- 内部 SVG は `aria-hidden="true"` かつ `focusable="false"` であること
- 円の `stroke-linecap` は `round` であること
- `default` サイズは実効 `font-size` と幅・高さが一致すること
- `label` と `aria-label` が同一の解決済みラベルへ収束すること
- 実行時に `role` / `aria-label` を壊しても自己修復されること
- `lg` は `--icon-xl` に追従すること

## 契約の要点

`ui-spinner` の要点は、派手なローディング演出ではありません。**値を持たない進行中状態を、アクセシブルに、静かに、文脈サイズへ追従させて示すこと** にあります。

したがって、今後の変更でも次の 4 点は崩さない方がよいです。

1. 意味主体は常にホスト要素であること。
2. `role="status"` と非空の `aria-label` を緩めないこと。
3. `default` が `1em` に追従すること。
4. reduced motion で表示を消さず、動きだけを止めること。

## 契約が不明瞭な箇所

本節は、現行の公開契約を直ちに否定するものではなく、**長期保守の観点ではなお設計判断が未固定であり、将来の破壊的変更や責務衝突を招きやすい箇所** を明示するものです。ここで挙げる論点は、現行実装の都合よりも、**設計のきれいさ、責務分離、保守性、拡張容易性** を優先して整理しています。

### 1. 状態通知の意味主体が曖昧である

現行契約では `ui-spinner` 自体が `role="status"` と `aria-label` を保持し、状態通知の意味主体を兼ねています。一方で、button 内や overlay 内では周辺文言や領域全体が実質的な意味主体になることが多く、**図形としての spinner** と **状態通知主体** が同一コンポーネントに混在しています。

この混在は、単体利用では簡潔ですが、複合コンポーネントへ組み込んだときに責務衝突を起こしやすいです。特に、外側コンテナが別途 `status` や loading message を持つ場合、誰が読み上げの主語なのかが曖昧になります。

### 2. 可視文言とアクセシブル名の所有者が曖昧である

現行 Storybook では、spinner と可視文言を並置する例があります。しかし、**可視文言がある場合でも spinner 自体が独立した **``** を持つべきか**、あるいは **可視文言側が名前の所有者であるべきか** は固定されていません。

この曖昧さを放置すると、読み上げ重複、意味の重複、文脈依存の実装ばらつきを招きます。

### 3. button 内利用時の責務境界が曖昧である

button 内ローディングは頻出文脈ですが、spinner 契約書ではそれを使用文脈として列挙するに留まり、**button 側の loading 契約と spinner 側の責務境界** は固定していません。

長期的には、button の `loading` 状態と spinner の表示責務をどちらが主導するかを明確にしないと、button / spinner の双方にローディング責務が重複しやすくなります。

### 4. 利用文脈が参考例なのか正式サポート範囲なのかが曖昧である

契約書は inline、overlay、空状態、文中など複数文脈を列挙していますが、それらが **正式サポート対象** なのか、単なる **代表例** なのかが固定されていません。

利用文脈の境界が曖昧なままだと、新しい文脈が増えた際に互換性判断の基準を持てません。

### 5. `label` property と `aria-label` attribute の正規 API が曖昧である

現行契約では `label` と `aria-label` を同一入力の別入口として扱っています。しかし、長期的には **どちらを主たる読み書き API とみなすか**、**どちらが source of truth なのか** を固定する必要があります。

同値入力として扱い続けるだけでは、実行時変更、外部監視、DOM 操作系ユーティリティとの整合が曖昧なまま残ります。

### 6. 自己修復の保証範囲と保証時点が曖昧である

現行契約は `role` と `aria-label` の自己修復を定義していますが、**どの時点で契約値へ戻ることを保証するか**、**中間不整合状態に依存してよいか**、**どこまでの属性を自己修復対象に含めるか** は明文化されていません。

これは runtime 監視、テスト、ラッパーコンポーネント設計に影響します。

### 7. 公開スタイリング API の安定範囲が曖昧である

契約書は CSS Custom Properties を公開スタイリング API として列挙していますが、それらが **安定公開面** なのか、**現行実装が参照しているだけの内部依存** なのかまでは区別していません。

このままでは、将来トークン構造を変更した際に破壊的変更の判定基準を持てません。

### 8. CSS Custom Properties の不正値に対する責務が曖昧である

列挙型入力である `size` は正規化されますが、duration、stroke width、size 系の CSS Custom Properties は、現状では妥当性検証や clamp 方針を公開契約として持ちません。

したがって、値異常がコンポーネント責務で救済されるのか、トークン層責務であるのかが曖昧です。

### 9. `size` が意味バリアントなのか見た目バリアントなのかが曖昧である

`default` と `lg` は現状有効に機能していますが、これが **用途に結び付いた意味階層** なのか、単なる **寸法差分** なのかはなお曖昧です。

ここを固定しないままサイズ段階を増やすと、見た目都合のバリエーション追加が進み、設計が崩れやすくなります。

### 10. 形状不変条件と内部実装詳細の境界が曖昧である

現行 Storybook では `viewBox="0 0 50 50"`、単一 circle、`stroke-linecap: round` を確認しています。しかし、長期的には **視覚意味として固定すべきこと** と **内部実装詳細として可変でよいこと** を切り分ける必要があります。

細部まで固定しすぎると内部改善余地が狭まり、逆に緩すぎると視覚後退を招きます。

### 11. 行内組み込み時の組版契約が十分に固定されていない

`default` が `1em` に追従することは明記されていますが、本文行内・注釈内・ボタン内で、**どの程度ベースラインや行送りに干渉してよいか** はまだ厳密ではありません。

Rouault のように読書体験を重視する文脈では、ここは視覚仕様よりも上位の組版契約として整理した方が長期的に安定します。

### 12. 関係 ARIA 属性の扱いが未固定である

現行では `aria-describedby`、`aria-live`、`aria-atomic` などを公開していません。ただし、それを **spinner では恒久的に扱わない方針** なのか、**将来 pass-through を許可する余地があるのか** は明確ではありません。

### 13. 既定ラベルのローカライズ方針が未固定である

既定ラベルは現状 `"読み込み中"` ですが、これは **コンポーネントが日本語を内包する設計** を意味します。Rouault においては実用上問題がない一方、長期的には **ローカライズ責務をコンポーネントが持つのか、利用側が持つのか** を固定しないと、汎用部品化や埋め込み先の locale 切り替えに不整合が生じます。

### 14. 複数 spinner 併存時の通知単位が未固定である

現行契約は単一 spinner ごとの契約を中心に構成されています。しかし実運用では、サイドバー、本文、フッター、検索パネルなど複数箇所で同時に読み込みが発生し得ます。そのとき、**どの spinner が通知主体であるか**、**同時存在時にどう冗長通知を避けるか** は未固定です。

### 15. 長時間待機時の状態昇格条件が未固定である

spinner は不定進捗に適していますが、待機が長引く場合には、説明文、retry、error、progress など、より情報量の高い状態表現へ昇格させるべき場面があります。現行契約はそれらを責務外としていますが、**どの時点で spinner だけでは不十分とみなすか** は規定していません。

### 16. primitive 部品として扱うのか semantic component として扱うのかが曖昧である

現行の `ui-spinner` は、見た目としては primitive に近い一方で、`role="status"` と `aria-label` を自己修復する点では semantic component に近い性質を持ちます。この中間状態は短期的には便利ですが、長期的には設計の重心がぶれやすく、上位コンポーネントとの責務分離を難しくします。

## 長期固定方針

本節は、前節の曖昧点を将来どの方向へ固定すると、Rouault 全体の設計がよりきれいで保守しやすくなるかを示すものです。現行実装へ直ちに適用する義務ではありませんが、**将来の契約改訂ではこの方向へ寄せることを推奨** します。

### 1. 状態通知主体は spinner から分離する

長期的には、**spinner は不定進捗の図形を提供する primitive** とし、`status`、`live region`、説明文の所有は上位の loading region / busy state コンポーネントへ委譲する方が設計はきれいです。

この方針を採る場合、次を固定します。

- spinner は原則として視覚的部品である
- 状態通知の意味主体は外側コンテナが持つ
- spinner 単体で意味通知まで担う運用は例外扱いとする

### 2. アクセシブル名の所有者は 1 つだけにする

可視文言、loading message、spinner 本体がそれぞれ名前を持つ設計は避け、**1 つの loading unit につき名前の所有者は 1 つだけ** と固定します。

推奨は次のとおりです。

- spinner 単体利用時のみ spinner が名前を持つ
- 可視文言や loading region が存在する場合は、そちらが名前を持つ
- spinner 自体は装飾として扱う

### 3. button 内ローディングは button 側契約へ寄せる

button 内の loading は、spinner の一般契約ではなく、**button 側の loading 契約の一部** として扱う方が責務分離が明確です。

この方針を採る場合、spinner 契約書では button 内利用を代表例として残しつつ、a11y と状態遷移の主語は button にあることを明示します。

### 4. 利用文脈をプロファイルとして固定する

利用文脈は列挙するだけでなく、**正式サポートプロファイル** として定義します。たとえば次のように整理できます。

| プロファイル    | 位置付け               | 推奨サイズ              | 名前の所有者                     |
| --------- | ------------------ | ------------------ | -------------------------- |
| `inline`  | 文中・軽量な補助表示         | `default`          | 文脈に応じて外側または spinner        |
| `control` | button / control 内 | `default`          | 原則として control              |
| `region`  | パネル・空状態・カード内       | `lg` または `default` | 原則として region               |
| `overlay` | 領域全体待機             | `lg`               | 原則として overlay / page shell |

### 5. `label` を正規 API、`aria-label` を投影先とする

JavaScript からの正規 API は `label` に固定し、`aria-label` は HTML 初期入力および DOM への投影先とみなすと、source of truth が明確になります。

この方針を採る場合、契約書には次を明記します。

- 読み書きの主 API は `label`
- `aria-label` は HTML 利用時の入力経路である
- 実行時の観測値は最終的に host の `aria-label` に反映される

### 6. 自己修復の保証モデルを明文化する

自己修復を持ち続けるなら、**どの属性を、どの時点までに、どの粒度で回復するか** を明文化する必要があります。

推奨は次のとおりです。

- 自己修復対象は `role` とアクセシブル名に限定する
- 契約保証時点は update サイクル完了時とする
- 一時的な中間不整合状態への依存は禁止する

### 7. 公開スタイリング API を安定度で格付けする

CSS Custom Properties は一括公開ではなく、**安定公開面** と **将来変更のあり得る面** に分ける方がよいです。

たとえば次のように整理できます。

- Stable: `--spinner-size`、`--icon-xl`、`--spinner-stroke-width`
- Stable: `--spinner-rotation-duration`、`--spinner-dash-duration`
- Internal: dash pattern、半径、座標系の exact 値

### 8. 不正値責務を token 層か component 層のどちらかへ寄せる

size や duration などの値妥当性は、**component 側で保護する** か、**design token 層が保証する** かを選び、混在させない方が保守しやすいです。

長期的には、列挙値は component が正規化し、長さ・時間などのトークン値は token 層が妥当性保証を持つ整理が最も自然です。

### 9. `size` は意味階層として定義する

サイズは単なる寸法差分ではなく、**利用密度と文脈の違いを表す意味階層** として固定します。

- `default`: 行内、制御内、軽量表示
- `lg`: 領域待機、視認性を少し高める場面

この意味付けを固定しておけば、将来 `sm` や `xl` を追加する場合も、用途基準で整理できます。

### 10. 形状不変条件は意味レベルと実装レベルに分ける

長期的には、次のように切り分ける方が保守しやすいです。

- 意味不変: 単色、円弧、回転、不定進捗、過度に主張しないこと
- 視覚不変: `round` linecap、本文を壊さない静かな見え方
- 実装可変: `viewBox` の exact 値、半径、dashoffset の exact 値

これにより、視覚後退を防ぎつつ内部最適化余地を残せます。

### 11. 組版契約を prose 文脈中心に固定する

Rouault では読書体験が重要であるため、spinner の行内組み込みは icon 一般よりも厳しく扱う方がよいです。長期的には、次を組版契約として固定します。

- `default` は本文の行送りを不必要に押し広げない
- ベースライン近傍で視覚的に破綻しない
- 周辺テキストの読書リズムを崩さない

### 12. 関係 ARIA 属性は spinner ではなく loading region 側へ寄せる

`aria-describedby`、`aria-live`、`aria-atomic` などは、長期的には spinner 単体で抱え込まず、**loading region 側の責務** に寄せた方が設計が明快です。spinner に pass-through を増やしすぎると、primitive と semantic の境界が再び曖昧になります。

### 13. 既定ラベルの国際化方針を固定する

長期的には、次のいずれかへ固定すべきです。

- Rouault 専用内部部品として日本語既定値を許容する
- 共通 UI 部品として i18n provider 経由にする
- 汎用性を優先し、アクセシブル名は利用側必須にする

汎用部品としてのきれいさを優先するなら、利用側必須または i18n provider 化の方が整っています。

### 14. 通知単位として loading unit を導入する

複数 spinner 併存時の乱れを避けるには、**1 つの読み込み領域 = 1 つの通知単位** という loading unit の概念を導入するのが有効です。

この場合、spinner は loading unit の内部要素であり、通知責務は unit 側が一元的に持ちます。

### 15. 長時間待機時は richer state へ昇格させる

spinner は短時間・不定・非致命の待機表示に限定し、長時間待機では次のように段階的に昇格させる方がよいです。

- 短時間: spinner のみ
- 中時間: spinner + 説明文
- 長時間: retry / timeout / error / progress を伴う状態表示

### 16. `ui-spinner` の位置付けを primitive に寄せる

総合的には、`ui-spinner` は **semantic component ではなく primitive 部品** に寄せる方が、Rouault 全体の責務分離と再利用性に整合します。

その場合、意味通知を担う別コンポーネントを必要に応じて設け、spinner は図形とサイズ体系、環境適応、静かな視認性に集中させます。

## 新規で追加を検討する価値がある機能

本節は、現行の `ui-spinner` に対して、**長期的な設計のきれいさ、責務分離、保守性** の観点から、新規に追加を検討する価値がある機能を整理するものです。単に機能数を増やすことは目的ではなく、**spinner 自体に持たせる価値があるもの** と **別コンポーネントへ分離した方がよいもの** を切り分けて扱います。

### 最優先で検討する価値がある機能

#### 1. 装飾モードと通知モードの分離

現行の `ui-spinner` は、図形であると同時に `role="status"` と `aria-label` を保持する通知主体でもあります。この二重性は単体利用では便利ですが、button、overlay、loading region と組み合わせると責務が衝突しやすいです。

そのため、長期的には次の 2 モードへの分離を検討する価値があります。

- **decorative mode**: spinner を純粋な視覚部品として扱う
- **announcing mode**: spinner 自体が状態通知主体となる

この機能を導入すると、可視文言や外側コンテナとの意味衝突を避けやすくなり、spinner を primitive 部品へ寄せやすくなります。

#### 2. loading region / busy state コンポーネントの導入

これは厳密には spinner 単体の機能追加ではありませんが、**Rouault 全体として最も導入価値が高い拡張** です。spinner に timeout、retry、説明文、live region 制御まで抱え込ませるより、上位に loading region / busy state コンポーネントを設け、そこへ意味通知責務を集約した方が設計は明快です。

この拡張を採る場合、spinner は図形とサイズ体系に集中し、次の責務は上位コンポーネントが担います。

- 説明文の表示
- `status` / `aria-live` の所有
- 長時間待機時の状態昇格
- retry / timeout / error との接続

#### 3. アクセシブル名ポリシーの明示 API

可視文言が存在する場合に、spinner 自体が名前を持つべきか、外側文言を意味主体とすべきかは現状未固定です。これを明示化するために、アクセシブル名の所有方針を選べる API を追加する価値があります。

たとえば、次のような設計が考えられます。

- spinner 自体が名前を持つモード
- 外側文言が名前を持ち、spinner 自体は装飾扱いとなるモード

これは見た目追加ではなく、意味論の衝突を減らすための機能です。

### 条件付きで検討する価値がある機能

#### 4. サイズ段階の追加

現行の `default` / `lg` で不足する利用文脈が明確になった場合に限り、`sm` または `xl` の追加は検討価値があります。ただし、単なる見た目都合でサイズを増やすのではなく、用途階層として増やす必要があります。

想定される位置付けは次のとおりです。

- `sm`: 注釈、補助 UI、高密度ツールバー
- `xl`: 空状態中央、広い overlay、ページ全体待機

#### 5. 既定ラベルの国際化対応

現行の既定ラベルは日本語固定です。Rouault 専用部品としては運用可能ですが、共通 UI 部品としての整合を高めるなら、既定ラベルの国際化対応は検討価値があります。

考えられる方向は次のとおりです。

- i18n provider 経由で既定ラベルを解決する
- 既定ラベルを廃止し、利用側指定を必須にする

#### 6. 公開 `part` の導入

テーマ拡張要求が強まる場合に限り、内部 SVG や円図形への `part` 公開は検討価値があります。ただし、これは公開面の増加を伴うため、CSS Custom Properties だけでは不足することが明確になった場合に限って採用する方がよいです。

### 追加しない方がよい機能

#### 7. determinate progress API の追加

`ui-spinner` は不定進捗専用です。`value`、`min`、`max`、`aria-valuenow` などを導入して determinate progress へ拡張することは、責務を混濁させるため採るべきではありません。

#### 8. retry / timeout / error の内蔵

retry、timeout、error は待機状態の上位設計に属する責務であり、spinner 自体に内蔵すると意味範囲が広がりすぎます。これらは loading region / busy state 側で扱う方が適切です。

#### 9. button 文脈専用ロジックの内蔵

button 内ローディングは頻出ですが、それは button 側契約で扱うべきであり、spinner に button 専用状態や制御を内蔵するべきではありません。spinner は button が利用する下位部品に留める方が責務分離として整っています。

### 優先順位の要約

| 優先度 | 項目                              | 方向              |
| --- | ------------------------------- | --------------- |
| 最優先 | 装飾モード / 通知モードの分離                | spinner 自体の意味整理 |
| 最優先 | loading region / busy state の導入 | 上位コンポーネントへの責務分離 |
| 高   | アクセシブル名ポリシーの明示                  | 意味主体の固定         |
| 中   | サイズ段階の追加                        | 用途階層の追加         |
| 中   | 既定ラベルの国際化                       | locale 対応       |
| 低   | 公開 `part` の導入                   | スタイル拡張面の増加      |
| 非推奨 | determinate progress 化          | 責務逸脱            |
| 非推奨 | retry / timeout / error の内蔵     | 上位責務の混入         |
| 非推奨 | button 専用ロジックの内蔵                | button 契約との重複   |

### 本節の位置付け

本節に挙げた項目は、現時点で採用が決まっているものではありません。ただし、長期的な設計の方向としては、**spinner 自体を多機能化するより、primitive に寄せつつ、意味通知や待機状態の統合は上位コンポーネントへ分離する** 方が、Rouault 全体の保守性と一貫性に優れます。

## 現行実装で未対応の事項

本節は、現行の `spinner.ts` および `spinner.stories.ts` を基準として、**契約書内で将来拡張または厳密化対象として触れているが、現時点では未実装、未公開、または未強制である事項** を整理するものです。

### 1. 補助説明との関連付け

現行実装が直接扱うアクセシビリティ属性は `role` と `aria-label` に限られます。`aria-describedby`、`aria-live`、`aria-atomic` などの制御は未公開です。

### 2. サイズ段階の追加

現行実装が受理するサイズは `default` と `lg` のみです。`sm`、`xl` などの段階化は未対応です。

### 3. スタイル拡張面の公開

現行実装は `::part(...)` を公開していません。外部からの拡張は `color` 継承と CSS Custom Properties に実質的に限定されます。

### 4. determinate progress への拡張

現行実装は値付き進捗を扱いません。`value`、`min`、`max`、`aria-valuenow` など progressbar 的 API は未対応です。これは未実装であるだけでなく、現行方針としても責務外です。

### 5. 外側コンテナとの通知統合

spinner を含む button、overlay、page shell 側で、どのように loading message をまとめて通知するかは未整備です。現行 Storybook は spinner 単体契約を確認しますが、複合コンポーネントとの通知統合までは扱っていません。

### 6. アクセシブル名所有者の分離

現行実装では spinner 自体が `role="status"` と `aria-label` を保持します。可視文言や loading region 側へ意味主体を分離する設計は未対応です。

### 7. 既定ラベルの国際化

既定ラベルは日本語文字列として内部定数化されており、locale に応じた差し替えや利用側必須化は未対応です。

### 8. loading unit の導入

複数 spinner 併存時に通知主体を一元化する loading unit の概念は、現行実装および Storybook には導入されていません。

### 9. 長時間待機からの状態昇格

spinner のみで待機を表す期間の上限や、timeout / retry / error への昇格規則は未整備です。

### 10. 利用文脈プロファイルの固定

現行契約書は inline、control、region、overlay のような利用文脈プロファイルを長期固定方針として提案していますが、現行実装および Storybook はそれを正式なサポート境界としては未固定です。したがって、どの文脈が正式対象で、どの文脈が参考例に留まるかは未強制です。

### 11. `label` を正規 API、`aria-label` を投影先とする整理

現行実装は `label` property と `aria-label` attribute を相互に収束させますが、契約上はなお、どちらを主たる読み書き API とみなすかが未固定です。`label` を source of truth とし、`aria-label` を HTML 初期入力および投影先とする整理は未明文化です。

### 12. 自己修復の保証モデル

現行実装には `role` と `aria-label` の自己修復がありますが、**いつまでに** 修復されるか、**どの属性まで** を自己修復対象とするか、**中間不整合状態へ依存してよいか** までは未明文化です。これは実装には存在するが、契約としては未固定の領域です。

### 13. 公開スタイリング API の安定度格付け

現行契約書は CSS Custom Properties を公開スタイリング API として列挙していますが、Stable / Experimental / Internal のような安定度格付けは未導入です。したがって、どの変数に将来まで依存してよいかは未固定です。

### 14. CSS Custom Properties の不正値責務

`size` 列挙値はコンポーネント側で正規化されますが、`--spinner-size`、duration 系、stroke width 系などの不正値について、component 側で救済するのか、token 層で妥当性保証を持つのかは未固定です。

### 15. 形状不変条件の階層化

現行 Storybook は `viewBox="0 0 50 50"`、単一 circle、`round` linecap を確認しますが、それらのうち何が **意味不変** で、何が **内部実装詳細として可変** なのかは未整理です。視覚後退防止と内部改善余地の切り分けは未対応です。

### 16. prose 文脈における組版契約

`default` が `1em` に追従することは確認されていますが、本文行内で行送りをどの程度押し広げてよいか、ベースライン近傍でどの程度のズレを許容するかなど、読書文脈に特有の組版契約は未強制です。

### 17. 装飾モード / 通知モードの分離

新規機能候補として整理した decorative mode / announcing mode の分離は、現行実装には導入されていません。現在の `ui-spinner` は常に通知主体として振る舞い、純粋な装飾モードは未対応です。

### 18. `ui-spinner` の primitive 化

長期固定方針では `ui-spinner` を primitive 部品へ寄せることを推奨していますが、現行実装は `role="status"` と `aria-label` を自己修復するため、なお semantic component 的性質を持ちます。primitive と semantic の責務分離は未完了です。

### 19. 本節の扱い

本節に記載した事項は、現行公開契約として利用者が依存してよいものではありません。これらを採用する場合は、実装、Storybook、契約書の 3 点を同時に更新し、未対応状態を残したまま公開契約へ昇格させません。
