# Pagination

## 概要

本書は、`ui-pagination` のコンポーネント契約を定義します。

`ui-pagination` は、分割された一覧や記事列に対して、**現在位置**、**移動可能性**、**移動不能境界**を明示するためのページ移動ナビゲーションです。本コンポーネントは、見た目の部品ではなく、**URL を伴うリンク集合**として振る舞います。

本書では、現行実装の詳細をそのまま説明するのではなく、長期的な保守性と設計の明瞭性を優先して、公開契約として固定すべき事項を定義します。現行実装がこの契約に未追随の箇所は、末尾の「現行実装との差分」に整理します。

## 設計原則

### URL 指向

`ui-pagination` は、状態変更イベントを中心にしたコンポーネントではなく、**URL によって移動先を表現するリンク集合**です。ページ移動の意味論は `<a href>` に置きます。

### 現在ページもリンク

現在ページは単なる強調表示ではなく、**現在内容の canonical URL を持つリンク**として扱います。これにより、再訪、新規タブ、リロード、リンクコピーの可能性を失いません。

### 責務の分離

本コンポーネントは、ページ番号の表現、境界の表現、移動先 URL の埋め込みを責務とします。表示密度の決定、単一ページ時の非表示判断、データ取得との連動は上位レイヤで制御します。

### 1 行の安定性

ページネーションは 1 行で認知されることを前提とします。途中折り返しで前後関係を壊しません。狭幅時の縮退は、折り返しではなく表示モードの選択で解決します。

### 複合ウィジェット化しない

本コンポーネントは、toolbar や carousel のような複合キーボードウィジェットにはしません。通常のリンク集合として振る舞い、HTML 標準の移動規則に従います。

## 公開契約

### 公開面

公開面はカスタム要素 `<ui-pagination>` です。Shadow DOM 内部に `nav` とページ項目群を描画します。

公開入力は次のとおりです。

| 名前      | 種別                 | 必須   | 意味                                   |
| --------- | -------------------- | ------ | -------------------------------------- |
| `current` | property / attribute | はい   | 現在ページ番号                         |
| `total`   | property / attribute | はい   | 総ページ数                             |
| `getHref` | property             | はい   | ページ番号から URL を返す関数          |
| `mode`    | property / attribute | いいえ | 表示モード。`regular` または `compact` |

既定の `mode` は `regular` とします。

### 入力値の意味

`current` と `total` の**意味上の有効域**は次のとおりです。

- `total` は 1 以上の整数でなければなりません。
- `current` は 1 以上 `total` 以下の整数でなければなりません。

`total = 0`、負値、非整数、`current > total` などは**契約上の有効入力ではありません**。実装が防御的に補正することはありますが、その補正結果に利用者は依存しません。

したがって、`total = 0` を「0 ページ」として扱う意味論も、「1 ページへ自動補正される意味論」も公開契約には含めません。入力検証が必要な場合は、上位レイヤで行います。

### `getHref` 契約

`getHref(page)` は、指定ページに対応する**正規の遷移先 URL** を返さなければなりません。

`getHref(page)` は次を満たします。

- 同じ `page` に対して決定的でなければなりません。
- 非空の文字列を返さなければなりません。
- 例外を送出してはなりません。
- 本コンポーネントが描画するすべてのページ項目について、有効な遷移先を返さなければなりません。

本コンポーネントは `getHref(page)` の失敗を内部で回復しません。例外送出、空文字、またはページ移動先として意味を成さない文字列を返すことは、利用側の契約違反です。

ここでいう「正規の遷移先 URL」とは、同一ページ番号に対して一貫して解釈される代表 URL を意味します。URL 正規化の詳細、クエリ設計、履歴戦略、ルーター都合の吸収は上位レイヤの責務です。

### `mode` の公開化

現行実装は内部状態で `compact` 表示を切り替えています。本書では、表示密度を公開入力 `mode` として定義し、どの状況で `compact` を使うかを上位レイヤの責務へ移します。

これは将来候補の提示ではなく、本書が採る公開契約そのものです。したがって、表示密度の決定を内部環境判定へ戻すことは、本書の方針に含めません。

### イベント契約

`ui-pagination` は、`pagechange`、`change`、`input` などの独自イベントを公開しません。ページ移動はリンク遷移として表現します。SPA ルーターによるリンク横取りが必要な場合、その責務は上位レイヤにあります。

### 公開スタイル面

公開スタイル面は次に限ります。

- CSS Custom Properties
- `::part(nav)`
- `::part(list)`

公開 part は次のとおりです。

| part 名 | 役割                             |
| ------- | -------------------------------- |
| `nav`   | ルートの `nav` 要素              |
| `list`  | ページ項目群を保持するリスト要素 |

### 公開しない面

次は公開 API に含めません。

- 内部状態
- Shadow DOM 内部 class 名
- `li` の配置順の細部
- 使用アイコンライブラリ
- 表示範囲を算出する内部 helper 関数

実装が helper 関数をエクスポートしていても、それはコンポーネント契約の一部ではありません。公開契約は**描画結果**に置きます。

## 状態モデル

### 基本状態

最小状態は `current = 1`、`total = 1`、`mode = regular` です。この状態ではページ 1 のみを表示し、Prev / Next はともに無効です。

### 現在ページ状態

現在ページは `<a aria-current="page">` として描画します。現在ページはリンクであり続け、canonical URL を持ちます。現在ページを `<span>` や `<button>` に置換しません。

### 前後移動状態

Prev / Next は、移動可能な場合は `<a>`、移動不能な場合は `<span aria-disabled="true">` として描画します。見た目だけ disabled にして `href` を残す構成は採りません。

### 単一ページ状態

`total = 1` の場合でも、本コンポーネントは自動的に自身を非表示にしません。単一ページ時にコンポーネント全体を出さない方針を採る場合、その責務は上位レイヤにあります。

### 表示モード状態

`mode = regular` と `mode = compact` は公開状態です。環境判定による暗黙切替は契約に含めません。

## ページ範囲契約

本節は、**描画結果としてのページ範囲**を定義します。内部 helper 関数名は契約に含めません。

### `regular` モード

`regular` モードでは、次の規則でページ番号列を構成します。

- `total <= 7` の場合、全ページを省略なしで表示します。
- `total >= 8` の場合、先頭ページ `1` と末尾ページ `total` を常に表示します。
- 現在ページの近傍として `current - 1`、`current`、`current + 1` を候補とします。
- 欠落が 1 ページだけの区間は、省略記号ではなく実ページ番号を挿入します。
- 欠落が 2 ページ以上の区間は、省略記号 `…` を挿入します。

この規則により、`total = 7` と `total = 8` の間に明確な閾値が存在します。この閾値は公開契約です。

### `regular` モードの代表例

代表例を次に示します。表記上、`[n]` は現在ページを表します。

- `total = 1, current = 1`
  - `[1]`

- `total = 7, current = 4`
  - `1 2 3 [4] 5 6 7`

- `total = 8, current = 1`
  - `[1] 2 3 … 8`

- `total = 8, current = 4`
  - `1 2 3 [4] 5 … 8`

- `total = 8, current = 5`
  - `1 … 4 [5] 6 7 8`

- `total = 9, current = 4`
  - `1 2 3 [4] 5 … 9`

- `total = 9, current = 5`
  - `1 … 4 [5] 6 … 9`

これらの例は説明用であり、現在ページの視覚表現そのものを `[n]` に固定する意味ではありません。固定するのはページ範囲の構成結果です。

### `compact` モード

`compact` モードでは、次の規則でページ番号列を構成します。

- 現在ページのみを表示します。
- 先頭ページでない場合は前方に省略記号を置きます。
- 末尾ページでない場合は後方に省略記号を置きます。
- 省略不要な側には何も表示しません。

`compact` モードは、狭い領域での省略優先表現です。ただし、どの状況で `compact` を選ぶかは本コンポーネントの責務ではありません。

### 省略記号の意味

省略記号はページそのものではありません。欠落区間の存在を示す視覚記号です。クリック可能要素にしません。

## DOM / Accessibility

### ルート構造

本コンポーネントは、ページ移動のナビゲーションとして意味づけられなければなりません。実装は Shadow DOM 内部で `nav` を用いてこれを表現します。

`nav` には `aria-label="ページナビゲーション"` を与えます。Rouault ではこの文言を固定します。

代表的な構造は次のとおりです。

```text
<ui-pagination>
  #shadow-root
    <nav part="nav" aria-label="ページナビゲーション">
      <ul part="list">
        <li>[Prev]</li>
        <li>[page or ellipsis]</li>
        ...
        <li>[Next]</li>
      </ul>
    </nav>
</ui-pagination>
```

公開契約として重要なのは、ページネーション全体がナビゲーションとして解釈されること、およびページ項目群が順序を持つ集合として表現されることです。内部の補助要素や class 構成は公開契約に含めません。

### ページ項目の意味論

ページ項目は、意味上、次のいずれかとして描画されます。

```text
<a href="..." aria-label="Xページへ移動">X</a>
<a href="..." aria-current="page" aria-label="現在のページ、Xページ">X</a>
<span aria-hidden="true">…</span>
<a href="..." aria-label="前のページへ移動">[Prev]</a>
<a href="..." aria-label="次のページへ移動">[Next]</a>
<span aria-disabled="true" aria-label="前のページへ移動">[Prev]</span>
<span aria-disabled="true" aria-label="次のページへ移動">[Next]</span>
```

ここで固定するのは、要素の**意味**です。内部でどの文字、アイコン、SVG、またはテキストを使うかは公開契約ではありません。ただし、利用者にとって前後移動の意味が識別できなければなりません。

### ラベル契約

本コンポーネントのアクセシビリティ文言は日本語固定とします。

- `ページナビゲーション`
- `前のページへ移動`
- `次のページへ移動`
- `Xページへ移動`
- `現在のページ、Xページ`

多言語化が必要な場合は、本コンポーネントにローカライズ機構を持ち込むのではなく、上位レイヤでラップして差し替えます。

### フォーカス契約

本コンポーネントは通常のリンク集合であり、複合ウィジェットではありません。キーボード操作時のフォーカス順は DOM 順に従います。

- 通常ページはフォーカス可能です。
- 現在ページもフォーカス可能です。
- disabled な Prev / Next はフォーカス対象に入りません。
- 省略記号はフォーカス対象にも読み上げ対象にも入りません。

### キーボード契約

本コンポーネントは roving tabindex を持ちません。Arrow、Home、End などの独自キーボード操作を追加しません。リンクとしての標準挙動に従います。

### アイコン契約

Prev / Next のアイコン glyph、使用ライブラリ、内部タグ名は公開契約ではありません。公開契約として固定するのは、**前後移動の意味**だけです。

## Visual Contract

### 識別の原則

視覚表現は、少なくとも次の識別を常に維持しなければなりません。

- current / non-current
- enabled / disabled
- focus visible / not focused
- page / ellipsis
- prev / next

現在ページは、通常ページと明確に区別できなければなりません。disabled 項目は、存在が知覚でき、かつ操作不能であることが分からなければなりません。省略記号は、ページ項目より弱い補助情報として読めなければなりません。

### 1 行維持

ページネーションは 1 行で保持します。途中折り返しは許容しません。前後関係の破壊を防ぐためです。

### 狭幅時の扱い

`regular` モードのまま inline size が不足する場合、本コンポーネントは自動縮退しません。上位レイヤは次のいずれかを選びます。

- `compact` モードへ切り替える
- 親要素で横スクロールを許可する
- コンポーネント自体を出さない

どの戦略を採るかは上位レイヤの責務です。

### 現在ページの表現

現在ページは、背景、線、文字色、太さなどのいずれかにより、通常ページと安定して識別できなければなりません。現在ページであることを hover のみで表現してはなりません。

現在ページはリンクであり続けますが、通常ページと同一の強い hover / press 演出を必須とはしません。再訪可能な現在位置であることと、現在位置の識別可能性が優先されます。

### フォーカス表示

フォーカス可視性は必須です。`focus-visible` は、背景のみ、色差のみ、または box-shadow のみへの過度な依存で失われてはなりません。Forced Colors でも識別可能でなければなりません。

### 動きの制限

pagination は補助導線です。永続アニメーション、過大な拡大縮小、強い発光、本文より先に視線を奪う装飾は採りません。状態変化に伴う動きがある場合でも、短く、補助的で、読書体験を阻害しない範囲に留めなければなりません。

### 外部スタイル変更の制限

外部スタイルは、次の識別を壊してはなりません。

- current / non-current
- enabled / disabled
- focus visible / not focused
- page / ellipsis
- prev / next

`::part(nav)` や `::part(list)` による変更であっても、意味上の識別が失われる変更は契約違反です。

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、動きは即時完了に近い表現へ縮退します。移動感を強調しません。

### Forced Colors

`forced-colors: active` 環境では、現在ページ、通常ページ、disabled 状態、フォーカス表示の区別をシステムカラーで維持します。box-shadow 依存の表現は前提にしません。

### Dark Mode

ダークモードは専用分岐ではなく、トークン差し替えで吸収します。色差は上位テーマが供給します。

## 責務境界

### 本コンポーネントの責務

- ページ番号列の構成
- current / non-current の表現
- Prev / Next の境界表現
- URL の埋め込み
- `nav` と link の意味論
- `compact` / `regular` の描画差
- 省略記号による欠落区間の表現

### 本コンポーネントの責務ではないもの

- どの幅で `compact` に切り替えるか
- 単一ページ時に全体を非表示にするか
- `first` / `last` のような境界ナビゲーションを出すか
- `sibling-count` / `boundary-count` のような範囲密度を外部入力で可変にすること
- ラベル差し替えや多言語化機構を内包すること
- 任意ページ番号入力
- ページサイズ変更
- 総件数表示
- データ取得のやり直し
- SPA ルーターとの結合
- スクロール位置の復元

### 上位レイヤが決めるべき事項

- `mode` の選択
- `current` と `total` の妥当性
- `getHref` の URL 設計
- 単一ページ時の表示有無
- 狭幅時のレイアウト戦略
- 境界ナビゲーション、総件数表示、入力補助などを別途併設するか
- 多言語化が必要な場合のラップ方針

## 境界条件

### 単一ページ

`total = 1` の場合、ページ 1 のみを表示します。Prev / Next はともに disabled です。省略記号は表示しません。

### 小規模ページ群

`total <= 7` の場合、全ページを表示します。省略記号は使用しません。

### 7 / 8 の閾値

`total = 7` では省略なし、`total = 8` では省略記号が現れ得ます。この閾値は固定です。

### 1 ページ欠落区間

欠落が 1 ページだけの場合、省略記号ではなく実ページ番号を表示します。

### 先頭付近

`current` が先頭に近い場合、左側の冗長な省略記号を表示しません。

### 末尾付近

`current` が末尾に近い場合、右側の冗長な省略記号を表示しません。

### 不正入力

不正入力に対する実装上の防御的補正はあり得ますが、その補正結果は契約化しません。契約上の有効入力は、`total >= 1` かつ `1 <= current <= total` のみです。

## 検証マトリクス

Storybook または同等の検証では、少なくとも次を確認しなければなりません。

| 検証項目 | 確認内容 |
| --- | --- |
| root navigation semantics | `nav` がページ移動ナビゲーションとして解釈され、`aria-label="ページナビゲーション"` を持つこと |
| current page link | 現在ページが `aria-current="page"` を持つリンクであること |
| prev/next enabled state | 移動可能時の Prev / Next がリンクであること |
| prev/next disabled state | 境界で Prev / Next が `<span aria-disabled="true">` になること |
| ellipsis semantics | 省略記号が非対話要素であり、フォーカス対象にも読み上げ対象にも入らないこと |
| single page | `total = 1` でページ 1 のみが表示され、省略記号が出ないこと |
| small total | `total <= 7` で全ページが表示されること |
| threshold 7/8 | `total = 7` と `total = 8` の閾値が維持されること |
| one-page gap | 欠落が 1 ページのとき、省略記号ではなく実ページ番号が表示されること |
| near start / near end | 冗長な省略記号が表示されないこと |
| compact mode | `compact` で current と必要な側の省略記号だけに圧縮されること |
| representative examples | 本書の代表例と描画結果が一致すること |
| no custom event assumption | 利用側テストがコンポーネント固有イベントに依存していないこと |
| reduced motion | Reduced Motion 環境でも動きが補助的表現に留まり、識別が失われないこと |
| forced colors | 強制カラーで current / non-current、enabled / disabled、focus visible の区別が維持されること |
| dark theme tokens | トークン差し替えで暗色環境に適応できること |
| structural privacy | テストが内部 class 名、private state、helper 関数の戻り値に依存せず、公開入力と描画結果だけを見ていること |

## 非採用方針

次の方向は採りません。

- 現在ページを link 以外へ置換すること
- disabled 項目へ `href` を残したまま見た目だけ無効化すること
- 省略記号をクリック可能にすること
- 独自 `pagechange` イベントへ責務を移すこと
- pointer 種別や viewport 幅から暗黙に公開状態を決めること
- helper 関数の戻り値仕様をそのまま公開契約にすること
- composite widget 化すること
- `first` / `last` のような境界ナビゲーションを本コンポーネントの標準契約に含めること
- `sibling-count` / `boundary-count` によりページ範囲規則を外部から可変化すること
- ラベル差し替えや多言語化機構を本コンポーネント自身の公開 API に含めること
- 任意ページ番号入力、ページサイズ変更、総件数表示を本コンポーネントへ持ち込むこと

本コンポーネントは、URL を伴うページ移動ナビゲーションに責務を限定します。追加の導線、入力、設定、情報表示が必要な場合は、上位レイヤまたは別コンポーネントで扱います。

## 現行実装との差分

本書の契約と現行実装には、主に次の差分があります。

### `mode` の公開化

現行実装は内部状態で `compact` 表示を切り替えています。本書では、表示密度を公開入力 `mode` へ昇格し、どの状況で `compact` を使うかを上位レイヤの責務へ移します。

### 不正入力の扱い

現行実装は `current` / `total` を防御的に補正して描画します。本書では、その補正結果を公開意味論へ含めず、有効入力域を明示的に限定します。

加えて、現行実装では**コンポーネント描画と helper 関数で不正入力時の振る舞いが一致していません**。

- コンポーネント描画は `normalizePagination()` により `total <= 0` を `1` へ補正します。
- `computeRange()` / `computeCompactRange()` は `total <= 0` のとき空配列を返します。

本書はこの二重意味を公開契約に含めません。

### helper 関数の扱い

現行実装は `computeRange()`、`computeCompactRange()`、`RangeItem` を公開しています。本書では、helper 関数名やその戻り値仕様を公開契約から外し、描画結果だけを契約対象とします。

### responsive 判定の責務

現行実装は pointer 環境に応じて `compact` を自動選択します。本書では、自動判定を契約に含めず、`mode` の選択を上位レイヤへ戻します。

この差分には、次の具体的な未整合を含みます。

- 現行実装は `connectedCallback()` で `window.matchMedia('(hover: none) and (pointer: coarse)')` を監視します。
- したがって、SSR 初期描画では `regular` 相当、hydration 後に `compact` 相当へ切り替わることがあります。
- 本書はこの暗黙遷移を公開契約へ含めず、表示密度は明示入力で決める方針を採ります。

### `getHref` の既定値

現行実装では、`getHref` に `?page=${String(p)}` を返す既定値が与えられています。本書では `getHref` を意味上は必須入力として扱い、**URL 設計は上位レイヤが明示的に与えるべき責務**として整理しています。既定値の存在は実装上の便宜であり、長期契約の中心には置きません。

### 本書の適用範囲外である機能

現行実装には、本書が適用範囲外とする次の機能は公開 API として含まれていません。

- `first` / `last` 直接移動
- `sibling-count`
- `boundary-count`
- ラベル差し替え入力
- 任意ページ番号入力
- ページサイズ変更
- 総件数表示

これは現行実装の不足を意味しません。本書は、Pagination の責務を URL を伴うページ移動ナビゲーションへ限定するため、これらを公開契約へ含めません。

### テスト専用内部アクセス

現行 Storybook は `compact` 表示の検証のために private state `_isCompact` を型アサーション経由で直接変更しています。本書はこれを公開契約とみなしません。これは検証上の便宜であり、利用側が依存してよい拡張点ではありません。

以上の差分は、実装が誤っているという意味ではありません。責務を分離し、公開契約の境界を明確にするための再構成です。
