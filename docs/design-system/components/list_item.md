# List Item

## 概要

本書は、`ui-list-item` の長期契約を定義します。

`ui-list-item` は、``** 配下で 1 行を構成する従属コンポーネント**です。独立した一覧部品ではありません。責務は、**行セルの構成、主列と補助列の視覚階層、モバイル時の可視列縮退、行内セル移動、行アクティブ状態の表示**に限定します。

本書では、現行実装の振る舞いをそのまま追認しません。`ui-list-item` を長期的に保守しやすい形へ収束させるため、**責務境界が明確で、意味論が一貫し、親 **``** と衝突しにくい契約**を採用します。

---

## 適用範囲

本書は、`ui-list-item` の次の事項を対象とします。

- 位置づけ
- 公開契約
- 状態モデル
- DOM / Accessibility
- Visual Contract
- 環境別の振る舞い
- 関連契約
- 境界条件
- Storybook 契約
- 現行実装との差分

本書は次の事項を扱いません。

- 一覧全体の並び順、ソート、フィルタリング、ページネーション
- 行選択結果の永続化
- 行遷移、ルーティング、ダイアログ起動
- 列定義の最終決定
- 各セル内部の個別 UI コンポーネント契約
- データ取得

これらは `ui-list` または上位レイヤの責務です。

---

## 位置づけ

`ui-list-item` は、``** が供給する列定義と表示モードに従って描画される行部品**です。独立利用は正式サポート対象に含めません。

親 `ui-list` が存在しない場合でも、コンポーネントは壊れずに描画されてよいですが、それは**境界条件としてのフォールバック**であり、通常運用の前提ではありません。したがって、単体利用時の見た目や振る舞いに外部利用者が強く依存しません。

この位置づけにより、`ui-list-item` は次を行いません。

- 自身で列定義を所有しません。
- 自身で主遷移を決定しません。
- 自身で選択状態を永続化しません。
- 自身で行操作の意味を決定しません。

`ui-list-item` は、**親が決定した一覧構造を、読みやすく、操作しやすい 1 行へ正確に投影する部品**です。

## 公開契約

### 前提契約

`ui-list-item` は `ui-list` 配下で使用します。親 `ui-list` は、列定義、モバイル状態、論理行 index、およびアクティブ行・アクティブセル状態を子へ供給します。

`ui-list-item` 単体は、列定義スキーマを決定しません。列定義の正当性検証は親 `ui-list` 側契約で扱います。

### 入力契約

`ui-list-item` の長期契約として公開する入力は次のとおりです。

| 名前              | 種別                                       | 必須   | 内容                   | 契約                                                    |
| ----------------- | ------------------------------------------ | ------ | ---------------------- | ------------------------------------------------------- |
| `itemId`          | property / attribute (`item-id`)           | はい   | 行 ID                  | `ui-active-change` の識別子です。空文字列は許可しません |
| `active`          | property / attribute                       | いいえ | 行がアクティブか       | `true` の場合に行強調とセルロービングを有効にします     |
| `activeCellIndex` | property / attribute (`active-cell-index`) | いいえ | 行内アクティブセル位置 | **可視セル順 + action セル** を基準とします             |
| `rowIndex`        | property / attribute (`row-index`)         | いいえ | 1-based の論理行 index | 指定時に `aria-rowindex` を出力します                   |

### 非契約入力

次の表面は現行実装に存在していても、長期契約には含めません。

| 名前      | 扱い   | 理由                                           |
| --------- | ------ | ---------------------------------------------- |
| `href`    | 非契約 | 主遷移責務は `ui-list-item` が持たないためです |
| `managed` | 非契約 | 親管理下かどうかは接続関係で決まるためです     |

これらは将来削除または内部化してよく、外部利用者は依存しません。

### スロット契約

| 名前                | 種別       | 内容                 | 契約                                              |
| ------------------- | ---------- | -------------------- | ------------------------------------------------- |
| 列 ID 対応スロット  | named slot | 各列のセル内容       | `columns[].id` と一致する slot 名だけを受理します |
| `actions`           | named slot | 行末操作群           | action セルに描画します                           |
| `mobile-supplement` | named slot | モバイル時の補助情報 | 非表示化したメタ情報の要約再掲だけに使います      |

既定スロットは通常運用の公開入力ではありません。親未接続時のフォールバックに限って存在してよいですが、外部利用者は正規入力として依存しません。

### 未知スロット契約

列定義に存在しない named slot は描画に寄与しません。開発時は警告対象として扱います。既知列の slot が未提供の場合は、空セルとして描画します。

### 親コンテキスト契約

`ui-list-item` は親 `ui-list` から次の情報を受け取る前提で動作します。

| 名前       | 内容                 | 契約                                                     |
| ---------- | -------------------- | -------------------------------------------------------- |
| `columns`  | 列定義配列           | `id` は一意であり、slot 名として有効でなければなりません |
| `isMobile` | モバイル表示かどうか | 真の場合は mobile 縮退契約を適用します                   |

列定義には次の不変条件を課します。

- `id` は一意です。
- `primary` は高々 1 つです。
- `primary` 列は `hideOnMobile=true` を許可しません。
- action セルは `columns` に含めません。
- `columns` が空の場合、`ui-list-item` は正規動作しません。

主列指定がない場合、先頭の可視列を主列とみなします。

### 出力イベント契約

`ui-list-item` が公開する固有イベントは `ui-active-change` のみです。

| 名前               | 種別        | detail                | 契約                                           |
| ------------------ | ----------- | --------------------- | ---------------------------------------------- |
| `ui-active-change` | CustomEvent | `{ rowId, colIndex }` | 行内セルのアクティブ位置変更要求を親へ返します |

`rowId` は `itemId` です。`colIndex` は **可視セル順 + action セル** を基準とします。論理列 index は外部契約へ露出しません。

`ui-active-change` は `** かつ **` で送出します。キャンセル可能イベントとしては扱いません。

### 非公開協調面

親子間で使う `ui-list-context-request` および同種の再同期機構は、`** と **`** の内部協調契約**です。一般利用者向け公開 API としては扱いません。

同様に、`requestListContext()` は長期契約では公開メソッドとみなしません。再同期の駆動責務は親 `ui-list` 側に置きます。

### 責務範囲

`ui-list-item` の責務は次に限定します。

- 行セルの構成
- 主列 / 補助列 / action セルの視覚階層
- 行アクティブ状態の表示
- 行内セル移動要求の送出
- モバイル時の可視列縮退
- 一覧読書面としての過度なノイズ抑制

次は責務に含めません。

- 主遷移の実行
- 行編集開始
- ダイアログ起動
- Space / Enter の意味付け
- 列定義の妥当性決定
- 行アクティブ状態の最終決定

## 状態モデル

### 基本状態

最小状態は、親から正当な列定義を受け取り、`itemId`、`active`、`activeCellIndex`、`rowIndex` を持つ状態です。`active=false` のとき、行は描画されますがセルロービングは成立しません。

### 主列状態

主列は `columns` のうち `primary=true` の列です。指定がない場合は先頭可視列です。主列は、行の意味を代表する列であり、モバイル縮退時の情報統合先でもあります。

### 補助列状態

主列以外の列は補助列です。補助列は、主列の理解を助けるメタ情報を静かな強度で表示します。補助列は主列と同格ではありません。

### action セル状態

action セルは、可視列列群の末尾に常に存在する独立セルです。`actions` スロットが空であっても、構造上の action セルは維持します。これにより、行構造、index、整列を安定させます。

### アクティブ行状態

`active=true` の場合、行はアクティブ状態です。背景強調、左アクセント、`aria-selected="true"` を出力します。`active=false` の場合、`aria-selected` は偽または未設定です。

### アクティブセル状態

`activeCellIndex` は **可視セル順 + action セル** を基準とする 0-based index です。非表示列を数えません。action セルは常に末尾 index です。

`activeCellIndex` に対して、次の面をすべて同一基準にそろえます。

- セルロービング
- `ui-active-change.detail.colIndex`
- `aria-colindex`
- 内部セル識別
- Storybook の期待値

### モバイル状態

`isMobile=true` の場合、`hideOnMobile=true` の補助列は DOM から抑制します。主列は常時表示します。`mobile-supplement` は、非表示になった補助情報の要約だけを主列に再掲できます。

モバイル時は、可視列だけで新しいグリッドを構成します。非表示列は、視覚上だけでなく DOM とアクセシビリティ上も存在しません。

### フォールバック状態

親 `ui-list` が存在しない場合でも、描画は壊れてはなりません。ただしこの状態は正式運用契約ではなく、**障害耐性のための境界条件**です。単体フォールバックの DOM や操作性に外部利用者は依存しません。

## DOM / Accessibility

ルートは `:host` です。ホストは `role="row"` を持ち、その内部にセル要素を持ちます。各セルは `role="gridcell"` を持ちます。

```text
<ui-list-item role="row" aria-selected="..." aria-rowindex="...">
  #shadow-root
    <div class="cell cell--primary" role="gridcell" aria-colindex="1">
      <div class="cell-content">
        <slot name="title"></slot>
        [mobile-supplement]
      </div>
    </div>
    <div class="cell cell--meta" role="gridcell" aria-colindex="2">...</div>
    <div class="cell cell--action" role="gridcell" aria-colindex="N">
      <div class="actions">
        <slot name="actions"></slot>
      </div>
    </div>
</ui-list-item>
```

### アクセシビリティ契約

- ホストは常に `role="row"` を持ちます。
- 各セルは常に `role="gridcell"` を持ちます。
- `rowIndex` 指定時のみ `aria-rowindex` を出力します。
- `aria-colindex` は **可視セル順 + action セル** に基づいて振ります。
- 行アクティブ状態は `aria-selected` で表現します。
- 行内タブ停止はセルを主体とします。
- フォーカス可視表示はセル単位で扱います。

### フォーカスモデル契約

`ui-list-item` は、**セル主体のロービングフォーカス**を採用します。

したがって、次を契約とします。

- 非 action セル内に、自然 tab stop を持つ対話要素を置きません。
- 主列セル内の `a[href]` は存在してよいですが、逐次 Tab 移動の主体にはしません。
- action セル内の対話要素だけを、個別操作用の自然フォーカス対象として許可します。

これにより、行読み取りと個別操作の二つの操作系を衝突させません。

### 非採用の補助 ARIA 属性

`aria-haspopup`、`aria-keyshortcuts`、`aria-description` は、`ui-list-item` の一般契約に含めません。

これらは、上位の一覧操作モデルが明示的に必要と判断した場合にのみ、親側で追加する補助面です。`ui-list-item` 自体は、dialog 起動や Space / Enter の意味付けを持ちません。

## Visual Contract

`ui-list-item` は、一覧の中で主情報、補助情報、操作を過不足なく並置し、**読む流れを阻害しないこと**を最優先にします。

### 情報順位

- 主列は本文に近い強度で表示します。
- 補助列は控えめな文字サイズと色で表示します。
- action セルは通常時に強く主張しません。
- アクティブ行だけを背景と左アクセントで識別します。

### レイアウト契約

ホストはグリッドコンテナです。列テンプレートは親 `ui-list` と整合したものを使います。`ui-list-item` 単体は列幅体系を所有しません。

各セルは同一行高を基本とし、可読性を損なわない余白を持ちます。action セルは空であっても構造上維持します。

### 視覚状態契約

- 通常時の行背景は透明です。
- hover および focus-within 時は、弱い hover 背景を適用します。
- `active` 時は、より強い背景と左アクセントを適用します。
- action 操作群は通常時に視覚ノイズを抑え、hover、focus-within、active 時に前景化します。

### テキスト選択契約

本文読書面としての性格を優先し、**テキスト選択は selection-neutral** とします。テキスト選択操作は行アクティブ変更を引き起こしません。

### スタイル拡張契約

`ui-list-item` は CSS Custom Properties による基本トークン差し替えを許可します。一方で、内部 class、内部データ属性、Shadow DOM 構造、内部グリッド変数は公開 API ではありません。`::part(...)` も公開しません。

## 環境別の振る舞い

### Mobile

モバイルでは `hideOnMobile=true` の補助列を DOM から抑制します。主列は常時表示します。`mobile-supplement` は hidden metadata の要約再掲に限定します。

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、行背景や action 群の遷移時間を極小化します。

### Forced Colors

`forced-colors: active` 環境では、アクティブ左アクセントとフォーカス輪郭をシステム色へ置き換え、境界と選択可視性を維持します。

### Print

印刷では、アクティブ背景と action 群を除去します。行情報は残し、操作ノイズだけを削除します。

## 関連契約

### 行アクティブ変更契約

`ui-list-item` は、**非 action セルに対する単純 click** と **左右矢印キー** により `ui-active-change` を送出します。

| 入力         | 前提                                               | 結果                                              |
| ------------ | -------------------------------------------------- | ------------------------------------------------- |
| `click`      | 非 action セルであり、テキスト選択操作ではないこと | 対象セル index で `ui-active-change` を送出します |
| `ArrowLeft`  | 左境界でないこと                                   | 1 つ前のセル index を送出します                   |
| `ArrowRight` | 右境界でないこと                                   | 1 つ次のセル index を送出します                   |

`focusin` は状態遷移の正規トリガーに含めません。フォーカス追従は表示整合のために存在してよいですが、外部契約上の状態変化源としては扱いません。

### action セル契約

action セル内操作は **selection-neutral** です。action セル内の `button` や `a` の操作は、行アクティブ変更を暗黙に伴いません。行アクティブ変更と個別操作は別契約として分離します。

### 主列リンク契約

主列セル内に `a[href]` を置くことは許可します。ただし、それは行の意味を表す内容要素であり、行ロービングフォーカスの主体ではありません。主遷移の実行責務は `ui-list-item` が持ちません。

### モバイル補助情報契約

`mobile-supplement` は、hidden metadata の要約再掲専用です。desktop に存在しない独立コンテンツを mobile のみへ追加しません。

### 親再同期契約

列構成、モバイル状態、または表示モードが変化したときの再同期責務は親 `ui-list` が持ちます。`ui-list-item` は、再同期後の新しい可視列構成に従って `activeCellIndex` と `aria-colindex` を再解釈します。

## 境界条件

### 列定義不正

`columns` が空、`id` が重複、`primary` が複数、または primary が mobile hidden の場合、親 `ui-list` 側契約違反です。`ui-list-item` はできる限り安全側へ倒れてもよいですが、その状態を正式契約として扱いません。

### スロット未提供

既知列の slot が未提供であっても、セル構造は維持します。未提供列は空セルです。

### 未知スロット

未知 slot は描画に寄与しません。開発時は警告対象です。

### action セル空

`actions` スロットが空でも action セルは維持します。

### モバイル縮退

モバイル時の非表示列は DOM に存在しません。したがって、スクリーンリーダー、キーボード移動、index 計算の対象にも含めません。

### 単体フォールバック

親未接続時のフォールバック描画は許容しますが、通常運用契約ではありません。外部利用者は依存しません。

## Storybook 契約

各 Story は見本ではなく、契約確認点です。少なくとも次を固定します。

| Story                             | 固定する契約                                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `DefaultInList`                   | `ui-list` 配下で `role="row"`、`role="gridcell"`、主列 / 補助列 / action セル構造が成立すること       |
| `VisibleIndexContract`            | `activeCellIndex`、`ui-active-change.detail.colIndex`、`aria-colindex` が可視セル順基準で一致すること |
| `ActionCellSelectionNeutral`      | action セル内操作が行アクティブ変更を暗黙に伴わないこと                                               |
| `FocusableContentBoundary`        | 非 action セル内に自然 tab stop を持つ要素を置かないこと                                              |
| `MobileSupplement`                | モバイル時に hidden metadata だけが主列へ再掲されること                                               |
| `UnknownSlotIgnoredWithWarning`   | 未知 slot が描画に寄与せず、警告対象になること                                                        |
| `TextSelectionDoesNotActivateRow` | テキスト選択操作が行アクティブ変更を引き起こさないこと                                                |
| `MissingSlotBoundary`             | 既知列 slot 未提供時もセル構造を維持すること                                                          |
| `ForcedColorsMode`                | forced-colors 環境で境界とフォーカス可視性を維持すること                                              |
| `ReducedMotion`                   | reduced-motion 環境で不要な視覚遷移を極小化すること                                                   |
| `PrintContract`                   | 印刷時に行情報を残し、操作ノイズだけを除去すること                                                    |

現行 Storybook に実在する Story は、`DefaultInList`、`ActiveCellIndexFocus`、`EmitsActiveChangeOnArrow`、`EdgeBoundaryStops`、`MissingSlotBoundary`、`MobileSupplement`、`StandaloneFallback`、`DarkMode` です。`VisibleIndexContract`、`ActionCellSelectionNeutral`、`FocusableContentBoundary`、`UnknownSlotIgnoredWithWarning`、`TextSelectionDoesNotActivateRow`、`ForcedColorsMode`、`ReducedMotion`、`PrintContract` は、長期契約として固定したい検証観点であり、現行 Story 実装が未追随である可能性があります。

## 新規で追加を検討する価値がある機能

本節は、`ui-list-item` の責務境界を崩さず、長期的な可読性、保守性、および一覧読書面としての完成度を高めるために、追加を検討する価値がある機能を整理するものです。

ここで挙げる候補は、`ui-list` の責務を奪うものではありません。行部品としての `ui-list-item` に自然に属し、かつ既存契約と衝突しにくいものに限定します。

### 最優先で検討する価値がある機能

#### 1. モバイル要約の自動合成

現行契約では、モバイル時に非表示化した補助列の情報を `mobile-supplement` に再掲できます。ただし、この方式を完全に手動運用へ委ねると、desktop 側の補助列内容と mobile 側の再掲内容が二重管理になりやすいです。

したがって、長期的には **hidden metadata の一部を自動的に要約再掲する仕組み** を追加する価値があります。たとえば、列定義側で「モバイル再掲対象」を指定し、`ui-list-item` が可視縮退時に自動合成する方式が考えられます。

この機能は、`mobile-supplement` を廃止することを意味しません。自動合成を既定値とし、必要な場合にのみ明示上書きを許可する設計が望ましいです。これにより、mobile 補助情報の source of truth を整理しやすくなります。

#### 2. action 表示ポリシーの切替

現行契約では、action 群は通常時に視覚ノイズを抑え、hover、focus-within、active 時に前景化します。この既定値は合理的ですが、すべての一覧で最適とは限りません。

一覧の性格によっては、常時表示の方がよい場合、hover ではなく active 時だけ見せたい場合、または touch 前提で hover 依存を弱めたい場合があります。したがって、**action 表示ポリシーを切り替えられる機能** を追加する価値があります。

この機能は、action セルの責務を拡張するものではなく、既存の視覚契約を用途別に調整するための機能です。既定値は現行どおり抑制表示とし、必要時のみ opt-in で切り替えます。

#### 3. 主列の複数行表示モード

現行の主列表示が常に単一行省略である場合、タイトルや主情報が少し長いだけで意味量が大きく落ちます。Rouault のように「読む」性格を持つ一覧では、主列の情報欠落は想像以上に不利です。

そのため、**主列だけは 2 行程度まで表示を許可するモード** を追加する価値があります。これにより、一覧密度を極端に崩さずに、主情報の意味保持を改善できます。

この機能は、主列の責務を変えるものではなく、視覚密度と意味保持のバランスを調整するための補助機能です。既定値は単一行でもよいですが、コンテンツ特性に応じて切り替え可能にしておくと運用しやすいです。

### 条件付きで検討する価値がある機能

#### 1. 開発時診断の強化

未知 slot、`columns.id` 重複、`primary` 複数指定、非 action セル内の自然 tab stop 要素など、契約違反を早期に発見するための診断を拡充する価値があります。

これは利用者向け新機能というより、契約維持を助ける開発支援機能です。公開 API を増やさず保守性を上げられるため、実装コストが低ければ有力な候補です。

#### 2. 非アクティブ行モード

将来的に、説明行、集計行、区切り行のような「選択対象ではない行」を同一の視覚体系で扱いたくなる可能性があります。その場合は、行活性化を持たないモードを検討してよいです。

ただし、これは `ui-list-item` を「通常は選択可能行である」という前提から少し外すため、必要性が具体化するまでは導入しません。

### 追加しない方がよい機能

次の機能は、`ui-list-item` の責務境界を越えやすいため、本書の方針では追加対象にしません。

- 行クリックによる自動遷移
- inline edit
- ソート UI
- 複数選択
- ドラッグ並べ替え
- 行内メニュー開閉責務
- Enter / Space の意味付けの内蔵

これらは、親 `ui-list` または上位レイヤの責務として分離する方が設計のきれいさと保守性を維持しやすいです。

## 補足

`ui-list-item` で守るべき核心は次のとおりです。

1. `ui-list-item` は `ui-list` の従属行であり、独立一覧部品ではありません。
2. 外部契約上の index は **可視セル順 + action セル** に統一します。
3. action セルは **selection-neutral** です。
4. 非 action セルはセル主体フォーカスを崩しません。
5. 主遷移、dialog 起動、Space / Enter の意味付けは親側責務です。
6. モバイル縮退では hidden 列を DOM / A11y / index のすべてから除外します。

## 現行実装との差分

本節は、現行実装が本契約へまだ一致していない可能性がある点を記録します。

### `href`

現行実装に `href` が存在していても、本契約では採用しません。主遷移責務は `ui-list-item` に持たせません。

### `managed`

現行実装に `managed` が存在していても、本契約では採用しません。親管理下であるかどうかは接続関係で決まります。

### `requestListContext()`

現行実装に公開メソッドが存在していても、本契約では外部公開 API とみなしません。再同期責務は親 `ui-list` 側に移します。

### `focusin` による `ui-active-change`

現行実装が `focusin` を状態変化トリガーとして扱っている場合でも、本契約では採用しません。状態遷移の正規トリガーは click と左右矢印だけです。

### `data-item-id` の Storybook 期待値

現行 Storybook が `data-item-id` の同期を検証していても、本契約では採用しません。行識別の公開面は `item-id` に一本化します。`data-*` 属性は内部観測面であり、公開契約に昇格させません。

### `aria-selected` の偽値出力

現行実装が `active=false` の場合にも `aria-selected="false"` を常時出力していても、本契約では偽値の常時出力を必須化しません。行選択モデル全体との整合を見て、`false` を明示するか未設定にするかは親側を含めて整理します。

### action セル内操作と行活性化の同時発火

現行実装が action セル操作時にも `ui-active-change` を送出している場合、本契約では採用しません。action セルは selection-neutral へ寄せます。

### テキスト選択と行活性化の衝突

現行実装が単純 click とテキスト選択を十分に分離できていない場合、本契約では採用しません。テキスト選択は selection-neutral です。

### 非セルクリックと疑似要素クリック

現行実装が `.cell` に属さない click でも、現在 index へ正規化して `ui-active-change` を送出している場合、本契約では採用しません。行活性化は、意味上のセルを特定できる入力に限定します。

### action 群の opacity のみでの隠蔽

現行実装が action 群を `opacity: 0` のみで隠している場合、本契約では「視覚的に隠れているが操作可能である」状態を前提にしません。長期的には、視覚状態と操作可能状態の関係を明示的にそろえる方が望ましいです。

### `aria-haspopup` / `aria-keyshortcuts` / `aria-description`

現行実装がこれらを常時付与していても、本契約では一般行契約として採用しません。必要なら親側の opt-in に移します。

### `content-visibility` / `contain-intrinsic-height` / 最小タッチ領域疑似要素

現行実装が `content-visibility: auto`、`contain-intrinsic-height`、および最小タッチ領域を補う疑似要素を持っていても、これらは現時点では実装最適化面です。公開契約としては固定せず、性能特性とポインタ挙動の両面を整理したうえで必要なら昇格させます。

### index の基準

現行実装に論理列 index と可視列 index の混在が残っている場合、本契約では採用しません。外部契約・A11y・内部セル識別のすべてを可視セル順へ統一します。

### 単体フォールバック

現行実装に単体描画が存在していても、本契約では通常運用面に昇格させません。障害耐性のための境界条件にとどめます。
