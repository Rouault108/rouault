# Banner

## 1. 概要

本書は、`ui-banner` の公開契約、状態モデル、DOM / Accessibility、Visual Contract、環境別の振る舞い、および関連契約を定義するものです。

`ui-banner` は、アプリケーション全体に関わる**持続的な状態通知**を提示するコンポーネントです。通知の意味は `variant` により表現し、支援技術向けの意味付けは `role` により確定します。`warning` / `error` は即時性の高い通知として扱い、`info` / `success` は補助的な状態通知として扱います。

本コンポーネントの要点は、単に色付きの帯を表示することではありません。**意味的バリアントから live region の性格を導出すること**、**action slot を補助操作のために限定すること**、および **dismiss 時に DOM 除去と前進型フォーカス移動を一体で扱うこと** にあります。

配色、モーション、高コントラスト対応は、コンポーネント固有のモード分岐ではなく、**トークン契約**により成立します。

本書は規範文書です。構文上受理され得る入力の全てを公開契約へ昇格させません。**公開契約は、本書に明示した面に限ります。**

---

## 2. 適用範囲

本書は、`ui-banner` の次の事項を対象とします。

- 公開契約
- 状態モデル
- DOM / Accessibility
- Visual Contract
- 環境別の振る舞い
- 関連契約
- 境界条件
- Storybook 契約
- 現行実装との差分整理

本書は、次の事項を対象外とします。

- バナーの配置レイヤやページ上での設置位置
- 複数バナーのキューイングやスタック制御
- dismiss 後のアプリケーション状態同期そのもの
- action の業務的意味や遷移先の妥当性
- 通知文面生成の一般論
- 永続化や再表示抑止の仕組み
- i18n 方針の一般化
- 自動消滅タイマー
- toast 的な pause / resume 制御
- 複数レイアウトモードの導入
- バリアントごとの自動見出し生成
- action 領域の過度な主従 API
- 未採用の将来拡張候補そのものの実装仕様

ただし、本書は通知文面生成の一般論を扱わない一方で、`ui-banner` が通知として成立するための**本文の最小契約**は扱います。本文が単独で意味を成し、色やアイコンのみに依存しないことは、本コンポーネント固有の契約に含みます。

これら以外の事項は、上位レイヤまたは呼び出し側の責務です。

## 3. 公開契約

`variant` と `dismissible` は公開 property / attribute です。`role` は明示指定可能な公開 attribute です。`aria-atomic` は補助的なアクセシビリティ attribute として扱います。本文は default slot、アイコンは `slot="icon"`、補助操作は `slot="action"` で受け取ります。

default slot は通知本文です。実装上は空でも成立し得ますが、実運用では空の通知を使用しません。`variant` は `info` / `warning` / `error` / `success` を正規値として扱います。不正値は受理されても、公開契約上は `info` に正規化されたものとして扱います。

`variant` は、本コンポーネントの意味状態、フォールバックアイコン、視覚トーン、および自動 `role` を一貫して成立させるための一次入力です。そのため、公開契約上も全域的に解決される入力として扱います。一方、`role` は live region の意味付けを明示上書きするための補助入力であり、公開契約として許容する明示値は `status` と `alert` に限ります。

したがって、`variant` は契約外値であっても `info` へ収束させますが、`role` は限定列挙の override 入力として扱い、それ以外の値を公開 API としては許容しません。

### 3.1 Property / Attribute

| 名前          | 種別                 | 必須   | 内容                   | 契約                                                                                        |
| ------------- | -------------------- | ------ | ---------------------- | ------------------------------------------------------------------------------------------- |
| `variant`     | property / attribute | いいえ | 意味的バリアント       | `info` / `warning` / `error` / `success` を正規値とします。不正値は `info` として解決します |
| `dismissible` | property / attribute | いいえ | 閉じる操作の有無       | `true` の場合のみ閉じるボタンを表示し、dismiss 操作を有効化します                           |
| `role`        | attribute            | いいえ | live region の意味付け | 明示指定可能値は `status` / `alert` に限ります。未指定時は自動マッピングを適用します        |
| `aria-atomic` | attribute            | いいえ | live region の更新単位 | 未指定時は `true` を補完します。明示指定時はその値を保持します                              |

### 3.2 Slot

| 名前            | 種別 | 位置づけ | 内容                                                                             |
| --------------- | ---- | -------- | -------------------------------------------------------------------------------- |
| default slot    | slot | 主入力   | 通知本文です                                                                     |
| `slot="icon"`   | slot | 任意入力 | アイコン上書きです。未指定時はバリアント対応のフォールバックアイコンを使用します |
| `slot="action"` | slot | 任意入力 | 補助操作です。1 個以上の対話要素を許容します                                     |

### 3.3 責務境界

本コンポーネントは、通知本文の表示、バリアント正規化、`role` の自動決定、action 領域の表示切替、dismiss に伴う DOM 除去、および dismiss 後のフォーカス移動を担います。

一方で、dismiss 完了イベントの発火、呼び出し側 state の更新、action 実行の意味付け、通知の自動消滅タイマー、およびバナーの再表示制御は担いません。

本書の規定は、実装が一時的に許容し得る広い入力範囲より優先します。**構文上挿入可能であること**と**公開契約として許容すること**は同義ではありません。

### 3.4 公開状態属性 / 非公開状態属性

ホスト要素には、解決済み状態または遷移中状態を表す属性が付与される場合があります。ただし、これらは同一の契約強度を持ちません。

| 名前                    | 種別           | 公開性                     | 契約                                                                                                 |
| ----------------------- | -------------- | -------------------------- | ---------------------------------------------------------------------------------------------------- |
| `data-resolved-variant` | host attribute | 読み取り専用の公開状態属性 | `variant` の解決結果を反映します。作者入力には使用しません。監査、テスト、診断目的の参照は許容します |
| `data-dismissing`       | host attribute | 非公開の内部遷移属性       | dismiss 退出中に一時付与されます。外部 CSS / JS / テストが恒久依存してはなりません                   |

`data-resolved-variant` は、入力値そのものではなく正規化後の意味状態を観測するための属性です。一方、`data-dismissing` は内部遷移制御に属するため、外部契約面として扱いません。

### 3.5 イベント契約

`ui-banner` 自身は、dismiss、`variant` 更新、`role` 自動更新、action 領域表示切替に対して独自 `CustomEvent` を発火しません。

| 事象               | 独自イベント   | 契約                                                          |
| ------------------ | -------------- | ------------------------------------------------------------- |
| dismiss ボタン押下 | 発火しません   | 要素は内部遷移後に DOM から除去されます                       |
| `variant` 更新     | 発火しません   | 必要に応じて `role` と `data-resolved-variant` が同期されます |
| `role` の自動適用  | 発火しません   | 属性更新のみを行います                                        |
| action 要素の操作  | 正規化しません | 配置されたネイティブ要素自身のイベントに委譲します            |
| `slotchange`       | 公開しません   | 内部状態同期にのみ使用します                                  |

したがって、dismiss をアプリケーション状態へ反映したい場合は、呼び出し側が外側の state 管理と同期します。本コンポーネントに対して `dismiss` 完了通知の発火を期待しません。

将来拡張として独自イベントを導入する場合は、単一イベントではなく、**ライフサイクルを分離した 2 段階モデル**を採用します。

| 候補イベント             | 性質           | 意図                                               |
| ------------------------ | -------------- | -------------------------------------------------- |
| `banner-dismiss-request` | cancelable     | dismiss 開始前に呼び出し側が介入できるようにします |
| `banner-dismissed`       | non-cancelable | dismiss 完了を外側 state と同期できるようにします  |

将来拡張を導入する場合でも、`variant` 更新や `role` 自動更新までイベント駆動には拡張しません。イベント対象は dismiss ライフサイクルに限定します。

### 3.6 Slot 内容制約

slot は構文上比較的自由ですが、公開契約として依存できる内容には制約があります。

| slot            | 許容                                             | 契約しない内容                                                 |
| --------------- | ------------------------------------------------ | -------------------------------------------------------------- |
| default slot    | 通知本文、簡単な強調、非対話的な補助マークアップ | 主操作や補助操作をここへ配置すること                           |
| `slot="icon"`   | 1 要素の視覚アイコン                             | 複数要素、意味読み上げを前提とした要素                         |
| `slot="action"` | 1 個以上の対話要素                               | テキスト単独、非対話要素のみ、表示成立を内部判定へ依存すること |

default slot は本文領域です。対話要素を置くこと自体は DOM 構文上可能でも、主要または補助の操作導線を default slot に依存させることは公開契約に含めません。操作導線は `slot="action"` に配置します。

`slot="icon"` は視覚アイコン上書きのための slot です。ここには 1 要素の presentational なアイコンを配置します。複数要素を与えた場合のレイアウトと読み上げは契約しません。

`slot="action"` は補助操作のための slot です。`button`、`a[href]` 等の対話要素を想定します。テキストノード単独では action 領域を成立させません。

### 3.7 通知本文契約

default slot に与える本文は、通知の意味が**本文単独で完結**することを前提とします。`slot="action"` は補助導線であり、本文理解の前提にはしません。

したがって、次の状態は公開契約に反します。

- 色またはアイコンだけで意味を成立させること
- action を読まなければ通知の意味が確定しないこと
- dismiss 操作の存在自体を本文の代替情報として扱うこと

`role="alert"` として扱われる通知では、本文は短く、状態変化または必要な対処を先頭付近で示します。詳細説明を含める場合でも、先頭の 1 文で通知要旨が把握できる構成を推奨します。

本契約は文面生成ルールの一般化ではなく、`ui-banner` が通知コンポーネントとして成立するための最小条件を定めるものです。

## 4. 状態モデル

`variant` の解決値は、正規値であればそのまま使用し、不正値であれば `info` を採用します。解決結果は `data-resolved-variant` attribute に反映します。描画とスタイルは、入力値そのものではなく、この解決値に依存します。

### 4.1 `variant` と `role` の解決

`variant` の解決は、視覚トーン、フォールバックアイコン、および自動 `role` の共通基盤です。正規値であればそのまま採用し、契約外値であれば `info` を採用します。

`role` は、明示指定がない場合にのみ `variant` から自動導出します。対応関係は次表のとおりです。

| 解決バリアント | 自動 `role` |
| -------------- | ----------- |
| `info`         | `status`    |
| `success`      | `status`    |
| `warning`      | `alert`     |
| `error`        | `alert`     |

`role` を明示指定した場合、その値は `variant` 更新後も保持します。ただし、公開契約として許容する明示値は `status` と `alert` に限ります。自動マッピングへ戻す契約は、`role` attribute を除去した場合に限ります。

`role` に上記以外の値が与えられた場合の保持、矯正、例外発生は公開契約として規定しません。これは、`variant` が意味状態を全域的に成立させる入力であるのに対し、`role` が限定列挙の意味上書き入力であるためです。

### 4.2 `aria-atomic` の解決

`aria-atomic` は、未指定時のみ `true` を補完します。`aria-atomic="false"` のような明示指定は、`variant` 更新後も保持します。

### 4.3 action 領域の解決

action 領域は `slot="action"` の**割り当て要素**から導出します。1 個以上の割り当て要素が存在する場合に `.actions` を表示します。割り当て要素が存在しない場合、`.actions` は非表示です。

空白以外のテキストノードのみを用いて action 領域を成立させることは、公開契約に含めません。

### 4.4 dismiss 遷移

dismiss 後のフォーカス移動は**前進型**です。元の `activeElement` は復元しません。

本コンポーネントにおける dismiss は、単なる視覚的消去ではなく、通知提示の終了と、その後続文脈への遷移を一体で完了させる操作です。したがって、既定方針は「元の操作へ戻す」ことではなく、「通知の後続文脈へ進む」ことです。

dismiss 状態は内部遷移として扱います。dismiss 開始時には、次の順序でフォーカス移動先を解決します。

1. 同一文脈上の後続要素内にある最初のフォーカス可能要素
2. `main` 要素内にある最初のフォーカス可能要素
3. 解決不能な場合はフォーカス移動を省略し、DOM 除去のみを行います

`prefers-reduced-motion: reduce` 環境では、dismiss は即時完了します。通常環境では `data-dismissing` を付与し、退出アニメーション完了後に DOM から要素を除去します。

将来拡張として dismiss 後フォーカス先の制御を導入する場合は、任意 selector 文字列ではなく、列挙型の戦略指定を優先します。候補は `dismiss-focus-strategy="next|main|none"` のような小さな戦略集合です。

この方針により、次の点を維持します。

- 契約監査が容易です
- ページ固有 selector への依存を避けられます
- Storybook と実装の整合を保ちやすくなります
- 既定値を現行の前進型戦略へ自然に対応させられます

### 4.5 再入可能性と多重操作

dismiss 処理は再入不可です。dismiss 開始後に閉じる操作が再度実行されても、新しい遷移は開始しません。

この契約により、次の事項が保証されます。

- 退出アニメーションは多重開始しません
- フォーカス移動先は 1 回だけ解決します
- DOM 除去は 1 回だけ実行します
- fallback timer と animationend による二重完了は抑止されます

### 4.6 最小状態

最小状態は、本文のみを持つ `variant="info"` の非 dismissible バナーです。この場合、アイコンと本文のみが存在し、action 領域と閉じるボタンは存在しません。

## 5. DOM / Accessibility

ルートは `ui-banner` ホスト要素です。内部構造は、アイコン、本文、action 領域、閉じる操作の順に構成します。概念構造は次のとおりです。

```text
<ui-banner role="status|alert" aria-atomic="true" data-resolved-variant="...">
  <span class="icon" aria-hidden="true">
    <slot name="icon">[fallback icon]</slot>
  </span>
  <div class="message">
    <slot></slot>
  </div>
  <div class="actions" hidden>
    <slot name="action"></slot>
  </div>
  [ui-button aria-label="通知を閉じる"]
</ui-banner>
```

### 5.1 意味付け

アイコン領域は `aria-hidden="true"` とし、意味は本文と `role` により表現します。`warning` / `error` が `alert` として読み上げられるのは、自動 `role` が有効な場合です。`role` を明示指定した場合は、その指定を優先します。

`aria-atomic` の既定値は `true` です。これにより、通知の更新は断片ではなくまとまりとして扱います。呼び出し側が別の live region 戦略を採る場合は、`aria-atomic` を明示指定して上書きします。

本コンポーネントでは、通知の意味を色、アイコン、配置順だけで成立させません。通知本文は単独で意味が完結していなければなりません。したがって、視覚表現は本文の補助であり、本文の代替ではありません。

### 5.2 dismiss 操作

閉じる操作は `ui-button` により実装し、`aria-label` は固定値 `通知を閉じる` とします。dismiss は、通知を単に消去するのではなく、通知提示を終了し、その後続文脈へ利用者を進める完了操作です。

現契約では、dismiss ラベルはコンポーネント契約の一部として固定します。これは、日本語固定を推奨するという意味ではなく、現時点では局所的な文言外部化 API を導入せず、契約面を小さく保つためです。

将来拡張として文言外部化を導入する場合は、`dismiss-label` property / attribute により上書き可能とします。ただし、この拡張は次の条件を満たす場合に限って採用価値があります。

- プロジェクト全体で UI 文言の外部化方針を採ること
- 他コンポーネントでも `aria-label` の局所固定を避けること
- 日本語固定前提を解除すること

上記条件を満たさない限り、dismiss ラベルの固定は設計上の単純性を優先して維持します。

### 5.3 action 導線

`slot="action"` は補助導線です。ここに渡された素の `<a href>` は、クラス付与なしでも常時下線を持ち、`focus-visible` 時には可視リングを提示します。

action は本文理解の前提ではなく、通知を読んだ後に利用者が任意に進める補助操作です。

Rouault においては、補助導線を装飾ではなく操作要素として扱うこと、かつ本文を主情報として維持することを重視します。

## 6. Visual Contract

正規の情報順序は、アイコン、本文、action 領域、閉じる操作の順です。本文は中央の主領域として伸長し、action と閉じる操作は右側の固定領域として扱います。

### 6.1 レイアウト

ルート要素は `display: flex`、`align-items: center`、`width: 100%` とし、横方向のギャップには `var(--space-3)` を用います。パディングは `var(--space-3) var(--space-4)`、最小高さは `var(--control-min-touch)` とします。下端には意味境界として `border-bottom` を持たせます。

本文領域は `flex: 1` とし、`font-size: var(--text-sm)`、`font-weight: var(--font-medium)`、`line-height: var(--line-height-normal)` を基準とします。本文 slot 配下の直下要素はマージンを持ちません。

action 領域は `flex-shrink: 0` の横並び領域です。`slot="action"` に渡された `<a href>` は常時下線とし、hover 時には下線を強調します。これはリンク判別性を hover に依存させないための契約です。

### 6.2 本文長と折返し

本文領域は `min-width: 0` を持ち、利用可能幅に応じて折り返します。長文時も情報順序は維持されます。

本コンポーネントにおける主情報は本文です。したがって、狭い幅では**本文の読了可能性を補助操作より優先**します。

- 本文は横幅不足時に折り返します
- アイコンは固定サイズのまま保持します
- 閉じる操作は dismissible 時に常に到達可能でなければなりません
- action 領域は必要に応じて本文の後段へ回り込むことを許容します
- action の単一行固定や右端固定そのものは公開契約に含めません

したがって、公開契約として保証するのは次の 3 点です。

1. 本文が視覚的に隠されないこと
2. action が存在する場合に操作可能であること
3. 閉じる操作が dismissible 時に到達可能であること

非常に長い action ラベルや多数の操作を詰め込んだ場合のレイアウト最適化は契約しません。ただし、その場合でも本文可読性を先に損なわないことを優先します。

### 6.3 バリアント別トークン写像

各バリアントの視覚トーンは、解決バリアントに応じて次表のトークンへ写像します。

| 解決バリアント | 前景色         | 背景色                | 下端境界           |
| -------------- | -------------- | --------------------- | ------------------ |
| `info`         | `--fg-info`    | `--bg-tip-subtle`     | `--primary`        |
| `success`      | `--fg-success` | `--bg-success-subtle` | `--success`        |
| `warning`      | `--fg-warning` | `--bg-warning-subtle` | `--border-warning` |
| `error`        | `--fg-danger`  | `--bg-danger-subtle`  | `--border-danger`  |

### 6.4 dismissible 状態

dismiss 可能状態では、閉じる操作を右端に配置します。閉じる操作自体の見た目は `ui-button` 側契約に委譲しますが、本コンポーネントでは `variant="ghost"`、`size="sm"`、`icon-only` の組み合わせを前提とします。

### 6.5 モーション

出現時は `banner-enter`、退出時は `banner-exit` を用います。出現は `var(--duration-normal)` と `var(--ease-out)`、退出は `var(--duration-fast)` と `var(--ease-in)` に従います。退出時の高さは固定値ではなく `--ui-banner-exit-height` で与え、内容量に追従させます。

### 6.6 参照トークン

本コンポーネントは、モード別の直接分岐ではなく、**セマンティックトークン参照**で成立します。主な参照トークンは次表のとおりです。

| 用途             | トークン                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 前景色           | `--fg-info`, `--fg-success`, `--fg-warning`, `--fg-danger`                               |
| 背景色           | `--bg-tip-subtle`, `--bg-success-subtle`, `--bg-warning-subtle`, `--bg-danger-subtle`    |
| 境界色           | `--primary`, `--success`, `--border-warning`, `--border-danger`                          |
| 余白             | `--space-2`, `--space-3`, `--space-4`                                                    |
| 最小タッチ高さ   | `--control-min-touch`                                                                    |
| フォントサイズ   | `--text-sm`                                                                              |
| フォントウェイト | `--font-medium`                                                                          |
| 行高             | `--line-height-normal`                                                                   |
| アイコンサイズ   | `--icon-base`                                                                            |
| フォーカスリング | `--focus-ring-width`, `--focus-ring-color`, `--focus-ring-offset`, `--focus-ring-radius` |
| モーション       | `--duration-fast`, `--duration-normal`, `--ease-in`, `--ease-out`, `--animation-focus`   |

### 6.7 スタイリング拡張点

本コンポーネントは、外部向けの `::part` を公開しません。`ui-banner` 固有の公開 CSS custom property も定義しません。

したがって、外部が依存してよいスタイリング拡張点は次に限ります。

- 公開 property / attribute
- slot に渡す内容
- セマンティックデザイントークン
- 読み取り専用の `data-resolved-variant`

一方で、次の面は内部実装に属し、外部依存を許可しません。

- shadow DOM 内部クラス名
- `data-dismissing`
- 内部計算用 CSS 変数
- fallback icon の DOM 詳細
- dismiss 操作を支える内部セレクタ

## 7. 環境別の振る舞い

### 7.1 Reduced Motion

`prefers-reduced-motion: reduce` 環境では、出現アニメーションと退出アニメーションを無効化します。dismiss はアニメーション待ちを行わず、即時に完了します。

### 7.2 高コントラスト

高コントラスト環境では、境界線を `CanvasText` 基準で再解釈します。通常時のアイコンは `GrayText` を基調とし、`error` ではアイコンと本文を `Highlight` に寄せて強調します。action リンクは `LinkText` に委譲します。

`dismissible` が有効な場合、閉じる操作は高コントラスト環境でも視認可能でなければなりません。ここで保証するのは**閉じる操作の可視性**であり、内部 class 名や selector ではありません。

### 7.3 印刷

印刷環境では、背景色を除去し、前景色を通常文脈へ戻し、境界線を単色化します。icon、action 領域、および閉じる操作は表示しません。通知の意味は色ではなく本文により成立させます。

### 7.4 ダークモード

ダークモード対応はトークン差し替えにより成立させます。`prefers-color-scheme` によるコンポーネント内分岐には依存しません。

### 7.5 媒体別検証範囲

環境別契約の検証粒度は一様ではありません。

- reduced motion は dismiss 即時完了として振る舞いを検証します
- dark mode はトークン参照の有無そのものではなく、ダークモード時の UI outcome を検証します
- forced colors は UI outcome 契約として維持します
- print は UI outcome 契約として維持します

本コンポーネントでは、環境別契約を可能な限り**結果ベース**で検証します。内部セレクタ、media query 記述、または特定のトークン参照方法そのものは、公開契約の一次対象ではありません。

forced colors と print の契約は、内部セレクタの存在ではなく、最終的な見え方と非表示要素の結果で確認します。dark mode についても同様に、最終的な視覚整合を主確認点とします。

## 8. 関連契約

`ui-banner` は単独で完結する要素ですが、次の下位契約に依存します。

| 項目                   | 契約                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| フォールバックアイコン | `iconify-icon` を用い、`variant` ごとに `lucide:info` / `lucide:triangle-alert` / `lucide:circle-x` / `lucide:circle-check` を使い分けます |
| 閉じる操作             | `ui-button` を用います。`variant="ghost"`、`size="sm"`、`icon-only`、`aria-label="通知を閉じる"` を前提とします                            |
| action リンク          | `slot="action"` の素の `<a href>` は常時下線、hover 強調、`focus-visible` リングを持ちます                                                 |
| カスタムアイコン       | `slot="icon"` によりフォールバックを上書きします                                                                                           |

また、`slot="action"` に配置できるのはリンクに限りません。`button` 等の操作要素も配置可能です。ただし、本コンポーネントは action の意味や実行結果を解釈しません。

## 9. 境界条件

不正な `variant` 値は `info` として扱います。見た目、フォールバックアイコン、`role` の自動決定は、いずれも解決後の `info` に従います。

`role` を明示指定した場合、その値は `variant` 更新後も維持します。ただし、公開契約として許容する値は `status` と `alert` に限ります。その他の値を指定した場合の扱いは契約しません。

`aria-atomic` を明示指定した場合、その値は維持します。既定値補完は未指定時に限ります。

`slot="action"` に割り当て要素が存在しない場合、`.actions` は表示しません。テキストノード単独は action 領域成立条件に含めません。複数 action は許容します。

`dismissible="false"`、または未指定時には閉じるボタンを表示しません。`dismissible="true"` の場合のみ閉じる操作を提供します。

dismiss 実行後、要素は DOM から除去されます。非表示状態へ遷移して残留する契約ではありません。

フォーカス移動先が 1 つも解決できない場合、dismiss は失敗せず、DOM 除去のみを行います。

`slot="icon"` に複数要素が与えられた場合の見え方、`slot="action"` に過剰な数の操作が与えられた場合の折返し最適化、default slot に複雑な対話 UI を埋め込んだ場合の操作性は契約しません。

## 10. Storybook 契約

各 Story はデモではなく、**契約確認点**として扱います。将来変更時には、各 Story が固定する契約を維持します。

| Story                           | 固定する契約                                                                                  |
| ------------------------------- | --------------------------------------------------------------------------------------------- |
| `Default`                       | 基本の `warning` バナー、`alert` の自動付与、`aria-atomic="true"` の補完、action 領域の表示   |
| `VariantStateCombinations`      | `variant` ごとの `role`、フォールバックアイコン、action 有無、dismissible 有無の組み合わせ    |
| `RoleOverridePersistence`       | `role` の明示指定が自動マッピングより優先されること                                           |
| `SlotBoundaryConditions`        | `slot="icon"` の上書き、action 未指定時の非表示、複数 action の許容                           |
| `DismissFocusManagement`        | dismiss 後の DOM 除去、前進型フォーカス移動                                                   |
| `InvalidVariantFallback`        | 不正 `variant` が `info` へ収束し、意味・アイコン・見た目が `info` と整合すること             |
| `AtomicOverridePersistence`     | `aria-atomic` 明示指定の保持                                                                  |
| `ReducedMotionDismissImmediate` | reduced motion 環境での即時 dismiss                                                           |
| `DarkModeVisualOutcome`         | ダークモード対応が UI outcome として成立すること                                              |
| `ForcedColorsVisualOutcome`     | forced colors 環境で本文、action、dismiss の可視性が公開契約どおり維持されること             |
| `PrintVisualOutcome`            | print 環境で icon、action、dismiss が非表示になり、本文のみで通知意味が維持されること         |

### 10.1 Storybook から読める契約境界

Storybook 上で観測される host attribute のうち、`data-resolved-variant` は契約確認点として扱います。一方、`data-dismissing` は内部遷移観測に用いられることがあっても、外部依存を許可する公開面ではありません。

また、Storybook に存在すること自体は公開 API を意味しません。契約強度は、本書に公開と記載された面に限ります。

### 10.2 追加が必要な検証

設計のきれいさと保守性を優先する場合、次の検証を追加します。

- `role` に `status` / `alert` 以外を与えた場合を公開契約外として扱うこと
- `slot="action"` にテキスト単独を与えても action 領域成立条件に含めないこと
- forced colors 環境で dismiss 操作の可視性が維持されること
- print 環境で icon、action、dismiss が非表示になること
- 本文が action 非依存で意味完結している構成を Story 上で維持すること

これらは内部 selector の存在確認ではなく、**公開契約としての結果**を検証します。

将来拡張候補を採用する場合は、追加で次を検証します。

- `banner-dismiss-request` が cancelable であること
- `banner-dismissed` が dismiss 完了と一対一に対応すること
- `dismiss-focus-strategy` の既定値が現行の前進型戦略と整合すること
- `dismiss-focus-strategy="none"` がフォーカス移動を抑止すること
- `dismiss-label` 指定時に `aria-label` へ正しく反映されること

## 12. 現行実装を踏まえた未対応事項

本章は、現行実装を基準に、契約書で規定したが実装が未追随のもの、または本文で将来拡張として言及しているが未実装のものを記録します。本章は将来候補の一般論ではなく、現時点の差分整理です。

### 12.1 契約と実装が未一致の項目

| 項目                                        | 現行実装                                                                 | 現行契約                                             | 未対応内容                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `role` の許容範囲                           | `role` 属性が存在すれば明示指定として保持します                          | `status` / `alert` のみを公開契約値とします          | 不正 `role` の矯正、拒否、または契約外入力としての明示的処理が未実装です                     |
| `slot="action"` の成立条件                  | 割り当て要素に加え、空白以外のテキストノードでも `.actions` を表示します | 割り当て要素がある場合のみ action 領域を成立させます | テキスト単独を成立条件から除外する実装修正が未完了です                                       |

### 12.2 現時点で未実装の機能

| 機能                     | 現状       |

現行 `ui-banner` は、dismiss の内部完了処理と前進型フォーカス移動を自前で持ちますが、外側が介入・同期・上書きするための公開 API は持ちません。

### 12.3 現時点で未追加の検証

契約を実装へ収束させるためには、次の Storybook 検証が未追加です。

- `role="log"` など契約外の明示値を与えた場合の扱い

将来拡張候補を採用した場合の追加検証は、10.2 の規定に従います。

### 12.4 優先順位

保守性を優先する場合、対応順序は次のとおりです。

1. `slot="action"` の成立条件を契約どおり要素基準へ寄せます
2. dismiss 操作の forced colors / print 用内部 hook を整合させます
3. `role` の契約外入力に対する実装方針を固定します
4. その後に dismiss イベント、focus strategy、dismiss-label のような公開拡張 API を検討します

この順序により、**まず契約と実装の不一致を解消し、その後で機能拡張を行う**という、きれいな移行順序を維持できます。
