# Video

## 概要

本書は、`ui-video` の公開契約、状態モデル、操作契約、アクセシビリティ、視覚契約、および関連する設計判断を定義するものです。

`ui-video` は、本文文脈に埋め込まれる自己ホスト動画を、**本文から過度に遊離しない操作密度**で扱うコンポーネントです。単に `<video>` を包むのではなく、**状態機械**、**字幕トラックの扱い**、**独自コントロール**、**全画面時と通常時の操作差**、**読書文脈での視覚的ノイズ制御**を公開契約として固定します。

Rouault における video は、強い娯楽 UI ではなく、**読む体験の補助として埋め込まれるメディア**です。したがって、本コンポーネントの契約は、動画視聴に必要な操作性を確保しつつ、**「没入して読む」ことのできるデザイン**を維持する方向で定義します。

- 公開契約

## 設計原則

`ui-video` の契約は、次の設計原則に基づきます。

1. **本文補助性**: 動画は本文の代替ではなく、本文理解を補助するメディアとして扱います。
2. **低主張性**: 通常時は視覚的ノイズを抑え、必要時のみ操作面を前景化します。
3. **予測可能性**: 状態遷移、操作結果、エラー回復は一貫した規則で扱います。
4. **責務分離**: プレイヤー本体の責務と、上位レイヤまたは派生コンポーネントの責務を混同しません。
5. **アクセシビリティ優先**: キーボード操作、名前付け、状態通知、タッチターゲットを契約として明示します。

## 公開契約

`ui-video` は、`src`、`poster`、`autoplay`、`loop`、`muted`、`playsinline`、`aspectRatio`、`caption`、`title`、`ariaLabel`、`captionsPolicy`、`tracks` を公開入力として扱います。字幕トラックは `tracks` property を正規入力とし、`slot="tracks"` は互換・低レベルの escape hatch としてのみ受け取ります。

内部実装はネイティブ `<video>` を核としつつ、公開面としては `ui-video` を契約単位に扱います。利用者は Shadow DOM 内部のネイティブコントロールや内部 class 名に依存してはなりません（MUST NOT）。

`muted` の既定値は `true`、`playsinline` の既定値は `true` です。`autoplay=true` かつ `muted=false` が与えられた場合、`muted` は `true` に補正されます（MUST）。一方で、**手動再生時に追加の強制ミュートは行いません**。

また、`caption` は本文図版としての説明、`title` はプレイヤー識別および全画面時タイトル、`ariaLabel` はプレイヤー全体のアクセシブルネームに使います。`captionsPolicy` の既定値は `track-default` です。

### 入力契約

| 名前 | 種別 | 必須 | 内容 | 契約 |
| --- | --- | --- | --- | --- |
| `src` | property / attribute | いいえ | 動画 URL | 前後空白は除去して扱います。空文字列または空白のみは未設定とみなし、`EMPTY` 状態に遷移します |
| `poster` | property / attribute | いいえ | ポスター画像 URL | 前後空白は除去して扱います |
| `autoplay` | property / attribute | いいえ | 自動再生 | `true` の場合でも `muted=false` は許可せず、`muted=true` に補正します |
| `loop` | property / attribute | いいえ | ループ再生 | ネイティブ `<video>` の `loop` に反映します |
| `muted` | property / attribute | いいえ | ミュート状態 | 既定値は `true` です。手動再生時は現在値をそのまま尊重します |
| `playsinline` | property / attribute (`playsinline`) | いいえ | インライン再生 | 既定値は `true` です |
| `aspectRatio` | property / attribute | いいえ | 表示アスペクト比 | 有効な `aspect-ratio` 相当値を受け取ります。未指定時は `16 / 9` にフォールバックします |
| `caption` | property / attribute | いいえ | 図版キャプション | 前後空白は除去して扱います。空文字列はキャプションなしとして扱います |
| `title` | property / attribute | いいえ | プレイヤー題名 | 全画面時タイトルおよびプレイヤー識別に使います |
| `ariaLabel` | property / attribute | いいえ | アクセシブル名 | `title` がない場合のプレイヤー全体の名前として使います |
| `captionsPolicy` | property / attribute | いいえ | 字幕初期化戦略 | `off` / `track-default` / `on` を受け取ります。既定値は `track-default` です |
| `tracks` | property | いいえ | 字幕 / テキストトラック群 | `Track[]` を受け取る正規入力です。attribute 文字列経由の設定はサポートしません |
| `width` | property / attribute | いいえ | 互換入力 | `aspectRatio` が未指定の場合に限り、`height` と組で互換的に比率算出へ使います。新規利用では非推奨です |
| `height` | property / attribute | いいえ | 互換入力 | `aspectRatio` が未指定の場合に限り、`width` と組で互換的に比率算出へ使います。新規利用では非推奨です |

### `Track` 契約

`tracks` property は、次の構造を持つ `Track` を要素とする配列を受け取ります。

| 名前 | 型 | 必須 | 契約 |
| --- | --- | --- | --- |
| `src` | `string` | はい | 前後空白を除去し、空文字列は無効です |
| `srclang` | `string` | はい | 前後空白を除去し、空文字列は無効です |
| `label` | `string` | はい | 前後空白を除去し、空文字列は無効です |
| `kind` | `TrackKind` | はい | `subtitles` / `captions` / `descriptions` / `chapters` / `metadata` のみ受理します |
| `default` | `boolean` | いいえ | ネイティブ `<track default>` に反映します |

列挙外 `kind`、空の `src` / `srclang` / `label` を持つトラックは無効として破棄します。利用者は無効トラックが描画されることを期待してはなりません（MUST NOT）。

### スロット契約

| 名前 | 種別 | 位置づけ | 内容 |
| --- | --- | --- | --- |
| `tracks` | named slot | 互換・低レベル入力 | ネイティブ `<track>` 要素を light DOM から追加できます |

`tracks` property が正規入力です。`slot="tracks"` は、既存のネイティブ `<track>` 供給を併用したい場合の escape hatch に位置付けます。新規実装では `tracks` property の利用を優先します。

### 公開メソッド

`ui-video` は次の公開メソッドを持ちます。

| 名前 | 種別 | 契約 |
| --- | --- | --- |
| `playVideo()` | method | 再生を開始します。`ENDED` 状態では先頭に戻して再生します |
| `pauseVideo()` | method | 再生を停止します |
| `retry()` | method | エラー状態から再読み込みを試行します |

### 公開メソッドの失敗セマンティクス

| 名前 | 成功時 | 無効条件 | 失敗時の扱い |
| --- | --- | --- | --- |
| `playVideo()` | 再生開始を試み、成功すれば `PLAYING` へ遷移します。`ENDED` では先頭へ戻してから再生します | `EMPTY` または `ERROR` では no-op です | `video.play()` が拒否された場合でも例外を外部へ再送出せず、状態を `ERROR` に遷移させます |
| `pauseVideo()` | 一時停止し、通常は `PAUSED` へ遷移します | 再生対象がない場合は no-op です | 例外を公開 API として送出しません |
| `retry()` | `video.load()` を呼び、状態を `LOADING` に戻します | `src` が未設定の場合は no-op です | 失敗理由の詳細コードは公開しません |

利用者は、これらのメソッドが**状態遷移中心の API**であり、失敗理由を例外や戻り値で精密に取得する API ではないことを前提に扱います。

### 公開面の重要な補足

- `ui-video` はネイティブ `<video controls>` を公開しません。操作は独自 UI を通じて成立させます。
- `preload` は `metadata` に固定されます。
- 複数 `<source>` による source fallback は公開契約に含みません。
- 再生位置、再生速度、音量、状態列挙は内部 state として保持されますが、双方向バインディング用の公開 property 群としては公開しません。

## 状態モデル

`ui-video` は次の状態を持ちます。

| 状態 | 意味 |
| --- | --- |
| `EMPTY` | 有効な動画ソースが存在しません |
| `LOADING` | メタデータまたは再生準備を読み込み中です |
| `PAUSED` | 再生可能だが一時停止中です |
| `PLAYING` | 再生中です |
| `BUFFERING` | 再生継続のために待機中です |
| `ENDED` | 再生末尾まで到達しています |
| `ERROR` | 読み込みまたは再生開始に失敗しました |

### 1. 初期状態

`src` が空または空白のみの場合、初期状態は `EMPTY` です。`src` が有効な場合、初期状態は `LOADING` です。

### 2. メタデータ確定後

`loadedmetadata` 到達後、長さ、現在位置、バッファ終端、音量状態を同期します。`autoplay` により実際に再生が進行している場合は `PLAYING`、それ以外は `PAUSED` へ遷移します。

### 3. 再生・バッファリング・終了

- `playing` で `PLAYING` に遷移します。
- `waiting` は `PLAYING` 中にのみ `BUFFERING` に遷移します。
- `pause` は `ENDED` でない限り `PAUSED` に遷移します。
- `ended` で `ENDED` に遷移します。

### 4. エラー状態

`error` または `play()` 失敗時は `ERROR` に遷移します。`ERROR` では中央オーバーレイ操作面を除去し、再試行 UI を優先表示します。

### 5. `src` 変更時のリセット

`src` が変更された場合、次を初期化します。

- 現在時刻
- duration
- buffered end
- エラーメッセージ
- 初回再生済みフラグ
- フローティングバー表示状態
- スキップインジケータ状態
- 全画面・字幕・オーバーレイに関連する内部表示状態

そのうえで、有効ソースなら `LOADING`、無効ソースなら `EMPTY` に遷移します。

### 6. 音声ポリシー

音声ポリシーは、**autoplay と手動再生を分離して扱います**。

- `autoplay=true` の場合は、ブラウザ制約に合わせて `muted=true` を必須とします
- 手動再生時は、現在の `muted` と `volume` をそのまま尊重し、追加の強制ミュートは行いません
- `muted=true` と `volume=0` は同値ではなく、別状態として扱います

したがって、利用者は手動再生時にコンポーネント独自の追加ミュート補正が入ることを期待してはなりません（MUST NOT）。

## 操作契約

`ui-video` は、中央オーバーレイ、下部フローティングバー、キーボード、ポインター操作を組み合わせて再生制御を提供します。

### 再生 / 一時停止

- 中央オーバーレイの再生ボタンは再生と一時停止をトグルします
- フローティングバーの再生ボタンも再生と一時停止をトグルします
- `ENDED` 状態で再生した場合は先頭へ戻してから再生します

### シーク

- フローティングバーのシークバーで任意位置へ移動できます
- 10 秒戻る / 10 秒進む操作を提供します
- `ArrowLeft` / `ArrowRight` は 5 秒単位で移動します
- `j` / `l` は 10 秒単位で移動します

### 音量

- 音量スライダーは 0〜1 を 0.05 刻みで扱います
- `ArrowUp` / `ArrowDown` は 0.1 単位で増減します
- `m` でミュートを切り替えます
- ミュート解除時は、直前の非 0 音量を復元します

### 数値操作の規則

- シーク値は常に `0` 以上 `duration` 以下へクランプします
- 音量値は常に `0` 以上 `1` 以下へクランプします
- `duration` が未確定、非有限、または 0 以下の間は seek を無効化します
- `NaN`、`Infinity`、負数などの不正値は有効操作として扱いません
- `muted=true` と `volume=0` は別状態であり、相互に自動同一化しません

### 字幕

- `captions` / `subtitles` 系トラックが存在する場合にのみ字幕トグルを表示します
- 字幕初期状態は `captionsPolicy` に従います
- `captionsPolicy="off"` は常に初期非表示です
- `captionsPolicy="track-default"` は `track.default` を尊重します
- `captionsPolicy="on"` は最初の利用可能な `captions` / `subtitles` を表示対象にします
- `c` キーで字幕表示を切り替えます

### 全画面

- 全画面ボタンで全画面表示を切り替えます
- `f` キーで全画面表示を切り替えます
- **精密ポインターかつ hover 可能な環境**ではダブルクリックで全画面表示を切り替えます
- 全画面は明示的な表示状態であり、切り替え時には公開イベントで通知します

### 長押し・ダブルタップ

- 再生中に長押しすると一時的に 2 倍速再生になります
- 長押し解除で再生速度は 1 倍に戻ります
- **粗ポインターかつ hover 不能な環境**では、左半分 / 右半分のダブルタップで 10 秒戻る / 10 秒進むを行います
- viewport 幅は入力能力の代理変数として使いません

### オーバーレイとフローティングバー

- 中央オーバーレイは再生開始後約 1 秒で自動非表示になります
- フローティングバーは初回再生前は非表示です
- 再生中のフローティングバーは、表示後約 3 秒で自動非表示になります
- 外部クリック、ポインター離脱、再生継続などに応じて表示を畳みます

### キーボードショートカット

プレイヤーは次のキーボードショートカットを定義します。

| キー | 契約 |
| --- | --- |
| `Space` / `Enter` / `k` | 再生 / 一時停止トグル |
| `j` | 10 秒戻る |
| `l` | 10 秒進む |
| `ArrowLeft` | 5 秒戻る |
| `ArrowRight` | 5 秒進む |
| `ArrowUp` | 音量を 0.1 増やす |
| `ArrowDown` | 音量を 0.1 下げる |
| `m` | ミュート切り替え |
| `f` | 全画面切り替え |
| `c` | 字幕切り替え |

### フォーカス主体とキーボード到達性

`ui-video` ホストを**プレイヤー全体の対話主体**とします。ホストは Tab 到達可能であり、focus は内部の主要対話面へ委譲されます。キーボードショートカットは、**ホスト、主要対話面、または内部コントロールにフォーカスがある場合に保証**します。

したがって、利用者は document 全体に対するグローバルショートカットとして扱ってはなりません（MUST NOT）。また、個別コントロールへ直接フォーカスがある場合でも、プレイヤー全体ショートカットは競合解決規則に従って解釈されます。

### 状態別コントロール可用性

各状態における主要コントロールの可用性は次のとおりです。

| 状態 | 中央再生ボタン | フローティングバー | シーク | 音量 | 字幕 | 全画面 | retry |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `EMPTY` | disabled | 非表示 | 不可 | 不可 | 不可 | 不可 | 不可 |
| `LOADING` | 原則不可 | 非表示または待機扱い | 不可 | 不可 | 原則不可 | 不可 | 不可 |
| `PAUSED` | 可 | 条件付き表示 | 可 | 可 | トラックがあれば可 | 可 | 不可 |
| `PLAYING` | 可 | 条件付き表示 | 可 | 可 | トラックがあれば可 | 可 | 不可 |
| `BUFFERING` | 可 | 条件付き表示 | 原則可 | 可 | トラックがあれば可 | 可 | 不可 |
| `ENDED` | 可（再始動） | 条件付き表示 | 可 | 可 | トラックがあれば可 | 可 | 不可 |
| `ERROR` | 非表示 | 非表示 | 不可 | 不可 | 不可 | 不可 | 可 |

ここで「条件付き表示」とは、初回再生済みフラグ、再生中かどうか、オートハイド、ポインター操作、全画面状態などに依存して表示 / 非表示が切り替わることを意味します。

### ジェスチャ競合と優先順位

ポインター操作とコントロール操作が競合する場合、次の優先順位を契約とします。

1. **ボタン、スライダー、`ui-button`、フローティングバー内部の直接操作を最優先**します。
2. それらの操作は、シェル全体に対する再生トグルや表示トグルへ再解釈しません。
3. 長押し判定が成立した直後の click は、長押し解除に伴う副作用として扱い、再生トグルへ再解釈しません。
4. 外側クリックは、必要に応じてフローティングバーを閉じるために使います。
5. 初回再生前は、再生中専用ジェスチャであるダブルタップスキップや長押し 2x を保証しません。

### 時定数・閾値

本コンポーネントは、次の内部定数に依存します。これらは**固定値として扱い、公開入力では変更できません**。

| 項目 | 値 | 契約 |
| --- | --- | --- |
| 長押し判定 | 500 ms | 再生中のみ 2 倍速ジェスチャ判定に使います |
| ダブルタップ判定 | 300 ms | 粗ポインター環境で左右 10 秒スキップ判定に使います |
| 中央オーバーレイ自動非表示 | 1000 ms | 再生開始後の中央再生ボタン退避に使います |
| フローティングバー自動非表示 | 3000 ms | 再生中のコントロール退避に使います |
| スキップ量 | 10 s | ダブルタップ、`j` / `l`、スキップボタンに使います |
| 矢印シーク量 | 5 s | `ArrowLeft` / `ArrowRight` に使います |

利用者は、これらの値が外部設定で変更可能であることを期待してはなりません（MUST NOT）。

## DOM / Accessibility

ルートは `figure.root` です。動画本体、状態レイヤ、中央オーバーレイ、フローティングバー、キャプション、スクリーンリーダー用状態通知がこの配下に配置されます。

```text
<ui-video>
  #shadow-root
    <figure class="root">
      <div class="player-shell">
        <video class="video-element">
          [track*]
          <slot name="tracks"></slot>
        </video>
        [state-layer]
        [speed-badge]
        [skip-indicator]
        [fullscreen-caption]
        [overlay-center]
        [floating-bar]
      </div>
      [figcaption]
      <p class="sr-only">状態通知</p>
    </figure>
</ui-video>
```

### Accessibility 契約

- `ui-video` ホストはプレイヤー全体の対話主体として Tab 到達可能です
- ルートは `figure` とし、主要対話面は必要に応じて `group` として扱います
- `application` role は採用しません
- `figure.root` は `aria-busy` と `aria-disabled` を状態に応じて持ちます
- `title` が存在する場合、プレイヤー全体は `aria-labelledby` により名前付けします
- `title` がなく `ariaLabel` が存在する場合、プレイヤー全体は `aria-label` により名前付けします
- `caption` が存在する場合、`player-shell` と内部 `video` の `aria-describedby` は `figcaption` を参照します
- 状態通知は `sr-only` の live region で公開します
- `ERROR` 時は再試行ボタンへフォーカスを移します
- シークバーと音量バーはそれぞれ `aria-label`、`aria-valuenow`、`aria-valuetext` を持ちます
- 再生ボタン、ミュート、字幕、全画面などの操作要素は明示的な `aria-label` を持ちます

### 個別コントロールのアクセシビリティ契約

| コントロール | アクセシブル名 / 状態 | 契約 |
| --- | --- | --- |
| 中央再生ボタン / 再生ボタン | `aria-label` を持ちます | 再生中か否かに応じて意味が切り替わります。`EMPTY` では disabled です |
| シークバー | `aria-label="再生位置"` | `aria-valuenow` と `aria-valuetext` により、現在位置を時刻表現で伝えます |
| 音量スライダー | `aria-label="音量"` | `aria-valuenow` と `aria-valuetext` により、現在音量を伝えます |
| ミュートボタン | `aria-label` を持ちます | ミュート状態の切り替え対象であり、視覚アイコンだけに依存しません |
| 字幕ボタン | `aria-label` を持ちます | `captions` / `subtitles` が存在するときのみ描画対象です |
| 全画面ボタン | `aria-label` を持ちます | 全画面切り替えの意味が名称で伝わります |
| retry ボタン | `aria-label` または可読ラベルを持ちます | `ERROR` でのみ主要操作面として現れ、フォーカス遷移先になります |

### live region 契約

状態通知文言は次の意味を持ちます。

- `EMPTY`: 動画ソース未設定
- `LOADING`: 読み込み中
- `BUFFERING`: バッファリング中
- `PAUSED`: 一時停止中
- `PLAYING`: 再生中
- `ENDED`: 再生終了
- `ERROR`: 再生不可または開始失敗

重大通知のみを `alert` とし、それ以外は `status` として扱う方針です。現行実装では `ERROR` が成立する場面は、実質的に再試行可能ソース付きケースが中心です。

### 字幕アクセシビリティ契約

字幕トグルは `captions` / `subtitles` トラックが存在する場合のみ描画します。`descriptions`、`chapters`、`metadata` 単独では字幕トグルの表示条件を満たしません。

## Visual Contract

`ui-video` の視覚契約は、**本文に埋め込まれた動画が過度にプレイヤー然としないこと**にあります。通常時は動画面をやや沈め、操作が必要なときだけ前景 UI を立ち上げます。

### レイアウト

- ルートは `display: block` です
- `aspectRatio` が指定されている場合は、それを主契約として `aspect-ratio` を決定します
- `aspectRatio` が未指定で `width` / `height` が正規値なら、互換入力として `aspect-ratio: width / height` を用います
- いずれも正規化できない場合は `aspect-ratio: 16 / 9` を用います
- `.prose` 文脈では左右に張り出して幅を広げます

### 動画面

- 動画は `object-fit: cover` です
- 通常時は明度を抑え、再生中・hover・focus-within 時に本来の明るさへ戻します
- したがって、動画全面表示よりも**本文に沿った図版感**を優先します

### コントロール

- 中央再生ボタンは円形の浮遊操作面です
- フローティングバーは下部の半透明サーフェスです
- スキップボタンは全画面かつ粗ポインター環境でのみ視覚的に有効です
- 長押し 2x バッジ、スキップインジケータ、全画面タイトルは一時表示要素として扱います

### タッチターゲット

動画面上の操作要素は、**視覚寸法と実効ヒット領域を同一視しません**。本文埋め込みメディアとしての低主張性を保ちつつ、**実効ヒット領域は原則として最小 40 × 40 CSS px** を確保します。

常設フローティングバー内の主要操作は 40 × 40 CSS px 以上、中央再生ボタンはそれ以上の十分な押下領域を持つことを契約とします。

### キャプション

- 通常時の本文キャプションは `figcaption` で表現します
- 全画面時の左上タイトルは `title` を優先して表示します
- `title` が空で `caption` が存在する場合に限り、互換的に `caption` を全画面タイトルとして再掲できます
- `caption` が空文字列なら、通常時の `figcaption` は描画しません

### 参照トークン

本コンポーネントは、主として次のトークンに依存します。

| 用途 | トークン |
| --- | --- |
| 境界線 | `--border-width` / `--border-ghost` / `--border-default` |
| 背景 | `--bg-fill-neutral` / `--bg-surface-2` / `--bg-surface-3` |
| 前景色 | `--fg-default` / `--fg-muted` / `--fg-on-primary` |
| 主色 | `--primary` |
| 角丸 | `--radius-md` / `--radius-lg` / `--radius-full` |
| スペーシング | `--space-*` |
| アイコン寸法 | `--icon-md` / `--icon-xl` |
| 影 | `--elevation-md` |
| モーション | `--duration-fast` / `--duration-normal` / `--ease-out` |
| フォーカス | `--focus-ring-width` / `--focus-ring-color` / `--focus-ring-offset` / `--animation-focus` |
| 補助 | `--blur-sm` / `--scale-hover-lg` / `--scale-pressed` |

## 環境別の振る舞い

### Prose 文脈

`:host-context(.prose)` では、本文幅より少し広く見せるために左右マージンを負に振り、動画面の没入感を高めます。

### Reduced Motion

`prefers-reduced-motion: reduce` では、各種 transition 時間を極小化し、ローディングスピナーのアニメーションを停止します。

### Forced Colors

`forced-colors: active` では、ボタン、バッジ、入力スライダーをシステム色へフォールバックし、box-shadow に依存しません。

### Print

`@media print` では `.player-shell` を非表示にします。したがって、**印刷時はプレイヤー本体を出力せず、`figcaption` があれば残り得る**契約です。インタラクティブ UI 全体を印刷対象にすることは意図しません。

## 関連契約

### 字幕供給契約

字幕供給面は二系統あります。

1. `tracks` property による構造化入力
2. `slot="tracks"` によるネイティブ `<track>` の直接供給

`slot="tracks"` に投入するノードは、**正規入力としてはネイティブ `<track>` のみ**を想定します。その他のノードが与えられた場合の描画や意味付けは保証しません。

両者は併用可能ですが、**重複除去、優先順位の自動解決、意味的統合は行いません**。利用者は同一トラックの重複投入、あるいは property 側と slot 側の競合解決に依存してはなりません（MUST NOT）。

また、字幕トグルの操作対象は `captions` / `subtitles` に限ります。`descriptions`、`chapters`、`metadata` はトグル対象に含めません。

### エラー回復契約

`retry()` は内部 `video.load()` を呼び、状態を `LOADING` に戻します。エラーは少なくとも次の原因語彙へ正規化して扱います。

- `SOURCE_MISSING`
- `LOAD_FAILED`
- `PLAY_BLOCKED`
- `DECODE_FAILED`
- `FULLSCREEN_DENIED`

UI 文言は統合して構いませんが、原因語彙は内部および公開イベントの detail で識別可能であることを契約とします。

### イベント契約

`ui-video` は、ネイティブ media event をそのまま再送出するのではなく、次の公開カスタムイベントのみを安定契約とします。

| イベント名 | detail | 契約 |
| --- | --- | --- |
| `ui-video-state-change` | `{ state }` | 再生状態機械の遷移を通知します |
| `ui-video-error` | `{ code, message? }` | 正規化済みエラー原因を通知します |
| `ui-video-captions-change` | `{ active }` | 字幕表示の有効 / 無効を通知します |
| `ui-video-fullscreen-change` | `{ fullscreen }` | 全画面状態の変化を通知します |

外部利用者は、`play`、`pause`、`timeupdate`、`ended` などのネイティブ動画イベントを `ui-video` の安定 API とみなしてはなりません（MUST NOT）。

### スタイル拡張契約

外部スタイル拡張は、**設計トークンと公開 `part` のみ**を正規面とします。内部 class 名や Shadow DOM 構造には依存してはなりません（MUST NOT）。

公開 `part` は少なくとも次を持つものとします。

- `media`
- `overlay-center`
- `floating-bar`
- `caption`

### フォーム契約

`ui-video` はフォーム関連コンポーネントではありません。フォーム送信、入力バリデーション、値シリアライズなどの責務は持ちません。

## 境界条件

### 1. `src` 未設定

`src` が空または空白のみの場合、状態は `EMPTY` です。再生操作は無効化されます。

### 2. `autoplay=true` かつ `muted=false`

この入力はそのまま保持せず、`muted=true` に補正します。

### 3. `width` / `height` 不正

0、負数、非有限数などは無効です。正規化できない場合、アスペクト比は `16 / 9` にフォールバックします。

### 4. 空白のみの `caption`

空白のみの `caption` は空文字列として扱い、`figcaption` を描画しません。

### 5. 無効な `tracks`

空の `src` / `srclang` / `label`、または列挙外 `kind` を持つトラックは描画しません。

### 6. `ERROR` 状態

`ERROR` では中央オーバーレイを除去し、再試行パネルを表示します。再試行ボタンはフォーカス対象になります。

### 7. 初回再生前

初回再生前はフローティングバーを前面 UI として常時表示しません。`j` / `l` 系スキップは再生開始前には成立しません。

### 8. `track.default=true`

`captionsPolicy="track-default"` の場合、ネイティブ `<track default>` を尊重して初期字幕表示を決定します。`captionsPolicy="off"` と `captionsPolicy="on"` は、それぞれ戦略入力を優先します。

### 9. 全画面 API 不成立

全画面 API の失敗は `FULLSCREEN_DENIED` として扱い、公開イベントの detail で識別可能にします。UI 文言として常に前景通知することまでは必須ではありませんが、少なくとも原因語彙の観測可能性は維持します。

## 新規で追加を検討する価値がある機能

本節は、現行契約に含まれていないものの、**Rouault における video を「読む体験を補助するメディア」として強める観点から、追加を検討する価値が高い機能**を整理するものです。

ここで重要なのは、娯楽プレイヤーとしての機能追加ではなく、**本文との往復、参照、再訪、理解補助**に資するかどうかです。したがって、本節に挙げる候補は、派手さや一般的な動画プレイヤー機能の網羅性ではなく、Rouault の設計思想との整合で評価します。

### 1. 再生速度選択

現行契約には長押し中の一時的な 2 倍速再生がありますが、**持続的な再生速度選択**はありません。本文補助メディアとしての動画では、娯楽用途よりも、理解速度や確認速度を最適化できることの方が価値を持ちます。

そのため、`0.75 / 1.0 / 1.25 / 1.5 / 2.0` のような限定的な再生速度選択は、追加を検討する価値があります。

長期的には、次の方針がよいです。

- まずは内部 state として持つ
- 必要になった時点で `defaultPlaybackRate` と公開イベントへ昇格する
- 長押し 2x は一時ブースト、再生速度選択は持続設定として役割を分離する

要点は、**長押し 2x と恒常速度設定を別機能として扱うこと**です。

### 2. 時間リンク / 現在時刻共有

本文中の動画を参照可能な対象として強くするなら、**特定時刻への深いリンク**は高い価値があります。これは派手な UI ではありませんが、ノート、引用、再参照、議論の基点として非常に有効です。

たとえば次のような機能が考えられます。

- 初期時刻を与える `startTime` または `initialTime`
- 現在時刻を URL 断片または共有形式へ変換する操作
- 現在時刻変化を上位レイヤへ通知する公開イベント

これは動画を「ただ再生するオブジェクト」から、**本文中で参照・再訪可能なオブジェクト**へ変える拡張です。

### 3. チャプターマーカー

現行契約では `chapters` track を受け入れますが、UI としては活用していません。しかし、本文補助メディアにおいては、動画全体の連続視聴よりも、**特定区間へ戻ること**の方が重要な場面が多くあります。

そのため、シークバー上の章マーカーや現在章ラベルは追加価値があります。

ただし、追加するなら次の順で段階導入するのがよいです。

1. シークバー上の章マーカー
2. 現在章ラベル
3. 必要なら章ジャンプリスト

重要なのは、**いきなり重い章一覧 UI を導入せず、まずは再訪導線としての軽量表現から始めること**です。

### 4. 時間同期トランスクリプト連携

Rouault の方向性に最もよく適合する拡張候補のひとつが、**時間同期トランスクリプト**です。字幕は視聴補助ですが、トランスクリプトは検索、引用、熟読、要点確認のためのテキスト資産になり得ます。

ただし、これは `ui-video` 単体へ大きな UI を抱え込ませるべきではありません。

長期的には、次の責務分離が妥当です。

- `ui-video`: 現在時刻、シーク、字幕、同期フックを提供する
- 別コンポーネントまたは上位 composition: トランスクリプト表示、検索、ハイライト、クリックジャンプを担う

つまり、**本体に入れるべきなのはトランスクリプト UI そのものではなく、時間同期のための接続面**です。

### 5. ポスター時の要約メタ情報

再生前に、動画の内容を低密度に理解できることは、本文文脈において有益です。したがって、ポスター上またはポスター近傍に、次のような**軽量メタ情報**を出せると価値があります。

- 再生時間
- 字幕の有無
- 章の有無
- 題名

これは視聴前判断を助けますが、常時前景化すると読書面のノイズになるため、**ポスター時限定、または hover / focus 時のみ**とするのが望ましいです。

### 6. 再生終了後の補助オーバーレイ

資料や説明用動画では、再生終了後にそのまま終わるより、**再視聴、冒頭へ戻る、該当箇所を見直す**ための補助動作がある方が有用です。

そのため、終了時に次のような最小限の補助オーバーレイを追加する価値があります。

- 再視聴
- 冒頭へ戻る
- 必要なら最後に視聴した章へ戻る

これは大きな機能ではありませんが、**学習・参照用途に対して実用価値が高い**拡張です。

### 7. 条件付きで検討する価値がある機能

次の機能は価値はあるものの、優先度は一段下がります。

#### 7.1 静的プレビューサムネイル

シーク時のサムネイルプレビューは利便性がありますが、生成コストとデータ管理が増えます。本文補助メディアとしては、**チャプターマーカーや時間リンクの方が先**です。

#### 7.2 設定の記憶

字幕オン / オフ、再生速度、音量などの設定保持には価値があります。ただし、永続化責務は `ui-video` 単体よりも上位レイヤで担う方が設計としてきれいです。

#### 7.3 Picture-in-Picture

一般論では有用ですが、本文への没入という観点とはやや逆方向です。導入するとしても後順位であり、本コンポーネントの核機能とはみなしません。

### 8. 本コンポーネントに入れない方がよい機能

次の機能は、一般的な動画プレイヤーでは価値があっても、`ui-video` を本文補助コンポーネントから逸脱させやすいため、原則として本コンポーネントへ入れない方がよいです。

- プレイリスト
- レコメンド
- コメント / リアクション
- 重い分析イベント送信
- AirPlay / Cast などの外部再生
- 複数ソース自動切替

これらは `ui-video` をメディアアプリ化しやすく、Rouault における役割境界を曖昧にします。

### 9. 優先順位

新規追加を検討する場合の優先順位は次のとおりです。

1. 再生速度選択
2. 時間リンク / 現在時刻共有
3. チャプターマーカー
4. 時間同期トランスクリプト連携
5. 再生終了後の補助オーバーレイ
6. ポスター時の要約メタ情報

この順序は、**実装コストに対する利用価値が高く、かつ既存契約を壊しにくいものから順に並べたもの**です。

### 10. 本節の扱い

本節に記載した機能は、現時点では公開契約ではありません。これらを採用する場合は、単なる機能追加としてではなく、**本文補助メディアとしての責務に合うか、`ui-video` 本体へ入れるべきか、それとも上位レイヤへ分離すべきか**を確認したうえで契約へ昇格します。

## 設計として固定した事項

長期的な保守性と設計の一貫性を優先し、本書では次を**曖昧論点から公開契約へ昇格**しました。

1. `ui-video` ホストをプレイヤー全体の対話主体とすること
2. 動的状態は非制御モデルを原則とし、公開イベントで外部連携すること
3. ネイティブ media event を再送せず、意味論に沿った公開イベントのみを安定契約とすること
4. 表示比率は `aspectRatio` を主契約とし、`width` / `height` は互換入力へ縮退させること
5. `caption`、`title`、`ariaLabel` を責務分離すること
6. `tracks` property を正規入力、`slot="tracks"` を escape hatch とすること
7. 字幕初期状態は `captionsPolicy` で制御すること
8. 強制ミュートは autoplay に限定し、手動再生では現在の音声状態を尊重すること
9. ジェスチャ分岐は viewport 幅ではなく入力能力で行うこと
10. 数値操作、エラー語彙、全画面状態、アクセシビリティ命名、role、スタイル拡張面、タッチターゲットを定量・定義可能な契約へ寄せること

これらは「将来検討」ではなく、本書における**採用済み設計判断**として扱います。

---

## 補足

`ui-video` の要点は、多機能プレイヤーであることではありません。**本文文脈に載る動画として、読む体験を壊さずに必要十分な再生操作を成立させること**にあります。

したがって、今後の変更でも次の点は崩さない方がよいです。

1. `EMPTY` / `LOADING` / `PAUSED` / `PLAYING` / `BUFFERING` / `ENDED` / `ERROR` の状態機械を維持すること。
2. `caption` と `aria-describedby` の連動を維持すること。
3. `tracks` property と `slot="tracks"` の双方を受け入れること。
4. 初回再生前と再生中で UI 密度を切り替え、常時コントロール前景化を避けること。
5. 読書面で過剰な輝度・装飾・アニメーションに依存しないこと。

## 現行実装で未対応の事項

本節は、現行の `video.ts` および `video.stories.ts` を基準として、**本書で固定した契約のうち、まだ実装や Storybook が追随していない事項**を整理するものです。

### 1. ホストを対話主体とするフォーカス導線

本契約では `ui-video` ホストを Tab 到達可能な対話主体と定めましたが、現行実装は `.player-shell` 前提のキーボード解釈に留まっています。focus 委譲、ホスト到達性、関連テストは未整備です。

### 2. `aspectRatio` / `title` / `ariaLabel` / `captionsPolicy` の公開入力

本契約ではこれらを公開入力へ昇格しましたが、現行実装の主要入力面は `width` / `height`、`caption`、内部字幕 state に依存しています。新入力の導入、互換戦略、`title` を全画面タイトルへ優先適用する処理、`ariaLabel` をプレイヤー全体のアクセシブルネームへ接続する処理は未対応です。

### 3. 手動再生時の非強制ミュート方針への移行

本契約では強制ミュートを autoplay に限定しましたが、現行実装は初回 `playVideo()` 時に追加ミュートを適用します。この差分は未解消です。

### 4. `captionsPolicy` に基づく字幕初期化

本契約は `off` / `track-default` / `on` を許容しますが、現行実装は `_captionsActive=false` を既定としており、`track.default` 尊重や明示戦略入力は未対応です。

### 5. 公開カスタムイベント

`ui-video-state-change`、`ui-video-error`、`ui-video-captions-change`、`ui-video-fullscreen-change` は契約へ昇格しましたが、現行実装はこれらを安定イベントとして公開していません。

### 6. エラーコード体系

本契約では `SOURCE_MISSING`、`LOAD_FAILED`、`PLAY_BLOCKED`、`DECODE_FAILED`、`FULLSCREEN_DENIED` を定義しましたが、現行実装は文字列メッセージ中心で、原因語彙の体系化は未対応です。

### 7. 入力能力ベースのジェスチャ分岐

本契約は `pointer` / `hover` 能力で分岐しますが、現行実装と Story は viewport 幅による近似に依存しています。能力ベース判定への移行、既存 `matchMedia('(min-width: 768px)')` 依存の解消、関連 Story の書き換えは未対応です。

### 8. `muted` と `volume=0` の分離ポリシー

本契約では `muted=true` と `volume=0` を別状態として扱いますが、現行実装は音量スライダーを 0 にすると `video.muted = true` を自動適用します。したがって、音量 0 とミュートの自動同一化をやめる移行は未対応です。

### 9. 公開 `part` の提供

本契約は `media`、`overlay-center`、`floating-bar`、`caption` を公開 `part` としましたが、現行実装はこれを公開面としてまだ固定していません。

### 10. Storybook の二層化

本契約は公開契約 Story と実装回帰 Story の分離を前提にしますが、現行 Storybook は両者が混在しています。再編は未対応です。

### 11. プレイヤー全体の role / naming の実装

本契約では、ホストを対話主体とし、`title` または `ariaLabel` によるプレイヤー全体の名前付け、必要に応じた `group` の採用を定めました。しかし現行実装は `aria-describedby` 中心であり、プレイヤー全体の naming と role 戦略は未実装です。

### 12. 本節の扱い

本節に記載した事項は、契約としては**すでに採用済み**ですが、実装と Storybook はまだ追随していません。これらを完了させるときは、**実装、Storybook、契約書の 3 点を同時に更新**します。
