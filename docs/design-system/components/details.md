# Details

## 概要

本書は、`ui-details` の公開契約、状態モデル、アクセシビリティ、および視覚契約を整理するものです。

`ui-details` は、本文の流れを断ち切らずに補足情報を段階的に開示するためのコンポーネントです。単に開閉できる箱を描画するのではなく、**何が開閉トリガーであるか**、**閉状態の内容をどのように操作対象から隔離するか**、**開閉状態をどのイベントと ARIA 属性で公開するか**を公開契約として固定します。

また、本コンポーネントは native `<details>` を直接利用しません。これは、閉じるアニメーション、閉状態のフォーカス隔離、内部レイアウト制御を一貫して扱うためです。その代わりに、**ネイティブ **`**、**`**、**`**、**` を組み合わせて disclosure を構成します。

Rouault における details は、補足、注記、FAQ、設計上の但し書きなどを必要な時だけ展開するための要素です。したがって、本コンポーネントの契約は、開閉可能性の明示と、**「没入して読む」ことのできるデザイン**の維持を両立する方向で定義します。

## 本書の読み方

本書は、まず **公開契約** と **状態モデル** で外部から依存してよい面を固定し、その後に **DOM / アクセシビリティ**、**視覚契約**、**環境別の振る舞い** を続けます。後半では、現時点でなお判断が残る論点、今後優先して契約化する事項、現行実装で未対応の事項を分けて整理します。

そのため、利用者がまず確認すべきなのは公開契約と境界条件です。将来の設計方針まで含めて確認したい場合は、後半の各節を参照します。

## 公開契約

`ui-details` は、`ariaLabel`、`summary`、`open`、`variant`、`region` を公開入力として扱います。スロットは `summary` スロットと既定スロットを持ちます。内部実装はネイティブ `button` を起点に構成されますが、利用者は `ui-details` を disclosure 契約単位として扱います。

`ariaLabel` は必須です。未指定または空文字は許可しません（MUST）。これは実装上も例外送出により強制します。可視サマリーが存在していても、この必須制約は緩みません。

`summary` は、`summary` スロット未指定時のフォールバック文字列です。`summary` スロットがある場合は、`summary` property より必ず優先されます。

`open` の既定値は `false` です。`variant` の既定値は `default` です。`region` の既定値は `false` です。

### 入力契約

| 名前        | 種別                                | 必須   | 内容                         | 契約                                                                          |
| ----------- | ----------------------------------- | ------ | ---------------------------- | ----------------------------------------------------------------------------- |
| `ariaLabel` | property / attribute (`aria-label`) | はい   | トリガーのアクセシブルネーム | 空文字および未指定は許可しません                                              |
| `summary`   | property / attribute                | いいえ | サマリーテキスト             | `summary` スロット未指定時のみ使用します                                      |
| `open`      | property / attribute                | いいえ | 開閉状態                     | `true` で展開、`false` で折りたたみます                                       |
| `variant`   | property / attribute                | いいえ | 外枠バリアント               | `default` / `bordered`                                                        |
| `region`    | property / attribute                | いいえ | ランドマーク化               | `true` の場合、コンテンツに `role="region"` と `aria-labelledby` を付与します |

### スロット契約

| 名前         | 種別       | 位置づけ   | 内容                                   |
| ------------ | ---------- | ---------- | -------------------------------------- |
| `summary`    | named slot | 見出し入力 | リッチな見出し領域を受け取ります       |
| 既定スロット | slot       | 本文入力   | 折りたたみコンテンツ本体を受け取ります |

`summary` スロットは、アイコン、強調、複数行テキストを含むリッチな見出しを受け取れます。`summary` スロットが存在する場合、`summary` property の文字列は表示に寄与しません。

`summary` スロットはトリガー `button` の内部に配置されるため、受け入れる内容の範囲を次のように制限します。

- `summary` スロットは非対話の phrasing content を前提とします。
- `a`、`button`、`input`、`select`、`textarea` などの独立した interactive control を入れてはなりません（MUST NOT）。
- 装飾アイコン、強調、補助ラベル、複数行テキストは許容します。

既定スロットは閉状態でも DOM から削除されません。閉状態では `inert` と `aria-hidden` により、操作対象およびアクセシビリティツリー上の露出を抑制します。したがって、本コンポーネントは閉状態で内容をアンマウントしません。

### 公開イベント

`ui-details` は、状態変化を外部へ通知するために `toggle` イベントを発火します。

| 名前     | 種別          | 発火条件            | detail              |
| -------- | ------------- | ------------------- | ------------------- |
| `toggle` | `CustomEvent` | `open` が変化した時 | `{ open: boolean }` |

`toggle` は `bubbles: true` かつ `composed: true` で発火します。初期描画時には発火しません。値が変化しない同値代入でも発火しません。

### 属性反映契約

公開入力のうち、`ariaLabel`、`summary`、`open`、`variant`、`region` は property と attribute の両面から操作できます。`ariaLabel` の HTML 属性名は `aria-label` です。`open` と `region` は boolean attribute として扱います。

| property    | attribute    | reflect | 備考                                            |
| ----------- | ------------ | ------- | ----------------------------------------------- |
| `ariaLabel` | `aria-label` | なし    | 必須です                                        |
| `summary`   | `summary`    | あり    | `summary` スロット未指定時のみ表示に寄与します  |
| `open`      | `open`       | あり    | 開閉状態とトリガー / コンテンツ属性を同期します |
| `variant`   | `variant`    | あり    | `default` / `bordered` を受理します             |
| `region`    | `region`     | あり    | `true` の場合のみランドマーク化します           |

### 列挙外値・無効値の扱い

`variant` は公開上 `default` / `bordered` を契約とします。HTML 属性として列挙外文字列を与えること自体は可能ですが、公開契約としては未サポートです。利用者は列挙外値に依存してはなりません（MUST NOT）。

`ariaLabel` は空白のみの文字列も無効値として扱います。`trim()` 後に空となる場合は契約違反であり、実装は例外を送出します。

`summary` は空文字または空白のみであっても実装上は受理され得ますが、契約上は「未指定」と同等に扱います。したがって、可視サマリーを持つ disclosure を意図する場合、空白のみの `summary` に依存してはなりません（MUST NOT）。

### 責務範囲

責務範囲には、トリガーの描画、開閉状態に応じた ARIA 属性反映、閉状態コンテンツの `inert` 化、開閉アニメーション、ランドマーク化、および `toggle` イベント通知を含みます。

一方で、相互排他グループ制御、永続化、URL 同期、初回展開時のみの lazy mount、本文内容そのものの編集規則は責務に含めません。

### 非提供契約

現行の `ui-details` は公開メソッドを持ちません。`focus()`、`blur()`、`show()`、`hide()`、`toggle()` などの imperative API は公開しません。

外部制御は、`open` の更新またはトリガー操作を通じて行います。将来的に公開メソッドを導入する場合は、破壊的変更の有無を含めて別途契約を更新します。

## 状態モデル

`ui-details` の主要状態は、**開いているか閉じているか**、**見出し入力がどこから来るか**、**コンテンツを独立したセクションとして扱うか**によって読み分けます。

### 基本状態

最小状態は、`aria-label` を持ち、`summary` または `summary` スロットを持ち、`open=false`、`variant="default"`、`region=false` の状態です。この状態では、補足情報を閉じたまま保持する disclosure として振る舞います。

### 開閉状態

`open=false` の場合、コンテンツは折りたたまれ、`aria-hidden="true"` および `inert` が付与されます。`open=true` の場合、コンテンツは展開され、`aria-hidden="false"` となり、`inert` は除去されます。

トリガーの `aria-expanded` は `open` と常に同期します。アイコンは `open=false` で右向き、`open=true` で 90 度回転した状態をとります。

### サマリー入力状態

見出しの入力経路は次の 2 系統です。

| 入力経路           | 優先順位 | 内容                                           |
| ------------------ | -------- | ---------------------------------------------- |
| `summary` スロット | 高       | リッチな見出しを受け取ります                   |
| `summary` property | 低       | プレーンテキストのフォールバックとして扱います |

両方を同時に与えた場合、表示に参加するのは `summary` スロットです。`summary` property はフォールバックとしてのみ意味を持ちます。

### バリアント状態

`variant` は視覚的な外枠の有無だけを切り替えます。意味は次表のとおりです。

| `variant` 値 | 意味     | 想定用途                                               |
| ------------ | -------- | ------------------------------------------------------ |
| `default`    | 外枠なし | 本文中の軽い補足、注記、FAQ 項目                       |
| `bordered`   | 外枠あり | 他のセクションから独立させたい補足、カード的なまとまり |

`variant` は情報の重要度や開閉ロジックそのものを変更しません。あくまで視覚的な境界の強さを調整する契約です。

### ランドマーク状態

`region=true` の場合、コンテンツ領域は `role="region"` を持ち、`aria-labelledby` でトリガーを参照します。`region=false` の場合、追加ランドマークは生成しません。

`region` は常に使う値ではありません。ページ全体の landmark 密度を不必要に高めないため、**独立セクションとして読む価値がある場合にのみ**有効化します。

### 初期描画と更新状態

初期描画では、`open` の現在値に応じて DOM と属性が描画されますが、`toggle` イベントは発火しません。以後、`open` が実際に変化した更新でのみ `toggle` が発火します。

したがって、`ui-details` は **初期状態の通知** と **状態変化の通知** を分離して扱います。

### 状態所有権

`ui-details` は、完全 controlled component ではありません。トリガー操作時には自ら `open` を更新する self-updating な disclosure として振る舞います。

同時に、`open` は外部から設定可能な同期入力でもあります。したがって、本コンポーネントの状態所有権は次のように定義します。

- 内部トリガー操作時の状態更新はコンポーネント自身が行います。
- 外部から `open` を更新した場合も、その値を受理して状態へ反映します。
- controlled / uncontrolled を別 API として分離しません。

### キーボード状態

トリガーはネイティブ `button` です。したがって、Enter / Space による起動タイミングはブラウザ標準の button 契約に従います。独自キーボードハンドラには依存しません。

### 閉状態隔離

`ui-details` は閉状態でも本文をアンマウントしません。閉状態では `inert` によりフォーカス移動、クリック、その他の対話を抑止します。したがって、本コンポーネントの閉状態は、**単なる視覚的非表示ではなく、対話的にも閉じている状態**です。

また、閉状態で内容を保持すること自体が契約です。初回展開時のみの lazy mount や、閉状態での unmount は現行契約に含みません。

## DOM / アクセシビリティ

ルートは `:host` です。Shadow DOM 内部に単一のトリガー `button` と、内容を包む `.content-wrapper` を持ちます。

```text
<ui-details>
  #shadow-root
    <div class="root">
      <button class="trigger" part="trigger">
        <span class="icon" aria-hidden="true"></span>
        <span class="summary" part="summary">
          <slot name="summary">{summary}</slot>
        </span>
      </button>
      <div class="content-wrapper" part="content-wrapper">
        <div class="content-inner">
          <div class="content-body" part="content">
            <slot></slot>
          </div>
        </div>
      </div>
    </div>
</ui-details>
```

### アクセシビリティ契約

アクセシビリティ上の重要点は次のとおりです。

- 対話主体はネイティブ `button` です。
- トリガーのアクセシブルネームは `aria-label` により与えます。
- `aria-label` は必須であり、空文字は許可しません（MUST）。
- トリガーは `aria-expanded` と `aria-controls` を持ち、制御対象コンテンツと結び付きます。
- コンテンツは `open=false` の時に `aria-hidden="true"` となり、`inert` が付与されます。
- `region=true` の場合のみ、コンテンツは `role="region"` と `aria-labelledby` を持ちます。
- アイコンは装飾要素であり、`aria-hidden="true"` です。
- フォーカス可視表示は `:focus-visible` で扱います。
- 最低タップ領域の補助はトリガー疑似要素で補います。

本コンポーネントで重要なのは、**見出しテキストをただ見せることではなく、開閉トリガーとして正しく公開すること**です。`div[role="button"]` やクリック可能な非対話要素には依存しません。

### アクセシブルネームに関する補足

現行実装では `aria-label` が必須であり、トリガーへ常に設定されます。したがって、アクセシブルネームの第一義的なソースは `summary` 表示内容ではなく `aria-label` です。可視サマリーと `aria-label` が乖離すると、視覚上の見出しと支援技術上の名前がずれるため、両者は意味的に一致させなければなりません（MUST）。

可視見出しを動的に差し替える場合でも、`aria-label` は自動同期されません。可視見出しの意味が変わる場合、利用者は `aria-label` も同期更新しなければなりません（MUST）。

### 内部 ID 契約

`aria-controls` および `aria-labelledby` に用いる ID は内部生成値です。これらはアクセシビリティ接続のための内部実装であり、公開 API ではありません。

利用者は、生成される ID 文字列そのもの、命名規則、連番規則に依存してはなりません（MUST NOT）。再マウント、描画順、将来の実装変更により値が変わり得ます。

## 視覚契約

`ui-details` の視覚契約は、本文の流れの中で補足情報の存在を示しつつ、**開くまで本文の主役性を奪わないこと**にあります。

### 情報順位

- サマリー行は本文よりやや強いが、見出しよりは弱い視覚重量とします。
- アイコンは開閉可能性のシグナルであり、情報主役ではありません。
- 展開コンテンツはサマリーに従属する補足領域として扱います。
- `bordered` は独立した小セクションとしてのまとまりを補助します。

本文近傍では、details は注目を奪うための装置ではなく、**必要な時だけ情報密度を上げるための装置**として振る舞います。したがって、過度な塗り、常時目立つアニメーション、強い装飾線には依存しません。

### レイアウト

トリガーは横並びの `flex` で構成し、アイコンとサマリーを並置します。コンテンツ本文はアイコン幅とトリガー間ギャップの合計分だけ左に揃え、見出しと本文の開始位置の秩序を保ちます。

`bordered` では、外枠と内側パディングにより、サマリー行と本文をひとまとまりのブロックとして見せます。

### 視覚仕様

- トリガーは全幅クリック可能です。
- アイコンは `open` に応じて 90 度回転します。
- コンテンツは `grid-template-rows` と `opacity` で開閉します。
- 閉状態では `visibility: hidden` を併用し、視覚的にも非表示とします。
- `bordered` ではルートに境界線と角丸を与えます。

### フォーカス表示

フォーカスリングは `outline` と `outline-offset` で描画します。これは box-shadow に依存したリングではありません。トリガー全幅に対して明瞭に見えることを優先しつつ、本文の読書リズムを壊さない強度に保ちます。

### モーション

開閉モーションは短く抑え、**開いたこと・閉じたことが知覚できる最小限の差分**にとどめます。モーションは情報の意味付けではなく状態遷移の補助です。

### 参照トークン

本コンポーネントは、主として次のトークンに依存します。

| 用途               | トークン                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------- |
| 既定文字色         | `--fg-default`                                                                            |
| 控えめ文字色       | `--fg-muted`                                                                              |
| 既定境界線         | `--border-default`                                                                        |
| 角丸               | `--radius-sm` / `--radius-md`                                                             |
| 余白               | `--space-2` / `--space-3` / `--space-4`                                                   |
| アイコン寸法       | `--icon-base`                                                                             |
| 行高               | `--line-height-normal`                                                                    |
| フォントサイズ     | `--text-base`                                                                             |
| フォントウェイト   | `--font-medium`                                                                           |
| フォントファミリー | `--font-sans`                                                                             |
| 遷移時間           | `--duration-fast` / `--duration-slow`                                                     |

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、アイコン回転と開閉アニメーションの duration を極小化し、delay を除去します。状態差分は残しますが、移動量や時間感覚への依存を最小化します。

### Forced Colors

`forced-colors: active` 環境では、アイコン色、外枠色、フォーカスリング色をシステムカラー `CanvasText` に追従させます。固有色の見え方には依存しません。

### Dark Mode

本コンポーネントは dark mode 専用のメディアクエリを直接持ちません。暗色面への適応はセマンティックトークン差し替えで吸収します。したがって、ダークモード対応の主契約は、**個別分岐ではなくトークン参照の維持**です。

### Print

現行実装は印刷専用スタイルを持ちません。印刷時の表示制御は本コンポーネント単体の契約には含めません。

## 関連契約

### 文書内到達契約

`ui-details` は補足情報の disclosure であると同時に、文書内到達性を阻害しないことを目標とします。とくに、次に正式契約へ昇格させる事項として、URL hash による内部要素到達時の自動展開を位置付けます。

現時点では次期正式契約として扱いますが、将来の正式化後は次を満たします。

- `ui-details` 内部要素への hash 到達時には、対象を含む `ui-details` を展開します。
- 必要に応じて祖先 `ui-details` を順に展開します。
- URL 同期や履歴管理全体までは扱いません。

### 開閉イベント契約

`ui-details` は独自の複雑なイベント体系を持ちません。外部へ公開する状態通知は `toggle` のみです。

- トリガー操作により `open` が変化した場合、`toggle` を 1 回発火します。
- 外部から `open` を変更した場合も、値が変化すれば `toggle` を発火します。
- 初期描画時には発火しません。
- 同値代入では発火しません。
- `detail.open` は変更後の値です。

`toggle` は **ユーザー操作イベントではなく、**``** の状態変化通知** として扱います。したがって、利用者は `toggle` を state synchronization の起点として扱えます。一方で、起動理由、入力デバイス種別、元イベント参照などの追加情報には依存してはなりません（MUST NOT）。

### スタイル拡張契約

`ui-details` は外部スタイル拡張を全面自由とはしません。公開するのは、本書に列挙した CSS Custom Properties と `::part(...)` に限定される拡張面です。

| part 名           | 役割                           |
| ----------------- | ------------------------------ |
| `trigger`         | 開閉トリガー                   |
| `summary`         | 見出し表示領域                 |
| `content-wrapper` | 開閉アニメーションを担うラッパ |
| `content`         | 実際の本文領域                 |

利用者は `::part(trigger)`、`::part(summary)`、`::part(content-wrapper)`、`::part(content)` に対して装飾調整を行えます。ただし、意味を変更するための display 構造破壊やインタラクション破壊は行ってはなりません（MUST NOT）。

本書の視覚契約に列挙した CSS Custom Properties のみを安定した公開トークンとして扱います。それ以外の内部 class 名、Shadow DOM 内部の細部構造、内部要素名、`iconify-icon` の存在そのものには依存してはなりません（MUST NOT）。将来変更時に互換性を保証しません。

### 閉状態隔離契約

閉状態で本文が操作不能であることは本コンポーネントの本質契約です。したがって、外部スタイルや外部スクリプトで `inert` 前提を破壊してはなりません（MUST NOT）。閉状態コンテンツを視覚的に見せるような override は、契約上サポートしません。

## 境界条件

### hash 到達時の扱い（次期正式契約）

URL hash が `ui-details` 内部要素を指す場合、対象を含む `ui-details` は展開対象です。ネストがある場合は、対象到達に必要な祖先 `ui-details` も展開対象です。

一方で、hash が `ui-details` 外部を指す場合、本コンポーネントは何も行いません。対象が存在しない場合も例外は送出しません。

### 基本ケース

`aria-label` と `summary` を与えた通常ケースでは、閉状態で描画され、トリガーは button として機能します。

### `summary` スロット優先

`summary` スロットと `summary` property を同時に与えた場合、表示されるのは `summary` スロットです。`summary` property は表示に寄与しません。

### サマリー未指定

`summary` スロットも `summary` property も与えない場合でも、`aria-label` が有効なら実装上は描画可能です。この場合の可視トリガーは実質的にアイコンのみとなります。技術的には成立しますが、本文中の disclosure としては説明不足になりやすいため、常用しません（SHOULD NOT）。

### `aria-label` 空文字

`aria-label` が未指定、空文字、または空白のみの場合は契約違反です。実装は例外を送出し、描画継続を保証しません。

### `region=true`

`region=true` の場合、コンテンツは landmark として公開されます。ただし、すべての details を landmark 化すると情報構造が過密になるため、独立セクションとしての読み上げ価値がある場合に限定します。

FAQ の個別項目や軽量な注記のような細粒度補足では、通常 `region` を使いません。単独で見出し付き小節として読ませたい内容に限定して利用します。

### 閉状態の内部フォーカス

閉状態では `inert` により内部対話要素へフォーカス移動できません。これは単なるスタイル上の不可視ではなく、操作上の隔離です。

### 同値代入

`open` に現在値と同じ値を代入しても `toggle` は発火しません。外部同期ロジックはこの前提に依存してよいです。

### 列挙外 `variant`

`variant` に列挙外値を与えた場合、表示は未定義です。利用者は `default` / `bordered` 以外を使ってはなりません（MUST NOT）。

### icon-only の位置付け

## 優先して先に正式契約へ昇格させる事項

本節は、現行の `details.ts` および `details.stories.ts` を前提として、**新規機能候補の中から、次に正式契約として先に固定する事項**を定めるものです。

ここで重要なのは、実装順ではなく**契約順**です。`ui-details` を accordion や汎用 panel へ肥大化させるのではなく、**本文補足 disclosure としての役割を保ったまま、文書到達性を最も強く改善するもの**を先に固定します。

本書では、次に正式契約へ昇格させる事項を **ハッシュ到達時の自動展開** と定めます。印刷時の展開ポリシーは重要な次点候補ですが、先に固定する対象には含めません。

### ハッシュ到達時の自動展開

最も優先して正式契約へ昇格させるのは、**URL フラグメントが **`** 内部要素を指す場合に、親 **`** を自動で展開する機能**です。

現行契約では、閉状態コンテンツは `aria-hidden` と `inert` により隔離され、視覚的にも非表示です。そのため、details 内部に見出し、脚注、注記アンカー、コードブロック見出しなどを含める運用を行う場合、`#fragment` による直接到達と閉状態が衝突します。

この機能を先に固定する理由は次のとおりです。

- 恒久的リンクから補足情報へ直接到達できるようになります。
- 検索結果や TOC から details 内部の目標へ移動した時に、到達先が閉じたままになる問題を防げます。
- 画面上の見た目を増やさず、読書導線だけを改善できます。
- `ui-details` の責務を disclosure の範囲内に保ったまま価値を増やせます。

したがって、本書では次の内容を**次期正式契約**として先に固定します。

#### 契約の目的

`ui-details` は、文書内の補足情報を段階的に開示する一方で、**文書内到達性を阻害してはなりません**。URL hash により内部要素が直接参照された場合、閉状態であることを理由に到達性を失わせないことを契約目的とします。

#### 契約本文

- 現在の URL hash が `ui-details` 内部の要素を指す場合、対象要素を含む `ui-details` は展開されなければなりません（MUST）。
- ネストした `ui-details` が存在する場合、対象要素までの祖先 `ui-details` を、内側到達に必要な範囲で順に展開しなければなりません（MUST）。
- hash 到達による展開は、通常の `open` 更新と同じ状態遷移として扱います。
- hash が `ui-details` 外部を指す場合、本コンポーネントは何も行いません。
- hash の対象要素が存在しない場合、例外を送出してはなりません（MUST NOT）。
- hash 到達による展開後、対象要素の可視性と到達可能性が回復していなければなりません（MUST）。

#### イベントとの整合

hash 到達によって `open` が `false` から `true` へ変化した場合、その変化は通常の状態更新として扱います。したがって、`toggle` の契約に従い、値変化が発生した場合に限って `toggle` を発火させて構いません。

一方で、hash 解決専用の追加イベントは導入しません。文書到達は状態変化として吸収し、イベント面を不必要に増やしません。

#### 境界

- `ui-details` 外部の要素を指す hash には介入しません。
- hash 到達は単体 disclosure の責務として扱いますが、URL 同期や履歴管理そのものは責務に含めません。
- hash 到達を理由に `summary`、`variant`、`region` の意味は変化しません。

#### 実装状態

本契約は、**先に文書として固定する次期正式契約**です。現時点では現行実装へ未反映であっても、この方向で実装・Storybook・関連契約を更新することを前提とします。

### 印刷時の展開ポリシー（次点候補）

次に優先度が高いのは、**印刷時に **``** をどのように出力するかを契約として固定すること**です。これは重要な候補ですが、本書では先に正式契約へ昇格させる対象には含めません。

現行文書では print 契約を未定義としています。しかし、details は補足本文を抱えるため、印刷時に閉じたまま内容が失われると、画面上では読めた情報が紙面では欠落する可能性があります。

Rouault の文脈では、details は装飾的な UI ではなく、本文に従属する補足情報です。そのため、印刷時の既定方針としては **常時展開** が最も整合的です。

採用する場合の契約は、次のように定義するのがよいです。

- 印刷媒体では、`ui-details` は `open` の現在値にかかわらず内容を可視化します。
- 印刷媒体では、開閉アニメーションおよび回転アニメーションには依存しません。
- 印刷媒体では、内容を視覚的に隠すための `visibility: hidden`、`opacity`、`grid-template-rows` の閉状態表現を無効化します。
- 印刷媒体では、トリガーは開閉 UI ではなく見出し行として出力されても構いません。

この機能はスクリーン上の操作性を複雑化させず、媒体横断で情報欠落を防ぎます。読書アプリケーションとしての一貫性を高めるため、ハッシュ到達時の自動展開に次ぐ優先候補とします。

### 本節の位置付け

本節に記載した事項のうち、**先に正式契約へ昇格させるのはハッシュ到達時の自動展開**です。印刷時の展開ポリシーは、その次に契約化を検討する候補として扱います。

したがって、今後の更新順は次のとおりです。

- ハッシュ到達時の自動展開を、公開契約・状態モデル・境界条件・Storybook 契約へ段階的に吸収します。
- 印刷時の展開ポリシーは、print 実装方針が固まり次第、環境別の振る舞いへ正式に吸収します。

採用する場合は、実装だけでなく、Storybook、関連契約、環境別の振る舞いも合わせて更新します。

本節は、現行の `details.ts` および `details.stories.ts` を基準として、**details コンポーネントとして将来的に検討余地はあるが、現時点では未実装または未公開である事項**を整理するものです。

### `summary` スロット内容の実行時バリデーション

本文契約では、`summary` スロットを非対話の phrasing content に制限し、`a`、`button`、`input` などの独立した interactive control を入れてはならないとしています。しかし、現行実装は `summary` スロット内容を実行時に検証しません。

### 可視 summary と `aria-label` の整合検証

本文契約では、可視サマリーと `aria-label` は意味的に一致しなければならないとしています。しかし、現行実装が検証するのは `aria-label` の非空性だけであり、可視 summary との意味整合までは確認しません。

したがって、視覚上の見出しと支援技術上の名前が乖離していても、現時点では実装が自動検知しません。この契約をより実効的にしたい場合は、開発時警告や Storybook 境界テストの追加が必要です。

### lazy mount / unmount

閉状態でも本文は DOM に残ります。`inert` による隔離は行いますが、初回展開時のみマウントする lazy mount や、閉時にアンマウントする戦略は未対応です。

### 開閉理由の詳細通知

`toggle` イベントが返す情報は `{ open: boolean }` のみです。ポインター起動、キーボード起動、外部 property 更新などの詳細理由は公開しません。

### 公開メソッド

現行実装は `focus()`、`blur()`、`show()`、`hide()`、`toggle()` などの公開メソッドを持ちません。外部制御は property 更新またはトリガー操作に依存します。

### ハッシュ到達時の自動展開

URL hash が `ui-details` 内部要素を指す場合に親 `ui-details` を自動展開する契約は、次に正式化する方針を本書で先に固定していますが、現行実装には未反映です。

### 印刷専用契約

印刷時に展開状態をどう扱うか、非表示にするか、常時展開するかといった print 契約は、重要な次点候補として整理済みですが、現時点では未定義です。
