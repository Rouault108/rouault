# Details

## 概要

本書は、`ui-details` の公開契約、状態モデル、アクセシビリティ、および視覚契約を整理するものです。

`ui-details` は、本文の流れを断ち切らずに補足情報を段階的に開示するためのコンポーネントです。単に開閉できる箱を描画するのではなく、**何が開閉トリガーであるか**、**閉状態の内容をどのように操作対象から隔離するか**、**開閉状態をどのイベントと ARIA 属性で公開するか**を公開契約として固定します。

また、本コンポーネントは native `<details>` を直接利用しません。これは、閉じるアニメーション、閉状態のフォーカス隔離、内部レイアウト制御を一貫して扱うためです。その代わりに、**ネイティブ `button`、ARIA 属性、`inert`、および内部ラッパ構造**を組み合わせて disclosure を構成します。

Rouault における details は、補足、注記、FAQ、設計上の但し書きなどを必要な時だけ展開するための要素です。したがって、本コンポーネントの契約は、開閉可能性の明示と、**「没入して読む」ことのできるデザイン**の維持を両立する方向で定義します。

## 本書の読み方

本書は、`ui-details` の契約を次の 2 段階に分けて記述します。

1. **現行正式契約**
   現在の実装・Storybook・利用者コードが依存してよい事項です。

2. **採用決定済み・未実装**
   仕様方針としては確定しているが、現行実装および Storybook へは未反映の事項です。利用者は、実装反映前にこれらへ依存してはなりません（MUST NOT）。

したがって、利用者が最初に確認すべきなのは **公開契約**、**状態モデル**、**境界条件** のうち、現行正式契約として記述された部分です。未実装事項は、方針共有のための記述であり、現行保証ではありません。

本書では、現行正式契約と採用決定済み・未実装事項を混同しないことを最優先とします。

## 公開契約

`ui-details` は、`summary`、`open`、`variant`、`region`、`ariaLabel` を公開入力として扱います。スロットは `summary` スロットと既定スロットを持ちます。内部実装はネイティブ `button` を起点に構成されますが、利用者は `ui-details` を disclosure 契約単位として扱います。

本コンポーネントの**標準利用**では、**可視 summary を持つこと**を前提とします。可視 summary は `summary` property または `summary` スロットのいずれかで与えます。両方を同時に与えた場合、`summary` スロットを優先します。

アクセシブルネームの主ソースは、**常に可視 summary**です。したがって、標準利用では可視 summary と支援技術上の名前が一致しなければなりません。`ariaLabel` は、**可視 summary を持たない icon-only 利用時に限って使用する補助入力**です。

したがって、通常利用では `summary` または `summary` スロットのいずれかを与えなければなりません（MUST）。`ariaLabel` は常時必須ではありませんが、**icon-only 利用では必須**です（MUST）。

`open` の既定値は `false` です。`variant` の既定値は `default` です。`region` の既定値は `false` です。

### 入力契約

| 名前          | 種別                                  | 必須     | 内容             | 契約                                                           |
| ----------- | ----------------------------------- | ------ | -------------- | ------------------------------------------------------------ |
| `summary`   | property / attribute                | 条件付き必須 | サマリーテキスト       | `summary` スロット未指定時の可視 summary として使用します                       |
| `ariaLabel` | property / attribute (`aria-label`) | 条件付き必須 | トリガーのアクセシブルネーム | icon-only 利用時にのみ使用します                                        |
| `open`      | property / attribute                | いいえ    | 開閉状態           | `true` で展開、`false` で折りたたみます                                  |
| `variant`   | property / attribute                | いいえ    | 外枠バリアント        | `default` / `bordered`                                       |
| `region`    | property / attribute                | いいえ    | ランドマーク化        | `true` の場合、コンテンツに `role="region"` と `aria-labelledby` を付与します |

補助ルールは次のとおりです。

* `summary` スロットが存在する場合、`summary` property より優先します。
* `summary` スロットも `summary` property も持たない icon-only 利用は、例外用途としてのみ許容します。
* icon-only 利用では、`ariaLabel` を必須とします（MUST）。
* 可視 summary が存在する場合、`ariaLabel` を別名義で併用してはなりません（MUST NOT）。
* icon-only は本文中の一般的な補足 disclosure の標準利用には含めません。補助操作・高密度 UI・ツールバー内補助トリガーなど、可視テキストを置けない限定用途にのみ用います。

### スロット契約

| 名前        | 種別         | 位置づけ  | 内容                  |
| --------- | ---------- | ----- | ------------------- |
| `summary` | named slot | 見出し入力 | リッチな見出し領域を受け取ります    |
| 既定スロット    | slot       | 本文入力  | 折りたたみコンテンツ本体を受け取ります |

`summary` スロットは、アイコン、強調、複数行テキストを含むリッチな見出しを受け取れます。`summary` スロットが存在する場合、`summary` property の文字列は表示に寄与しません。

`summary` スロットはトリガー `button` の内部に配置されるため、受け入れる内容の範囲を次のように制限します。

* `summary` スロットは非対話の phrasing content を前提とします。
* `a`、`button`、`input`、`select`、`textarea` などの独立した interactive control を入れてはなりません（MUST NOT）。
* 装飾アイコン、強調、補助ラベル、複数行テキストは許容します。

`summary` スロットの内容は、初期描画後に動的に差し替えて構いません。動的差し替え後も、`summary` スロット優先、`summary` property フォールバック、icon-only 境界条件の各契約をその時点の DOM に基づいて再評価します。

ただし、本コンポーネントは動的差し替えのための**特別な移行ロジックや履歴保持ロジックを持ちません**。`open`、`variant`、`region` の状態は維持され、見出し入力だけがその時点の DOM に従って更新されます。可視 summary を除去して icon-only 状態へ移行する場合、利用者は同時に有効な `ariaLabel` を与えなければなりません（MUST）。

既定スロットは閉状態でも DOM から削除されません。閉状態では `inert` と `aria-hidden` により、操作対象およびアクセシビリティツリー上の露出を抑制します。したがって、本コンポーネントは閉状態で内容をアンマウントしません。

### 公開イベント

`ui-details` は、状態変化を外部へ通知するために `toggle` イベントを発火します。

| 名前       | 種別            | 発火条件          | detail              |
| -------- | ------------- | ------------- | ------------------- |
| `toggle` | `CustomEvent` | `open` が変化した時 | `{ open: boolean }` |

`toggle` は `bubbles: true` かつ `composed: true` で発火します。初期描画時には発火しません。値が変化しない同値代入でも発火しません。

### 属性反映契約

公開入力のうち、`ariaLabel`、`summary`、`open`、`variant`、`region` は property と attribute の両面から操作できます。`ariaLabel` の HTML 属性名は `aria-label` です。`open` と `region` は boolean attribute として扱います。

| property    | attribute    | reflect | 備考                            |
| ----------- | ------------ | ------- | ----------------------------- |
| `ariaLabel` | `aria-label` | なし      | icon-only 利用時にのみ必須です          |
| `summary`   | `summary`    | あり      | `summary` スロット未指定時のみ表示に寄与します  |
| `open`      | `open`       | あり      | 開閉状態とトリガー / コンテンツ属性を同期します     |
| `variant`   | `variant`    | あり      | `default` / `bordered` を受理します |
| `region`    | `region`     | あり      | `true` の場合のみランドマーク化します        |

### 列挙外値・無効値の扱い

`variant` は公開上 `default` / `bordered` を契約とします。HTML 属性として列挙外文字列を与えること自体は可能ですが、公開契約としては未サポートです。利用者は列挙外値に依存してはなりません（MUST NOT）。

`ariaLabel` は空白のみの文字列も無効値として扱います。`trim()` 後に空となる場合は契約違反であり、実装は例外を送出します。

`summary` は空文字または空白のみであっても実装上は受理され得ますが、契約上は「未指定」と同等に扱います。したがって、可視サマリーを持つ disclosure を意図する場合、空白のみの `summary` に依存してはなりません（MUST NOT）。

### 責務範囲

責務範囲には、トリガーの描画、開閉状態に応じた ARIA 属性反映、閉状態コンテンツの `inert` 化、開閉アニメーション、ランドマーク化、および `toggle` イベント通知を含みます。

一方で、相互排他グループ制御、永続化、URL 同期、初回展開時のみの lazy mount、本文内容そのものの編集規則は責務に含めません。

### 非提供契約

現行の `ui-details` は公開メソッドを持ちません。`focus()`、`blur()`、`show()`、`hide()`、`toggle()` などの imperative API は公開しません。

外部制御は、`open` の更新またはトリガー操作を通じて行います。将来的に公開メソッドを導入する場合は、破壊的変更の有無を含めて別途契約を更新します。

## 状態モデル

`ui-details` の主要状態は、**開いているか閉じているか**、**見出し入力がどこから来るか**、**コンテンツを独立したセクションとして扱うか**によって読み分けます。

### 基本状態

最小状態は、有効なアクセシブルネームを持ち、`summary` または `summary` スロットを持ち、`open=false`、`variant="default"`、`region=false` の状態です。この状態では、補足情報を閉じたまま保持する disclosure として振る舞います。

### 開閉状態

`open=false` の場合、コンテンツは折りたたまれ、`aria-hidden="true"` および `inert` が付与されます。`open=true` の場合、コンテンツは展開され、`aria-hidden="false"` となり、`inert` は除去されます。

トリガーの `aria-expanded` は `open` と常に同期します。アイコンは `open=false` で右向き、`open=true` で 90 度回転した状態をとります。

### サマリー入力状態

見出しの入力経路は次の 2 系統です。

| 入力経路               | 優先順位 | 内容                 |
| ------------------ | ---- | ------------------ |
| `summary` スロット     | 高    | リッチな見出しを受け取ります     |
| `summary` property | 低    | プレーンテキストのフォールバックです |

両方を同時に与えた場合、表示に参加するのは `summary` スロットです。`summary` property はフォールバックとしてのみ意味を持ちます。

標準利用では、アクセシブルネームの主ソースもこの可視 summary です。可視 summary を持たない icon-only は、状態モデル上でも例外用途としてのみ扱います。

### バリアント状態

`variant` は視覚的な外枠の有無だけを切り替えます。意味は次表のとおりです。

| `variant` 値 | 意味   | 想定用途                        |
| ----------- | ---- | --------------------------- |
| `default`   | 外枠なし | 本文中の軽い補足、注記、FAQ 項目          |
| `bordered`  | 外枠あり | 他のセクションから独立させたい補足、カード的なまとまり |

`variant` は情報の重要度や開閉ロジックそのものを変更しません。あくまで視覚的な境界の強さを調整する契約です。

### ランドマーク状態

`region=true` の場合、コンテンツ領域は `role="region"` を持ち、`aria-labelledby` でトリガーを参照します。`region=false` の場合、追加ランドマークは生成しません。

`region` は常に使う値ではありません。ページ全体の landmark 密度を不必要に高めないため、**独立セクションとして読む価値がある場合にのみ**有効化します。

### 初期描画と更新状態

初期描画では、`open` の現在値に応じて DOM と属性が描画されますが、`toggle` イベントは発火しません。以後、`open` が実際に変化した更新でのみ `toggle` が発火します。

したがって、`ui-details` は **初期状態の通知** と **状態変化の通知** を分離して扱います。

### 状態所有権

`ui-details` は、内部操作で自律的に状態更新できる一方、`open` を外部から同期入力として受け取れる **self-updating + externally synchronizable** な disclosure です。controlled / uncontrolled を別 API として分離しません。

状態所有権は次のように定義します。

* 内部トリガー操作時には、コンポーネント自身が現在値を基準に `open` を更新します。
* 外部から `open` が与えられた場合、コンポーネントはその値を受理し、現在状態として反映します。
* 内部更新後に外部が別値を書いた場合、**最後に反映された `open` 値**を正とします。
* コンポーネントは、内部操作の意図を後続の外部更新より優先して保持しません。
* `toggle` は、ユーザー意図そのものではなく、**確定した状態変化**のみを通知します。

したがって、本コンポーネントは「内部操作が常に最優先」でも「外部制御が常に最優先」でもありません。**その時点で最後に確定した `open` 値が唯一の真実源**です。

再入時の扱いは次のとおりです。

* 同値代入では `toggle` を発火しません。
* 連続更新が発生した場合も、各値変化に対してのみ `toggle` を発火します。
* `toggle` を契機に親が `open` を上書きすることは許容します。
* その場合でも、コンポーネントは追加の意図解釈を持たず、単に更新後値へ追従します。

この契約により、利用者は `toggle` を同期の起点として使えますが、内部操作理由や優先権モデルには依存してはなりません（MUST NOT）。

### キーボード状態

トリガーはネイティブ `button` です。したがって、Enter / Space による起動タイミングはブラウザ標準の button 契約に従います。独自キーボードハンドラには依存しません。

### 閉状態隔離

`ui-details` は閉状態でも本文をアンマウントしません。閉状態では `inert` によりフォーカス移動、クリック、その他の対話を抑止します。したがって、本コンポーネントの閉状態は、**単なる視覚的非表示ではなく、対話的にも閉じている状態**です。

また、閉状態で内容を保持すること自体が契約です。初回展開時のみの lazy mount や、閉状態での unmount は現行契約に含みません。

閉状態隔離は、**ネイティブ `inert` をサポートするブラウザ環境**を前提とします。本コンポーネントは、`inert` 非対応環境のための polyfill 提供や代替契約を内包しません。`inert` 非対応環境では、閉状態隔離契約を保証しません。

## DOM / アクセシビリティ

ルートは `:host` です。Shadow DOM 内部に単一のトリガー `button` と、内容を包む `.content-wrapper` を持ちます。

```text
<ui-details>
  #shadow-root
    <div class="root">
      <button class="trigger" part="trigger">
        <span class="icon" aria-hidden="true"></span>
        <span class="summary" part="summary">
          <slot name="summary">{summary}</slot>
        </span>
      </button>
      <div class="content-wrapper" part="content-wrapper">
        <div class="content-inner">
          <div class="content-body" part="content">
            <slot></slot>
          </div>
        </div>
      </div>
    </div>
</ui-details>
```

### アクセシビリティ契約

アクセシビリティ上の重要点は次のとおりです。

* 対話主体はネイティブ `button` です。
* トリガーのアクセシブルネームは、標準利用では可視 summary から決定されます。
* icon-only 利用時に限り、`aria-label` によりアクセシブルネームを与えます。
* icon-only 利用で `aria-label` が未指定、空文字、または空白のみの場合は契約違反です。
* トリガーは `aria-expanded` と `aria-controls` を持ち、制御対象コンテンツと結び付きます。
* コンテンツは `open=false` の時に `aria-hidden="true"` となり、`inert` が付与されます。
* `region=true` の場合のみ、コンテンツは `role="region"` と `aria-labelledby` を持ちます。
* アイコンは装飾要素であり、`aria-hidden="true"` です。
* フォーカス可視表示は `:focus-visible` で扱います。
* 最低タップ領域の補助はトリガー疑似要素で補います。

本コンポーネントで重要なのは、**見出しテキストをただ見せることではなく、開閉トリガーとして正しく公開すること**です。`div[role="button"]` やクリック可能な非対話要素には依存しません。

### アクセシブルネームに関する補足

本コンポーネントの標準利用では、アクセシブルネームの主ソースは**可視 summary**です。したがって、通常ケースでは可視 summary と支援技術上の名前が分離しないことを優先します。

`ariaLabel` は icon-only など、可視 summary を持たない例外ケースに限定します。可視 summary が存在する場合、`ariaLabel` を別名義で併用してはなりません（MUST NOT）。

可視見出しを動的に差し替える場合、アクセシブルネーム契約もその時点の可視 summary または icon-only 条件に従って再評価されます。可視 summary を外して icon-only 状態へ移行する場合、利用者は `ariaLabel` を同時に与えなければなりません（MUST）。

### 内部 ID 契約

`aria-controls` および `aria-labelledby` に用いる ID は内部生成値です。これらはアクセシビリティ接続のための内部実装であり、公開 API ではありません。

利用者は、生成される ID 文字列そのもの、命名規則、連番規則に依存してはなりません（MUST NOT）。再マウント、描画順、将来の実装変更により値が変わり得ます。

## 視覚契約

`ui-details` の視覚契約は、本文の流れの中で補足情報の存在を示しつつ、**本文や見出し階層の主従を壊さないこと**にあります。details は注目獲得装置ではなく、補足情報への入口です。

### 情報順位

* サマリー行は、本文より識別可能でなければなりません（MUST）。
* サマリー行は、同一文脈の見出しより強く見えてはなりません（MUST NOT）。
* アイコンは開閉可能性の記号であり、テキスト内容より強く見えてはなりません（MUST NOT）。
* 展開コンテンツは、サマリーに従属する補足領域として読めなければなりません（MUST）。

### レイアウト

* トリガーは全幅クリック可能でなければなりません（MUST）。
* アイコンとサマリーは同一行の disclosure として知覚できなければなりません（MUST）。
* 展開コンテンツの本文開始位置は、サマリー行との視覚的秩序を保たなければなりません（MUST）。
* `bordered` では、外枠と内側余白により小さな補足ブロックとして認識できなければなりません（MUST）。

### 視覚仕様

* `default` では、常時強い塗りや過剰な装飾線に依存してはなりません（MUST NOT）。
* `bordered` は、意味の昇格ではなく視覚的境界の強化としてのみ機能しなければなりません（MUST）。
* 閉状態は、開状態と明確に区別できなければなりません（MUST）。
* 開閉アイコンは、状態差分の補助としてのみ機能しなければなりません（MUST）。

### フォーカス表示

* フォーカスリングは、キーボード利用時にトリガー全体の到達先が判別できる強度を持たなければなりません（MUST）。

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、アイコン回転と開閉アニメーションの duration を極小化し、delay を除去します。状態差分は残しますが、移動量や時間感覚への依存を最小化します。

### Forced Colors

`forced-colors: active` 環境では、アイコン色、外枠色、フォーカスリング色をシステムカラー `CanvasText` に追従させます。固有色の見え方には依存しません。

### Dark Mode

本コンポーネントは dark mode 専用のメディアクエリを直接持ちません。暗色面への適応はセマンティックトークン差し替えで吸収します。したがって、ダークモード対応の主契約は、**個別分岐ではなくトークン参照の維持**です。

### Print

現行実装は印刷専用スタイルを持ちません。印刷時の表示制御は本コンポーネント単体の契約には含めません。

## 関連契約

### 文書内到達契約（採用決定済み・未実装）

`ui-details` は補足情報の disclosure であると同時に、文書内到達性を不必要に阻害しないことを目標とします。そのため、URL hash による内部要素到達時の自動展開を、**採用決定済みだが現行正式契約ではない事項**として定義します。

この節に記載する内容は、実装および Storybook へ反映されるまでは**利用者が依存してよい現行保証ではありません**。

正式反映後は、次を満たします。

* `ui-details` 内部要素への hash 到達時には、対象を含む `ui-details` を展開します。
* 必要に応じて祖先 `ui-details` を順に展開します。
* URL 同期や履歴管理全体までは扱いません。

### 開閉イベント契約

`ui-details` は独自の複雑なイベント体系を持ちません。外部へ公開する状態通知は `toggle` のみです。

* トリガー操作により `open` が変化した場合、`toggle` を 1 回発火します。
* 外部から `open` を変更した場合も、値が変化すれば `toggle` を発火します。
* 初期描画時には発火しません。
* 同値代入では発火しません。
* `detail.open` は変更後の値です。

`toggle` は **`open` の状態変化通知**として扱います。したがって、利用者は `toggle` を state synchronization の起点として扱えます。一方で、起動理由、入力デバイス種別、元イベント参照などの追加情報には依存してはなりません（MUST NOT）。

### スタイル拡張契約

`ui-details` は外部スタイル拡張を全面自由とはしません。公開するのは、本書に列挙した CSS Custom Properties と `::part(...)` に限定される拡張面です。

| part 名            | 役割              |
| ----------------- | --------------- |
| `trigger`         | 開閉トリガー          |
| `summary`         | 見出し表示領域         |
| `content-wrapper` | 開閉アニメーションを担うラッパ |
| `content`         | 実際の本文領域         |

利用者は `::part(trigger)`、`::part(summary)`、`::part(content-wrapper)`、`::part(content)` に対して装飾調整を行えます。ただし、意味を変更するための display 構造破壊やインタラクション破壊は行ってはなりません（MUST NOT）。

本書の視覚契約に列挙した CSS Custom Properties のみを安定した公開トークンとして扱います。それ以外の内部 class 名、Shadow DOM 内部の細部構造、内部要素名、`iconify-icon` の存在そのものには依存してはなりません（MUST NOT）。将来変更時に互換性を保証しません。

### 閉状態隔離契約

閉状態で本文が操作不能であることは本コンポーネントの本質契約です。したがって、外部スタイルや外部スクリプトで `inert` 前提を破壊してはなりません（MUST NOT）。閉状態コンテンツを視覚的に見せるような override は、契約上サポートしません。

また、この契約はネイティブ `inert` を前提とします。`inert` 非対応環境は本コンポーネントのサポート対象外です。

## 境界条件

### hash 到達時の扱い（採用決定済み・未実装）

URL hash が `ui-details` 内部要素を指す場合に対象 disclosure を自動展開する方針は、仕様として採用済みです。ただし、**現行実装および Storybook に未反映である限り、現行保証には含めません**。

したがって、利用者は現時点でこの挙動へ依存してはなりません（MUST NOT）。

正式反映後は、対象を含む `ui-details` と必要な祖先 `ui-details` を展開対象とし、対象が存在しない場合でも例外を送出しません。

### 基本ケース

可視 summary を与えた通常ケースでは、閉状態で描画され、トリガーは button として機能します。

### `summary` スロット優先

`summary` スロットと `summary` property を同時に与えた場合、表示されるのは `summary` スロットです。`summary` property は表示に寄与しません。

### サマリー未指定

`summary` スロットも `summary` property も与えない利用形態は、標準利用には含めません。本文中の補足 disclosure としては、内容予告性が不足し、読書中の理解負荷を上げやすいためです。

したがって、通常利用では `summary` または `summary` スロットのいずれかを与えなければなりません（MUST）。

例外として、icon-only disclosure を採用する場合に限り、可視 summary の欠如を許容します。この場合、`aria-label` は必須です（MUST）。ただし、この利用は本文中の一般的な補足 disclosure ではなく、限定用途として扱います。

### `aria-label` 空文字

icon-only 利用において `aria-label` が未指定、空文字、または空白のみの場合は契約違反です。実装は例外を送出し、描画継続を保証しません。

### `region=true`

`region=true` の場合、コンテンツは landmark として公開されます。ただし、すべての details を landmark 化すると情報構造が過密になるため、独立セクションとしての読み上げ価値がある場合に限定します。

FAQ の個別項目や軽量な注記のような細粒度補足では、通常 `region` を使いません。単独で見出し付き小節として読ませたい内容に限定して利用します。

### 閉状態の内部フォーカス

閉状態では `inert` により内部対話要素へフォーカス移動できません。これは単なるスタイル上の不可視ではなく、操作上の隔離です。

### 同値代入

`open` に現在値と同じ値を代入しても `toggle` は発火しません。外部同期ロジックはこの前提に依存してよいです。

### 列挙外 `variant`

`variant` に列挙外値を与えた場合、表示は未定義です。利用者は `default` / `bordered` 以外を使ってはなりません（MUST NOT）。

### 現行正式契約の確認点

## 補足

`ui-details` の要点は、見た目上たためることにあるのではありません。**閉状態の内容を対話的にも閉じ、開閉状態を意味として公開し、本文の読書リズムを壊さずに補足情報を差し込めること**にあります。

したがって、今後の変更でも次の点は崩さない方がよいです。

* 開閉トリガーの実体は常にネイティブ `button` であること。
* 閉状態では `inert` により内部対話を隔離すること。
* `summary` スロット優先と `summary` property フォールバックの関係を崩さないこと。
* アクセシブルネームは可視 summary 主体とし、icon-only 時のみ `aria-label` を用いること。

## 現行実装で未対応の事項

本節は、現行の `details.ts` および `details.stories.ts` を基準として、**details コンポーネントとして将来的に検討余地はあるが、現時点では未実装または未公開である事項**を整理するものです。

### 相互排他グループ制御

現行実装は単体 disclosure のみを扱います。複数項目を accordion として束ね、1 つ開いたら他を閉じるような群制御は未対応です。

### `disabled` 状態

現行実装は常にトリガー操作可能であり、開閉を無効化する `disabled` や `readonly` に相当する公開入力を持ちません。

### `summary` スロット内容の実行時バリデーション

本文契約では、`summary` スロットを非対話の phrasing content に制限し、`a`、`button`、`input` などの独立した interactive control を入れてはならないとしています。しかし、現行実装は `summary` スロット内容を実行時に検証しません。

したがって、契約上は不正としたい入力であっても、現時点では DOM 上へそのまま挿入できてしまいます。将来的にこの契約を厳密化する場合は、実行時バリデーションまたは開発時検証を追加する必要があります。

### lazy mount / unmount

閉状態でも本文は DOM に残ります。`inert` による隔離は行いますが、初回展開時のみマウントする lazy mount や、閉時にアンマウントする戦略は未対応です。

### 開閉理由の詳細通知

`toggle` イベントが返す情報は `{ open: boolean }` のみです。ポインター起動、キーボード起動、外部 property 更新などの詳細理由は公開しません。

### 公開メソッド

現行実装は `focus()`、`blur()`、`show()`、`hide()`、`toggle()` などの公開メソッドを持ちません。外部制御は property 更新またはトリガー操作に依存します。

### ハッシュ到達時の自動展開

URL hash が `ui-details` 内部要素を指す場合に親 `ui-details` を自動展開する契約は、採用決定済みですが、現行実装には未反映です。

### 印刷専用契約

印刷時に展開状態をどう扱うか、非表示にするか、常時展開するかといった print 契約は、現時点では未定義です。

### ネイティブ `<details>` 互換 API

現行実装は disclosure の意味を提供しますが、native `<details>` / `<summary>` そのものではありません。そのため、ブラウザ既定の `<details>` 振る舞い、スタイル継承、検索連携などに完全互換ではありません。

### 本節の扱い

本節に記載した事項は、現行公開契約として利用者が依存してよいものではありません。これらを採用する場合は、実装、Storybook、契約書の 3 点を同時に更新し、未対応状態を残したまま公開契約へ昇格させません。
