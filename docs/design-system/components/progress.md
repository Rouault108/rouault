# Progress

## 概要

本書は、`ui-progress` の目標契約を定義します。ここでいう目標契約とは、現行実装の偶然的な振る舞いをそのまま固定するものではなく、長期的な保守性、意味の明瞭さ、およびアクセシビリティの一貫性を優先して採用する公開仕様です。

`ui-progress` は、**完了へ向かう進捗**を表すコンポーネントです。任意の尺度、メーター、評価値、残量、スコアを表すための汎用部品ではありません。`0` から `max` までの進捗を受け取り、その比率を `progressbar` として表現します。

Rouault における progress は読書体験の主役ではありません。したがって、本コンポーネントは視線を奪う装飾ではなく、文脈に付随する静かな補助情報として設計します。

- 意味領域

- タスク制御や再試行
- 完了後の副作用

これらは上位レイヤまたは別コンポーネントの責務です。

## 意味領域

`ui-progress` は **completion progress 専用**です。すなわち、「始点から完了に向かってどこまで進んだか」を表します。

本コンポーネントは次を表しません。

- 任意範囲のスカラー値
- 比較対象付きスコア
- 残量メーター
- 温度、信号強度、満足度などの抽象尺度

これらを扱う必要がある場合は、`ui-progress` を拡張せず、別の意味名を持つコンポーネントへ分離します。

進行開始点は常に `0` です。したがって、本コンポーネントは「始点が固定された進捗」を前提にします。

## 設計原則

### 意味主体はホストです

公開契約の主体は `ui-progress` 自身です。`progressbar` のセマンティクスはホストに載せます。内部ノードは視覚表現のための実装詳細であり、意味の主体ではありません。

### 名前付きが原則です

`ui-progress` は意味を持つ進捗を表すため、アクセシブル名を必須とします。名前なしの progress は本契約では正規入力に含めません。

### 復旧処理と意味契約を分離します

不正入力に対して描画継続のための復旧処理を持つことはありますが、その復旧値に意味を与えません。利用者が依存してよいのは正規入力時の意味契約であって、異常入力時の暫定復旧値ではありません。

### 自然言語は外部責務を優先します

progress 自体は数値進捗を表現する部品です。自然言語の説明文、印刷用接頭辞、ロケール依存表現は極力外部責務とします。

### 公開契約は実装手段に依存しません

公開契約は、利用者が観測できる結果を定義します。内部レイアウト、描画手法、更新機構、フレームワーク固有 API は公開契約に含めません。

## 公開契約

`ui-progress` は `value`、`max`、`label`、`labelRef`、`valueText` を公開入力として扱います。slot は持ちません。公開スタイリング面は CSS Custom Properties のみに限定します。

### 入力契約

| 名前 | 種別 | 必須 | 内容 | 契約 |
| --- | --- | --- | --- | --- |
| `value` | property / attribute | はい | 現在値 | 有限数であり、`0 <= value <= max` を満たさなければなりません |
| `max` | property / attribute | はい | 最大値 | 有限数であり、`max > 0` を満たさなければなりません |
| `label` | property | 条件付き | アクセシブル名 | `labelRef` が未指定の場合に使います |
| `labelRef` | property / attribute (`label-ref`) | 条件付き | 外部ラベル参照 | `label` の代替です。存在する要素 ID を参照しなければなりません |
| `valueText` | property / attribute (`value-text`) | いいえ | 読み上げ用補助文言 | 進捗値と矛盾しない補助表現でなければなりません |

`label` と `labelRef` のいずれか一方は必須です。両方を同時に与える場合、`labelRef` を優先します。

### 公開属性契約

`value` と `max` は HTML 属性として観測可能です。`labelRef` と `valueText` も対応する属性名を持ちます。

| property | attribute | 備考 |
| --- | --- | --- |
| `value` | `value` | 現在値です |
| `max` | `max` | 最大値です |
| `label` | なし | property 専用です |
| `labelRef` | `label-ref` | 外部ラベル参照です |
| `valueText` | `value-text` | 補助文言です |

### 文字列入力の正規化契約

`label`、`labelRef`、`valueText` は次の規則で正規化します。

- 前後空白は除去します。
- 空白のみの文字列は未指定として扱います。
- 空文字相当の `label` は無効です。
- 空文字相当の `labelRef` は無効です。
- 空文字相当の `valueText` は未指定として扱います。

### 小数入力契約

`value` と `max` は整数専用ではありません。小数入力を許容します。

- 視覚上の進捗率は `value / max` の比率に従います。
- 自動割合文言は、四捨五入した整数百分率文字列です。
- 視覚上の進捗率と自動割合文言の完全一致は保証しません。

### `valueText` 契約

`valueText` は自由文ではありますが、同一状態の補助表現でなければなりません。次を許容します。

- `24%`
- `3件中1件完了`
- `同期中、残り2件`

一方で、次のような **数値進捗と矛盾する文言**は許容しません。

- `value=20, max=100` に対する `完了`
- `value=80, max=100` に対する `未開始`

### `labelRef` 契約

`labelRef` は単なる文字列 pass-through ではありません。存在するラベル要素を参照しなければなりません。参照先の解決は利用側の責務です。

## 正規入力と復旧処理

### 正規入力

利用者が依存してよい前提は次のとおりです。

- `max` は有限数であり、`max > 0` です。
- `value` は有限数であり、`0 <= value <= max` です。
- `label` または `labelRef` のいずれかが有効です。
- `valueText` を与える場合、進捗値と矛盾しません。

### 復旧処理

実装は異常入力に対して描画継続のための復旧処理を持つことがあります。たとえば、`value` のクランプや `max` のフォールバックです。しかし、それらは **公開意味契約ではなく、障害緩和策**です。

したがって、次の方針を採ります。

- 異常入力時の復旧値に意味を与えません。
- 復旧値を前提に利用者がロジックを組んではなりません。
- 可能な限り開発時警告を出します。

### 開発時警告

開発時には少なくとも次を警告対象とします。

- `max <= 0`
- `value < 0`
- `value > max`
- `value` または `max` が非有限数
- `label` と `labelRef` の双方が無効

`valueText` と進捗値の意味的整合性は契約上の要件ですが、実装が必ずしも機械的に検出できるとは限りません。したがって、その検査は補助的なものとして扱います。

警告は公開契約の一部ではなく、契約違反を早期発見するための補助手段です。

## 状態モデル

状態は装飾的バリアントではなく、意味と入力条件によって定義します。

### 基本状態

`value=0`、`max>0` の状態です。未開始を意味します。

### 進行中状態

`0 < value < max` の状態です。完了へ向かう途中であることを意味します。

### 完了状態

`value=max` の状態です。完了を意味します。

### 補助文言付き状態

`valueText` を持つ状態です。補助文言は同一状態の補足説明であり、視覚上の進捗率を変更しません。

### 外部ラベル参照状態

`labelRef` により外部ラベルを参照する状態です。アクセシブル名は外部ラベルから決定します。

### 契約違反状態

不正な `value`、`max`、無名構成、矛盾する `valueText` などの状態です。実装が復旧して描画継続することはありますが、正規公開状態としては扱いません。

## Accessibility 契約

### 意味主体

`role="progressbar"` はホスト `ui-progress` に付与します。値属性と名前属性もホストに付与します。

### アクセシブル名

アクセシブル名の決定規則は次のとおりです。

| 条件 | 出力 |
| --- | --- |
| `labelRef` が有効 | 外部ラベル参照を出力し、内蔵ラベル属性は出力しません |
| `labelRef` が無効で `label` が有効 | 内蔵ラベル属性を出力します |
| いずれも無効 | 契約違反です |

### 値属性

- 最小値は `0` 固定です。
- 最大値は `max` です。
- 現在値は `value` です。
- 補助文言は `valueText` を優先し、未指定時は自動割合文字列です。

### 自動割合文言の既定方針

自動生成される補助文言は、四捨五入した整数百分率文字列とします。ロケール依存の自然言語化は行いません。

### 非採用方針

- `aria-live` は progressbar 自体に付与しません。
- 可視ラベル描画を内蔵しません。
- 自然言語の完了通知を内蔵しません。

## DOM 契約

公開契約の単位は `ui-progress` です。内部 DOM 構造は実装詳細です。利用者は内部ノード名、class 名、Shadow DOM の木構造、疑似要素構成に依存してはなりません。

公開上保証するのは次の点のみです。

- ホストが進捗の意味主体であること
- 内部に進捗トラックと充填表現を持つこと
- 内部構造は将来変更可能であること

セマンティクスはホスト側に集中させ、内部ノードは視覚表現のみを担います。

## Visual Contract

### 情報順位

- トラックは背景面です。
- 充填表現は進捗率のみを表現します。
- 色は意味状態を表しません。
- 説明責務はラベルと補助文言に委ねます。

### レイアウト

本コンポーネントは、親が与える幅の中で水平に進捗を表現します。標準用途は独立した進捗表示であり、インラインテキスト中の微小装飾は標準用途に含めません。

充填方向は、目標契約として **論理開始位置から論理終端**を原則とします。物理的な left 固定ではなく、将来的な書字方向に追従可能な設計を優先します。

### 視覚仕様

- トラック背景は控えめな中立色とします。
- 充填表現は進捗率のみを示す単色塗りとします。
- 角丸は十分に大きく、静かな形状を保ちます。
- アニメーションがある場合、変化対象は進捗表現そのものに限定します。
- 色差だけに依存した意味付けは行いません。

### 公開トークン

| 用途 | トークン |
| --- | --- |
| トラック高さ | `--ui-progress-track-size` |
| 充填色 | `--ui-progress-fill-color` |
| トラック色 | `--ui-progress-track-color` |
| 角丸 | `--ui-progress-radius` |
| 変化時間 | `--ui-progress-duration` |
| 変化イージング | `--ui-progress-easing` |

コンポーネント固有トークンの既定値は、foundation token によって定義されることがあります。ただし、foundation token 名そのものは本コンポーネントの公開 API ではありません。

### トークン値域

| トークン | 想定値 |
| --- | --- |
| `--ui-progress-track-size` | 正の長さ値 |
| `--ui-progress-fill-color` | 有効な CSS color |
| `--ui-progress-track-color` | 有効な CSS color |
| `--ui-progress-radius` | 有効な border-radius 値 |
| `--ui-progress-duration` | 有効な time 値 |
| `--ui-progress-easing` | 有効な easing 関数 |

不正なトークン値に対する描画は公開保証しません。

### スタイル公開面

公開スタイル面は CSS Custom Properties のみです。`part` は公開しません。slot も持ちません。内部 DOM への直接依存は禁止します。

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` ではアニメーションを停止します。進捗率そのものは維持します。

### Forced Colors

`forced-colors: active` ではシステムカラーを優先します。独自色指定より可読性を優先します。

### Print

印刷時は視覚バーを補助的扱いとし、値の可読性を優先します。コンポーネント内部で自然言語接頭辞を固定しません。

印刷時に公開上保証するのは次の点です。

- 数値進捗または補助文言が可読なテキストとして取得できること
- 何の進捗かという説明は外部ラベル側が担うこと

## Storybook 契約

Storybook は見本ではなく契約確認点を保持する場所です。少なくとも次の観点を継続的に検証します。

| 検証観点 | 固定する契約 |
| --- | --- |
| 名前付き進捗 | 名前付き progress として成立すること |
| 補助文言 | `valueText` が補助表現として扱われること |
| 外部ラベル参照 | `labelRef` が `label` より優先されること |
| 契約違反入力 | 警告または復旧が行われること |
| Reduced Motion | motion 抑制時にアニメーションが停止すること |
| Forced Colors | システムカラー優先で可読性を維持すること |
| Print | 自然言語固定に依存せず値可読性を維持すること |

Storybook では次を正規例として提示しません。

- 無名状態
- 色変更を意味状態として読む例
- 内部 DOM 構造への依存例

暗色環境への適応はコンポーネント個別責務ではなく、トークン差し替えの結果として扱います。

## 将来拡張の原則

本節は、`ui-progress` に新規機能を追加する際の判断基準を定義します。追加可否は、利便性の高さではなく、**進捗という責務を汚さずに意味を拡張できるか**で判断します。

### 最優先で検討する価値がある拡張

#### indeterminate progress

総量不明の待機状態が頻出する場合、決定進捗とは分離した indeterminate 状態を追加する価値があります。これは本コンポーネントの意味領域を壊さずに補完できる、最優先の拡張候補です。

追加する場合は、次を満たします。

- 決定進捗と indeterminate を同時に成立させません。
- indeterminate 時は `value` / `max` を意味契約から外します。
- 自動割合文言を流用しません。
- motion 抑制環境ではアニメーションを停止します。
- 印刷時は自然言語固定を持ち込まず、値または外部説明に責務を分離します。

### 条件付きで検討する価値がある拡張

#### secondary progress

主進捗とは別に、バッファ、先読み、下準備済み範囲などの副次的進捗を表したい需要が継続的に存在する場合、二層進捗は検討価値があります。

ただし、これは単なる見た目の追加ではなく、意味モデルを一段複雑にします。採用する場合は、次を満たします。

- 主進捗と副進捗の意味を明確に分離します。
- 副進捗は主進捗の代替値として扱いません。
- アクセシビリティ上の主値はあくまで主進捗に限定します。
- 色差だけで意味を伝える設計にしません。

二層進捗の必要性が限定的である場合は、`ui-progress` 本体に持ち込まず、別コンポーネントまたは上位表現で扱います。

#### 論理方向ベースの充填

将来的に書字方向や論理方向への対応が必要になる場合、充填方向を物理方向ではなく論理開始位置から論理終端へ定義する改善は検討価値があります。

これは新機能というより、国際化と長期互換性のための設計改善です。必要性が明確になるまでは目標契約として保持し、実装は段階的に追従します。

### 周辺責務として検討する拡張

#### 可視ラベル連携

可視ラベルや補助テキストを一体で扱う需要が高い場合でも、`ui-progress` 本体にレイアウト責務を持ち込むのではなく、周辺コンポーネントとの組み合わせとして追加します。

#### 可視値表示

進捗率や件数などの可視値表示が頻出する場合でも、`valueText` と混同せず、視覚表示は周辺責務として切り出します。`ui-progress` 自体に `showValue` のような責務を追加しません。

### 採用しない方針

- 汎用 meter への拡張
- `slot` / `part` の追加
- 通知コンポーネント化
- live region の内蔵
- 進捗値算出ロジックの内蔵
- 色による意味状態の標準化
- 完了イベントや状態遷移イベントの内蔵
- 可視値表示や可視ラベル表示の本体内蔵

## 補足

`ui-progress` を小さな部品として保つために重要なのは、見た目のバリエーションを増やすことではなく、**何を表し、何を表さないかを明確に固定すること**です。

そのため、本書では次を中核契約とします。

1. `ui-progress` は completion progress 専用です。
2. アクセシブル名は必須です。
3. 意味主体はホストです。
4. 復旧処理は意味契約ではありません。
5. `valueText` は同一状態の補助表現に限ります。
6. 自然言語責務は外部を優先します。
7. 色は意味状態を表しません。

## 付録: 現行実装との差分

本付録は、目標契約と現行実装の差分を整理するための補助情報です。公開契約の本体ではありません。

### セマンティクスの主体

現行実装では `progressbar` のセマンティクスが内部要素にあります。目標契約ではホスト `ui-progress` を意味主体とします。

### 無名状態

現行実装では名前なし状態で描画継続します。目標契約では無名状態を正規入力に含めません。

### 復旧値の扱い

現行実装では `max <= 0` のフォールバック値などが外部から観測可能です。目標契約では、それを意味契約へ昇格させません。

### 充填方向

現行実装では物理方向に寄った描画を行います。目標契約では論理開始位置から論理終端への充填を原則とします。

### 印刷文言

現行実装では印刷時に自然言語接頭辞を内部生成します。目標契約ではコンポーネント内部の自然言語固定を避けます。

### 開発時警告

現行実装では警告対象が限定的です。目標契約では契約違反全般をより広く警告対象とします。

### 外部ラベル参照

現行実装では `aria-labelledby` 透過に近い扱いです。目標契約では `labelRef` を公開入力とし、有効な参照であることを利用側責務として明示します。

### 公開入力名

現行実装は `ariaLabelledBy` / `aria-labelledby` を公開面に持ちます。目標契約では、ARIA 属性名の透過ではなく、ドメイン API として `labelRef` / `label-ref` へ整理します。

### 公開トークン名

現行実装は `--ui-progress-track-height` と `--ui-progress-bar-background` を中心に公開しています。目標契約では、意味がより明確なコンポーネント固有トークン群へ再編します。

### Storybook の正規例

現行 Storybook には無名状態の境界条件例と、色差が意味状態に見え得る例が残っています。目標契約では、これらを正規例として扱いません。
