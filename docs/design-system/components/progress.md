# Progress

## 概要

本書は、`ui-progress` の公開契約を定義します。ここでいう公開契約とは、利用者が依存してよい意味、入力、観測結果、および検証観点を定めるものです。現行実装の偶然的な振る舞いを固定することは目的としません。

`ui-progress` は、**完了へ向かう決定進捗**を表すコンポーネントです。任意の尺度、メーター、評価値、残量、スコアを表すための汎用部品ではありません。`0` から `max` までの進捗を受け取り、その比率を `progressbar` として表現します。

Rouault における progress は読書体験の主役ではありません。したがって、本コンポーネントは視線を奪う装飾ではなく、文脈に付随する静かな補助情報として設計します。

- 意味領域
- 設計原則

- DOM 契約

これらは上位レイヤ、周辺コンポーネント、または別コンポーネントの責務です。

## 意味領域

`ui-progress` は **completion progress 専用**です。すなわち、「始点から完了に向かってどこまで進んだか」を表します。

本コンポーネントは次を表しません。

- 任意範囲のスカラー値
- 比較対象付きスコア
- 残量メーター
- 温度、信号強度、満足度などの抽象尺度
- 総量不明の待機状態
- 主進捗とは別の副次的進捗

これらを扱う必要がある場合は、`ui-progress` を拡張せず、別の意味名を持つコンポーネントまたは別仕様へ分離します。

進行開始点は常に `0` です。したがって、本コンポーネントは「始点が固定された進捗」を前提にします。

## 設計原則

### 意味主体はホストです

公開契約の主体は `ui-progress` 自身です。`progressbar` のセマンティクス、値、名前はホストに載せます。内部ノードは視覚表現のための実装詳細であり、意味の主体ではありません。

### 名前付きが原則です

`ui-progress` は意味を持つ進捗を表すため、アクセシブル名を必須とします。名前なしの progress は本契約では正規入力に含めません。

### 復旧処理と意味契約を分離します

異常入力に対して描画継続のための復旧処理を持つことはありますが、その復旧値に意味を与えません。利用者が依存してよいのは正規入力時の意味契約であって、異常入力時の暫定復旧値ではありません。

### 自然言語は外部責務を優先します

`ui-progress` 自体は数値進捗を表現する部品です。自然言語の説明文、印刷用接頭辞、ロケール依存表現、可視ラベル、可視値表示は本体責務に含めません。

可視ラベルや補助テキストを一体で扱う必要がある場合でも、`ui-progress` 本体にレイアウト責務を持ち込まず、周辺コンポーネントとの組み合わせで扱います。進捗率や件数などの可視値表示が必要な場合も、`valueText` と混同せず、視覚表示は周辺責務として切り出します。

### 公開契約は観測結果で定義します

公開契約は、利用者が入力でき、観測でき、検証できる結果を定義します。内部レイアウト、描画手法、更新機構、フレームワーク固有 API は公開契約に含めません。

## 公開契約

`ui-progress` は `value`、`max`、`label`、`labelRef`、`valueText` を公開入力として扱います。slot は持ちません。公開スタイリング面は CSS Custom Properties のみに限定します。

### 公開入力一覧

| 名前        | 種別                                | 必須     | 内容               |
| ----------- | ----------------------------------- | -------- | ------------------ |
| `value`     | property / attribute                | はい     | 現在値             |
| `max`       | property / attribute                | はい     | 最大値             |
| `label`     | property                            | 条件付き | アクセシブル名     |
| `labelRef`  | property / attribute (`label-ref`)  | 条件付き | 外部ラベル参照     |
| `valueText` | property / attribute (`value-text`) | いいえ   | 読み上げ用補助文言 |

### 正規入力

利用者が依存してよい正規入力は次のとおりです。

- `max` は有限数であり、`max > 0` です。
- `value` は有限数であり、`0 <= value <= max` です。
- `labelRef` を指定しない場合、`label` は正規化後に空でない文字列です。
- `labelRef` を指定する場合、`labelRef` は正規化後に空でない文字列であり、参照先要素が存在します。
- `valueText` を指定する場合、正規化後に空でない文字列であり、数値進捗と矛盾しません。

### 公開属性契約

`value` と `max` は HTML 属性として観測可能です。`labelRef` と `valueText` も対応する属性名を持ちます。

| property    | attribute    | 備考               |
| ----------- | ------------ | ------------------ |
| `value`     | `value`      | 現在値です         |
| `max`       | `max`        | 最大値です         |
| `label`     | なし         | property 専用です  |
| `labelRef`  | `label-ref`  | 外部ラベル参照です |
| `valueText` | `value-text` | 補助文言です       |

## 入力解釈規則

### 数値入力の解釈規則

`value` と `max` は整数専用ではありません。小数入力を許容します。

- property 経由では、有限な JavaScript number のみを正規入力として扱います。
- attribute 経由では、前後空白除去後の文字列全体が 10 進数表記として解釈可能である場合に限り正規入力として扱います。
- `NaN`、`Infinity`、`-Infinity`、空文字、部分解釈に依存する文字列は正規入力に含めません。
- 視覚上の進捗率は `value / max` の比率に従います。
- 自動割合文言は、`(value / max) * 100` を四捨五入した整数百分率文字列です。
- 視覚上の進捗率と自動割合文言の完全一致は保証しません。

### 文字列入力の正規化規則

`label`、`labelRef`、`valueText` は次の規則で正規化します。

- 前後空白は除去します。
- 空白のみの文字列は未指定として扱います。
- 正規化後に空となる `label` は無効です。
- 正規化後に空となる `labelRef` は無効です。
- 正規化後に空となる `valueText` は未指定として扱います。

### `labelRef` の解釈規則

`labelRef` は単なる文字列 pass-through ではありません。外部ラベル参照を意味する公開入力です。

- `labelRef` は、同一 document 内の既存要素 ID を参照しなければなりません。
- `labelRef` が指定された場合、アクセシブル名の決定には `labelRef` を用います。
- `labelRef` が指定された場合、`label` はフォールバックとして使用しません。
- `labelRef` が指定され、かつ参照先が存在しない場合は契約違反です。

### `valueText` の解釈規則

`valueText` は、数値進捗と**同一状態**を別の表現で補足するための入力です。自由文ではありますが、任意の文言を許容するものではありません。

次は許容します。

- `24%`
- `3件中1件完了`
- `同期中、残り2件`

一方、次のような**数値進捗と矛盾する文言**は許容しません。

- `value=20, max=100` に対する `完了`
- `value=80, max=100` に対する `未開始`

`valueText` の意味的整合性は著者責務です。実装は補助的な検査を行うことがありますが、完全な自動検証は公開保証しません。

## 契約違反と復旧処理

### 契約違反

次は契約違反です。

- `max <= 0`
- `value < 0`
- `value > max`
- `value` または `max` が非有限数
- `labelRef` 未指定かつ `label` 無効
- `labelRef` 指定済みかつ参照先未解決
- `valueText` が数値進捗と矛盾する

契約違反は公開状態ではありません。利用者はこれらの状態に依存してはなりません。

### 復旧処理

実装は異常入力に対して描画継続のための復旧処理を持つことがあります。たとえば、`value` のクランプや `max` のフォールバックです。しかし、それらは **公開意味契約ではなく、障害緩和策**です。

したがって、次の方針を採ります。

- 異常入力時の復旧値に意味を与えません。
- 復旧値を前提に利用者がロジックを組んではなりません。
- 契約違反状態を正規例として扱いません。
- 可能な限り開発時警告を出します。

### 開発時警告

開発時には少なくとも次を警告対象とします。

- `max <= 0`
- `value < 0`
- `value > max`
- `value` または `max` が非有限数
- `labelRef` 未指定かつ `label` 無効
- `labelRef` 指定済みかつ参照先未解決

`valueText` の意味的整合性は契約上の要件ですが、機械的に確定できない場合があります。したがって、その検査は補助的なものとして扱います。

警告は公開契約の一部ではなく、契約違反を早期発見するための補助手段です。

## 状態モデル

状態は装飾的バリアントではなく、意味と入力条件によって定義します。本コンポーネントの公開状態は、**主状態**と**付加軸**の組み合わせで表します。

### 主状態

#### 未開始状態

`value = 0` かつ `max > 0` の状態です。始点にあり、完了していないことを意味します。

#### 進行中状態

`0 < value < max` の状態です。完了へ向かう途中であることを意味します。

#### 完了状態

`value = max` の状態です。完了したことを意味します。

### 付加軸

#### ラベル供給軸

アクセシブル名の供給元は次のいずれかです。

- `label`
- `labelRef`

両者は同時に公開状態を構成しません。`labelRef` が指定された場合、公開上の名前供給元は `labelRef` です。

#### 補助文言軸

`valueText` は、主状態を変更しない補助軸です。存在しても、未開始 / 進行中 / 完了の意味を変えません。

### 契約違反状態

契約違反状態は存在し得ますが、正規公開状態としては扱いません。実装が描画継続することはありますが、利用者が依存してよい状態ではありません。

## Accessibility 契約

### 意味主体

`role="progressbar"` はホスト `ui-progress` に付与します。値属性と名前属性もホストに付与します。

### アクセシブル名

アクセシブル名の決定規則は次のとおりです。

| 条件                                 | 結果                         |
| ------------------------------------ | ---------------------------- |
| `labelRef` が指定され、参照先が有効  | 外部ラベル参照で名前を与える |
| `labelRef` 未指定かつ `label` が有効 | `label` で名前を与える       |
| 上記のいずれも満たさない             | 契約違反                     |

### 値属性

- 最小値は `0` 固定です。
- 最大値は `max` です。
- 現在値は `value` です。
- 補助文言は `valueText` を優先し、未指定時は自動割合文字列です。

### 自動割合文言の既定方針

自動生成される補助文言は、四捨五入した整数百分率文字列とします。ロケール依存の自然言語化は行いません。

### 非採用方針

- `aria-live` は progressbar 自体に付与しません。
- 可視ラベル描画を内蔵しません。
- 自然言語の完了通知を内蔵しません。

## DOM 契約

公開契約の単位は `ui-progress` です。内部 DOM 構造は実装詳細です。利用者は内部ノード名、class 名、Shadow DOM の木構造、疑似要素構成に依存してはなりません。

公開上保証するのは次の点のみです。

- ホストが進捗の意味主体であること
- 内部に進捗トラックと充填表現を持つこと
- 充填表現の割合が正規入力時の `value / max` に対応すること
- 内部構造は将来変更可能であること

セマンティクスはホスト側に集中させ、内部ノードは視覚表現のみを担います。

---

## Visual Contract

### 情報順位

- トラックは背景面です。
- 充填表現は進捗率のみを表現します。
- 色は意味状態を表しません。
- 説明責務はラベルと補助文言に委ねます。

### レイアウト

本コンポーネントは、親が与える幅の中で水平に進捗を表現します。標準用途は独立した進捗表示であり、インラインテキスト中の微小装飾は標準用途に含めません。

充填方向は **論理開始位置から論理終端**を原則とします。物理的な left 固定ではなく、書字方向および論理方向に追従可能な設計を公開契約として採用します。

### 公開視覚保証

- 正規入力時、充填率は `0%` から `100%` の範囲に収まります。
- トラックと充填表現は視覚的に区別可能でなければなりません。
- 色差だけに依存した意味付けは行いません。
- 視覚表現の中に固定文言を内蔵しません。
- アニメーションがある場合、変化対象は進捗表現そのものに限定します。

### 公開トークン

| 用途           | トークン                    |
| -------------- | --------------------------- |
| トラック高さ   | `--ui-progress-track-size`  |
| 充填色         | `--ui-progress-fill-color`  |
| トラック色     | `--ui-progress-track-color` |
| 角丸           | `--ui-progress-radius`      |
| 変化時間       | `--ui-progress-duration`    |
| 変化イージング | `--ui-progress-easing`      |

コンポーネント固有トークンの既定値は foundation token によって定義されることがあります。ただし、foundation token 名そのものは本コンポーネントの公開 API ではありません。

### トークン値域

| トークン                    | 想定値                  |
| --------------------------- | ----------------------- |
| `--ui-progress-track-size`  | 正の長さ値              |
| `--ui-progress-fill-color`  | 有効な CSS color        |
| `--ui-progress-track-color` | 有効な CSS color        |
| `--ui-progress-radius`      | 有効な border-radius 値 |
| `--ui-progress-duration`    | 有効な time 値          |
| `--ui-progress-easing`      | 有効な easing 関数      |

不正なトークン値に対する描画は公開保証しません。

### スタイル公開面

公開スタイル面は CSS Custom Properties のみです。`part` は公開しません。slot も持ちません。内部 DOM への直接依存は禁止します。

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` ではアニメーションを停止します。進捗率そのものは維持します。

### Forced Colors

`forced-colors: active` ではシステムカラーを優先します。独自色指定より可読性を優先します。

### Print

印刷時は視覚バーを補助的扱いとし、値の可読性を優先します。コンポーネント内部で自然言語接頭辞を固定しません。

印刷時に公開上保証するのは次の点です。

- `valueText` 指定時は、その値が印刷結果で可視テキストとして読めること
- `valueText` 未指定時は、自動割合文言が印刷結果で可視テキストとして読めること
- 上記の可視テキストは CSS generated content のみに依存しないこと
- 何の進捗かという説明は外部ラベル側が担うこと

## Storybook 契約

Storybook は見本ではなく契約確認点を保持する場所です。少なくとも次の観点を継続的に検証します。

| 検証観点        | 固定する契約                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------------- |
| 名前付き進捗    | `label` により名前付き progress として成立すること                                                |
| 外部ラベル参照  | `labelRef` により名前付き progress として成立すること                                             |
| `labelRef` 優先 | `label` と `labelRef` を同時指定した場合、公開上の名前供給元が `labelRef` であること              |
| 無効 `labelRef` | `labelRef` 指定時に参照先未解決なら契約違反として扱われ、`label` に黙ってフォールバックしないこと |
| 補助文言        | `valueText` が主状態を変更せず、補助表現として扱われること                                        |
| 契約違反入力    | 警告観測と描画継続が区別して確認できること                                                        |
| Reduced Motion  | motion 抑制時にアニメーションが停止すること                                                       |
| Forced Colors   | システムカラー優先で可読性を維持すること                                                          |
| Print           | 印刷時に可視テキストとして値を読めること                                                          |

Storybook では次を正規例として提示しません。

- 無名状態
- 色変更を意味状態として読む例
- 内部 DOM 構造への依存例
- 矛盾した `valueText` を正規使用例として見せる例

暗色環境への適応はコンポーネント個別責務ではなく、トークン差し替えの結果として扱います。

---

## 非採用方針

本書の契約では、次を採用しません。

- 汎用 meter への拡張
- indeterminate progress の同居
- secondary progress の同居
- `slot` / `part` の追加
- 通知コンポーネント化
- live region の内蔵
- 進捗値算出ロジックの内蔵
- 色による意味状態の標準化
- 完了イベントや状態遷移イベントの内蔵
- 可視値表示や可視ラベル表示の本体内蔵

これらが必要な場合は、別責務として分離します。

## 現行実装で未対応の事項

### 公開 API 再設計として未対応の事項

- `aria-labelledby` 透過ではなく `labelRef` / `label-ref` を公開入力とする再設計
- `labelRef` 指定時に `label` へ黙ってフォールバックしない契約の明示化
- 名前付き原則を前提にした API への再整理
- 外部ラベル参照の有効性を前提とした開発時検証

### 公開スタイル面の再設計として未対応の事項

- `--ui-progress-track-size` への移行
- `--ui-progress-fill-color` への移行
- `--ui-progress-track-color` への移行
- `--ui-progress-radius` への移行
- `--ui-progress-duration` への移行
- `--ui-progress-easing` への移行
- foundation token 直参照を前提にしないコンポーネント固有トークン面への再編

### 目標契約に対して未対応の整備事項

- ホスト主体のセマンティクス
- 無名状態を契約違反として扱う実装上の明示化
- 契約違反全般に対する広い警告
- `labelRef` 未解決時の契約違反化
- コンポーネント内部自然言語の排除
- 印刷時に CSS generated content のみに依存しない値可読化
- 色と意味状態の厳密分離を反映した Storybook 構成
- 無名状態を正規例から除外した Storybook 構成
- 公開 API 名と Storybook 表示名の目標契約への追従

## 補足

`ui-progress` を小さな部品として保つために重要なのは、見た目のバリエーションを増やすことではなく、**何を表し、何を表さないかを明確に固定すること**です。

そのため、本書では次を中核契約とします。

1. `ui-progress` は completion progress 専用です。
2. アクセシブル名は必須です。
3. 意味主体はホストです。
4. 復旧処理は意味契約ではありません。
5. `labelRef` 指定時は `label` に黙ってフォールバックしません。
6. `valueText` は同一状態の補助表現に限ります。
7. 自然言語責務は外部を優先します。
8. 色は意味状態を表しません。

## 付録: 現行実装との差分

本付録は、目標契約と現行実装の差分を整理するための補助情報です。公開契約の本体ではありません。

### セマンティクスの主体

現行実装では `progressbar` のセマンティクスが内部要素にあります。目標契約ではホスト `ui-progress` を意味主体とします。

### 無名状態

現行実装では名前なし状態で描画継続します。目標契約では無名状態を正規入力に含めません。

### 復旧値の扱い

現行実装では `max <= 0` のフォールバック値などが外部から観測可能です。目標契約では、それを意味契約へ昇格させません。

### `labelRef` の失敗時挙動

現行実装では `aria-labelledby` 透過に近い扱いです。目標契約では `labelRef` を公開入力とし、指定時に参照先未解決なら契約違反とします。

### 状態モデル

現行文書では補助文言や外部ラベル参照が主状態と同列に並びます。目標契約では、主状態と付加軸を分離して定義します。

### 印刷契約

現行文書では印刷時の値可読性の保証対象が曖昧です。目標契約では、`valueText` または自動割合文言が可視テキストとして読めることを保証します。

### Storybook の確認点

現行文書では契約違反入力について「警告または復旧」としていました。目標契約では、警告観測と描画継続を分けて確認します。

### 適用範囲

現行文書では indeterminate progress を将来拡張候補として強く残していました。目標契約では、現在の意味領域から外し、本書の適用範囲外とします。
