# Slider

## 概要

本書は、`ui-slider` の公開契約、値モデル、操作契約、アクセシビリティ、および視覚契約を定義するものです。

`ui-slider` は、音量、明るさ、倍率、しきい値など、**量子化規則を持つ数値**を 1 軸上で調整するためのコンポーネントです。単に値を左右へ動かせる入力を描画するのではなく、**どの範囲を有効値として扱うか**、**不正な入力値をどのように正規化するか**、**入力中の更新と確定後の更新をどのように分離するか**、**Shadow DOM 内部にネイティブ range input を保持したままどのように視覚を差し替えるか**を公開契約として固定します。

本コンポーネントは、ネイティブ `<input type="range">` を透明にして最前面に配置する **Input-on-Top Overlay パターン**を採用します。これは見た目だけを自作して操作を模倣するのではなく、**実体として range input を維持したまま、カスタムトラックと Thumb を背面で同期させる**ための設計です。

Rouault における slider は、値調整のための操作部品であると同時に、**本文や注記の読書リズムを乱さず、静かに操作できること**を求めます。したがって、本コンポーネントの契約は、触覚的な追従性と、**「没入して読む」ことのできるデザイン**の維持を両立する方向で定義します。

## 適用範囲

本書は、`ui-slider` の**現行公開契約**のみを対象とします。対象は次のとおりです。

- 公開入力
- 値の正規化規則
- イベント契約
- キーボード契約
- DOM / Accessibility 契約
- 視覚契約
- 環境別の振る舞い
- 境界条件
- Storybook による契約確認点

一方で、本書は次の事項を扱いません。

- 値変更に応じて何を更新するかという上位アプリケーション責務
- 現在値ラベル、単位表示、補助説明文の具体的文言設計
- 値意味フォーマッタ、`aria-valuetext` 生成、意味付き値読上げ API などの文脈化された値表現
- `readonly` 相当の第三状態
- 目盛り、ラベル刻み、ティックマーク、ツールチップなど周辺 UI の詳細設計
- 範囲入力を 2 つ以上組み合わせたレンジセレクタ、および複数 thumb を持つ slider
- 数値入力欄との双方向同期ロジック
- 縦向き slider、RTL / 双方向書字における完全な増減方向契約
- データ保存、送信、永続化の責務
- 将来拡張候補、未対応事項、実装上の検討メモ

これらは上位レイヤ、別コンポーネント、または設計メモの責務です。

## 公開契約

### 入力契約

`ui-slider` は、`min`、`max`、`step`、`value`、`label`、`disabled` を公開入力として扱います。

`min` の既定値は `0`、`max` の既定値は `100`、`step` の既定値は `1` です。`value` が未指定の場合、初期値は**正規化後の `min`**を採用します。

`label` は公開契約上必須です。実装上は未指定時に開発時警告を出し、アクセシブル名として `"Slider"` をフォールバック使用しますが、これは障害回避用の最低保証にすぎません。利用者は必ず文脈に即した `label` を指定しなければなりません。

| 名前       | 種別                 | 必須   | 内容                       | 契約                                                             |
| ---------- | -------------------- | ------ | -------------------------- | ---------------------------------------------------------------- |
| `min`      | property / attribute | いいえ | 最小値                     | 数値として扱います。既定値は `0` です                            |
| `max`      | property / attribute | いいえ | 最大値                     | 数値として扱います。既定値は `100` です                          |
| `step`     | property / attribute | いいえ | 増減の刻み幅               | `> 0` の数値を正規入力とします。既定値は `1` です                |
| `value`    | property / attribute | いいえ | 現在値                     | 未指定時は正規化後の `min` を採用します                          |
| `label`    | property / attribute | はい   | スクリーンリーダー用ラベル | 空文字は契約違反です。実装上は `"Slider"` をフォールバックします |
| `disabled` | property / attribute | いいえ | 無効状態                   | `true` の場合、操作を受け付けません                              |

### スロット契約

スロットは `prefix` と `suffix` を持ちます。

| 名前     | 種別       | 位置づけ | 内容                                           |
| -------- | ---------- | -------- | ---------------------------------------------- |
| `prefix` | named slot | 補助表示 | アイコン、単位、最小値ラベルなどを配置します   |
| `suffix` | named slot | 補助表示 | アイコン、現在値、最大値ラベルなどを配置します |

`prefix` と `suffix` は補助表示のための公開面です。`ui-slider` 自身は現在値テキストを自動描画しません。現在値表示が必要な場合、利用側が `suffix` などで構成します。

`prefix` と `suffix` は原則として、アイコン、単位、最小値ラベル、最大値ラベル、現在値表示などの**非対話な補助表示**を主用途とします。ボタンやメニューなどの対話要素を配置すること自体は技術的には可能ですが、それらは slider の一部ではなく隣接 UI として扱います。slider 本体の操作責務、フォーカス順序、アクセシビリティ意味をスロット内要素へ委譲してはなりません。

`suffix` 内で数値を表示する場合、実装は `font-variant-numeric: tabular-nums` によるジッター抑制を想定しています。したがって、連続更新する数値を表示する場合は、幅揺れを防ぐ構成を推奨します。

### 公開メソッド

`ui-slider` は、ホスト要素への基本操作を内部 input へ委譲するため、次の公開メソッドを持ちます。

| 名前              | 種別   | 契約                                                |
| ----------------- | ------ | --------------------------------------------------- |
| `focus(options?)` | method | 内部 `input[type="range"]` にフォーカスを委譲します |
| `blur()`          | method | 内部 `input[type="range"]` からフォーカスを外します |

利用者は Shadow DOM を直接探索せず、これらの公開メソッドを使用します。

### 属性反映契約

公開入力のうち、`min`、`max`、`step`、`value`、`label`、`disabled` は property と attribute の両面から操作できます。boolean 値である `disabled` は attribute の有無で反映します。数値入力は反映後に正規化されます。

一方で、公開入力として定義していないネイティブ `input[type="range"]` 属性を包括的に透過する契約は持ちません。`name`、`tabindex`、`autofocus`、`required` などを host へ与えても、内部 input へ自動委譲される前提では扱いません。

| property   | attribute  | reflect | 備考                                             |
| ---------- | ---------- | ------- | ------------------------------------------------ |
| `min`      | `min`      | あり    | 列挙ではなく数値として扱います                   |
| `max`      | `max`      | あり    | 列挙ではなく数値として扱います                   |
| `step`     | `step`     | あり    | `<= 0` または非数値は `1` にフォールバックします |
| `value`    | `value`    | あり    | 正規化後の値へ同期されます                       |
| `label`    | `label`    | あり    | 空文字は契約違反です                             |
| `disabled` | `disabled` | あり    | boolean attribute として扱います                 |

### フォーム連携契約

`ui-slider` は現時点で form-associated custom element ではありません。内部に `input[type="range"]` を保持しますが、その値がフォーム送信、フォームリセット、`name` 属性連携へ自動参加する契約は持ちません。

したがって、フォーム値として送信したい場合は、上位レイヤで hidden input などへ明示同期します。利用者は `ui-slider` 単体がネイティブ form control と同等に送信参加する前提で実装してはなりません。

将来 form-associated custom element 化を行う可能性は否定しませんが、それは現行公開契約には含みません。現時点では、フォーム参加は本コンポーネントの責務外です。

### 責務範囲

責務範囲には、range input の保持、値正規化、`input` と `change` の再発火、フォーカスの Thumb への視覚移譲、無効状態の制御、強制カラー環境での可視性確保を含みます。

一方で、次の事項は責務に含めません。

- 現在値の文言生成
- 単位表示
- `aria-valuetext` を含む意味付き値表現
- 目盛り表示、ラベル刻み、ティックマーク
- ツールチップや常時値ラベルの内蔵表示
- 補助説明文
- `readonly` 相当の第三状態
- 外部 state 管理
- 複数スライダー間の連動
- 複数 thumb を持つ range selector

これらが必要な場合は、上位レイヤまたは別コンポーネントで構成します。

## 状態モデル

### 1. 値状態

`value` は現在値です。ただし、公開上の `value` は入力値そのものではなく、**常に正規化後の canonical value** です。したがって、`value="35"` かつ `step="10"` のような構成では、最終的な公開値は `40` になる場合があります。

この契約により、利用者は `value` を「最後に与えた値」ではなく、**現在有効な値**として扱います。

### 2. 正規化状態

`ui-slider` は、入力値をそのまま受理するのではなく、次の規則で正規化します。

1. `min` と `max` が数値でない場合、既定値 `0` と `100` を用います。
2. `min > max` の場合、値を入れ替えます。
3. `step <= 0` または非数値の場合、`1` を用います。
4. `value` が未指定の場合、正規化後の `min` を採用します。
5. `value` は `min...max` にクランプします。
6. クランプ後の値を、`min` 基準で最も近い有効ステップへ丸めます。
7. ちょうど中間値に位置する場合は、大きい側の有効ステップへ丸めます。
8. 小数ステップでは、`step` の小数桁精度に揃えて丸めます。
9. 公開 `value` は正規化後の値へ同期されます。

利用者は、与えた `value` がそのまま保持されるとは限らない前提で扱います。特に `step` に合わない値、範囲外値、`min > max` の構成は、**正規化後の結果に依存する契約**です。

### 3. プログラム更新状態

property や attribute の設定、またはそれに伴う正規化による値更新は、ユーザー操作イベントではありません。したがって、`min`、`max`、`step`、`value` をプログラムから変更しても、`input` と `change` は自動発火しません。利用者はプログラム変更の通知をこれらのイベントに依存してはなりません。

### 4. 範囲状態

`min` と `max` は値域を表します。`min < max` が正規形ですが、入力上は逆順指定も受け入れ、内部で入れ替えます。`min === max` の場合、値域は 0 となります。

このとき `ui-slider` は **値域ゼロの有効入力** として扱います。すなわち、`disabled` へ自動昇格はせず、要素自体は存在し続けますが、値は実質的に変化しません。見た目としては動かせないスライダーに見えても、意味論上は disabled とは別状態です。

## 操作契約

### イベント契約

`input` は、ドラッグ中やキー操作中など、値が変化するたびに発火する追従イベントです。利用側は、現在値表示の同期や軽量なプレビュー更新など、逐次反応をここへ接続します。

`change` は、UI 操作単位の確定を表すイベントです。利用側は、保存、重い再計算、確定後の副作用などをここへ接続します。

`ui-slider` は、内部のネイティブ `input[type="range"]` が発火する `input` と `change` を受け取り、自身から再発火します。

- `input` は値が変化するたびに発火します
- `change` は値の変更が確定した時点で発火します
- 両イベントは `bubbles: true` かつ `composed: true` で再発火します
- 再発火されるイベントは `CustomEvent` ではなく plain `Event` です
- `detail` は持ちません
- 利用者はイベントから値を推測するのではなく、受信時点の `ui-slider.value` を読みます
- `disabled=true` の場合、値更新もイベント再発火も行いません
- 同一操作において両方が発火する場合、順序は `input` が先、`change` が後です

property や attribute の変更、およびそれに伴う正規化はユーザー操作ではありません。したがって、`min`、`max`、`step`、`value` のプログラム変更によって `input` と `change` が自動発火する契約は持ちません。

### キーボード契約

ネイティブ range input の標準挙動により、Right、Up、Left、Down、Home、End はブラウザ標準に従います。加えて、本コンポーネントは `PageUp` と `PageDown` を**`step * 10` の増減**として明示的に正規化します。

したがって、公開契約として `ui-slider` 自身が独自保証するのは `PageUp` と `PageDown` のみです。Arrow 系および `Home` と `End` は、range input の標準意味を利用する前提で扱います。

| キー       | 契約                       |
| ---------- | -------------------------- |
| `PageUp`   | `step * 10` で増加させます |
| `PageDown` | `step * 10` で減少させます |

`PageUp` と `PageDown` の処理順序は次のとおりです。

1. `step * 10` を large step として算出します
2. 現在値から次の値を算出します
3. `min...max` にクランプします
4. `step` にスナップします
5. 小数精度丸めを行います
6. 値が変化した場合に `input` を発火し、その後に `change` を発火します

Arrow 系および `Home` と `End` について、`ui-slider` 独自の増減量や正規化順序を外部契約として期待してはなりません。

### disabled 状態

`disabled=true` の場合、内部 input は `disabled` となり、ポインター操作およびキーボード操作を受け付けません。視覚上は無効状態として表現されます。

無効状態は単なる見た目ではなく、**非操作・タブ停止・イベント非発火**を意味します。利用者は disabled な slider から `input` や `change` が来る前提で設計してはなりません。

`disabled` は、値域ゼロや読み取り専用状態とは別概念です。`min === max` だからといって `disabled` と同一視してはなりません。

また、現行公開契約には、**値は提示するが変更のみ禁止する `readonly` 相当状態**は含みません。変更禁止かつ可読・可視を両立したい場合は、上位レイヤで別途扱います。

## DOM / Accessibility

ルートは `:host` です。Shadow DOM 内部に単一のネイティブ `input[type="range"]` を持ち、その背面に `.track`、`.fill`、`.thumb` を配置します。

```text
<ui-slider>
  <slot name="prefix"></slot>
  #shadow-root
    <div class="slider-container">
      <input type="range" />
      <div class="track" part="track">
        <div class="fill" part="fill"></div>
        <div class="thumb" part="thumb"></div>
      </div>
    </div>
  <slot name="suffix"></slot>
</ui-slider>
```

### 対話主体

対話主体はネイティブ `input[type="range"]` です。カスタムの `.thumb` や `.track` は視覚表現にすぎず、ポインターイベントを受け取りません。これにより、スクリーンリーダー、キーボード操作、ブラウザ標準の range semantics を保持します。

### Accessibility 契約

アクセシビリティ上の公開契約は次のとおりです。

- 対話主体は常にネイティブ `input[type="range"]` です
- `label` は必須であり、内部 input の `aria-label` に反映します
- `label` が未指定または空文字の場合でも、実装は `"Slider"` をフォールバックしてアクセシブル名の空欄化を防ぎます
- `aria-valuemin`、`aria-valuemax`、`aria-valuenow` は正規化後の `min`、`max`、`value` を反映します
- `disabled=true` の場合、内部 input に `disabled` を付与します
- フォーカス可視表示は input 自身ではなく Thumb 側へ視覚移譲します
- 操作可能領域は input 側で確保し、少なくとも **44 × 44 CSS px 以上相当**を設計基準とします

アクセシブル名の正規入力は `label` のみです。`aria-labelledby`、`aria-describedby`、`aria-valuetext` などの関係属性および補助属性は、現時点では公開透過契約に含めません。利用者は、これらが host から内部 input へ自動委譲される前提で実装してはなりません。

また、本コンポーネントは現時点で、値意味フォーマッタや意味付き値読上げ API を公開契約として持ちません。数値そのものではなく文脈化された値表現が必要な場合は、上位レイヤで補います。

`label` 必須の品質担保は、ランタイム例外による強制ではなく、Storybook、テスト、レビューによる静的または準静的な検証を主とします。`"Slider"` フォールバックは契約順守の代替ではなく、アクセシブル名の空欄化を避けるための最低保証です。

また、外部 `<label>` 要素とのネイティブな labelable 連携も公開契約に含めません。`<label for="...">` や label 包含によって host と内部 input がネイティブ input 同等に結び付く前提で設計してはなりません。

本コンポーネントで重要なのは、見た目だけをスライダーらしく見せることではなく、**実体として range input を維持すること**です。`div` のドラッグ模倣や ARIA role のみの代替には依存しません。

### フォーカス移譲契約

フォーカス可視表示は `input:focus-visible ~ .track .thumb` という兄弟セレクタにより Thumb 側へ視覚移譲します。したがって、フォーカスリングの見た目は Thumb に現れますが、実際のフォーカス対象は常に input です。

利用者は、Thumb 自体がフォーカス主体である前提で実装してはなりません。

## 視覚契約

`ui-slider` の視覚契約は、値域全体、現在値までの到達量、現在位置の 3 つを識別可能に表現することにあります。視覚はカスタムであっても、操作主体は常にネイティブ `input[type="range"]` とします。

### 情報順位

- `.track` は値域全体を示します
- `.fill` は現在値までの到達量を示します
- `.thumb` は現在位置と操作主体を示します

本文近傍で使用する場合、最も強く知覚されてよいのは現在位置であり、トラック全体や補助表示が本文より優先的に視線を奪うことを前提にしてはなりません。

### Overlay パターン

視覚はカスタムですが、操作面はネイティブ input が最前面にあります。利用者は、見えている Thumb 自体を直接つかむ実装ではなく、**見えている操作領域のどこを操作しても実体 input が受ける構造**であることを前提に扱います。

### レイアウト契約

ルートは横並びの flex コンテナです。`prefix`、スライダー本体、`suffix` の順に配置します。スライダー本体は残余幅を占有し、トラックはその全幅に広がります。

`ui-slider` 自身は横幅を自律決定する部品ではなく、親レイアウトから与えられた幅に従います。利用者は slider を固定幅の単独ウィジェットとしてではなく、親幅に従属する一次元入力として配置します。

現行公開契約が対象とするのは**横向きレイアウトのみ**です。`prefix` と `suffix` は DOM 上の前後関係を示す補助スロットであり、値の増加方向、RTL における論理 start と end、縦向きレイアウトを意味しません。

縦向き slider、RTL / 双方向書字における完全な増減方向契約、論理 start / end に基づくレイアウト意味づけは、現行公開契約に含めません。必要な場合は別契約として導入します。

### 視覚仕様

- Track は値域全体を示す水平ラインとして描画します
- Fill は Track の左端から現在値位置までを示します
- Thumb は現在位置を示す単一のつまみとして描画します
- Disabled 時は視覚上も操作不可と識別できる状態でなければなりません

Hover、Dragging、Focus に応じた装飾差分を設けることはできますが、位置同期、可読性、コントラスト、フォーカス可視表示を壊してはなりません。

### フィル率契約

`fill` の幅および `thumb` の位置は、次の規則で決まります。

- `max - min = 0` の場合、`fillPercent = 0`
- それ以外の場合、`fillPercent = (value - min) / (max - min) * 100`

この値は正規化後の `min`、`max`、`value` に基づきます。したがって、逆順範囲、クランプ、ステップスナップ後の結果がそのまま視覚へ反映されます。

### 公開 part

外部スタイル拡張のため、次の `::part(...)` を公開します。

| part 名 | 役割                       |
| ------- | -------------------------- |
| `track` | 値域全体のトラック         |

利用者は `::part(track)`、`::part(fill)`、`::part(thumb)` に対して装飾調整を行えます。ただし、range input と overlay 構造を破壊する変更は行ってはなりません。

特に、`fill` の長さ方向寸法、`thumb` の位置決定、フォーカス可視表示の成立条件を壊す幾何変更には依存してはなりません。色、境界線、角丸、影などの非破壊的装飾調整は許容されます。

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、フォーカスアニメーションを停止します。Hover や Dragging の微小な transform は残り得ますが、持続的なアニメーションには依存しません。

### Dark Mode

ダークトークン環境では、`track`、`fill`、`thumb` のコントラストをトークン差し替えで確保します。特に Thumb と Track の境界が暗背景上で消失しないことを重視します。

### Forced Colors

`forced-colors: active` 環境では、独自の影表現を捨て、システムカラーを優先します。`fill` は `Highlight`、`track` は `ButtonBorder`、Thumb 境界は `CanvasText` を用います。影に依存せず、太い境界線で Thumb を識別可能にします。

## 境界条件

### 1. `min > max`

`min` と `max` が逆転している場合、自動的に入れ替えて正規化します。逆転範囲をそのまま意味づける契約は持ちません。

### 2. `step <= 0`

`step="0"` や負値は無効です。`1` にフォールバックします。

### 3. `value` が範囲外

`value` が `max` を超える場合は `max` に、`min` 未満の場合は `min` にクランプします。

### 4. `value` が step に合わない

`value` が step と一致しない場合、最も近い有効ステップへスナップします。スナップ基準は `0` ではなく `min` です。ちょうど中間値に位置する場合は、大きい側の有効ステップへ丸めます。

### 5. `value` 未指定

`value` を指定しない場合、正規化後の `min` を初期値とします。

### 6. `min === max`

範囲が 0 の場合、フィル率は `0%` とし、値域ゼロの有効入力として描画を継続します。見かけ上は操作不能ですが、`disabled` に自動昇格する契約は持ちません。クラッシュせず描画を継続することを優先します。

### 7. 小数ステップ

`step="0.1"` のような構成では、浮動小数点誤差を避けるため、`step` の小数桁精度に揃えて丸めます。したがって、`0.30000000000000004` のような値を公開 `value` として露出しない前提です。

### 8. 負の範囲

`min < 0` の負の範囲も受理します。`min=-50, max=50, value=0` のような構成では、中間値として 50% 位置に描画します。

### 9. `label` 未指定

`label` 未指定は契約違反です。ただし、実装はアクセシブル名の空欄化を防ぐため `"Slider"` をフォールバックします。利用者はこのフォールバックを本番契約として当てにしてはなりません。

### 10. Disabled 時の操作

`disabled=true` の場合、クリックやキー操作を試みても値は変化せず、`input` と `change` も再発火しません。

## Storybook 契約

各 Story は見本ではなく、**契約確認点**として扱います。将来変更時には、次の契約を維持します。

| Story                  | 固定する契約                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| `Default`              | 中間値、ARIA 属性、内部 input の存在が成立すること                                                     |
| `AtMinValue`           | `value=min` のとき Fill 幅が `0%` であること                                                           |
| `AtMaxValue`           | `value=max` のとき Fill 幅が `100%` であること                                                         |
| `DisabledNormal`       | disabled 状態で input が無効化されること                                                               |
| `DisabledAtMin`        | disabled かつ最小値の組み合わせが成立すること                                                          |
| `DisabledAtMax`        | disabled かつ最大値の組み合わせが成立すること                                                          |
| `WithSlots`            | `prefix` と `suffix` スロットを併用できること                                                          |
| `BrightnessControl`    | 補助表示付きの実用構成が成立すること                                                                   |
| `AllStates`            | 主要状態群を一覧表示できること                                                                         |
| `EventFiring`          | `input` と `change` の再発火契約が成立すること                                                         |
| `KeyboardNavigation`   | `PageUp` と `PageDown` の独自保証と、その他キーが range input 標準挙動に依存することが成立すること     |
| `MinGreaterThanMax`    | `min > max` が自動入れ替えされること                                                                   |
| `InvalidStepFallback`  | `step <= 0` が `1` にフォールバックされること                                                          |
| `ValueOutOfRange`      | 範囲上限超過値が `max` へクランプされること                                                            |
| `ValueBelowMin`        | 範囲下限未満値が `min` へクランプされること                                                            |
| `DecimalStepPrecision` | 小数ステップで精度丸めが成立すること                                                                   |
| `ValueUnspecified`     | `value` 未指定時に正規化後の `min` が採用されること                                                    |
| `ValueSnapToStep`      | `step` 非整合値が最近傍ステップへスナップされること                                                    |
| `DisabledClickBlocked` | disabled 時にイベントが発火せず値も変わらないこと                                                      |
| `MinEqualsMax`         | 範囲ゼロでも disabled へ自動昇格せず、有効入力として描画継続すること                                   |
| `NegativeRange`        | 負の範囲で中間値が正しく描画されること                                                                 |
| `DarkMode`             | ダークトークン環境で視認性が維持されること                                                             |
| `HighContrastFallback` | forced-colors 環境で視認性確保のフォールバックが成立すること                                           |
| `MissingLabelFallback` | 契約違反入力時でもアクセシブル名が空欄にならない最低限の退避挙動が存在すること                         |

`label` 必須の品質担保は、ランタイム例外による遮断ではなく、Storybook、テスト、レビューによる検証を主とします。したがって、`MissingLabelFallback` は正規入力を推奨するための Story ではなく、契約違反入力時にもアクセシブル名が空欄にならない最低保証を確認するための Story として扱います。

## 現行実装で未対応の事項

本節は、現行の `slider.ts` および `slider.stories.ts` を基準として、**契約書内で将来拡張または厳密化対象として触れているが、現時点では未実装、未強制、または未整合である事項**を整理するものです。

### 1. `label` 必須の実行時強制

公開契約上 `label` は必須ですが、現行実装は未指定時に `console.warn` を出し、`"Slider"` をフォールバック使用するのみです。描画停止や例外送出は行いません。したがって、**必須契約の実行時強制は未実装**です。

### 2. `readonly` 相当状態

現行実装は `disabled` と値域ゼロを区別していますが、**値は提示しつつ変更だけを禁止する状態**は持ちません。フォーカス可能性、読上げ継続、イベント非発火を伴う `readonly` 相当状態は、現行公開面にも内部状態にも未実装です。

### 3. 値意味フォーマッタ API

現行実装は数値としての現在値を扱いますが、「50 パーセント」「低」「中」「高」のような**人間向け意味表現を生成する API**は持ちません。したがって、`valueTextFormatter(value)` に相当する公開契約、またはそれに準ずる値意味フォーマット機構は未対応です。

### 4. `aria-valuetext` の pass-through

現行実装が反映する値関連 ARIA 属性は `aria-valuemin`、`aria-valuemax`、`aria-valuenow` に限られます。単位付き読み上げや語義化された値表現に必要な `aria-valuetext` は未対応です。

### 5. 補助説明との関係属性

`aria-describedby`、`aria-labelledby` など、外部ラベルや補助説明文と結び付けるための関係属性は現行公開面に含まれません。したがって、**ラベル以外の説明関係は包括的には公開していません**。

### 6. 外部 `<label>` 要素との連携

現行実装は内部にネイティブ input を保持しますが、host 自体がネイティブ input と同等の labelable 要素になるわけではありません。したがって、`<label for="...">` や label 包含による**外部 **``** 要素とのネイティブ連携は未対応**です。

### 7. ネイティブ input 属性の包括 pass-through

現行公開面は `min`、`max`、`step`、`value`、`label`、`disabled` に限定されており、`name`、`tabindex`、`autofocus`、`required` などのネイティブ input 属性を host から内部 input へ包括的に委譲する仕組みは持ちません。したがって、**ネイティブ input 属性の包括 pass-through は未対応**です。

### 8. 目盛り・刻みラベル

現行実装はトラック、フィル、Thumb のみを描画し、tick、marks、ラベル刻み、datalist 連携などは持ちません。**値域の視覚的補助目盛りは未対応**です。

### 9. 現在値表示の内蔵

現在値表示は Storybook で `suffix` スロットを使って構成していますが、コンポーネント自体は内蔵しません。したがって、**現在値の可視表示は利用側責務**です。

### 10. フォーム送信・フォームリセット参加

現行実装は form-associated custom element ではなく、`name`、送信値、フォームリセットへの自動参加を持ちません。したがって、**ネイティブ form control と同等のフォーム統合は未対応**です。

### 11. Arrow 系および `Home` と `End` の独自正規化

`PageUp` と `PageDown` は明示実装されていますが、Arrow 系および `Home` と `End` はネイティブ input の標準動作に依存しています。現状でも十分妥当ですが、将来ブラウザ差異を明示的に吸収する契約にはなっていません。

### 12. 印刷契約

現行実装と Storybook は print 時の扱いを特に定義していません。印刷で非表示にするのか、静的表示として残すのかは未固定です。

### 13. 縦向き・RTL・双方向書字の明文化

現行実装は横向き前提であり、RTL や縦書きに対する明示契約はありません。ブラウザ標準 input にある程度依存しますが、**視覚オーバーレイ側の完全な双方向契約は未固定**です。

### 14. タッチターゲット基準の整合

実装コメントには 44px 相当を示す記述がありますが、既定トークンは `--control-min-touch: 24px` を前提としています。したがって、**長期的に目標とするタッチターゲット基準と、現行既定値との整合は未解消**です。

### 15. Storybook による未対応確認

現行 Storybook には、`readonly` 相当状態、値意味フォーマッタ API、`aria-valuetext`、関係属性 pass-through、外部 `<label>` 連携、ネイティブ input 属性 pass-through、目盛り表示、縦向き表示、印刷時挙動を確認する Story は存在しません。したがって、これらは**契約候補としては検討余地があるが、現行 Storybook 契約には未反映**です。

### 16. 本節の扱い

本節に記載した事項は、現行公開契約として利用者が依存してよいものではありません。これらを採用する場合は、実装、Storybook、契約書の 3 点を同時に更新し、未対応状態を残したまま公開契約へ昇格させません。
