# Score

## 概要

本書は、`ui-score` の公開契約、状態モデル、アクセシビリティ、および視覚契約を定義します。

`ui-score` は、楽譜を SVG として表示するコンポーネントです。公開契約上の責務は、**単一譜例の表示**、**本文文脈での横スクロール**、**遅延読み込み**、**譜例説明のアクセシビリティ同期**、**テーマトークンによる紙面表現** に限定します。

本書は、現行実装の記述ではなく、利用者が依存してよい正規契約を定義します。現行実装との差分は末尾の「現行実装で未対応の事項」に分離します。

## 公開契約

`ui-score` は、`src`、`caption`、`label`、`description`、`aspectRatio`、`loading`、`primary` を公開入力として扱います。スロットは既定スロットのみを持ちます。

本コンポーネントは単一譜例を表示します。入力モードは build-inline と runtime fetch の 2 系統ですが、公開契約上はいずれも単一譜例表示として扱います。

`loading` の既定値は `lazy` です。`aspectRatio` の解決値既定は `3 / 1` です。`primary` は視覚強調ではなくランドマーク露出の切替を意味し、`true` の場合に限ってスクロール領域へ `role="region"` を付与します。`label` は完全なアクセシブル名であり、空文字の場合は `楽譜` に解決します。

### 入力契約

| 名前          | 種別                                  | 必須     | 内容                           | 契約                                                                                                                                   |
| ------------- | ------------------------------------- | -------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `src`         | property / attribute                  | 条件付き | runtime fetch 用の SVG ソース  | build-inline 入力がない場合に使用します。受理するのは `http:`, `https:`, `data:` のみです。未指定は error ではなく idle として扱います |
| `caption`     | property / attribute                  | いいえ   | 譜例下の短い説明文             | 空文字の場合は `figcaption` を出力しません                                                                                             |
| `label`       | property / attribute                  | いいえ   | スクロール領域のアクセシブル名 | 完全なアクセシブル名として扱います。空文字は `楽譜` へ解決します                                                                       |
| `description` | property / attribute                  | いいえ   | スクリーンリーダー向け詳細説明 | 空文字でない場合、sr-only テキストを生成し `aria-describedby` で参照します                                                             |
| `aspectRatio` | property / attribute (`aspect-ratio`) | いいえ   | スケルトン表示時の比率         | `N / M` 形式の正の値のみを受理します。不正値は `3 / 1` へフォールバックします                                                          |
| `loading`     | property / attribute                  | いいえ   | 読み込み方針                   | `lazy` / `eager`。列挙外値は `lazy` へフォールバックします。`lazy` は保証ではなく方針です                                              |
| `primary`     | property / attribute                  | いいえ   | ランドマーク露出               | `true` の場合、スクロール領域に `role="region"` を付与します                                                                           |

### スロット契約

| 名前         | 種別 | 位置づけ | 内容                             |
| ------------ | ---- | -------- | -------------------------------- |
| 既定スロット | slot | 正規入力 | 単一の inline SVG を受け取ります |

既定スロットの**正規入力は単一の \*\***svg\***\* 要素のみ**です。ラッパー要素の内側に `svg` を含める構成、複数 `svg` を同時に与える構成、譜例以外の light DOM を混在させる構成は公開契約に含めません。

build-inline 入力が存在する場合、`src` の有無にかかわらず runtime fetch は行いません。build-inline 入力は譜例の描画実体として扱います。slotted SVG は読み上げ主体にせず、`aria-hidden="true"`、`focusable="false"` を適用し、`role` は除去します。

### スロット変更時のモード切替契約

既定スロットの内容は `slotchange` 時にも再評価します。正規形の inline SVG が存在する場合は build-inline を優先し、進行中の runtime fetch を中断します。inline SVG が存在しなくなった場合は、`src` があれば runtime fetch 側の評価へ戻します。`src` と slot の優先順位は、常に slot 内の正規 inline SVG を最優先とします。

### フォーカス操作契約

`ui-score` は、キーボード利用者が譜例の横スクロール到達点へフォーカスできることを保証します。

公開契約として固定するのは、**外部から譜例のキーボード到達点へフォーカス可能であること**のみです。フォーカスの実体がホスト要素自身であるか、内部のスクロール領域へ委譲されるかは実装に含めます。利用者は内部 DOM、特定の公開メソッド名、またはフォーカス委譲先の要素種別に依存しません。

再読み込みの開始方法は公開契約に含めません。再取得が必要な場合、上位レイヤは `src` の更新その他の外部制御によって新しい読み込みサイクルを開始できます。

### 属性反映契約

公開入力のうち、`loading` と `primary` は reflect します。`src`、`caption`、`label`、`description`、`aspectRatio` は attribute から入力できますが、property 更新時に属性へ自動反映する契約ではありません。

| property      | attribute      | reflect | 備考                                       |
| ------------- | -------------- | ------- | ------------------------------------------ |
| `src`         | `src`          | なし    | runtime fetch 用入力です                   |
| `caption`     | `caption`      | なし    | 空文字で `figcaption` 非表示です           |
| `label`       | `label`        | なし    | 完全なアクセシブル名として扱います         |
| `description` | `description`  | なし    | 空文字で `aria-describedby` を出力しません |
| `aspectRatio` | `aspect-ratio` | なし    | スケルトン専用入力です                     |
| `loading`     | `loading`      | あり    | `lazy` / `eager` を受理します              |
| `primary`     | `primary`      | あり    | boolean attribute として扱います           |

### 列挙外値・無効値の扱い

`loading` は `lazy` / `eager` のみを正規入力とし、列挙外値は `lazy` へフォールバックします。`aspectRatio` は `N / M` 形式の正の有限値のみを正規入力とし、それ以外は `3 / 1` へフォールバックします。

`src` が許可されないスキームである場合は読み込みを開始せず、`不正な楽譜ソースです` を表示します。`src` の取得結果が SVG として解釈できない場合、または描画正規化後に SVG として成立しない場合は、`楽譜を読み込めませんでした` を表示します。

## 状態モデル

`ui-score` の主要状態は、入力モード、ネットワーク状態、表示状態、オーバーフロー状態によって定義します。

| 状態          | 入口条件                                                                                              | 観測可能な結果                                                                                                                                         |
| ------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| build-inline  | 既定スロットに正規形の inline SVG が存在する                                                          | `src` の有無にかかわらず runtime fetch は行いません。スケルトンは表示せず、`aria-busy` は `false` とします                                             |
| idle          | build-inline 入力がなく、`src` が未指定または空文字である                                             | 待機状態とし、error へ遷移しません。譜例表示は行わず、`aria-busy` は `false` とします                                                                  |
| runtime eager | build-inline 入力がなく、`src` が有効で、`loading="eager"` である                                     | 更新後ただちに取得を開始します                                                                                                                         |
| runtime lazy  | build-inline 入力がなく、`src` が有効で、`loading="lazy"` である                                      | `IntersectionObserver` による可視近傍到達後に取得を開始します。`lazy` は遅延開始の方針であり、保証ではありません                                       |
| loading       | runtime fetch 開始後、成功または失敗が確定していない                                                  | `figure.root` に `aria-busy="true"` を付与し、エラー表示は空とし、スケルトンを可視化し、実譜例コンテンツは不可視とします                               |
| ready         | SVG 取得と描画正規化に成功する                                                                        | runtime SVG を shadow DOM 内へ描画し、`aria-busy` は `false` とします。スケルトンは非表示となり、譜例コンテンツを表示します                            |
| error         | 許可されない `src`、fetch 失敗、SVG 解釈失敗、描画正規化失敗が発生する                                | `aria-busy` は `false` とし、`.error` 領域にエラーメッセージを表示します。error 領域は `aria-live="polite"` を持ちます                                 |
| aborted       | 進行中の fetch が `src` 変更、slot 変更、`reload()`、またはコンポーネント切り離しによって無効化される | 内部整合状態として扱います。公開エラーではありません                                                                                                   |
| overflow      | スクロール領域の `scrollWidth` が `clientWidth` を超える                                              | 左右端の到達状況に応じてフェード表示を切り替えます。先頭位置では右のみ、中間位置では左右、末尾位置では左のみを表示し、非 overflow 状態では表示しません |

## DOM / Accessibility

ルートは `figure.root` です。内部に横スクロール領域 `.score-scroll` を持ち、その内部に `.score-stage` を配置します。build-inline と runtime fetch のいずれでも、視覚的な譜例本体は `.score-content` に収まります。

```text
<ui-score>
  #shadow-root
    <figure class="root" aria-busy="...">
      <div
        class="score-scroll ..."
        [キーボード到達可能]
        [role="region"]
        aria-label="..."
        [aria-describedby="score-desc-..."]
      >
        <div class="score-stage">
          [div.skeleton]
          <div class="score-content ...">
            <slot></slot>
            [div.score-svg-host > svg]
          </div>
          [p.sr-only]
        </div>
      </div>
      <div class="error" aria-live="polite"></div>
      [figcaption.caption]
    </figure>
</ui-score>
```

### Accessibility 契約

対話主体は SVG ではなく、横スクロール可能な譜例コンテナとします。譜例コンテナはキーボードで到達可能でなければなりません（MUST）。その達成方法は公開契約に含めず、`tabindex`、ホストへのフォーカス委譲、または同等の実装手段のいずれでも構いません。

アクセシブル名は `label` から解決します。`label` が空文字の場合は `楽譜` を用います。`description` がある場合に限り、追加説明を生成し、譜例コンテナへ関連付けます。build-inline / runtime fetch のいずれでも、SVG 自体は読み上げ主体とせず、補助技術上の主対象は譜例コンテナ側に置きます。

loading 中のみ `figure.root` に `aria-busy="true"` を付与します。エラー通知は `.error` 領域で行い、通知方法は `aria-live="polite"` と同等の非侵襲的通知でなければなりません。

### `caption` とアクセシブル名の分離契約

`caption` は視覚的な譜例説明であり、アクセシブル名の構成要素に含めません。アクセシブル名は `label` から、追加説明は `description` から解決します。

`caption` は `figcaption` の表示内容としてのみ扱います。`caption` を与えても `aria-label` は変化せず、`aria-describedby` も自動生成しません。スクリーンリーダー向けの説明が必要な場合は `description` を明示しなければなりません（MUST）。`label` を省略した場合でも、アクセシブル名は `caption` から推論せず、既定値 `楽譜` を用います。

### フォーカス契約

フォーカスの公開到達点はホスト要素ではなく、内部のスクロール領域とします。ただし、利用者は内部 DOM に依存しません。`focus()` と `blur()` はホスト経由で利用できるものとし、フォーカスの実体は内部スクロール領域へ委譲します。

## Visual Contract

`ui-score` の視覚契約は、紙面として静かに読める譜例領域を成立させることにあります。主張の強いカードや画像ビューアではなく、本文の延長として参照できることを優先します。

### 基本外観

ルートは block 要素です。譜例コンテナは境界線、角丸、紙面背景、譜面インク色を持つ読書用領域として表示されます。内側余白の既定は `--space-4` とします。横方向オーバーフローを許可し、縦方向はクリップします。

譜面紙色は `--bg-score-paper`、譜面インク色は `--score-ink` に依存します。未指定時の既定は白地・黒相当の表示です。ダークモードでも紙面とインク色の自動反転は行いません。

スクロール操作は視覚的に把握可能でなければなりません（MUST）。スクロールバーや補助ヒントの具体的な装飾方法は実装に含めます。

### インク色契約

譜例インク色は常に固定黒ではありません。既定トークンでは黒相当の表示とし、公開トークン `--score-ink` により変更できます。

公開契約として固定するのは、**既定値では黒相当の譜例として表示されること**、および **公開トークンを通じて譜例インク色を変更できること** の 2 点です。SVG 内の色指定をどのように再解釈・再構成してこの契約を満たすかは実装に含めます。

### 本文文脈での幅契約

`:host-context(.prose)` 配下では、譜例は本文の流れを壊さない範囲で、可読性確保のために横方向へわずかに拡張されたレイアウトを取ることがあります。これは譜例の読解性を補うための本文文脈専用表現であり、通常文脈での常時全幅化を意味しません。

拡張量、適用ブレークポイント、余白計算方法は公開契約に含めません。これらは本文組版との整合を保つ範囲で実装が決定します。

print 時には、この本文文脈拡張を解除し、印刷用の通常幅へ戻します。

### loading 表示

loading 中は、実譜例の代わりにスケルトンを表示します。スケルトンは `aspect-ratio` に従った矩形プレースホルダーであり、shimmer アニメーションを持ちます。ready または error に移行すると、スケルトンは非表示になります。

### overflow フェード表示

譜例が横方向にはみ出す場合、スクロール領域の左右端にフェードマスクを付与します。これは「続きを横に読む」ことを視覚的に示すヒントです。forced colors 環境ではこのマスク表現に依存しません。

### フォーカス表示

スクロール領域が `:focus-visible` になった場合、アウトラインによるフォーカスリングを表示します。これは譜例全体をキーボード到達可能領域として扱うための契約です。

### スタイリング拡張契約

`ui-score` の視覚拡張は、公開された CSS カスタムプロパティと文脈依存スタイルに限定します。内部クラス名、shadow DOM 構造、子要素の入れ子順は公開スタイル API に含めません。

外部利用者は `.score-scroll`、`.score-stage`、`.score-content`、`.error` などの内部クラス名、shadow DOM 内部の要素順序、ラッパー要素、装飾要素の存在有無に依存しません。見た目の調整は、原則として公開トークンと `:host-context(.prose)`、およびメディア条件の範囲で行います。`part` / `exportparts` は現行公開面に含みません。内部構造の変更は、公開トークンと本文文脈契約を壊さない限り許容します。

## 環境別の振る舞い

| 媒体条件       | 条件                             | 振る舞い                                                                                                                                         |
| -------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Reduced Motion | `prefers-reduced-motion: reduce` | スケルトンの shimmer アニメーションを停止します。スケルトンと譜例コンテンツの transition 時間は極小化します                                      |
| Dark Mode      | `prefers-color-scheme: dark`     | スクロール領域の境界線色のみを dark 向けに補正します。譜例の紙面背景とインク色は自動反転しません                                                 |
| Forced Colors  | `forced-colors: active`          | スクロール領域の色を `Canvas` / `CanvasText` に委譲し、フォーカス表示もシステム色へ寄せます。overflow フェードに使う `mask-image` は無効化します |
| Print          | `@media print`                   | 譜例自体を印刷対象として維持します。スクロールは visible に変更し、overflow フェードは除去します。`.prose` 文脈での横方向拡張も解除します        |

| `src` 変更契約     | `src` が変化する                                                        | 既存の runtime SVG を破棄し、既存のエラーをクリアし、進行中の fetch があれば abort し、読み込みサイクル識別子を更新し、新しい `src` に対してあらためて読み込み計画を立てます。`src` 変更は再描画・再読み込みの正規トリガーです                                                                                                                                                                                                                                                                                                                                                                                                                             |

| SVG 描画正規化契約 | runtime fetch で SVG を取得する                                         | 取得した SVG には描画正規化を適用します。これは読書用譜例としての表示を安定させるための契約であり、完全なセキュリティ境界を構成しません。敵対的入力の完全防御は上位レイヤで担保しなければなりません（MUST）。描画正規化では、少なくとも `script`、`foreignObject`、`on*` イベント属性、危険な URL スキームを含む参照属性、および表示の安全性を損なう要素・属性を除去または無効化します。加えて、公開契約として、少なくとも受理要素カテゴリ、受理属性カテゴリ、代表的な拒否理由を文書および Storybook 上で追跡可能にしなければなりません（MUST）。厳格 allowlist の固定そのものは本契約に含めません。正規化の結果、受理できない SVG は error として扱います |

| エラー通知契約     | エラーテキストを出力する                                                | エラーテキストは `.error` 領域へ出力します。正常系でも `.error` 領域自体は常に存在しますが、テキストは空です。利用者は `.error` 領域の存在有無ではなく、テキスト内容に依存して状態を解釈しなければなりません（MUST）                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## 境界条件

| 条件                   | 入力・前提                                                              | 結果・契約                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| inline SVG 優先        | `src` と build-inline 入力を同時に与える                                | build-inline 入力を優先します。runtime fetch は行いません                                                         |
| `src` 未設定           | build-inline 入力がなく `src` が空文字である                            | error ではなく idle として扱います。スケルトンは表示せず、`aria-busy` は `false` とします                         |
| 不正 `src`             | 許可されないスキームの `src` を与える                                   | 読み込みを開始せず、`不正な楽譜ソースです` を表示します                                                           |
| 不正 `loading` 値      | `loading="invalid"` のような列挙外値を与える                            | `lazy` へフォールバックします                                                                                     |
| 不正 `aspect-ratio`    | `aspect-ratio="broken-ratio"` のような不正値を与える                    | `3 / 1` へフォールバックします。これはスケルトン表示にのみ影響し、読み込み完了後の SVG サイズには直接影響しません |
| fetch 失敗             | HTTP エラー、無効 SVG、描画正規化失敗が発生する                         | `楽譜を読み込めませんでした` を表示します。同一 `src` に対する再試行は上位レイヤによる外部制御で開始できます      |
| 非正規 slot 入力       | ラッパー要素内の `svg`、複数 `svg`、または譜例以外の light DOM を与える | その挙動には依存しません。公開契約上の正規入力は単一 inline SVG のみです                                          |
| `label` 空文字         | `label` が空文字である                                                  | `aria-label` は省略せず、既定値 `楽譜` を用います                                                                 |
| `description` 空文字   | `description` が空文字である                                            | sr-only 説明文も `aria-describedby` も出力しません                                                                |
| overflow 非発生        | SVG がコンテナ幅内に収まる                                              | fade ヒントは表示しません                                                                                         |
| 受理外要素を含む SVG   | 読書用譜例として許容しない要素を含む                                    | 描画正規化で除去または無効化できない場合は error として扱います                                                   |
| 危険参照を含む SVG     | 危険な URL スキームや危険な参照属性を含む                               | 該当参照を除去または無効化します。結果として譜例として成立しない場合は error として扱います                       |
| 受理プロファイル外入力 | 文書化された受理要素カテゴリ・受理属性カテゴリを外れる入力を含む        | その受理は保証しません。除去、無効化、または error のいずれかとして処理されます                                   |

## Storybook 契約

各 Story は見本ではなく、公開契約の確認点として扱います。将来変更時には、少なくとも次の観測可能結果を維持します。

| Story                         | 固定する契約                                                                                                                                                              |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Default`                     | eager runtime fetch が成立し、`primary=true` の場合にランドマーク露出が行われ、`label` / `description` / `caption` に対応する表示とアクセシビリティ関連付けが成立すること |
| `VariantStateMatrix`          | build-inline / runtime fetch、eager / lazy、caption 有無、description 有無、primary 有無の組み合わせで、入力モードと表示結果の整合が崩れないこと                          |
| `LoadingAndErrorStates`       | loading 中の `aria-busy`、skeleton 表示、invalid `src`、fetch failure、idle と error の分離、abort が失敗表示と混同されないこと                                           |
| `BoundaryConditions`          | 不正 `loading` 値、不正 `aspect-ratio`、非正規 slot 入力非保証に加えて、代表的な受理外要素・危険参照・描画正規化失敗が期待どおり除去、無効化、または error になること     |
| `VisualModesAndInkContrast`   | 既定トークンでは黒相当の譜例として表示され、公開トークン変更時には譜例インク色が追従して変化すること                                                                      |
| `OverflowAndFadeHints`        | overflow 時にスクロール可能性の視覚ヒントが出現し、スクロール位置に応じてその出し分けが変化すること                                                                       |
| `AccessibilityMediaContracts` | reduced motion でアニメーションが抑制され、forced colors でマスク依存のヒントが無効化され、print で overflow フェードと本文文脈拡張が解除されること                       |

## 現行実装で未対応の事項

本節は、現行の `score.ts` および `score.stories.ts` を基準として、本書で定義した事項のうち、現時点で未実装、未強制、または未整合であるものを整理します。

### `src` 未設定の idle 分離

現行実装は build-inline 入力がなく `src` も空の場合、idle ではなく `楽譜ソースが未設定です` を表示します。本書では、未設定待機は error ではなく idle と定義します。

### `src` スキーム制約

現行実装は `src` を `fetch()` 可能文字列としてそのまま扱います。本書では、公開契約上の正規入力を `http:`, `https:`, `data:` に限定します。

### `invalid-src` 専用エラー契約

現行実装には、許可されないスキームを事前に判定して `不正な楽譜ソースです` を返す契約がありません。不正な `src` は `fetch()` 側の失敗として処理され、公開面では一般の読み込み失敗と区別されません。本書では、`invalid-src` を独立した契約として扱います。

### `label` の解釈

現行実装は `aria-label` を `楽譜: {label}` の形で組み立てます。本書では、`label` を完全なアクセシブル名として扱い、内部接頭辞を自動合成しません。

### `label` 契約に対する Storybook の未整合

現行 Storybook の `Default` は、`aria-label` が `楽譜: {label}` 形式であることを前提に検証しています。本書では、`label` 自体を完全なアクセシブル名として扱うため、この Story は契約と未整合です。

### 正規 slot 入力の厳密化

現行実装はラッパー要素内部の `svg` も build-inline として検出します。本書では、正規入力を単一 inline SVG に限定し、非正規 slot 入力の挙動を公開保証から外します。

### slot 往復時の runtime 再入

現行実装は slot 変更時に build-inline への切替を行いますが、runtime fetch を一度実行した後に inline SVG を挿入し、その後ふたたび inline SVG を外した場合、同一 `src` へ自動再入しない場合があります。本書では、slot 内容の再評価後、`src` が有効であれば runtime 側の評価へ戻る契約を定義します。

### フォーカス到達点の公開整理

現行実装では、外部から譜例のキーボード到達点へどのようにフォーカスさせるかが公開面として明示されていません。本書では、外部から譜例のキーボード到達点へ到達可能であることを契約に含めますが、その達成方法自体は固定しません。

### retry トリガー

現行実装では同一 `src` の再試行に公開された統一手段がなく、事実上 `src` 変更が再読み込みトリガーです。本書では、再試行は上位レイヤによる外部制御で開始できれば足りるものとし、具体的なトリガー API 名は公開契約に含めません。

### SVG 受理プロファイルの明示

現行実装は描画正規化を行いますが、受理要素カテゴリ、受理属性カテゴリ、代表的な拒否理由を、公開契約と Storybook の双方で追跡可能な形には整理していません。本書では、描画正規化契約の一部として、少なくともこれらを監査可能にすることを要求します。

これは厳格 allowlist の固定を意味しません。公開契約として求めるのは、利用者が「どの種の入力が原則として受理対象で、どの種の入力が除去、無効化、または error になり得るか」を予測可能にすることです。

### `src` 未設定契約に対する Storybook の未整合

現行 Storybook の `LoadingAndErrorStates` には、`src` 未設定時に `楽譜ソースが未設定です` を表示することを前提にした検証があります。本書では、`src` 未設定を idle として扱い、error と分離します。この Story は契約と未整合です。

### `invalid-src` 契約に対する Storybook の未整合

現行 Storybook には、`invalid-src` を独立契約として検証する Story がありません。本書では、許可されないスキームに対して専用エラーを返す契約を定義しますが、現行 Storybook はこれを未検証です。

### print 契約に対する Storybook の未整合

現行 Storybook の `AccessibilityMediaContracts` は reduced motion および forced colors の存在を検証しますが、print 契約を検証していません。本書では、print 時の表示維持、overflow フェード除去、`.prose` 文脈での横方向拡張解除を契約に含めます。

### インク色 Story の整合

現行 Storybook には、light / dark 背景で常に黒であることを強く検証する Story があります。本書では、既定値は黒だが公開トークンで変更可能という契約を優先します。

### aborted 状態の公開整理

現行実装には fetch 中断がありますが、aborted を明示的な状態モデルとして整理していません。本書では、後勝ち防止のための整合状態として定義します。

### 描画正規化の位置づけ

現行実装は一部の危険要素・属性除去を行いますが、それを描画正規化として明示していません。本書では、完全なセキュリティ境界ではなく、表示安定化のための正規化として定義します。

### 本節の扱い

本節に記載した事項は、現行公開契約として利用者が依存してよいものではありません。これらは、本書が定義する正規契約と現行実装との差分です。採用する場合は、実装、Storybook、契約書の 3 点を同時に更新し、未整合状態を残したまま公開契約へ昇格させません。
