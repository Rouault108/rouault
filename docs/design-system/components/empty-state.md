# Empty State

## 文書の位置づけ

本書は、`ui-empty-state` の公開契約、状態モデル、アクセシビリティ、視覚契約、および現行実装との差分を定義する契約文書です。

`ui-empty-state` は、一覧・検索結果・本文領域において、**表示すべき主要内容が存在しない状態**、または**取得失敗等により主要内容を継続表示できない状態**を提示する状態提示コンポーネントです。対象は狭義の「空状態」に限らず、**no-result** および **failure** を含む広義の状態提示です。

本コンポーネントは、単に文言を中央寄せするためのものではありません。**見出し・補足説明・行動導線・補助的視覚表現**を、読書リズムを過度に損なわない順序で提示することを目的とします。主目的は状態の意味を短い構造で明確に伝えることであり、視覚効果や通知強度を常に高めることではありません。

Rouault における state presenter は、必要以上に騒がず、しかし意味の不足も生まないことを求めます。したがって本書では、状態の意味、入力の正規化、アクセシビリティ、視覚上の情報順位を公開契約として定義します。一方で、通知の要否や通知強度、導線の密度、象徴表現の有無は、すべてを固定値として強制するのではなく、**契約の核**と**推奨ガイド**を分けて扱います。

## 適用範囲

本書は、`ui-empty-state` の次の事項を対象とします。

- 公開契約
- 状態モデル
- DOM / Accessibility
- Visual Contract
- 環境別の振る舞い
- 関連契約
- 境界条件
- Storybook 契約
- 現行実装で未対応の事項

一方で、本書は次の事項を扱いません。

- 各画面で `ui-empty-state` をいつ表示するかという画面遷移条件
- 検索失敗・権限不足・ネットワーク失敗などの業務的分類そのもの
- アクション押下後の処理内容
- 再試行回数、取得戦略、権限回復導線などの業務ロジック
- 画像アセット自体の供給
- 国際化文言の管理方式
- ローディング状態や skeleton 表示の設計
- 画面全体のレイアウト責務
- 状態種別ごとの既定アイコン規則
- `sm` などのサイズバリアント
- `action-group-label` のような複数アクション向け補助契約
- `subtitle`、`footer`、`meta` などの補助スロット追加
- `alignment`、`fullHeight` などのレイアウト指定 API
- 内部 class や内部派生状態の公開 API 化
- `icon` と `illustration` の同時表示を前提とした複雑な装飾モード
- empty state 自体への非同期取得・再試行ロジックの内蔵
- `variant` の無制限な追加による画面固有分類の吸収

これらは上位レイヤ、別コンポーネント、または別契約で扱う事項です。

ただし、通知の要否および通知強度の公開制御については、本書では将来拡張候補としてではなく、公開入力 `announce` による現行契約として扱います。したがって、本書は通知制御を「将来の設計余地」として保留せず、現在の公開契約として定義します。

---

`ui-empty-state` は、`variant` と `announce` を公開入力として扱います。スロットは `heading`、`description`、`action`、`icon`、`illustration` を持ちます。内部実装は Shadow DOM 内の構造を持ちますが、利用者は `ui-empty-state` を契約単位として扱います。

本書において `variant` は、**視覚トーンではなく状態種別を表す semantic kind** として扱います。`default`、`search`、`error` は単なる見た目の違いではなく、利用者へ伝えるべき状態意味の分類です。したがって、色だけを変えるために `variant` を使うことには依存しません。

`variant` の既定値は `default` です。受理する正規値は `default`、`search`、`error` です。列挙外値は公開契約上の入力ではありません。無効値が与えられた場合、公開状態は正規値へ正規化されなければなりません（MUST）。

`announce` は、状態メッセージ領域を支援技術へ自動通知するかどうかを表す公開入力です。既定値は `off` です。受理する正規値は `off` および `polite` です。`announce="off"` の場合、本コンポーネントはライブリージョンであることを前提としません。`announce="polite"` の場合に限り、状態メッセージ領域を穏やかな通知対象として扱います。

`heading` スロットは公開契約上の必須入力です。実装は見出し欠落時に描画を停止しないことがありますが、アクセシブルで意味のある state presenter とするため、`heading` は必ず与えなければなりません（MUST）。

`description`、`action`、`icon`、`illustration` は任意です。`description` がない場合は見出しの下余白を調整し、`action` がない場合はアクション領域を描画に参加させません。`illustration` が与えられた場合は `icon` より優先され、`icon` は表示されません。

通知対象は常に **状態メッセージ領域** に限定します。通知本文に含める対象は `heading` と `description` であり、`action` は状態通知の一部として扱いません。`aria-label` は自動生成しません。支援技術へ伝えるべき状態の主内容は `heading` と、必要に応じた `description` に置かなければなりません（MUST）。

`ui-empty-state` は対話主体コンポーネントではありません。独自の公開メソッドは持たず、独自イベントも発火しません。利用者はホスト要素に対して imperative な制御 API や専用イベントを期待してはなりません（MUST NOT）。

### 入力契約

| 名前       | 種別                 | 必須   | 内容       | 契約                                                                 |
| ---------- | -------------------- | ------ | ---------- | -------------------------------------------------------------------- |
| `variant`  | property / attribute | いいえ | 状態種別   | semantic kind として `default` / `search` / `error` を受理します。既定値は `default` です |
| `announce` | property / attribute | いいえ | 通知モード | `off` / `polite` を受理します。既定値は `off` です                  |

### 属性反映契約

公開入力のうち `variant` および `announce` は property と attribute の両面から操作できます。

| property   | attribute   | reflect | 備考                                                                                  |
| ---------- | ----------- | ------- | ------------------------------------------------------------------------------------- |
| `variant`  | `variant`   | あり    | 列挙外値は公開契約上の入力ではありません。無効値は canonical な正規値へ正規化します |
| `announce` | `announce`  | あり    | 列挙外値は公開契約上の入力ではありません。無効値は canonical な正規値へ正規化します |

### スロット契約

| 名前           | 種別       | 位置づけ | 個数契約      | 内容                                                                 |
| -------------- | ---------- | -------- | ------------- | -------------------------------------------------------------------- |
| `heading`      | named slot | 必須入力 | 1 個          | 状態の主文言です。アクセシブルな状態理解の主たる入力です             |
| `description`  | named slot | 任意入力 | 0 または 1 個 | 状態の補足説明です。空または空白のみの場合は非表示として扱います     |
| `action`       | named slot | 任意入力 | 0 個以上      | 次に取る行動を提示する操作要素です。複数配置を許可します             |
| `icon`         | named slot | 任意入力 | 0 または 1 個 | 状態を補助的に示す簡潔な視覚要素です                                 |
| `illustration` | named slot | 任意入力 | 0 または 1 個 | 状態をより広い文脈で補助的に示す視覚要素です。`icon` より優先します |

`heading` スロットは、`h2`、`h3`、`h4` など、画面文脈に応じた見出し要素を受け取ることができます。見出しレベルはコンポーネント側で固定しません。利用側は文書アウトラインに整合する見出しレベルを選択しなければなりません（MUST）。

`heading` および `description` の**正規入力**は、空白テキストノードおよび comment node を除いた**トップレベル割当ノードが 1 個である構成**です。インライン強調、インラインコード、ルビ等のインライン表現は許可します。複数のトップレベルノードを与えた場合でも描画が継続することはありますが、公開契約上は非正規入力です。

`description` はテキストまたは段落要素を受け取ります。空白のみの場合は内容なしとして扱います。`description` にリンクを含めること自体は許可しますが、**リンク数の上限は公開契約の核には含めません**。ただし、静かな状態提示を保つ観点から、補助参照導線は 0 個または 1 個に抑えることを推奨します（SHOULD）。主要導線や主要操作を `description` 内リンクへ委ねる構成には依存してはなりません（MUST NOT）。

`action` は単一要素に限定しません。複数の操作要素を並べることができ、狭い横幅では折り返しを許可します。正規入力は `button`、`a`、またはそれに準ずる対話要素です。プレーンテキストのみを `action` スロットへ与える構成は描画され得ますが、公開契約上の正規入力ではありません。

複数の `action` を与える場合、**DOM 順序を情報順位として扱います**。先頭要素が最上位アクションであり、後続要素は同順位または下位アクションです。視覚順序、フォーカス順序、読み上げ順序は DOM 順序を保たなければなりません（MUST）。

`action` 数の上限は公開契約の核には含めません。ただし、small state presenter としての情報順位を保つため、**主要導線は 1 個、総操作数は 1 個または 2 個に抑えることを推奨**します（SHOULD）。3 個以上のアクションは許容し得ますが、密度上の推奨構成ではありません。

`icon` は単独の補助的視覚表現を想定します。`illustration` が存在する場合、`icon` の内容は描画上抑止されます。利用者は、`illustration` と `icon` を同時に常時見せる構成に依存してはなりません（MUST NOT）。

`icon` および `illustration` は、状態の**主意味**を担う入力ではありません。ただし、単なる装飾に限定するものでもありません。これらは、`heading` と `description` により既に成立している状態意味を**補助的に補強する視覚表現**として扱います。主要操作や状態理解に必須の文言を `icon` または `illustration` のみに載せてはなりません（MUST NOT）。

### 列挙外値・無効値の扱い

`variant` は公開上 `default`、`search`、`error` の 3 値を契約とします。`announce` は公開上 `off`、`polite` の 2 値を契約とします。列挙外値が入力された場合、`variant` は `default`、`announce` は `off` へ正規化します。

canonicalization の観測時点は次のとおりです。

- property は、設定直後の同期観測で正規値を返さなければなりません（MUST）。
- reflect される attribute は、同一更新サイクルの完了時点までに正規値へ一致しなければなりません（MUST）。
- render 結果および支援技術向けの意味付けは、常に正規化後の値に一致しなければなりません（MUST）。

利用者は、無効値が内部だけで吸収され、property・attribute・描画結果のいずれかに残存する構成に依存してはなりません（MUST NOT）。

### 責務範囲

責務範囲には、空状態の中心配置、見出し・補足説明・操作導線の構造化、ライブリージョンとしての意味付け、象徴要素の優先順位制御、バリアントに応じた色差、モーション抑制、および高コントラスト・印刷環境での表示調整を含みます。

一方で、どの画面で空状態へ遷移するか、どの失敗を `error` と定義するか、アクション押下後に何を実行するか、再試行回数や権限回復導線をどう設計するかは責務に含めません。また、画面全体の高さ確保やビューポート中央配置の責務も含めません。本コンポーネントは**割り当てられた領域の中で**中央寄せを行いますが、その領域の大きさを決めるのは上位レイアウトの責務です。

## 状態モデル

`ui-empty-state` の主要状態は、**どの状況を伝えるか、補助情報を持つか、操作導線を持つか、象徴要素をどの層で見せるか**によって読み分けます。

### 基本状態

最小状態は、`variant="default"` で、`heading` のみを持つ状態です。この状態では、余計な説明や操作を伴わず、空であることだけを簡潔に伝えます。

### 状態種別

`variant` は視覚差分の指定子ではなく、**state presenter の状態種別**です。意味は次表のとおりです。

| `variant` 値 | 意味                     | 想定用途                                   |
| ------------ | ------------------------ | ------------------------------------------ |
| `default`    | 中立的な内容不在状態     | 初期状態、未作成、未配置                   |
| `search`     | 条件不一致による結果不在 | 検索語や絞り込み条件に一致する結果がない状態 |
| `error`      | 継続表示不能な失敗状態   | 読み込み失敗、取得失敗、再試行が必要な状態 |

本コンポーネントは狭義の empty のみでなく、**no-result** および **failure** を含む広義の状態提示を担います。したがって `error` は命名上の例外ではなく、state presenter の 1 種別として扱います。ただし、失敗原因の業務分類や復旧戦略そのものは本契約の責務ではありません。

### 通知領域状態

通知対象は `heading` と `description` から成る状態メッセージ領域です。`action` は通知領域に含めません。通知の有無は `variant` ではなく `announce` によって決まります。

- `announce="off"` の場合、状態メッセージ領域は自動通知対象として扱いません。
- `announce="polite"` の場合、状態メッセージ領域のみを穏やかなライブリージョンとして扱います。

したがって、状態変化として支援技術へ伝えるべき内容は、操作ラベルではなくメッセージ本文に載せます。

### アクション有無状態

`action` に**対話要素**が存在する場合、アクション領域は表示されます。対話要素が存在しない場合、アクション領域は非表示となります。プレーンテキストのみを `action` に与えた構成は描画され得ますが、正規入力としてのアクションあり状態には数えません。

複数の `action` を与えた場合、アクション領域は `flex-wrap: wrap` により折り返し可能な配置を取ります。操作数自体に厳格な契約上限は設けませんが、情報順位の明確さを保つため、1 個または 2 個に抑える構成を推奨します（SHOULD）。

### 象徴要素状態

象徴要素は `illustration` と `icon` の 2 層を持ちます。優先順位は次のとおりです。

1. `illustration` が存在する場合は `illustration` を表示します。
2. `illustration` が存在せず `icon` が存在する場合は `icon` を表示します。
3. どちらも存在しない場合は、象徴要素を表示しない text-first の状態提示を既定とします。

`icon` または `illustration` の未指定を埋めるための**フォールバックアイコン表示は必須契約に含めません**。象徴要素がない状態でも、`heading` と必要に応じた `description` によって主意味が成立しなければなりません（MUST）。

### 見出し欠落状態

`heading` に可視テキストが存在しない場合でも描画は継続することがありますが、これは契約違反状態です。長期的には開発時エラー相当として扱うべき入力であり、互換性を保証しません。

### スロット同期状態

本コンポーネントは、初回描画後および各スロットの再割当に応じて、`heading`、`description`、`action`、`illustration` の内容を再評価します。したがって、スロット内容の動的追加・削除に追従し、説明領域やアクション領域の表示有無、象徴要素の優先関係は再同期されます。

一方で、割り当て済みノード内部の任意の深い変更すべてに対する追従までは公開契約に含めません。追従保証はスロット再割当を基準とします。

## DOM / Accessibility

ルートは `:host` です。Shadow DOM 内部に単一の `<section class="container">` を持ち、その内部を**状態メッセージ領域**と**操作領域**へ分離します。`illustration`、`icon`、`heading`、`description` は状態メッセージ領域に属し、`actions` はその外に置きます。

```text
<ui-empty-state variant="..." announce="off|polite">
  #shadow-root
    <section class="container" data-variant="...">
      <div class="message" data-announce="off|polite">
        <div class="illustration" aria-hidden="true">
          <slot name="illustration"></slot>
        </div>
        <div class="icon" aria-hidden="true">
          <slot name="icon"></slot>
        </div>
        <div class="heading" id="empty-state-heading">
          <slot name="heading"></slot>
        </div>
        <div class="description" id="empty-state-description">
          <slot name="description"></slot>
        </div>
      </div>
      <div class="actions" aria-labelledby="empty-state-heading">
        <slot name="action"></slot>
      </div>
    </section>
</ui-empty-state>
```

### Accessibility 契約

アクセシビリティ上の重要点は次のとおりです。

- `announce="polite"` の場合に限り、状態メッセージ領域へ `role="status"`、`aria-live="polite"`、`aria-atomic="true"` を適用します。
- `announce="off"` の場合、状態メッセージ領域はライブリージョンであることを前提としません。
- `action` はライブリージョンの本文に含めません。
- `aria-label` は自動生成しません。
- 読み上げ内容は `heading` と `description` の可視テキストに依存します。
- 状態理解に必須の意味は `heading` と、必要に応じた `description` に置き、`icon` や `illustration` のみに依存しません。
- `icon` および `illustration` は既定では `aria-hidden="true"` の補助的視覚表現として扱います。
- `variant` は状態種別を表しますが、それ単独で支援技術向けの意味変化や通知を保証しません。
- `heading` は必須です。文書アウトラインに適した見出しレベルは利用側が選択します。
- `action` に配置する操作要素は、利用側で個別にキーボード操作可能でなければなりません（MUST）。

本コンポーネントで重要なのは、**常時通知すること**ではなく、**必要な場合にだけ、必要な範囲を、過不足なく伝えること**です。したがって、empty state を一律に live announcement 前提で扱う設計は採りません。

### 内部派生状態

説明有無、アクション有無、イラスト有無などの派生状態は内部描画制御のための内部状態です。これらは公開入力ではなく、ホスト属性として外部へ観測可能な API にしません。利用者は派生状態へ依存して外部ロジックや CSS を組んではなりません（MUST NOT）。

## Visual Contract

`ui-empty-state` の視覚契約は、空白や失敗を**静かで短い状態提示**として成立させることにあります。強いプロモーションや警告バナーではなく、**読む流れの中断を最小限に抑えつつ、必要な意味差だけを見せること**を目的とします。

### 情報順位

- 見出しは主情報です。
- 説明文は見出しの補足です。
- アクションは必要な場合にのみ表示される導線です。
- イラストレーションは文脈説明を補助する上位視覚表現です。
- アイコンは簡潔な補助視覚表現です。

したがって、視覚的主役は常に `heading` です。`illustration` や `icon` は意味を補助しますが、本文や見出しの可読性を奪うほど強調してはなりません。

### レイアウト

ホストは縦方向の flex コンテナとして振る舞い、内容は中央揃え・中央寄せとします。内部 `.container` は全幅を取りつつ、各領域を縦方向に積み上げます。ただし、この中央寄せはコンポーネントに割り当てられた領域の中でのみ成立します。画面全体の中央に見せるために必要な高さ確保は上位レイアウトが担います。

視覚監査可能性を高めるため、最小限の定量条件を次のとおり固定します。

- `heading` と `description` を含むメッセージ領域の最大インラインサイズは **40ch 以下**とします。
- `heading` と `description` の間隔は **`--space-2` 以上**とします。
- メッセージ領域と `actions` の間隔は **`--space-4` 以上**とします。
- `icon` の最大寸法は **`--icon-xl` 以下**とします。
- `illustration` の最大幅は **`--empty-state-illustration-max-width`** で制御し、メッセージ領域より視覚的主役になってはなりません。
- `error` であっても、背景塗り・太線ボーダー・点滅・シェイク等の強い警告表現には依存しません。
- `icon` および `illustration` がない場合、象徴要素のための余白は折り畳まれなければなりません（MUST）。

### 視覚仕様

- `default` は中立的な文字色・補助色で構成します。
- `search` は条件不一致を補助的に示す穏やかな差分を許可します。
- `error` は失敗状態であることが判別できる差分を持ちますが、警告バナー相当の強度にはしません。
- `description` は見出しより一段弱い文字色で補助情報として見せます。
- `icon` は本文より弱く、補助情報として視認できる強度に保ちます。

### モーション

ホスト要素は登場時に軽い出現アニメーションを持ち得ます。ただし、動きは状況理解を補助する最小限にとどめ、注意喚起そのものをアニメーションへ依存させません。

### スタイル拡張面

公開されたスタイル拡張面は限定します。コンポーネント固有の公開 CSS Custom Property は `--empty-state-illustration-max-width` です。利用者は、コンポーネント単位で意味を持つ上書きは、このような専用プロパティを通じて行います。

一方で、`--fg-*`、`--space-*`、`--text-*`、`--icon-*` などは基盤トークン参照です。これらはデザインシステム全体の値として解決されるものであり、`ui-empty-state` 固有 API としては扱いません。

### 参照トークン

本コンポーネントは、主として次のトークンに依存します。

| 用途                     | トークン                                              |
| ------------------------ | ----------------------------------------------------- |
| 見出し色                 | `--fg-default`                                        |
| 説明文色                 | `--fg-muted`                                          |
| search アイコン色        | `--fg-subtle`                                         |
| error 見出し・アイコン色 | `--fg-danger`                                         |
| 余白                     | `--space-2` / `--space-3` / `--space-4` / `--space-6` |
| 文字サイズ               | `--text-lg` / `--text-sm`                             |
| フォント太さ             | `--font-semibold` / `--font-normal`                   |
| 行間                     | `--line-height-tight` / `--line-height-normal`        |
| アイコン寸法             | `--icon-xl` / `--icon-lg`                             |
| 動き                     | `--duration-normal` / `--ease-out`                    |
| イラスト最大幅           | `--empty-state-illustration-max-width`                |

## 環境別の振る舞い

### Reduced Motion

`prefers-reduced-motion: reduce` 環境では、登場アニメーション時間を極小化し、反復回数を 1 回に固定します。状態認識を動きに依存させません。

### Forced Colors

`forced-colors: active` 環境では、`icon` に `GrayText` を使用し、`error` の `icon` および `heading` は `CanvasText` へフォールバックします。独自色の意味差よりも、システム配色下での可読性を優先します。

### Print

`@media print` では、装飾的な `icon` および `illustration` は非表示としてよいものとします。これらは紙面上の主意味入力ではないためです。

`actions` については一律非表示を既定契約にしません。印刷時の扱いは次の原則に従います。

- URL を伴う補助参照リンクなど、紙面上でも意味が残る導線は表示を維持してよいものとします。
- `button` 等の純粋な画面内操作は非表示としてよいものとします。
- 印刷後も、`heading` 単独、または `heading` と `description` によって状態の主意味が成立しなければなりません（MUST）。

したがって、復旧手順や補助説明を紙面に残す必要がある場合は、`action` の存在だけに依存せず、必要な文脈を `description` にも保持します。

### Dark Surface

暗色背景上でも、見出しと説明文のコントラストは WCAG AA 相当の可読性を満たすことを前提とします。色そのものはトークン差し替えで吸収します。

## 関連契約

### アクション要素契約

`ui-empty-state` 自身はアクションの意味や挙動を定義しません。`action` スロットに何を置くかは利用側責務です。ただし、次を満たします。

- アクション要素はキーボード操作可能でなければなりません（MUST）。
- 主要操作が存在する場合でも、本文や見出しの読書リズムを奪う過剰な装飾に依存しません。
- 正規入力として扱うアクション数は 0 個から 2 個までです。
- 複数アクションを置く場合、情報順位は DOM 順序で明示しなければなりません（MUST）。
- 先頭アクションが第一候補です。後続アクションは補助または代替の位置づけとして扱います。
- 主要アクションは 1 個までです。2 個目を置く場合は secondary action として扱います。
- 3 個以上のアクションは描画され得ますが、公開契約上の正規入力ではありません。
- 折り返し後の見た目が複数行になっても、優先順位は表示行ではなく DOM 順序で解釈します。

### 見出し・説明文契約

`heading` と `description` は、どちらも**短い状態メッセージ単位**として扱います。公開契約上の正規入力は、空白テキストノードおよび comment node を除いたトップレベル割当ノードが 1 個である構成です。

- `heading` は 1 個の主見出しです。
- `heading` はインライン表現を含められます。
- `heading` に複数のトップレベルノード、複数の見出し、対話要素を含む構成は非正規入力です。
- `description` は 1 個の説明ブロックです。
- `description` はインライン強調、インラインコード、補助的リンクを含められます。
- `description` に複数のトップレベルノード、リスト、表、主要操作群を含む構成は非正規入力です。
- 実装上描画できることと、公開契約上保証することは同一ではありません。

この制約は、「意味が一つかどうか」という観念的判定に依存するためではなく、**トップレベル割当ノード数**という機械判定可能な基準へ落とすために置きます。

### 説明文内リンク契約

`description` 内のリンクは、empty state の意味を補助する**補助参照導線**として扱います。これは `action` スロットの代替ではありません。

- `description` にリンクを含めること自体は許可します。
- 静かな状態提示を保つ観点から、補助参照導線は 0 個または 1 個に抑えることを推奨します（SHOULD）。
- リンクは短く、単独でも意味が取れるテキストであることが望まれます（SHOULD）。
- リンク先へ進まなくても、empty state の主意味と第一行動は理解できなければなりません（MUST）。
- 主要な復旧導線、再試行導線、作成導線は `action` に置くことを推奨します（SHOULD）。
- リンクだけが説明の主意味になる構成、リンク先へ遷移しなければ状態意味が成立しない構成には依存してはなりません（MUST NOT）。

### アイコン契約

`icon` スロットは簡潔な象徴表現を受け取ります。`icon` は**装飾専用**ではなく、`heading` と `description` により既に成立している状態意味を**補助的に補強する視覚表現**として扱います。

`icon` は状態の主意味や主要操作の唯一の入力になってはなりません（MUST NOT）。`icon` 未指定時にフォールバックアイコンを必ず描画することは、本契約の必須条件には含めません。

### イラストレーション契約

`illustration` は `icon` より上位の補助視覚表現です。`illustration` もまた、主意味の唯一入力ではなく、既に成立している状態意味を広い文脈で補助する表現として扱います。

`illustration` が存在する場合、`icon` は表示されません。`illustration` に状態理解の必須情報や主要操作の唯一導線を担わせてはなりません（MUST NOT）。

### スタイル拡張契約

`ui-empty-state` は `::part` を公開しません。外部からの主な拡張面は、公開した CSS Custom Properties とスロット内容そのものです。

利用者は、内部 class 名、`data-variant`、内部派生状態、Shadow DOM 構造などの内部識別子に依存してはなりません（MUST NOT）。将来変更時に互換性を保証しません。

### 公開イベント・公開メソッド契約

`ui-empty-state` は独自の公開イベントを発火しません。また、公開メソッドも持ちません。利用側が監視すべきイベントや imperative API は、`action` スロットへ与えた要素側の契約に属します。

### 開発時警告契約

`heading` に可視テキストが存在しない場合、実装は開発時に警告を出し得ます。これは利用側へ契約違反を知らせる補助手段であり、描画停止や例外送出を意味しません。

## 境界条件

### 見出しのみ

`heading` のみを与えた場合、最小構成の empty state として描画します。説明文とアクションは表示されません。

### 説明文あり

`description` に可視テキストがある場合、見出しの下に補足説明を表示します。説明文は最大 `40ch` で折り返します。

### 空白のみの説明文

`description` が空白文字のみで構成される場合、内容なしとして扱います。説明領域は表示されず、`description` があることを前提とした余白にも依存しません。

### アクションなし

`action` が存在しない場合、アクション領域は表示されません。

### 複数アクション

複数の `action` を与えた場合でも表示を継続します。狭い幅では折り返しを許可します。ただし、優先順位は DOM 順序で解釈します。先頭要素が第一候補であり、後続要素は補助または代替導線です。正規入力は 2 個までとし、3 個以上は非正規入力です。

### `illustration` と `icon` の併存

両方を与えた場合、`illustration` を優先し、`icon` は非表示となります。両者同時表示には依存しません。

### `icon` 未指定

`icon` が指定されない場合でも描画は継続します。`illustration` も存在しない場合、本コンポーネントは text-first の状態提示として成立します。主意味は `heading` と、必要に応じた `description` によって伝えます。

### 見出し欠落

`heading` が欠落した場合でも描画は継続しますが、アクセシブルな empty state としては契約違反です。実装は警告を出し得ます。

### 複数の `heading` ノード

複数の見出しノードまたは複数の兄弟ノードを `heading` に与えた場合、描画が継続することはあり得ますが、公開契約上は非正規入力です。単一の主見出しとしての意味保証は行いません。

### 複数の `description` ブロック

複数段落、複数の兄弟ブロック、リスト、表などを `description` に与えた場合、描画が継続することはあり得ますが、公開契約上は非正規入力です。単一の短い説明ブロックとしての意味保証は行いません。

### 複数の主要アクション

複数の `action` を配置すること自体は許可しますが、複数の主要アクションを同列に置く場合、`ui-empty-state` はどれが第一候補かを自動判定しません。先頭要素を第一候補とみなす以外の意味保証は行いません。

### 補助リンクを含む説明文

`description` に補助的なインラインリンクを含めることはできますが、0 個または 1 個までとします。そのリンクを主要導線として扱う構成には依存しません。主要導線は `action` に置きます。

### 複数の説明文内リンク

`description` に複数のインラインリンクを含めた場合、描画が継続することはあり得ますが、公開契約上は非正規入力です。補助参照としての静かな説明文という性質を保証しません。

### リンクのみで成立する説明文

`description` が実質的にリンクのみ、またはリンク先へ遷移しなければ意味が成立しない文で構成される場合、公開契約上は非正規入力です。empty state の主意味はリンク先に依存しません。

### 無効な `variant`

無効な `variant` が与えられた場合、公開状態は `default` へ正規化されます。利用者は、無効値が内部だけで吸収され、属性や property に残る構成に依存してはなりません（MUST NOT）。

### 3 個以上のアクション

3 個以上の `action` を与えた場合、描画が継続することはあり得ますが、公開契約上は非正規入力です。小さな状態提示ユニットとしての情報順位を保証しません。

## 補足

`ui-empty-state` の要点は、単なる「空です」という表示ではありません。**状態の意味を短い構造へ圧縮し、必要なら次の行動へつなぎ、それでも本文の読書リズムを壊し過ぎないこと**にあります。

したがって、今後の変更でも次の 6 点は崩さない方がよいです。

1. `heading` を主情報とすること。
2. ライブリージョンの対象を状態メッセージ領域に限定すること。
3. `variant` を視覚トーンではなく状態種別として扱うこと。
4. `illustration` が `icon` より優先され、かつ既定では装飾的補助表現に留まること。
5. `description` や `action` の有無をスロット再割当に追従して同期すること。
6. 内部派生状態を公開 API にしないこと。

## 反映状況

本書の契約は、現行の `empty-state.ts` および `empty-state.stories.ts` へ反映する前提で維持します。特に次の点は、実装と Storybook の双方で継続確認する対象です。

- `announce` は公開入力として `off` / `polite` を受理し、列挙外値を `off` へ正規化すること。
- ライブリージョンはホスト全体ではなく、`announce="polite"` のときの状態メッセージ領域に限定されること。
- `variant` は `default` / `search` / `error` を受理し、列挙外値を `default` へ正規化すること。
- `icon` と `illustration` が未指定でも text-first の状態提示が正規構成として成立すること。
- `description` / `action` / `illustration` の再割当に表示状態が追従すること。
- 内部派生状態をホスト属性として公開しないこと。
- print 時に装飾要素を落としても主意味が残り、リンク型 action を一律非表示前提にしないこと。

一方で、`heading` / `description` のトップレベル割当ノード数のような非正規入力判定は、契約文書で定義していても実装側で完全には機械検証しない場合があります。この種の事項は、描画可能性ではなく**公開保証の有無**として読みます。
